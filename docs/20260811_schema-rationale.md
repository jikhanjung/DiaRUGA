## 스키마의 요점 셋

18개 모델의 자세한 모습은 `docs/20260810_db-specification.md` 와 `db-erd.md` 에 있다.
여기 적는 것은 **왜 그 모양인가**다.

```
Slide 1:N Viewpoint 1:N Image(kind = stack | frame | depth) 1:N Detection 1:N Candidate
                                    ↑
                           ObjectReview.image   UNIQUE (image, batch, mask_key)
                                    ↓ N:1
                              DiatomObject      개체 하나 = 사람이 하나로 보는 대상
```

**`batch` 가 열쇠에 들어간다** — 같은 이미지의 같은 마스크라도 **어느 검출을 보고
한 판단인지**가 다르면 다른 행이다. 사람이 그린 것은 `batch` 가 NULL 이라 그 제약이
안 잡으므로(SQLite 는 NULL 끼리 안 부딪힌다) 조건을 뒤집은 제약을 하나 더 둔다.

### 교정은 `Candidate` 가 아니라 `mask_key` 에 붙는다

FK 로 매면 재검출에서 사람의 판단이 조인 실패로 사라진다. **정규화가 덜 된 것이
아니라 소유 방향의 선택이다** — 재생성 불가한 것(교정)이 재생성 가능한 것(검출)의
자식이 되면 안 된다.

모든 교정 행이 `geom` 에 기하를 스스로 들고 있어 **검출기가 바뀌어도 읽힌다.**
지운 것도 학습의 음성 표본이다 — P04 에서 오검출 4,039건이 실제로 그렇게 쓰였다.

### `Image` 는 검출을 돌릴 수 있는 이미지 한 장이다 (P06)

열쇠는 `path` 다 — 파일 하나에 행 하나. 예전에는 합성본과 원본 프레임이 **테이블이
둘**이어서 `Detection` 이 `target`(`stack|frame`) + nullable `frame` 으로 다형 연관을
흉내 냈고, 그것이 교정의 열쇠까지 흔들었다. `(viewpoint, mask_key)` 는 시야마다 볼
이미지가 한 장일 때만 성립하는 열쇠다.

- **촬영·합성 메타는 `Frame`·`Stack` 에 그대로 있다.** `Image` 는 정체만 맡는다
- **`kind="depth"` 에는 검출이 안 붙는다** — 관행이 아니라 스키마에 적혀 있다
- **만드는 문은 `web/viewer/images.py` 하나다.** 파이프라인 네 자리와 재그룹핑이
  전부 여기를 지난다
- **`Image.viewpoint` 는 `SET_NULL`, `Image.stack` 은 `CASCADE`** — 시야를 가르면
  **프레임은 살아남고 합성본·깊이맵은 죽는다.** 방향이 반대인 것이 요점이다

이 정규화가 연 것이 **프레임별 검출을 검토할 자리**다.

### 개체와 판정은 다른 것이다 (P12 · 108)

프레임별 검출을 열어 놓으니 **같은 규조각이 초점면마다 따로 잡힌다.** 사람이 그것을
하나로 묶기 시작하면서(P11) 세 테이블이 반쯤 겹쳤고 — `ObjectReview`(판정) ·
`ObjectLink`(묶음) · `ObjectLinkMember`(멤버) — P12 에서 **둘로 모았다.**
**판정 행이 곧 멤버다.**

```
DiatomObject   이 규조각은 무엇인가        label · species · pose
   1:N
ObjectReview   이 판에서 무엇을 보았는가   removed · accepted · auto_confirmed
                                          · grade · note · geom · is_rep(대표)
```

가르는 기준은 **"초점을 옮기면 달라지는가"** 다.

- **개체의 것** — 분류·종명·자세. 같은 규조각이면 어느 판에서 보든 같다.
  묶으면 값이 하나로 합쳐지고, **엇갈리는데 사람이 안 고르면 서버가 409 로 거절한다**
  (개체가 값을 하나만 들 수 있어 "그대로 두기" 가 성립하지 않는다)
- **판정의 것** — 삭제·되살림·확인·등급·코멘트·기하. **"이 판에서는 초점이 안
  맞는다" 는 판마다 하는 말이다**

진실이 한 곳이라 **번지게 하는 코드가 없다** — 104 가 만들었던 전파 함수가 P12 에서
통째로 사라졌다. 읽는 자리 79곳은 `ObjectReview.label` 같은 **읽기 전용 통로**로
그대로 두었고, **쓰기는 `AttributeError` 다**(조용히 안 먹히는 것보다 낫다).

판정 행은 **개체 없이 설 수 없다**(NOT NULL). 그래서 행을 만드는 자리 셋(검토 저장 ·
그리기 · 카탈로그)이 **문 하나(`data.judgement_for`)를 지난다** — 규칙이 셋이면
하나만 빠뜨려도 `IntegrityError` 이거나, 더 나쁘게는 **대표 없는 개체**가 생긴다.
