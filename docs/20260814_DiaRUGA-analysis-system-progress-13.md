## 2. 카탈로그가 고치는 화면이 됐다 (P16 · 120 · `v0.13.0`)

### 2.1 무엇이 생겼나

| | 어디에 |
|---|---|
| 지우기·되살리기 | 카드의 `지운다` / `되살린다` |
| 지운 것 보기 | 거르개 `지운 것` 칩 (`?gone=1`) |
| 여러 장 한 번에 | 카드를 고르면 뜨는 띠 — 종명·유형·등급·자세 |
| 묶음 풀기 | 카드의 `묶음 N 풀기` |

**주소를 안 늘렸다.** 짚는 방식(`(슬러그, gid)` · 이미지 id · `mask_key`)과 막는
검사가 넷 다 같아서, 주소로 가르면 **같은 검사를 네 벌 적게 된다.** 대신
`act` 로 문을 갈랐다(`save`·`remove`·`restore`·`bulk`).

### 2.2 넘지 말아야 할 선 셋

이 화면은 사고가 났던 자리 위에 있다. 셋을 지켰다.

**범위를 갈아치우는 길에 안 싣는다.** `/review` 는 *그 (이미지, 묶음) 의 교정
전체를 갈아치운다* 는 전제 위에 있고 두 번 운영 자료를 잃은 자리다(14건 · 37건).
카드는 그 시야의 교정 전체를 알지 못하므로 **그 전제를 만들 수가 없다.**

**층이 다른 것을 한 payload 에 안 싣는다** (116). 지우기는
`(이미지, 묶음, mask_key)` 에 붙고 동정 다섯은 개체에 붙는다 — 116 이 바로
*시야에 붙는 표시*와 *판 단위 교정*을 한 요청으로 보내다 갈래 둘을 낸 건이다.

**읽기 전용은 되는 것처럼 보여서도 안 된다** (051). 카탈로그 JS 는
`if (READONLY) return;` 로 배선을 아예 안 건다. 더한 단추 셋도 그 줄 **아래**에
놓았다.

### 2.3 되돌릴 수 있는 일에 되돌릴 수 없는 일을 안 얹는다

계획에 없던 갈래가 하나 나왔다. `ops/check_db.py` 는 **판이 전부 오검출인 개체가
등급을 들고 있는 것**을 문제로 센다 — 등급으로 학습 대상을 고르므로 *오검출이면서
A* 는 그대로 자료 선택으로 간다. 지우기를 카드에 붙이면 그 상태가 쉽게 생긴다.

갈래 셋을 놓고 골랐다.

| | |
|---|---|
| 지우기를 거절한다 | 오검출을 발견하고도 못 지운다 — 화면이 사실을 막는다 |
| 지우면서 등급·자세를 비운다 | **되돌릴 수 있는 일(삭제)에 되돌릴 수 없는 일을 얹는다** |
| **묻고, 안 비운다** | 무엇이 남는지 말하고 사람이 고른다 ← **골랐다** |

파편으로 바꿀 때 묻는 자리(105)와 모양은 같지만 **결과가 반대다.** 파편 지정은
"이것은 완형이 아니다" 라 등급이 **뜻을 잃는** 것이고, 삭제는 되살릴 수 있어
등급이 **다시 쓰일 수 있는** 값이다.

### 2.4 지운 것을 되살릴 자리

지우기 단추만 붙이면 **되돌릴 수 없는 단추**가 된다. 그래서 같은 판에 둘을 함께
만들었다 — 지운 카드는 **그 자리에서 잠기고 `되살린다` 로 바뀌고**, `지운 것`
칩으로 나중에도 찾아간다.

**그 화면에서는 파편을 안 감춘다.** 기본 화면은 파편을 감추는데(2026-08-11 방침)
그 규칙이 그대로 걸리면 **파편으로 지운 개체는 되살릴 자리를 잃는다** — 살아
있는 교정의 65%가 파편이다. 렌더 결과를 눈으로 보다 잡았다.

## 3. 분류가 하나 늘었다 (122 · `0037` · `v0.13.1`)

`Rhizosolenia` — `Eucampia`·`Chaetoceros`([038](../devlog/20260804_038_chaetoceros.md))에
이어 셋째 속이다.

| 칸 | 값 |
|---|---|
| 약칭 | `RHZ` (속명이 길다 — 목록 표의 열이 넓어진다) |
| 단축키 | **`t`** (`q·w·e·r` 다음. `d`=그리기·스페이스=삭제·화살표와 안 겹친다) |
| 색 | 연보라 `185,130,255` |

**색을 고르는 데 규칙이 있다.** 색은 아직 표에서 뿜어져 나오지 않아 `ClassDef` 와
CSS 두 자리에 산다. 그래서 두 가지를 봤다.

- **색상환의 빈자리** — 분류가 쓰는 색만이 아니라 **화면이 쓰는 색까지** 놓고
  봐야 한다(빨강=지운 것 · 주황=경고 · 초록=정상 · 하늘=강조 · 금색=고른 개체).
  전부 늘어놓으면 **파랑과 분홍 사이 108° 가 가장 큰 빈자리**이고 그 한가운데가
  보라 266° 다
- **실제로 놓이는 네 자리를 그려서** — 배지 · 사진 위 마스크 · 윤곽만 보기 ·
  크롭 테두리. 후보로 놓았던 하늘색은 **봉상 파편과 사실상 같은 색**이라
  견본에서만 갈렸다

**행 하나로 안 끝난다.** 여덟 칸(`label`·`short`·`badge`·`color`·`hotkey`·
`counted`·`is_taxon`·`sort_order`)에 **CSS 여덟 자리**까지다. 하나라도 비면
**예외는 안 나고 그 분류만 조용히 다르게 굴러간다.**

> **이미 붙은 교정은 안 옮긴다.** 봉상으로 적어 둔 것 중 몇이 Rhizosolenia 인지는
> 사람이 봐야 안다. 카탈로그 거르개에서 `봉상` 을 골라 넘기며 옮기는 것이 지금
> 할 수 있는 일이다.

## 4. 오래 숨어 있던 고장 — 개수 줄의 `Chaetoceros`

검출 화면 머리의 개수 줄(`후보 12개 (rod 5, round 3…)`)을 만드는 자리가 **분류
다섯을 손으로 박아 두고 있었다**: `rod`·`round`·`rod_frag`·`round_frag`·
`eucampia`.

**`Chaetoceros` 는 표에 든 뒤로 그 줄에 한 번도 안 나왔다.** 040 이 `ClassDef` 에
행을 넣으면서 이 자리를 안 고쳤고, **예외도 경고도 없어서** `v0.10.x` 부터
`v0.13.0` 까지 그대로였다. 같은 목록이 **두 군데**에 있었다.

하나로 모으고 **표의 차례를 그대로 따르게** 했다 — 다음 분류는 코드를 안 고쳐도
낀다.

> **목록을 박는 것과 규칙을 박는 것은 다르다.** 개수 줄은 *무엇을 셀 것인가* 라
> 표를 따라야 하고, 세장비로 형태를 가르는 자동 판정은 *어떻게 가를 것인가* 라
> 표와 무관하다. 후자에 표를 물리면 **"엔진이 속을 판정한다" 는 틀린 그림**이
> 된다 — 속은 사람이 붙인다. 화면·파이프라인을 훑어 남은 자리가 뒤엣것뿐임을
> 확인했다.

## 5. 검토 화면에서 깊이 맵을 뺀다 (123 · `v0.13.1`)

시야 검토의 사진 줄에 **합성본 · 깊이 맵 · 프레임**이 나란히 놓였는데, 깊이 맵은
검토에 쓸 일이 없다 — Z 좌표가 없어 상대값이고 **검출이 붙지 않는 판**이라
골라도 볼 것이 없다.

**자료를 지우는 것이 아니다.** `Stack.depth_path` 도 `Image` 행도 그대로 두고
화면 조각 한 덩이만 걷었다. 볼 일이 생기면 되붙이면 된다.

**따라온 것 둘이 이 일의 절반이었다.**

- **주석 여섯**이 깊이 맵을 *"검출이 없는 판"의 대표 예*로 쓰고 있었다. 가드는
  남아야 한다 — `curKey` 가 null 이 되는 자리가 둘이었는데(깊이 맵 · **그 묶음에
  검출이 없는 프레임**) 하나만 없어졌다. **예가 사라진 채 두면 다음 사람이
  캐러셀에서 그것을 못 찾고 "이 갈래는 이제 없다" 고 읽어 가드를 뗀다**
- **116 의 회귀 시험**이 깊이 맵을 밟고 있어 깨졌다. 지우면 가드가 함께 사라지는지
  먼저 봤다 — 아니었다. 같은 파일에 *검출 없는 프레임* 을 밟는 시험이 있어 같은
  갈래를 지난다. 깊이 맵 케이스만 걷고 **왜 걷었는지를 머리말에 적었다**

**되살려서 잡히는 것을 보고 나서 "있다" 고 말한다** (064). 고장을 일부러 내
보는 과정에서 **시험 자체가 틀린 것을 두 번 잡았다.**

**첫째, 실패할 수 없는 시험이었다.** "읽기 전용 화면에 단추가 안 놓인다" 를
세워 놓고 일부러 단추를 내보게 고쳐도 통과했다 — 그 시험의 자료에 **카드가
0장**이었다(검토 대상을 다른 묶음으로 옮기는 쪽으로 세워서 화면에 아무것도 안
났다). 자동 처리가 안 끝난 슬라이드로 바꿔 세우고, **첫 줄이 카드가 있는지부터
보게** 했다.

같은 종류를 분류 쪽에서도 만났다 — 단축키 겹침 시험을 **마이그레이션만 도는
DB** 에 대고 짰는데, 거기에는 `round`·`rod`·`eucampia` 가 **없다**(초기 반입으로
들어온 것들이라서다). `Eucampia` 와 같은 키를 줘도 통과했다.

**둘째, 표시를 세고 있었다.** 깊이 맵이 안 보이는지를 `"깊이 맵"` 이라는 글자로
셌더니 **JS 주석에 걸렸다** — 왜 뺐는지 적어 둔 그 주석이 브라우저로 그대로
나간다. 글자로 세는 시험은 주석을 고칠 때마다 깨지고, 정작 단추가 되살아나도 그것을
못 가른다. `data-title`·`alt`·`.cap` **세 요소**를 짚게 바꿨다.

배포 → smoke → **화면 여덟을 손으로 열기** → `check_db` → 테스트 인스턴스 순으로
갔다.

스키마를 조이지 않고, 파이프라인은 `ClassDef` 에 쓰지 않는다. (026 이 판을 묶었다
푼 자리이고, 055·057 이 함께 올려야 하는 경우를 적어 둔 자리다.)

**`check_db` 의 경고는 1건 그대로다** — `obj#8094`(묶음에 지운 마스크). 08-13
배포 전 사본을 같은 질의로 세어 **원래 있던 것**임을 확인했다. *있던 경고와 새
경고를 가르지 않으면 원래 있던 1건을 방금 만든 것으로 읽는다.*

## 9. 그 밖에 — 작업 트리를 둘로 갈랐다

같은 계정의 작업 트리 하나에서 세션 둘이 돌다가 **한쪽이 브랜치를 파고
체크아웃하자 다른 쪽의 커밋이 그 브랜치로 갔다.** 잃은 것은 없다(브랜치를 같은
자리로 옮겨 수습했다).

**브랜치를 따로 파는 것으로는 안 갈린다** — 트리가 하나면 HEAD 도 하나라 커밋은
그때 HEAD 가 있는 곳으로 간다. `git worktree` 로 디렉토리를 따로 내어 갈랐다.

```
/home/sclee/projects/DiaRUGA      work/20260814-sclee      색인·WoRMS
/home/sclee/projects/DiaRUGA-ui   work/20260814-sclee-ui   뷰어 UI + 배포
```

**색인 쪽 작업이 나란히 돌았다** — WoRMS 대조표 통합, "없는 이름" 을 속을 근거로
가르기, AlgaeBase 반입, Schmidt 색인의 `Tafel` 번호 오독 114건 정정. 그쪽은
`devlog/121` 이고 **아직 `main` 에 병합되지 않았다** — 이 보고서는 그 내용을
담지 않는다. 다음 차수에서 함께 적는다.

그중 **뷰어에 걸릴 것 둘**만 미리 적어 둔다(P15 가 도감을 DB 로 넣을 때).

- **`Tafel` 번호를 열쇠로 쓰지 않는다.** OCR 로 읽은 값이라 114건이 틀려 있었다.
  **쪽 번호는 원래 맞았다** — 짚는 것은 쪽으로, Tafel 은 보여주기만 한다
- **AlgaeBase 와 WoRMS 가 엇갈리는 이름이 있다.** 화면에 학명을 하나만 내는

  사실이 화면에서 사라진다
