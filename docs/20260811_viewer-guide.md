## web/ — 확인·교정 뷰어 (Django 5.2)

**읽기·쓰기 모두 DB 다.** 예전에는 ORM 없이 `groups_*.json`·`out/*.json` 을 mtime
캐시로 직접 읽었는데, P02 에서 SQLite 로 옮겼다. `pipeline/judge.py` 를 뺀 나머지는 전부
`web/viewer/` 안에 있다:

| `naming.py` | 폴더 이름 → 층. **규칙은 여기 하나뿐이다** |

**엔진 비교는 검토 화면 안에서 한다** — 사진 위 탭줄의 `◉ SAM / ○ YOLO`
라디오(`?batch=<실행>`)다. 묶음을 한 표로 훑던 `/engine/` 화면은 075 에서 지웠다.

지도는 권역마다 투영이 다르다 — 남극 EPSG:3031(극구면), 한국 EPSG:5179. `전체` 탭에
지도가 없는 것은 **섞을 수 없기 때문이다.** 좌표가 없는 지역은 주황 마커 + 오차 원으로
대략값임을 드러낸다.

**목록의 "검출" 칸과 상세 화면의 검출 수는 다른 것을 센다.** 목록은
`ClassDef.counted` 가 켜진 분류만 더한다 — 파편을 개체로 세면 밀도가 부푼다(369cm
923 → 444). 상세 화면의 "검출 N → 검토 후 M" 은 검토가 얼마나 걸러 냈는가를 보는
줄이라 파편도 센다.

**목록의 마스크·배지·개수는 요청할 때마다 다시 계산한다** — 교정하고 목록으로 오면
그 자리에서 반영돼 있다. 다만 두 군데서 옛 화면이 남을 수 있어 막아 두었다:

- 이미지 주소에 원본 mtime(`v=`)을 박고 `Cache-Control: immutable` 로 보낸다.
  주소가 그대로면 합성본을 다시 만들어도 브라우저가 옛 그림을 붙잡는다. 반대로
  주소가 내용에 따라 바뀌면 마음껏 캐시해도 늘 맞고, 두 번째 방문이 빨라진다
  (`v=` 없이 들어온 주소는 `no-cache` 로 답한다)
- **뒤로 가기**로 돌아오면 브라우저가 캐시된 화면을 되살린다(bfcache). 그때는
  `pageshow` 에서 다시 받는다 — 교정·검토 표시가 옛것이면 안 된다

캐시된 값을 손대지 않는 것도 중요하다. `detection_for()` 는 후보를 **복사한 뒤**
교정을 얹는다 — 원본 dict 에 `removed`·`cls`·`note` 를 써 넣으면 그 값이 캐시에
남아, **교정을 되돌려도 옛 상태가 계속 따라붙는다.**

검출 레이어는 구운 오버레이 JPG 가 아니라 좌표에서 박스와 instance mask 를 SVG 로
직접 그린다.

시야 화면은 **검출 화면 / 개체 목록** 두 탭이고, 사진 아래 **캐러셀**에 합성본 ·
깊이 맵 · 원본 프레임이 모두 걸린다. 커서를 올리면 미리 보고 클릭하면 교체되는데,
**검출 레이어는 그대로 얹혀 있어 합성본이 아닌 원본에서도 검출이 맞는지 확인할 수
있다.** 다만 원본 프레임은 ECC 정렬 이전이라 마스크가 조금 어긋난다.

캐러셀은 `« ‹ [썸네일 목록] › »` 꼴이다. 썸네일에 붙은 파란 막대는 **선명도**
(그룹 내 최고 대비 비율)이고 원본 프레임에만 있다 — 합성본·깊이 맵에는 선명도가
없다. 막대 유무로 사진 위치가 어긋나지 않게 썸네일은 위에서부터 쌓는다(버튼의
기본 수직 중앙 정렬을 끈다).

캐러셀은 **← →** 로도 넘기고, **Ctrl+← →** 는 사진을 거치지 않고 곧바로 이웃
시야로 간다(`« »` 버튼과 같다 — 묻지 않는다). 마지막 사진에서 → 를 한 번 더 누르면 다음 시야로
넘어갈지 묻고(첫 사진에서 ← 도 대칭으로 동작한다), **다시 묻지 않기**를 고르면
이후로는 바로 넘어간다(localStorage). 이전 시야로 거슬러 갈 때는 그 시야의 마지막
사진에서 시작해 ← → 왕복이 끊기지 않는다. 시야를 옮기기 전에 **지연 저장 중인
교정을 먼저 밀어낸다** — 지우고 곧바로 → 를 눌러도 기록이 사라지지 않는다.

| 조작 | 동작 |
|---|---|
| 휠 / 우클릭 드래그 | 확대 / 이동 |
| hover | 개체 통계 팝업 |
| 클릭 · Shift+클릭 · 드래그 | 선택 · 추가/해제 · 범위 선택 |
| 같은 자리 반복 클릭 | **겹친 개체를 작은 것부터 돌려 가며 선택** (n/N 표시) |
| 우클릭 (정지) | 컨텍스트 메뉴 — 삭제 · **분류 지정** · **코멘트** |
| 빈 곳 클릭 | **마스크가 그 자리를 덮는** 탈락 후보를 잘라 보여줌 → 고르면 검출로 인정 |
| 좌상단 버튼들 | 선택 · 배율 초기화 · 삭제분 · 실행취소 · 교정 초기화 · **마스크 그리기** |
| **d** 또는 그리기 버튼 | 점을 찍어 마스크를 새로 그린다. **마지막 점에서 커서까지 점선이 따라온다** |
| 우클릭 → 모양 고치기 | 있는 마스크의 점을 끌어 옮긴다 (선분을 누르면 점이 는다) |
| 하단 가운데 **검토 완료** | 이 시야를 다 봤다고 표시 → **다음 시야로 이동** (목록에 ✓ 검토 배지) |
| 우상단 체크박스 | bbox · mask · **탈락** 표시 토글 (localStorage 에 남는다) |
| 캐러셀 hover / 클릭 | 그 사진 미리보기 / 교체 |
| **← →** 또는 **‹ ›** | 캐러셀 앞뒤 사진. **끝에서 한 번 더 누르면 이웃 시야로 넘어갈지 묻는다** |
| **« »** 또는 **Ctrl+← →** | 묻지 않고 바로 이웃 시야로 (없으면 비활성) |

교정 버튼은 사진 위에 얹혀 있다 — 좌상단에 도구, 하단 가운데에 **검토 완료**,
우상단에 레이어 토글, 우하단에 스케일바. 사진에서 눈을 떼지 않고 조작하려면
버튼이 사진 위에 있어야 한다(배율 표시는 남은 좌하단으로 뺐다).

**검토 완료**는 `ViewpointReview.done` 에 저장되고 시야 목록에 `✓ 검토` 배지로
나타난다. **묶음마다 따로다**(073) — `sam2-전수` 를 다 봤다고 `yolo-3차` 를 본
것이 아니기 때문이다. 시야 코멘트는 반대로 묶음과 무관해서 `batch=NULL` 인 줄에
따로 산다. **교정이 하나도 없어도 켤 수 있다** — 고칠 것이 없어서 기록이 빈 시야와
아직 보지 않은 시야는 전혀 다른 것이고, 그 구분이 재현율 실측과 학습 데이터 선별의
근거다.

완료로 표시하면 **곧바로 다음 시야로 넘어간다**(묻지 않는다 — 누른 사람의 뜻이
분명하다). 해제할 때는 한 번 더 묻는다 — 잘못 눌러 풀리면 "다 본 시야"라는
표시가 조용히 사라지기 때문이다.

#### 엔진 고르기는 이 화면 안에 있다

사진 위 탭줄의 `◉ SAM 0 ○ YOLO 3` 라디오다 — 누르면 **시야는 그대로 두고** 그림 위의
개체만 바뀐다. 이웃 시야로 넘어가도 고른 엔진을 들고 간다.

**묶음이 아니라 엔진으로 접는다.** 한 엔진에 묶음이 여럿이면 *지금 보는 것 → 현재
검출을 낸 것 → 나중 것* 순으로 대표를 세운다. 그래서 `yolo-4차` 를 쌓아도 칸이
늘지 않고 대표만 바뀐다.

#### 검출 결과만 보기 (`/d/<slug>/crops/`)

시야 목록의 **검출 결과만 보기** 링크. 검출된 개체만 bbox 로 잘라 썸네일로
늘어놓는다 — 시야를 하나씩 넘겨보지 않고 "이것들이 정말 규조각인가" 를 한 화면에서
훑기 위한 화면이다. **크기 내림차순이라 의심스러운 것(작고 밋밋한 것)이 뒤에 모인다.**
테두리 색이 판정(봉상·원형·수동복구)이고, 누르면 그 시야로 간다.
형태로 거를 수 있다(`?cls=rod|round|manual`).

**방향을 세워서 보여준다** — 마스크 폴리곤의 주축을 구해 **장축을 세로로** 돌린다.
방향이 통일되면 형태를 나란히 비교할 수 있다. 축 비율이 1.15 미만이면(원형처럼
방향이 뜻 없는 것) 돌리지 않는다 — 보간으로 흐릴 이유가 없다. `원래 방향` 칩으로
사진에 있는 그대로도 볼 수 있다(`?upright=0`).

주축은 **폴리곤의 면적 모멘트**를 닫힌 해로 풀어 구한다. 꼭짓점만 PCA 하면
`approxPolyDP` 로 단순화된 점 간격이 고르지 않아 결과가 치우친다. 회전과 자르기는
한 번의 affine 변환으로 함께 한다 — 잘라서 돌리면 모서리가 비고 두 번 보간하게 된다.
합성 타원(0·20·45·70·110·160°)으로 넣고 **결과 이미지를 다시 재서** 전부 90°(세로)로
서는 것을 확인했다.

썸네일마다 **스케일바**가 붙는다(1·2·5 눈금, 이미지 폭의 40%를 넘지 않게 내림).
바는 칸이 아니라 **이미지에 붙인다** — `object-fit` 여백만큼 길이가 어긋나기 때문이다.
감싼 요소가 이미지를 꼭 감싸므로 백분율이 곧 이미지 폭이 된다. 크롭이 몇 µm 폭인지
알 수 있는 것은 회전량과 결과 크기를 **자르기 전에 확정**해 두기 때문이다(여백까지
포함해서). 자르는 쪽에서 여백을 따로 더하면 그 값을 알 수 없다.

크롭은 서버가 잘라 `/data3/DiaRUGA/.thumbcache/` 에 캐시한다(개체마다 한 장, 여백 8%).
개체가 데이터셋마다 700~1,100개라 **한 페이지에 500개까지만 그리고** 나머지는
`?offset=` 으로 넘긴다.

화면에는 **1600 px 축소본**을 띄운다(원본 2752 px, 134 KB vs 606 KB). 그대로
확대하면 없는 화소를 늘리는 셈이라, **그려지는 폭이 지금 이미지의 실제 화소를 넘는
순간 원본으로 갈아 끼운다**(`naturalWidth` 로 재므로 축소본 폭을 코드에 박지 않는다).
요소도 배율도 그대로여서 화면은 흔들리지 않고 선명도만 올라간다. 캐러셀 hover
미리보기는 축소본을 쓴다 — 커서만 지나가는데 600 KB 를 받으면 무거워진다.

좌하단 **배율 표시는 원본 화소 기준**이다. 화면에 맞춘 상태를 100% 라고 하면 "지금
원본을 다 보고 있는가" 를 알 수 없다 — 2752 px 을 1460 px 폭에 맞춰 놓은 것이라 실제로는
`53%` 다. `100%` 는 원본 1화소가 화면 1화소라는 뜻이고, 원본을 받아 온 뒤에는 `· 원본`
이 붙는다. areolae 를 축소본을 늘린 화면으로 판단하면 안 되므로 무엇을 보고 있는지
드러나야 한다.

**선 두께는 확대해도 그대로다.** canvas 가 `scale(k)` 로 커지므로 두께를 쓰는 곳마다
`calc(2px * var(--inv))` 로 역수를 곱한다(`--inv` = 1/배율, `applyTransform()` 이 얹는다).
bbox 테두리·hover 후광·유령 ✕ 가 모두 여기 걸려 있다. 예전에는 JS 가 요소마다
`Math.max(1, 2/k)` 로 계산했는데, **2배를 넘으면 1px 하한에 걸려 오히려 배율만큼
두꺼워졌다**(12배에서 12px).

우하단 **스케일바**는 검출에 기록된 µm/px 로 그린다. 확대·이동에 상관없이 늘 같은
자리에 있고, 배율이 바뀌면 1·2·5 계열로 눈금을 다시 잡는다.

SAM2 는 한 자리에 여러 스케일의 마스크를 내므로 bbox 가 예사로 겹친다(후보의
84%가 더 큰 마스크 안에 든다). 맨 위의 것만 잡히면 아래 것을 고를 수 없으므로,
**같은 자리를 다시 클릭하면 다음 개체로 넘어간다** — 작은 것부터 돌고, 선택 정보에
`이 자리에 3개 겹침 (2/3)` 으로 몇 번째인지 나온다. Shift+클릭은 더하고 빼는
조작이라 순환하지 않는다(두 번 누르면 제자리로 돌아와야 한다).

bbox 를 끄면 화면에 보이는 것은 마스크뿐이므로 **클릭·hover 판정도 마스크(폴리곤)로
바뀐다** — 큰 물체의 빈 자리를 눌렀을 때 보이지도 않는 것이 잡히면 안 된다. bbox 가
보일 때는 bbox 로 잰다. 지운 것(점선 유령)은 마스크를 칠하지 않으므로 마스크 모드에서는
누를 수 없다 — 되살리려면 bbox 를 다시 켠다. 박스 요소 자체는 두 모드 모두 남긴다.

#### 분류 직접 지정과 코멘트

자동 판정은 **봉상 / 원형** 둘뿐인데, 조각난 규조각이 그 둘 중 하나로 잘못 들어가는
일이 있다. 개체를 고르고 우클릭하면 직접 지정할 수 있다.

| 분류 | 색 | 배지 | 키 | 센다 |
|---|---|---|---|---|
| 원형 `round` | 진한 초록 | `rnd` | `q` | ○ |
| 원형 파편 `round_frag` | 옅은 초록 | `rndf` | `q` (한 번 더) | ✕ |
| 봉상 `rod` | 진한 파랑 | `rod` | `w` | ○ |
| 봉상 파편 `rod_frag` | 옅은 파랑 | `rodf` | `w` (한 번 더) | ✕ |
| Eucampia | 분홍 | `euc` | `e` | ○ |
| Chaetoceros (`CRS`) | 연두 | `cha` | `r` | ○ |

**색상이 "무엇인가", 진하기가 "온전한가" 를 말한다.** 본체와 파편이 같은 색 가족이라
화면에서 관계가 읽힌다 — 축이 둘로 갈라져 분류가 늘어도 규칙이 선다. 단축키도 같은
모양이라 `q` 를 한 번 더 누르면 파편이다.

**형태 칸과 분류학 칸은 성격이 다르므로 메뉴에서 줄을 그어 나눈다**(`is_taxon`).
Eucampia 는 형태가 아니라 속(屬)으로 알아보는 것이고 남극 시료의 지시종이라, 형태
칸에 묶어 둘 수 없다.

**분류를 더할 곳은 `ClassDef` 테이블이다** — 코드가 아니다. 화면 규칙을 코드에서
테이블로 옮긴 목적이 "분류를 더할 때 배포가 필요 없게" 였다. 다만 **테이블에 행
하나로 끝나지 않는다**: `label`·`short`·`badge`·`color`·`hotkey`·`counted`·
`is_taxon`·`sort_order` 여덟에 `base.html` 의 CSS 까지다. 하나라도 비면 **예외는 안
나고 그 분류만 조용히 다르게 굴러간다** — 마스크가 투명해 "지정은 되는데 화면에 안
보이는" 상태가 될 뻔했다. `ops/check_db.py` 가 단축키·색 두 개는 잡아 준다.

**되돌릴 때는 행을 지우지 말고 `active=False` 로 끈다.** 지우면 그 분류로 붙인 교정이
이름 없는 분류가 되어 화면에서 안 읽힌다.

사람의 지정은 자동 판정을 덮어쓰지만 원래 값을 `cls_auto` 로 남긴다(툴팁에 `자동
판정: 원형` 으로 보인다). 사람이 지정한 것은 테두리가 점선이라 자동 판정과 구분된다.
`분류 지정 해제` 로 자동 판정으로 되돌린다. Ctrl+Z 도 듣는다.

**코멘트**는 개체마다 하나씩 달 수 있고(우클릭 → 코멘트, Ctrl+Enter 로 저장) **사진
오른쪽에 목록으로 나열된다.** 목록 항목에 커서를 올리면 그 개체가 선택되고, 반대로
개체를 고르면 그 코멘트가 강조된다 — 메모를 읽으면서 어느 것에 대한 말인지 바로
짚을 수 있어야 한다. 항목을 클릭하면 고칠 수 있다.

**시야 전체 코멘트**는 코멘트 칸 **아래쪽 고정 높이 자리에서 그 자리로 바로 적는다**
(팝업을 열지 않는다). 개체에 붙지 않는 이야기(초점 상태, 판정을 보류한 이유 같은 것)를
적는 곳이다. 빈 곳 우클릭 메뉴는 그 칸으로 커서를 보낸다. 타이핑하는 동안 저장이
흐르고, 칸을 벗어날 때 실행취소 한 칸으로 묶인다 — 글자마다 이력을 쌓으면 Ctrl+Z 가
쓸모없어진다. Esc·Ctrl+Enter 로 칸에서 빠져나온다.

개체 코멘트 칸과 시야 코멘트 칸은 **각각 스크롤되고**, 아래 칸은 높이가 고정이라
개체 코멘트가 길어져도 밀려나지 않는다. 시야 전체 코멘트는 `ViewpointReview.note` 에
저장된다.

교정은 **`mask_key` 로** 저장되므로 문턱을 바꾸거나 검출을 다시 돌려도 같은 마스크에
그대로 붙는다. 학습 데이터를 뽑을 때 이 값이 정답이 된다. **분류는 개체
(`DiatomObject`)에, 코멘트는 판정(`ObjectReview`)에 산다** — 위 "개체와 판정은
다른 것이다" 를 볼 것.

데이터셋 화면 두 번째 줄에 진척이 한 줄로 나온다 — **자동 검출 → 교정 후** 개수,
분류별 개수, 그리고 사람 손이 들어간 양(삭제·되살림·분류 지정·코멘트):

```
검출 811 → 교정 후 264개 (원형 38 · 원형 파편 31 · 봉상 119 · 봉상 파편 63 · Eucampia 8)
· 시야당 7.8 · 교정: 삭제 608 · 되살림 47 · 분류 지정 109 · 코멘트 2 (+시야 1)
```

자동 검출 수와 교정 후 수를 **함께** 보여야 뜻이 통한다 — 하나만 보면 문턱이 센 것인지
사람이 많이 지운 것인지 알 수 없다. 분류별 개수는 `ClassDef` 를 훑으므로 분류를 더해도
이 줄은 손댈 필요가 없다.

| `ObjectReview` 칸 (**판마다**) | 뜻 |
|---|---|
| `removed` | 오검출로 지운 개체 |
| `accepted` | 탈락분에서 **되살린** 개체 |
| `auto_confirmed` | 검토 완료가 남는 개체에 단 **확인 표시** (109). 되살림과 축이 달라 칸을 나눴다 — 뭉치면 "엔진이 놓친 것 몇 건" 을 못 센다. **마스크마다 누른 것이 아니라 이름이 `auto_` 다** |
| `grade` | 등급 `A`·`B`·`C` — **초점면마다 다르다** (파편에는 안 준다) |
| `note` | 개체별 메모 (최대 500자) — 판마다 하는 말이다 |
| `geom` | 기하를 스스로 들고 있다 — 검출기가 바뀌어도 읽힌다 |
| `is_rep` | 묶인 판들 중 **대표** (개체마다 하나) |

| `DiatomObject` 칸 (**개체마다**) | 뜻 |
|---|---|
| `label` | 사람이 지정한 분류 (자동 판정보다 우선) |
| `species` | 종명 — 자유 입력 + 자동완성 (개체 카탈로그 화면) |
| `pose` | 자세 `valve`·`girdle`·`other` — 초점을 옮겨도 안 변한다 |

시야 단위는 `ViewpointReview` 가 맡는다 — `note`(시야 전체 메모)와 `done`(다 봤다는
표시).

크롭 갤러리에도 `봉상 파편`·`원형 파편`·`사람 지정`·`코멘트 있음` 필터가 있다.

#### 탈락 후보는 마스크로만 판정한다

우상단 **탈락** 체크박스를 켜면 문턱에서 떨어진 후보가 **빨간 점선 테두리**로 보인다
(채우지 않는다 — 사진이 가려지면 정작 규조각인지 판단할 수 없다). 시야당 100개가 넘어
기본값은 꺼짐이다. 재현율을 눈으로 확인하거나 누락을 되살릴 때 켠다. 선 두께와 점선
간격은 `vector-effect: non-scaling-stroke` 라 확대해도 그대로다.

빈 곳 클릭으로 펼치는 후보도 **마스크가 그 지점을 덮는 것만** 고른다. bbox 로 재면
아무것도 없는 자리에서도 잔뜩 뜬다 — 실측으로 탈락 후보의 **bbox 합집합은 화면의
46.6%** 인데 **마스크 합집합은 19.5%** 다. 그 차이 25%p 가 "빈 곳인데 후보가 뜨는" 자리이고,
탈락분은 그려지지 않으니 왜 떴는지 알 수도 없다. bbox 는 폴리곤 판정 전의 값싼
1차 걸름망으로만 쓴다. (폴리곤이 없는 탈락 후보는 16,414개 중 0개라 잃는 것도 없다.)

**빈 곳을 클릭하면 그 자리의 탈락 후보를 펼쳐 보여준다.** 크롭은 서버(`/crop`)에서
잘라 오고 **원래 종횡비를 지킨다** — 칸에 억지로 맞추면 실측 종횡비 0.15~7.2 인 물체가
최대 9배까지 늘어나 형태를 보고 판단할 수가 없다. 그 위에 **마스크를 얹어** 무엇을
따온 것인지 보여준다(여백을 클라이언트가 계산해 `pad=0` 으로 넘기므로 폴리곤이 정확히
겹친다).

시야 목록의 표지 썸네일에도 **검출 마스크를 얹는다** — 목록에서 무엇이 잡혔는지 바로
보인다. 검출을 돌린 이미지와 표지가 같을 때만 그린다(다른 이미지의 좌표를 얹으면
조용히 어긋난 그림이 된다).

오검출로 지운 것은 점선으로 남아 클릭 한 번에 되살아난다(Ctrl+Z 도).

#### 사람이 지운 것이 문턱 변경으로 탈락분이 되면

`pipeline/refilter.py` 로 문턱을 올리면 사람이 이미 지워 둔 개체가 탈락분으로 옮겨갈 수 있다.
이때 **"사람이 지웠다"가 이긴다** — 지운 것이 조용히 되살아나는 것이 가장 나쁘다.
그런 개체는 여전히 빨간 점선 유령으로 남고, 툴팁에 `지금 문턱에서는 탈락분이다` 가
붙는다. 되살리면 수동 복구(`accepted`)로 저장되므로 문턱과 무관하게 유지된다.

같은 이유로 두 가지를 지킨다:

- 유령으로 이미 화면에 있는 것은 **"이 자리의 탈락 후보" 목록에서 뺀다** — 같은
  개체가 두 곳에 나오면 어느 쪽을 눌렀는지에 따라 결과가 달라진다
- 복구 목록(`accepted`)은 **서버가 준 것을 그대로 쓴다.** 예전에는 `manual` 표시로
  되짚었는데, 그러면 지워 둔 탈락분이 "복구된 것"으로 세어져 **다음 저장에서 지운
  것이 되살아났다**

#### 저장은 그 시야의 교정 **전체**를 갈아치운다

`/review` POST 는 받은 키 목록에 없는 교정을 지운다. **"뷰어는 늘 전체를 보낸다"**
가 전제이고, 깨지면 나머지를 지운다. 이것으로 **세 번 당했다** — 빈 키 목록을 운영
DB 로 보내 14건, "읽기 전용" 이라 적어 놓고 CSS 로 버튼만 감춘 화면에서 클릭 한 번에
37건, 그리고 저장이 **남의 시야로 가고 있어서** 138행이 노출됐다.

셋째가 가장 조용했다. 시야를 `stem` 하나로 찾았는데 **프레임 이름은 슬라이드끼리
겹친다**(카메라 일련번호라 같은 날 이어 찍으면 번호대가 이어진다 — 143종). 싱글턴
시야 135개 중 **12개가 다른 슬라이드의 시야를 열고 있었고**, 개체를 하나도 안
건드리고 **"검토 완료" 만 눌러도** 그쪽 교정이 통째로 지워졌다. 200 이 돌아오고
화면에는 "저장됨" 이 뜬다. 지금은 `(slug, gid)` 로 짚는다 — 이름은 겹쳐도 주소는
안 겹친다.

**그래서 화면을 눌러 보는 시험은 반드시 사본 DB 에 붙인다.**

`ALLOWED_HOSTS` 는 실제로 응답할 이름만 명시돼 있다. 인증이 없으므로 공개망에
그대로 올릴 물건이 아니다. 다른 호스트로 붙으려면 `DIARUGA_HOSTS` 환경변수를 쓴다.

### 문턱 조정 화면 (`/thresholds/`, `/d/<slug>/thresholds/`)

문턱을 만지는 일의 어려움은 **한 시야를 보며 정한 값이 시야 전부에 걸린다**는
것이다. 그 영향을 보지 못하면 적용하고 나서 시야를 하나씩 다시 확인해야 한다.

그래서 이 화면은 슬라이더를 움직이는 대로 **전체 영향**과 **영향받는 시야**를 함께
보여준다. 실측 근거가 있다(124 시야이던 때의 값이다).

| | |
|---|---|
| 전체 재판정 | **50 ms** (개체 18,936개) |
| 문턱을 바꿔도 판정이 뒤집히는 개체 | 전체의 **0.4~3.3%** |
| areolae 1500 → 2000 일 때 영향받는 시야 | **57/124** — 나머지 67개는 볼 이유가 없다 |

**볼 것은 그 차이뿐이다.** 시야를 2컬럼으로 늘어놓되 **영향 큰 순**으로 정렬하고,
빠지는 개체는 빨간 테두리, 들어오는 개체는 초록 테두리로 표시한다. 크롭만 보면
"이게 규조각인가" 를 판단할 맥락(주변 쇄설물, 다른 개체와의 대비)이 잘리므로 시야를
통째로 보여준다. 칸을 클릭하면 그 시야가 열린다.

**판정은 서버가 한다**(`pipeline/judge.py` 하나). 규칙을 JS 로 복사하면 두 곳이 어긋난다.
폴리곤은 시야마다 한 번만 받아 캐시하고, 슬라이더를 움직일 때는 판정
(`mask_key → cls`)만 다시 받아 색을 바꾼다 — 그래서 즉각 반응한다.

적용 범위는 **전역 또는 슬라이드**다. 시야마다 다른 문턱을 두지 않는다 — 같은
슬라이드 안에서도 시야별 텍스처 중앙값이 1,830~11,551 로 6배 넘게 벌어지는데, 그것은
**시료가 실제로 다른 것**이지 맞춰야 할 오차가 아니다. 시야마다 문턱을 맞추면 깊이별·
지역별 비교가 측정이 아니라 조정의 산물이 된다. 문턱이 갈라져 있으면 화면이 경고한다.

이력이 남고(`Run(kind=refilter)`) 항목을 누르면 그때 값을 불러온다. 탈락분을 지표째
보관하므로 문턱은 몇 번이든 왕복할 수 있다.
