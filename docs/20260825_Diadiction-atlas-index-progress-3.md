## 3. 꾸러미 셋을 못 읽었다 — 도구가 멈추게 했다 (153 1절)

### 3.1 파일 단위로 권한이 걸렸다

### 3.2 그냥 건너뛰면 판정이 조용히 뒤로 간다

`ingest_algaebase.py` 는 **같은 이름을 두 표가 다르게 말했을 때 `RANK` 로
가르는데**, 한쪽이 안 읽히면 **"읽힌 쪽" 이 이긴다.** 실제로 27~29일차가 이겨 둔
146줄 중 **여덟이 읽히는 표에도 있었고, 그중 둘은 판정이 뒤로 갔다.**

```
Navicula vridula      그대로 유효              ← day7_priority-148 은 「AlgaeBase 에 없다」
Nitzschia cireumsuta  Tryblionella circumsuta  ← day7_priority-148 은 「AlgaeBase 에 없다」
```

**예외가 안 나고 그냥 나빠지는 자리다.** 이 저장소가 되풀이해 만나는 종류이고,
자료 쪽에서 난 것이라 화면도 검사도 안 잡는다.

### 3.3 도구를 둘로 고쳤다

- **못 읽은 꾸러미를 세어서 말하고 멈춘다.** 역추적 대신 무엇을 못 읽었는지

  `RANK` 가 높으면 그 줄을 안 건드리고 목록에 낸다

지킨 줄 둘, 판정은 같고 비고만 바뀐 줄 열다섯이다(27~29일차를 가리키던 출처가
다른 표 이름으로 바뀐 것). **판정이 뒤로 간 줄은 없다.**

**이 셋은 다시 읽히게 되면 한 번 더 돌려야 한다** — 그때 저 열다섯 줄의 출처가
제자리로 돌아온다. 자료는 이미 대조표에 들어 있어 급하지 않다.

## 4. 안 풀리는 것은 갈래가 셋이다

`확인 필요` 97 · `AlgaeBase 에 없다` 100 · `안 적혀 있다` 15 를 한 덩어리로
보면 잘못 묻게 된다. **묻는 대상이 서로 다르다.**

### 4.1 동명이종 — 도감이 저자를 안 적었다

`확인 필요` 의 대부분이다. 148 구간은 **스물 중 스물이 전부 이것**이었고,
153 구간은 열 중 여덟이다.

```
#1209 Navicula interrupta    (W.Smith)판 → Pinnularia interrupta
                             Kützing판   → Diploneis interrupta
                             Ehrenberg판 → Ulnaria ulna
#1519 Pinnularia rostellata  Gregory판 → Navicula crucifera
                             Hustedt판 → Pinnularia acoricola var. rostellata
#1675 Surirella constricta   (Ehrenberg)판 → Navicula constricta
                             W.Smith판     → 그대로 유효
```

**목적지가 여럿인데 도감이 저자를 안 적었다.** 2차가 적어 둔 대로 **AlgaeBase 에
다시 물어도 안 풀린다** — 같은 답이 온다. 풀려면 **도감 원문의 저자 표기**를
읽거나 **어느 판을 택할지 정하는 규칙**이 있어야 한다.

### 4.2 OCR 절단 — 뒷부분이 잘려 후보가 여럿이다

`안 적혀 있다` 가 여섯 는 것이 전부 이것이다.

```
rivu · angulatnm · constr · japo · kamische · novae
```

표가 판정을 안 적어 온 것은 **표를 만든 쪽이 게을러서가 아니라 고를 수가
없어서**다. 등록부에 다시 물어도 안 나온다 — **원문을 다시 읽어야 하는 자리**다.

### 4.3 독일어 낱말 — 애초에 학명이 아니다

2차가 901~1200 에서 다섯을 봤고 148 은 1201~1500 에서 "이미 지났다" 고 적었는데,
**153 구간에서 여섯이 다시 나왔다.**

```
#1547 Pleurosigma erinnernde    #1792 Triceratium bedarf
#1611 Scoliopleura getrenut     #1804 Triceratium gehért   (gehört)
#1742 Syndetocystis eine        #1839 Triceratium vorliufig (vorläufig)
```

Schmidt Atlas 가 독일어 도감이라 본문 낱말이 종소명 자리로 흘러든 것이다.
**148 의 "지났다" 는 `Navicula` 구간이 그랬다는 말이었다** — 속이 바뀌면 다시
나온다. 교정해도 이름이 안 나오는 갈래라 **지우지 않고 대조표가 말하게

## 5. 잔여 140건을 채울 작업지를 냈다 (153 7절)

⑥' 가 닫혔으니 08-23 에 미뤄 둔 잔여 요청을 낼 자리다. **순번 꾸러미에 예외를
안 끼운 것은 #431 을 두 번 끼웠다가 두 번 다 안 왔기 때문이다.**

**다시 물으면 풀릴 것 — 140건**

```
AlgaeBase 에 없다   100
아직 안 찾았다        20
안 적혀 있다          15
미확인                 4
#431 Chaetoceros paradoxum (Pavillard 판)   1
```

**다시 물어도 안 풀릴 것 — 97건** (`확인 필요` · 4.1). **잔여 목록에 안 넣는다.**

### 5.1 고르는 기준이 달라졌다

사용자가 **직접 하나씩 조회하겠다**고 해서 `algaebase_worklist.py` 에
`--residual` 을 붙였다. 원래 것은 **`AlgaeBase` 칸이 빈 줄**을 골랐는데 이제 빈
줄이 없어 0건이 나온다. **잔여는 채워졌는데 안 풀린 것**이라 고르는 기준이 다르다.

가르는 열쇠는 그대로 **`원문확인` 칸**이다 — Schmidt 해설 원문을 읽어 둔 결과가
거기 있고, 등록부가 답할 수 있는 자리와 아닌 자리가 거기서 갈린다.

```
0층    1  원문 재판독 — 판을 지정해 다시 묻는다   (#431)
1층   68  원문이 학명이라고 보증한다 — 등록부에만 없다
2층   31  원문을 아직 안 봤다
3층    9  그 밖 — 등록부가 답할 수 있다
9층   31  물어도 안 나온다 — 원문이 학명이 아니다
```

**9층을 빼지 않고 남겼다.** 원래 도구는 이런 것을 목록에서 아예 뺐는데
(`NOT_A_NAME`), 이번엔 사람이 직접 보겠다고 한 자리라 **왜 소용없는지를 적어
같이 낸다** — 빼 놓으면 왜 없는지를 알 수 없고, 남기면 건너뛰는 판단을 사람이
한다. 표에 자리(`Schmidt Atlas Tafel 149`)와 원문이 말한 것(`fig 2 의 비교
문장이다`)을 함께 실었다.

**#431 의 자리가 비어 있었다.** `atlas/*.json` 을 이름으로만 걸어서 그렇다 —
**한국 도감 표제어는 저자까지 달고 있다**(`Chaetoceras paradoxum PAVILLARD`).
`binomial` 로도 걸어 `한국 도감 #306 · 도판 40 · 책 p.211` 이 붙었다.

### 5.2 빈 칸이 판정을 못 이기게 했다

작업지에 **"못 찾으신 것은 비워 두셔도 됩니다"** 라고 적었는데, 적고 보니
그대로가 아니었다.

`RANK` 가 `안 적혀 있다` 와 `아직 안 찾았다` 를 **둘 다 0** 으로 둬서 비고
길이로 갈리고, 작업지가 비고에 자리를 미리 적어 두는 바람에 **빈 칸 쪽이 길어서
이길 수 있었다.** 돌려받은 빈 칸이 이미 풀어 둔 판정을 덮는다는 뜻이다.

`안 적혀 있다` 를 **-1** 로 내렸다. 그것은 판정이 아니라 **표의 그 칸이 비어
있었다는 말**이라 어느 판정에도 못 이겨야 한다 — `아직 안 찾았다` 는 사람이
"검색 안 함" 이라고 **적은** 것이라 층이 다르다.

**지금 대조표에는 한 글자도 영향이 없다**(md5 그대로) — 앞으로 올 빈 칸에만
걸린다.

### 5.3 되살려서 확인했다

못 읽는 회차 셋을 흉내 낸 사본에 작업지를 `day38` 로 넣고 **140줄을 전부 빈
칸으로** 돌려받은 셈 치고 돌렸다.

- **판정이 바뀐 줄 0개**
- 3.3 의 지킴 갈래가 넷을 잡았다 (`Navicula rostochiensis`·`scutelliformis` 가
  못 읽는 회차 쪽이라 새로 걸렸다)

**처음 세운 사본은 못 읽는 파일을 아예 빼 놔서 그 갈래를 안 지났다** — 그때는
넷이 다 뒤로 갔다. *시험이 만든 상태가 그 갈래를 안 지나면 아무것도 안 본다*
는 것을 여기서도 한 번 겪었다.

## 6. 도감 반입 검사 — 설계를 근거째로 적었다 (아직 안 만들었다)

### 6.1 낡아도 아무도 안 알려 준다

`Atlas.source_sha256` 은 **저장하고 찍기만** 한다. `ops/import_atlas.py` 의
`✓ JSON 과 맞는다` 는 **방금 자기가 넣은 값을 되찍는 것**이고 `check_db` 는 이
칸을 안 본다. 그래서 **DB 의 도감이 이미지 안 JSON 보다 낡아도 조용하다.**

### 6.2 그 칸으로 검사하면 안 된다

`source_sha256` 은 색인 **md 의 해시**이고 `annotate_index.py` 가 꾸러미마다
`〔…〕` 를 다시 단다 — **파싱 결과가 한 글자도 안 바뀌어도 매번 바뀐다.**

실측(08-25): DB `c0d8978f…` · 이미지 `a5ae1f98…` 로 셋 다 다른데 **항목·자리
수는 전부 맞는다.** 그 칸으로 검사를 만들면 꾸러미마다 참이 아닌 경고가 뜨고,
**그러면 사람이 `check_db` 를 안 보게 된다.**

### 6.3 항목·자리 수로도 모자란다

`v0.16.1`(147)이 실제로 그 자리였다 — 쪽 대응표를 채운 판이라 **자리 512 는
그대로**이고 안의 `pdf_page` 만 찼다(`311/512 → 511/512`). **수만 보는
검사였으면 반입이 꼭 필요했던 그 판에서 "맞는다" 고 답했을 것이다.**

### 6.4 정한 것 — 항목 해시로 판정하고, 수는 사람이 읽게 함께 찍는다

- **칸을 새로 안 둔다.** 검사할 때 양쪽에서 같은 값을 만들어 비교한다
- **규칙 파일은 `tools/` 에 둔다** (`naming.py`·`judge.py`·`catalog.py` 와 같은
  자리 — 규칙은 그것을 만드는 집에 산다)
- **`parse_atlas.py` 에서 함수를 빼 오면 안 된다.** `dbsync.sh` 가 딸린 것을
  **전이적으로** 밀어서 `harvest_worms.py`·`annotate_index.py` 까지 따라간다 —
  **NAS 경로 상수를 든 색인 도구가 운영 스크립트 자리에 앉는다.** 의존 없는 작은
  모듈을 새로 두고 `parse_atlas.py` 가 그것을 부르게 한다
- **`AtlasEntry.line` 은 해시에서 뺀다.** 항목에 대한 사실이 아니라 md 의
  생김새에 대한 사실이고, 표시가 한 줄 늘면 **전 항목이 한꺼번에 뒤집힌다**
  (6.2 의 고장 그대로). 게다가 `check_db` 는 컨테이너 안에서 돌아 **md 를 볼
  수가 없다**
- **`extra` 는 중첩까지 `sort_keys`.** `JSONField` 는 SQLite 를 왕복하면 키
  순서가 안 지켜져, 정규화를 안 하면 **반입만 다시 해도 해시가 달라진다**
- **`placements` 정렬 기준을 값으로 못 박는다.** JSON 은 파서 순서, DB 는 행
  순서라 기준이 없다

### 6.5 빈 칸이 드문 자리가 아니다 — 실측

정렬 열쇠에 들어가는 칸을 **전부 눕혀야 한다.** 파이썬은 `None` 과 `int` 를 못
비교해 그냥 정렬하면 `TypeError` 이고, **빈 것이 어디로 가는지도 값의 일부**라
양쪽이 같은 규칙이어야 한다.

| 도감 | 자리 | `plate` 빔 | `pdf_page` 빔 | `figures` 빔 | 자리가 여럿인 항목 |
|---|---|---|---|---|---|
| 한국 | 512 | 2 | 1 | **512 (전부)** | **0개** |
| Schmidt | 1,911 | 0 | 0 | **716** | 254개 (최다 11) |
| 동남극 | 57 | **14** | 0 | 0 | 13개 (최다 3) |

**실제로 `None` 정렬을 지나는 것은 동남극뿐이다** — 자리가 여럿이면서 `plate`
가 빈 자리를 가진 유일한 도감이다. 한국은 `figures` 가 전부 비었지만 자리가
여럿인 항목이 없어 안 걸린다. ***지금* 그렇다는 것이지 규칙이 그렇다는 것은
아니다.**

**열쇠가 겹치면 멈춘다.** 겹치면 정렬이 안정적이지 않아 **입력 순서에 따라
해시가 흔들린다.** 지금은 셋 다 겹치는 항목이 0개라 이 열쇠로 충분한데, 나중에
겹치는 자료가 들어오면 **조용히 흔들리는 대신 그 자리에서 걸리게** 한다.

> 빈 칸의 예를 들 때 조심할 것 — **`#347 Climacodium biconcavum` 은 `plate` 가
> 없고, `#680 Surirella tenera` 는 `pdf_page` 가 없다**(발췌본이 책 p.369 에서
> 끝나 그렇다 · 147). 빠진 칸이 서로 달라서 "`pl.` 이 없는 자리가 둘" 로
> 뭉뚱그리면 틀린다.

**지금 자료는 성하다** — 항목·자리·해시가 다 맞으므로 이 검사를 넣어도 **바로
뜨지 않는다.** 넣기 좋은 때다.

## 8. 색인이 화면에 쓰이기 시작했다

`v0.17.0`(08-25)에서 **카탈로그의 종명 칸이 `AtlasEntry` 를 자동완성한다.**
자세한 것은 [16차 보고서](20260825_DiaRUGA-analysis-system-progress-16.md) 2절에
있고, 여기서는 **색인 쪽에서 지켜진 약속 둘**만 적는다.

- **값으로 내는 것은 `binomial` 뿐이다.** 비어 있다는 것은 도감이 속까지만
  내려갔거나(`sp.`·group) 표기를 못 읽는다는 뜻이라(119), 그것을 종명 칸에
  주면 **119 가 갈라 놓은 둘을 화면이 도로 섞는다**
- **가두지 않는다.** 도감에 없는 이름도 그대로 적힌다 — 화석속은 등록부가
  성글고, `DiatomObject.species` 는 계속 자유 입력이다. **대기 중인 `TaxonName`
  방침을 화면에서 앞질러 정하지 않는다**

**AlgaeBase 대조로 확정한 이름(`names/`)은 아직 DB 에 없다.** 자동완성이 주는
것은 도감에 실린 이름뿐이다 — 색인이 끝났으니 그쪽도 같은 문으로 낼 수 있다.
