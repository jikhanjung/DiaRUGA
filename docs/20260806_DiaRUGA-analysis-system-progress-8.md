## 1. 요약

시작은 사고 하나였다. 어제 만든 관찰 기능이 새 폴더에서 안 먹었고, 파 들어가니
**스키마의 층이 실제 자료의 층과 어긋나 있었다.** 사용자가 용어를 정리해 주면서
그 어긋남이 이름으로 드러났고, 그것을 맞추는 것이 이 차수의 일이 됐다.

```
권역   한국 · 남극                       Site.area
 └ 지역   BP(북평분지) · RS23            Site
    └ 지점   BP09(노두) · GC03(시추코어)  Locality   ← 예전 이름이 Core 였다
       └ 시료   0901 · 71cm              Sample     ← 없던 층
          └ 관찰   (1) · (2)             Slide
```

**첫째, "코어" 라는 말이 육상에 안 맞았다.** 북평분지는 노두이고 시추한 것이
아니다. 그 층을 **지점**으로 넓혔다.

**둘째, 시료 층이 없던 것이 사고의 뿌리였다.** `Slide` 하나가 시료와 관찰을 겸해서
소속이 **관찰 행마다** 앉아 있었고, 그래서 같은 시료의 관찰 둘이 서로 다른 소속을
가질 수 있었다 — 한 관찰이 아무 데도 안 붙어 **화면에서 통째로 사라졌다.**

**셋째, 자동 생성 마이그레이션을 그대로 돌렸으면 자료가 날아갔다.** Django 는
옛 표를 지우고 새 표를 빈 채로 만드는 순서를 냈다.

**넷째, 화면 여섯이 함께 들어왔다** — 검토 흐름 넷(사용자 제안), 관리 화면,
노두 현장 사진.

**다섯째, 눌러 보는 시험이 조용한 고장 넷을 잡았다.** 전부 예외도 경고도 없었다.

**그리고 이 차수에 검토가 전수 완료됐다 — 508/508 시야.** 슬라이드 11장이 전부
사람 손을 거쳤고 교정이 7,472건이다. 다음 판의 학습 자료가 여기서 나온다.

## 2. 사고 — `(1)` 은 읽혔는데 소속이 없었다

사용자가 `BP09-0901 (1)` 을 올렸고, 그것이 `BP09-0901` 과 같은 시료의 관찰로 서기를
기대했다. 안 그랬다.

```
id  이름              지점       깊이   관찰번호
 8  BP09-0901         BP09      —      0
12  BP09-0901 (1)     (없음)    —      1     ← 소속 없음
```

관찰 번호는 제대로 들어갔다. **빠진 것은 지점 연결이었다.**

원인은 폴더 이름을 읽는 정규식이다. `<지역>-<지점> <깊이>cm` 를 요구하는데
`BP09-0901` 은 노두라 `cm` 이 없어 매치가 안 된다. 슬라이드 8 의 지점은 파서가
붙인 것이 아니라 **사람이 속성 편집에서 손으로 넣은 것**이었고, 새 관찰은
물려받을 데가 없었다.

목록·지도·지점 페이지는 전부 `지점 → 위치 → 관찰번호` 로 묶으므로 **소속이 없는
관찰은 어느 화면에도 안 선다. 500 도 404 도 아니고 그냥 사라진다.**

### 덤으로 나온 것 둘

**하나.** 반입·그룹핑이 `update_or_create` 의 기본값에 빈 소속을 그대로 실었다.
즉 **다시 그룹핑하거나 다시 반입하면 사람이 넣은 지점이 지워진다.** 관찰 이름표는
"사람 것이라 기본값에서 뺀다" 고 해 놓고 소속은 안 그랬다.

**둘.** 사용자가 속성 편집으로 고치려다 실패했는데, 그 화면이

- 지역 코드를 비우면 **지점을 찾는 갈래가 통째로 건너뛰어져** 아무 일도 안
  일어나는데 **"저장했습니다" 가 떴고**
- 만약 성공했다면 **폼의 빈 칸으로 기존 지역·지점을 덮어썼을** 것이다. 북평분지·
  좌표·채취 방식이 다 지워지고 원본 관찰도 함께 당한다

두 번째는 실제로 일어나지 않았다(사용자가 지역 코드를 안 채웠다). 하지만
**성공했으면 더 나빴을 종류의 실패**다.

## 3. 용어 — 사용자가 층을 말해 주었다

여기서 방향이 바뀌었다. 사고를 막는 것보다 **왜 이런 사고가 가능한 구조인가**가
문제였다. 사용자가 정한 것 넷:

1. **"코어" 를 지점으로 넓힌다.** 육상은 시추한 것이 아니다. 지점은 시추코어와
   노두를 함께 담는 말이고 어느 쪽인지는 유형이 말한다
2. **유형은 지점의 성질이다.** 한 지점이 코어이면서 노두일 수 없다
3. **육상은 지점 = 노두 = 단면이 하나다.** 단면 층을 따로 두지 않는다
4. **관찰끼리는 동등하다.** 대표를 두지 않고 이름표로 구분하며, 통계에 무엇을
   넣을지는 숨김·집계 제외로 사람이 고른다

시료 코드를 읽는 법도 함께 정해졌다.

```
BP09-0901
└┬─┘ └┬┘
 │    └ 09 = 지점 번호가 되풀이된 것 · 01 = 그 노두의 첫 시료
 └ 지역 BP + 노두 번호 09
```

### 두 체계의 폴더 규칙이 다르다

| | 폴더가 담는 것 | 지역을 아는 법 |
|---|---|---|
| 남극 | `<지역>-<지점> <깊이>cm` | 폴더에 있다 |
| 육상 | `<지점>-<시료>` | 폴더에 없다 — 지점 코드의 앞 글자(`BP09` → `BP`) |

**가르는 표시는 `cm` 이 있느냐다.** 이 규칙을 한 파일로 모았다 — 예전에는 같은
정규식이 파이프라인 두 곳에 따로 있었고, 갈라지면 같은 폴더가 두 자리에 다르게
앉는다.

> **육상의 지역을 숫자를 떼어 얻는 것은 짐작이다.** 노두 코드가
> `<지역문자><번호>` 꼴이라는 전제이고, 어긋나면 없는 지역이 만들어진다. 그래도
> 비워 두는 쪽이 더 나쁘다 — 지역이 없는 관찰은 어느 권역 탭에도 안 나와 화면에서
> 사라진다(이 사고가 정확히 그것이었다). 대신 **관리 화면에서 사람이 고칠 수
> 있게** 했다.

## 4. 시료 층을 뽑았다

`Slide` 하나가 시료와 관찰을 겸하고 있었다. 시료 행이 있으면 관찰은 그것을
**가리키기만** 하므로 애초에 어긋날 수가 없다. 덤으로 "같은 시료의 다른 관찰" 이
**이름 짐작이 아니라 조인 한 번**이 된다 — 아침에는 이름을 잘라 비교해야 했고,
이름이 규칙에 안 맞으면 그대로 못 찾았다.

### 시료의 위치 칸이 둘이다

| 지점 유형 | 시료가 서는 값 |
|---|---|
| 시추코어 | 깊이 71 cm |
| 노두 | 단면상의 위치 1 |

한 칸에 몰지 않는 이유는 깊이를 문자열로 안 바꾼 것과 같다 — "369cm" 와
"단면 9번" 을 같은 축에 그리게 된다. 지점은 코어이거나 노두이거나 둘 중 하나라
정렬할 때는 어차피 한 칸만 본다.

**노두에는 cm 축을 아예 안 그린다.** 단면상의 위치는 "몇 번째로 딴 것" 이지
거리가 아니다. 축에 얹으면 **없는 간격을 지어내게 된다.**

### 마이그레이션 — 자동 생성본을 그대로 쓰면 안 됐다

Django 가 낸 순서는 이랬다.

```
CreateModel Locality → RemoveField slide.core → DeleteModel Core
```

**옛 표를 지우고 새 표를 빈 채로 만든다.** 그대로 돌리면 지점 다섯과 모든 관찰의
소속이 통째로 날아간다. 손으로 순서를 잡았다.

```
1. 새 표를 만든다
2. **자료를 옮긴다**  ← 여기가 가운데여야 한다
3. 그 다음에 옛 칸을 걷는다
4. 제약·인덱스는 자료가 다 앉은 뒤에
```

되돌리기도 함께 적었다 — 배포 게이트가 막히면 판을 되돌려야 하는데, 그때 자료가
없으면 되돌린 판이 빈 화면을 낸다.

> SQLite 가 한 번 물었다. 칼럼을 지울 때 표를 통째로 다시 만드는데 옛 제약이
> 아직 그 칼럼을 가리키고 있어 죽었다 — **제약을 먼저 뗀다.**

지점 유형은 그 지점에 달린 관찰들의 값에서 올렸다. **실측에서 지점 다섯 곳 전부
한 가지로 모여** 그대로 갔다.

## 5. 함께 들어온 화면 여섯

### 검토 흐름 넷 (사용자 제안)

- **검토 완료 숨기기** — 카드가 이미 표시를 달고 있어 화면에서 거른다. 서버에
  안 묻는다: 새로고침이 있으면 검토하다 말고 켜고 끌 수가 없다
- **다음 미검토** — 옆 시야로 한 칸 가는 것과 다른 일이다. 한 슬라이드가 86 중
  53 완료라 한 칸씩 눌러 이미 본 것을 계속 지나야 했다. 뒤에 없으면 앞으로
  돌아가되 **돌아갔다고 말한다**
- **밝기·대비** — 사진에만 건다. **마스크는 안 물든다**: 마스크 색이 분류를
  나타내는 판정 근거여서 사진과 함께 어두워지면 무엇으로 지정했는지가 안 읽힌다.
  보는 방식이지 자료가 아니라 DB 로도 안 간다
- **전체를 검토로 / 미검토로** — 되돌릴 수 없어 누르기 전에 묻는다. 완료 깃발만
  뒤집고 **행은 안 지운다**: 같은 행의 시야 코멘트가 사람의 판단이라 지우면 함께
  날아간다

### 관리 화면

지역·지점·시료를 만들고 지운다. **관찰은 만들지도 지우지도 못한다** — 폴더가
만드는 것이고 그 아래에 재생성 불가한 교정이 달려 있다.

**이 화면이 있어야 하는 첫째 이유는 소속 없는 관찰이다.** 그것은 다른 어느
화면에도 안 나온다. 여기서는 붙일 곳까지 추천해서 낸다.

**지우기에 문턱이 있다.** 시료를 지우면 관찰이 조용히 소속을 잃으므로, 딸린 것이
있으면 막고 **무엇이 몇 개 걸려 있는지 버튼에 미리 적는다.** 눌러 보고 "지울 수
없습니다" 를 만나면 무엇을 먼저 치워야 하는지 알 수 없다. 서버가 다시 검사한다 —
**화면에서 막는 것은 막는 것이 아니다.**

### 노두 현장 사진 (사용자 제안)

시추코어 지점에는 암상 띠가 들어올 자리가 잡혀 있는데 **노두 쪽은 비어 있었다.**
거기에 현장 사진을 넣었다.

**파일이 곧 자료다 — DB 에 행이 없다.** NAS 공유에 이름이 `<지점코드> (n).jpg` 인
것이 지점과 사진을 잇는 유일한 근거다. 탐색기로 직접 올려도 화면에 나타나고, 새
노두 지점을 만들고 사진만 두면 저절로 붙는다.

화면에서도 올린다(끌어다 놓기·파일 고르기). **이름은 서버가 짓는다** — 화면이 준
이름은 확장자조차 안 쓴다. 주소에도 이름이 없어서 경로 탈출이 애초에 불가능하다.

**세 장까지다**(용량 관리). 여럿이 쓰는 공유라 올릴 때 줄여서 다시 쓴다.

```
5568x3712  12.5 MB  →  2400x1600  0.97 MB   (8%)
```

**NAS 가 없어도 죽지 않는다** — 사진이 안 보이는 것과 지점 페이지가 500 이 되는
것은 고장의 크기가 다르다.

## 6. 눌러 보는 시험이 잡은 것 넷

**전부 예외도 경고도 없었다.** 코드를 읽어서는 하나도 안 걸렸을 것들이다.

| 무엇 | 증상 |
|---|---|
| 카드의 `display: block` 이 `hidden` 을 이겼다 | 감추라고 해 놓고 **그대로 보였다.** 특이도 싸움이고, 이 저장소가 같은 자리를 두 번째 밟았다 |
| 관리 폼에 같은 이름의 칸이 둘 | Django 가 뒤엣것을 집어 지점이 "모르는 층" 이 되어 **조용히 안 만들어졌다** |
| 스크립트가 제목 블록 안으로 들어갔다 | `<title>` 속이라 **JS 가 한 번도 안 돌았다** — 끌어다 놓기가 죽어 있었다 |
| 여러 줄 주석 문법을 잘못 썼다 | 주석이 화면에 그대로 나온다 (문서에 적혀 있는데도 밟았다) |

> 그리고 **개발 서버가 템플릿을 캐시한다.** 템플릿을 고쳐도 안 바뀌어 두 번
> 헛다리를 짚었다 — 고치면 다시 띄울 것.

## 7. 배포

**뷰어와 파이프라인을 함께 올렸다.** 스키마를 조이는 마이그레이션이라 갈라
놓으면 옛 파이프라인이 없는 칼럼에 쓴다.

**폴러 락을 잡은 채로 했다.** 마이그레이션이 도는 동안 옛 파이프라인이 돌면
폴러가 선다. 그리고 **굽고 나서, 배포 전에 새 파이프라인 이미지를 마이그레이션한
사본에 붙여 봤다** — 새 판 DB 를 읽고 시료를 제대로 찾는 것까지 확인한 뒤에 올렸다.

```
smoke 통과 — 판 v0.7.0 · 슬라이드 11 · 교정 7,472 · nginx 경유 200
마이그레이션 0024_locality_and_sample 적용
지역 BP · 지점 BP09(노두) · 시료 0901 · 관찰 2 · 소속 없는 관찰 0
DB 무결성 검사 7번(층) 전부 OK
운영 화면 11개 200 · 옛 주소는 302 로 새 주소에
노두 현장 사진 3장이 운영에서 그려진다 · 콘솔 오류 0
```

사본 셋을 남겼다 — 손으로 뜬 것 둘, `deploy.sh` 가 뜬 것 하나.

## 8. 곁들여 — 문서와 사본 정리

**DB 무결성 검사에 층 검사를 더했다.** 소속 없는 관찰 · 지점 유형과 안 맞는 위치
칸 · 위치 없는 시료 · 빈 지점. **여기서 잡는 것은 예외가 안 나고 그냥 틀린
상태다.**

**스키마 참조 파일이 한 판 낡아 있었다** — 어제 만든 `Image` 표가 빠져 있었다.
손으로 고치는 문서가 아니라 실제 DB 에서 떠야 하는 것이라 뜨는 도구를 만들었다.

**보고서 docx 의 도표가 코드 블록으로 떨어졌다.** 어제 디스크 정리에 mermaid 도구가
지워져 있었다 — **변환이 실패하지 않고 그냥 못생긴 문서를 낸다**(ERD 315 KB vs
751 KB). 이미 깔려 있는 브라우저를 재활용하게 해 다시 구웠고 그 방법을 적어 뒀다.

**옛 자동 사본 23개(2.4 GB)를 지웠다.** 이름 변경이 남긴 것이라 새 정리 규칙이
영영 못 걷는 것들이었고, 24시간 rolling 이 온전해진 것을 확인하고 지웠다. 그
과정에서 **오프사이트 사본이 교정 734건 뒤처져 있는 것**을 발견해 최신본을
밀어 뒀다.

## 9. 남는 것

- **육상 지역을 폴더에서 뽑는 규칙이 짐작이다.** 다른 꼴의 노두 코드가 들어오면
  없는 지역이 만들어진다 — 관리 화면이 고칠 수 있게 해 뒀지만, 들어올 때 사람에게
  물어보는 편이 나은지 볼 것
- **지점 코드를 바꾸면 노두 사진이 떨어진다.** 파일 이름이 유일한 근거라 그렇다 —
  간단함과 맞바꾼 대가이고, 코드를 바꾸는 일이 드물어 지금은 그대로 둔다
- **암상 모델**은 여전히 자리만 잡혀 있다. 기재 규칙이 정해져야 표가 선다
- **검토가 전수 완료됐으므로 다음은 학습이다** — 슬라이드 11장 · 교정 7,472건이
  다음 판의 자료다

## 10. 이 차수에서 얻은 것

**말과 표가 어긋나 있으면 사고가 난다.** 사용자가 용어를 정리해 준 것이 이 차수의
전환점이었다 — "코어" 가 육상에 안 맞는다는 한마디에서 시료 층이 없다는 것까지
드러났다.

**층을 겸하는 표는 어긋날 수 있다.** 시료와 관찰을 한 표에 두면 같은 시료의 관찰
둘이 다른 소속을 가질 수 있고, 그것이 실제로 일어났다.

**자동 생성 마이그레이션은 읽고 쓴다.** 모델 이름을 바꾸면 Django 는 지우고 새로
만든다 — 자료를 옮기는 단계를 사람이 가운데 끼워야 한다.

**화면이 아무 일도 안 하고 "됐다" 고 말하면 안 된다.** 못 한 것은 오류로 말하고,
막는 것은 눌러 보기 전에 보여야 하며, 서버가 다시 검사한다.

**눌러 보는 시험이 아니면 안 걸리는 고장이 있다.** 이번에 넷이었고 전부 조용했다.
