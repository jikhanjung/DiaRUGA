# DiaRUGA

극지 퇴적물 코어 시료의 규조류 광학현미경 사진 분석 파이프라인 + 검토·교정 뷰어.

사진에서 개별 규조각을 찾아 µm 단위로 계측하고, 웹 뷰어에서 확인·교정한다.

```
NAS 새 폴더 ─[반입]→ 사진 ─[그룹핑]→ 시야 ─[합성]→ all-in-focus ─[검출]→ 후보
                                                                 ─[판정]→ 규조각
                                                                 ─[교정]→ 사람
```

**원본은 `DiaRUGA.db` 다** (SQLite, WAL). 파이프라인 다섯 단계와 뷰어가 같은 DB 를
읽고 쓴다. `groups_*.json`·`out/*.json` 은 이제 **내보내기 형식**으로만 남아 있고
파이프라인 흐름에서는 빠졌다(P02 7단계).

**NAS 에 새 슬라이드가 올라오면 1분 안에 검출까지 스스로 간다** — `poll_nas.sh` 가
반입부터 검출까지 돌린다(P03). 손으로 부를 일은 다시 돌릴 때뿐이다.

> **지금 몇 장이 들어와 있고 검토가 어디까지 갔는지는 여기 적지 않는다** —
> 사람이 검토하는 동안에도 움직이는 값이라 적는 순간 낡는다. 그 숫자는
> [HANDOFF.md](HANDOFF.md) 와 `/healthz` 가 낸다.

## 데이터

ZEISS Axio Imager.A2 + ZEN 3.8.99 로 촬영한 명시야 투과광 사진.
사진마다 `<파일명>.jpg_metadata.xml` 이 동반된다.

**사진은 저장소 밖에 있다.** NAS 의 `DiatomPhotos/` 구조와 1:1 로

```
/data3/DiaRUGA/photos/<촬영일>/<슬라이드>/
```

에 놓인다(`.env` 의 `DIARUGA_DATA_ROOT`). 촬영일이 앞에 오므로 같은 시료를 다시
찍어도 폴더가 부딪히지 않는다.

시료는 남극 코어 여럿(로스해 · 남극반도 서안 · 아문젠해)과 **동해 북평분지 하나**다.
북평분지는 **별개 갈래다** — 한국 시료라 남극 것과 섞어 세지 않고, 뷰어 목록의
`[한국 | 남극 | 전체]` 탭이 그것을 가른다. 지도도 권역마다 투영이 다르다.

**한 시료에 관찰이 여럿일 수 있다** (056). 같은 시료를 처리 방법을 달리해 다시
찍은 것은 폴더 접미사 `(1)`·`(2)` 로 받아 `Slide.obs_no` 에 담는다. 뜻(`obs_label`)과
목록에서 숨길지·합계에서 뺄지는 사람이 고른다. **접미사는 숫자만 받는다** —
글자를 받으면 슬러그가 뭉개져 서로 다른 관찰이 한 슬러그로 부딪힌다.

### 촬영 조건 (XML에서 추출, 전 사진 동일)

- 대물 Plan-Apochromat 40x/0.95 Korr M27 (air, WD 250 µm)
- Optovar 1.6x, 카메라 어댑터 0.63x → 카메라측 실효배율 40.32x, 접안 기준 640x
- Axiocam 506c, 4.54 µm 픽셀, 14-bit 취득 후 8-bit BGR JPG 저장, binning 1x1
- TL 할로겐 3.13 V, 반사경 none, RL 셔터 닫힘 (투과광 명시야)
- 노출 195.568 ms
- 이미지 2752 x 2208

### 스케일

**0.112599 µm/pixel** (`Scaling/Items/Distance` = 1.1259920634920635e-7 m).
따라서 시야(FOV)는 **309.8 x 248.6 µm**. 크기 측정에 그대로 쓸 수 있다.

이 값은 상수로 박아 두지 않고 **사진마다 동반된 XML 에서 읽는다**(`pipeline/zen_meta.py`).
계측값·크기 관문·텍스처 대역이 모두 여기 걸려 있어서, 촬영 조건이 바뀌었는데
상수를 쓰면 예외도 경고도 없이 결과 전체가 배율만큼 어긋난다.

### XML의 한계

**스테이지 XY / 포커스 Z 좌표가 기록돼 있지 않다.** `ZPosition` 계열 태그가
나오지만 전부 `FixedZPosition=0` 같은 실험 설정 템플릿 값이고 실측 위치가 아니다.
Snap 단발 촬영이라 Z-stack 으로 기록되지 않았다.

같은 시야를 초점만 바꿔 찍은 두 장(21365, 21366)과 다른 시야의 한 장(21371)의
XML을 diff 하면 **차이가 완전히 동일**하다 — 타임스탬프와 내부 GUID 뿐이다.
즉 XML만으로는 초점 시리즈를 묶을 수 없어서 이미지 내용으로 판단해야 한다.

사진마다 유일하게 의미 있게 달라지는 값은 `AcquisitionDateAndTime` 이다.

## 파이프라인

다섯 단계이고 **전부 DB 를 읽고 쓴다.**

```
scan_nas → ingest_nas → group_focus_series → focus_stack → segment_diatoms
  NAS 감시    반입         초점 시리즈 묶기     all-in-focus    검출 + 판정
                                                                  ↑
                                                              judge.py  ← 판정 규칙은 여기 하나뿐
```

`deploy/poll_nas.sh` 가 이 흐름을 1분마다 돌린다 — **손으로 부를 일은 다시 돌릴
때뿐이고**, 그 명령은 [CLAUDE.md](CLAUDE.md)·[HANDOFF.md](HANDOFF.md) 에 있다.
`migrate/import_json.py` 는 파이프라인에서 빠졌다.

아래는 각 단계가 **왜 그렇게 되어 있는가**다. 그것이 이 문서가 하는 일이고,
지금 어떻게 돌리는가는 위 두 문서가 맡는다.

### scan_nas.py · ingest_nas.py — NAS 반입

`pipeline/scan_nas.py` 가 NAS 를 훑어 **아직 안 들여온 폴더**를 찾고, `pipeline/ingest_nas.py` 가
그것을 `/data3/DiaRUGA/photos/` 로 가져온다. 둘 다 일정 시간(기본 5분) 동안 파일이
안 늘어난 폴더만 건드린다 — **촬영 중인 폴더를 반쯤 들여오면 안 된다.**

### group_focus_series.py — 초점 시리즈 그룹핑

같은 위치를 초점만 바꿔 찍은 사진들을 묶는다. 축소 + 가우시안 블러로 고주파를
죽인 저주파 지문의 정규화 상관계수를 쓴다. 초점이 달라져도 입자 배치는
그대로이므로 초점 변화에는 둔감하고 시야 이동에는 민감하다.

**경로를 받는 유일한 단계다** — 나머지는 슬라이드 slug 로 부른다. `Slide`·
`Viewpoint`·`Frame` 행을 직접 만들고, `groups_*.json` 은 따로 요청할 때만 내보낸다.

RS23-GC03 71cm 기준 151장 → **34 그룹**. 분리가 매우 깨끗하다:
인접 상관계수가 **0.35 이하 아니면 0.936 이상**으로 양분되고 그 사이에 값이 없어,
기본 임계값 0.55는 빈 구간 한가운데에 놓인다.

> 이 깨끗한 양분은 **RS23에서만 확인된** 값이다. 116cm는 47그룹 중 26개가 단독인데,
> 초점 시리즈를 덜 찍은 것인지 임계값이 이 폴더에 안 맞는 것인지는 아직 구분되지
> 않았다. AM22-GC10B 261cm 는 27 중 26 이 단독이라 확인할 표본이 아예 없다.

**분포가 양분되지 않으면 사람을 부른다** — 그룹 안의 최소 상관과 경계의 최대 상관
사이가 벌어져 있어야 임계값에 뜻이 있다. 좁으면 `state="failed"` 로 남기고 넘어가지
않는다. 잘못 묶인 시야 위에 쌓은 검출과 교정은 되돌리기가 훨씬 비싸다.

**이미 검출하거나 교정한 슬라이드는 다시 묶지 않는다** — 강제하지 않는 한 스스로
거부한다. 재그룹핑은 `Viewpoint` 를 재편하므로 그 아래가 통째로 어긋난다.

그리고 **강제 재그룹핑은 교정을 지운다 — 고아로 만드는 것이 아니다.** 오래도록
안내문이 "교정은 `mask_key` 로 남지만 고아가 된다" 고 적혀 있었는데 **거짓이었다** —
`ObjectReview.viewpoint` 가 `CASCADE` 라 시야가 사라지면 행도 사라진다. `mask_key`
는 칼럼 값일 뿐이고, 행이 없으면 아무것도 아니다. 지금은 교정이 붙은 슬라이드면
플래그를 하나 더 요구하고, 그때도 지우기 전에 교정을 파일로 먼저 뽑는다.

### focus_stack.py — all-in-focus 합성 + 깊이 맵

그룹을 ECC로 정렬(초점 브리딩·스테이지 흔들림 보정)한 뒤, 픽셀별 국소 선명도를
가중치로 soft blending 한다.

시야는 DB(`Viewpoint`)에서 읽는다. 산출물은 `/data3/DiaRUGA/stacked/` 의
`<tag>_focused.jpg`, `<tag>_depth.jpg`, `<tag>_depth.npz` 이고, `Stack` 행과
`Image(kind="stack"|"depth")` 가 함께 만들어진다.

선명도 비교는 **전역 Laplacian 분산으로 하면 안 된다.** 초점이 크게 어긋난 덩어리는
짙은 그림자가 되어 오히려 분산을 키우므로, 합성이 성공해도 숫자가 내려간다
(실제로 0.77x 로 나왔다). 물체 영역의 국소 선명도로 비교해야 하며, 그 기준으로는
최선 단일 프레임 대비 1.04~1.15x 로 개선된다.

#### 깊이 맵에 대해 (현재는 참고용)

픽셀마다 어느 장이 가장 선명했는지가 곧 상대 높이라 깊이 맵이 함께 나온다.
포물선 보간으로 슬라이스 사이를 소수점 단위로 메우고, 초점 정보가 없는 배경은
신뢰도로 마스킹한다. 다만 **한 그룹이 5~6장뿐이고 실제 Z 좌표가 기록돼 있지 않아**
정량적인 높이로 쓸 수는 없다. 등간격 촬영이었는지조차 알 수 없다.
제대로 된 z-stack(Z 위치가 기록된)이 확보되면 그때 본격적으로 쓸 부분이다.

### segment_diatoms.py — 검출 + 규조각 판정

SAM2.1 AutomaticMaskGenerator 로 클래스 무관 후보를 뽑고, 형태·텍스처 지표를
계산해 규조각만 골라낸다. **엔진이 두 벌이다** — SAM2 와 YOLO11m-seg 를 같은 문으로
부르고, 무엇을 무엇과 비교하는지는 `RunBatch` 로 묶어 남긴다.

**두 엔진은 보는 자리가 다르다.** SAM2 는 시야마다 한 장(합성본, 없으면 가장 선명한
프레임)이고 YOLO 는 **합성본 + 프레임 전부**다 — `--all-images` 가 그것이다
(실측: `yolo-3차` 는 시야 452개에 프레임 검출 1,310개).

**묶음 안에서만 인계한다** (P10 · 076). 새 검출이 `is_current` 를 받을 때 끄는 것은
**같은 묶음의 같은 이미지**뿐이다. 안 가리면 나란히 쌓아 둔 다른 회차의 현재
표시가 통째로 꺼진다. "이미 검출했다" 를 판단하는 관문도 **이미지·묶음 단위**다 —
안 그러면 새 묶음으로 전수 재검출이 아예 안 돈다.

**어느 가중치가 이 묶음을 냈는지** 남긴다 (`Run.params.weights` — 경로·크기·
sha256). 회차를 돌리면 가중치가 여럿이 되고, 이름만으로는 같은 이름으로 다시
학습한 파일을 못 가른다. 이름 규칙은 `<모형>-<자료판>-<입력크기>[-<날짜>].pt` 이고
**덮어쓰지 않는다** — 덮어쓰면 옛 묶음의 근거가 사라진다.

통과분뿐 아니라 **탈락분도 지표째 남는다** — `Candidate.passed` 칼럼 하나로
갈린다. 이것이 문턱 재조정(`pipeline/refilter.py`)과 뷰어의 누락 복구를 가능하게 한다.
탈락분이 통과분의 예닐곱 배라 보관 비용은 그만큼 든다. 그래도 버리면 문턱을
되돌릴 수 없다.

DB 로 옮기면서 세 가지가 달라졌다.

- **검출을 덮어쓰지 않고 쌓는다.** 돌릴 때마다 새 `Detection` 행이다. 덮어쓰면
  엔진 교체 전후를 비교할 수 없다.

  **`is_current` 의 뜻은 P10 에서 좁아졌다** — 예전에는 "뷰어가 볼 것" 이었고
  이제는 **그 묶음 안에서 이 이미지의 최신 검출**이다. 뷰어가 무엇을 볼지는
  `RunBatch.for_review` 가 정하고(관리 · 운영에서 고른다), 화면이 그리는 것은
  **둘 다 켜진 것**이다 (`Detection.objects.reviewing()`)
- **사람의 교정을 다시 맺는다**(`migrate/rebind.py`). 개체 행이 통째로 새로 만들어지므로
  교정의 `candidate` 링크가 끊긴다. `is_current` 이동과 재바인딩은 **반드시 한
  트랜잭션**이다 — 중간에 끊기면 뷰어가 "교정이 붙지 않은 새 검출" 을 보여준다
- 실행이 `Run(kind=detect)` 에 남고, 준 이름이 `RunBatch` 가 된다

`out/<stem>_candidates.json` 은 **따로 요청할 때만** 쓴다(P02 7단계). 검출을 그려
넣던 `<stem>_overlay.jpg` 는 걷었다 — 뷰어가 같은 것을 SVG 로 그리는데 그쪽은 켜고
끄고, 확대하면 원본 화소로 가고, 사람의 교정까지 얹는다. 구운 그림은 그중 아무것도
못 한다.

개체마다 기록되는 값:

| 항목 | 내용 |
|---|---|
| 위치·크기 | bbox, 중심, 면적(px/µm²), 타원 장·단축(µm) |
| 형태 | 신장비, 타원 IoU, 볼록성(solidity), 매끈함(convexity), 원형도 |
| 텍스처 | 주기 구조 세기 |
| 윤곽 | 단순화한 외곽선 (뷰어가 instance mask 로 그린다) |
| SAM | predicted_iou, stability_score |

`sam3` 자리도 만들어 뒀으나 `facebook/sam3` 는 HF gated (manual approval) 모델이라
승인된 계정의 `HF_TOKEN` 이 필요하다. 익명 접근은 401이다.

#### 두 번째 엔진 — YOLO11m-seg (P04)

**사람이 검토한 264 시야를 그대로 학습 자료로 썼다**(`ops/export_yolo.py`). 지운 것도
같이 나간다 — 오검출 4,039건이 음성 표본이 됐다. 이것이 교정을 `mask_key` 에
매달아 재생성 가능한 것과 갈라 둔 값이다.

재현율을 지금 파이프라인과 같게 맞춰 놓고 재면 **정밀도가 SAM2+judge 의 1.7배,
속도는 320배**다.

**어느 묶음을 검토할지는 이제 사람이 고른다** (P10, 관리 · 운영). 검토 대상이 아닌
묶음은 검토 화면의 `◉ SAM / ○ YOLO` 라디오로 **읽기 전용**으로 견준다 — 화면이
POST 를 아예 안 보내고, 서버가 남의 검출 키를 409 로 거절하고, 우클릭 메뉴가 고치는
항목을 아예 안 낸다. 셋째가 중요하다: 저장만 잠그면 사람이 한 시야를 **헛검토한다.**

### 회차를 돌린다 — 묶음마다 조리법 (P10 6단계)

앞으로 자료를 늘리는 방식이 정해져 있다: **검토 → 정답 추출 → 학습 → 새 묶음으로
전수 검출 → 다시 검토.** 그래서 묶음이 여럿인 것이 기본이다.

`RunBatch.recipe` 가 묶음마다 "어떻게 검출하는가" 를 든다(`pipeline/segment_diatoms.py` 의
인자). 새 슬라이드가 들어오면 폴러가 **조리법이 적힌 묶음 전부**를 채운다 —
**검토 중인 묶음 먼저, 나머지는 최근 것부터.** 지금 사람이 보는 화면이 가장 먼저
메워지고, GPU 는 한 번에 하나만 도므로 이 순서가 곧 기다리는 순서다.

```
관리 · 운영 화면        조리법을 적는다 (비우면 그 묶음은 안 돈다)
batch_plan.py --args    순서대로 "<묶음> <탭> <인자들>" 을 낸다
deploy/poll_nas.sh      묶음이 바깥 고리, 슬라이드가 안쪽
```

**가중치 파일이 없으면 못 돈다** — 목록에 이유와 함께 남긴다. 조용히 빠지면
"왜 이 묶음만 비어 있나" 를 나중에 묻게 된다. 그래서 가중치는 NAS 로 함께
백업한다(`ops/sync_backup_nas.py` 의 `models_*.tar`, 정리하지 않는다).

### refilter.py — 재추론 없는 문턱 재조정

지표가 통과분·탈락분 **양쪽에** 남아 있으므로 문턱만 바꿔 다시 거를 수 있다.

**124 시야 재적용에 0.9초** (그때의 실측). 재추론이면 40분 이상이다. 문턱 실험은 이쪽으로 한다.

**묶음을 골라 돌린다** (`--batch <이름>` · `--all-batches`, 078). 두 가지가 다른
일이라 갈라 뒀다 — **문턱을 안 바꾸고 다시 판정**하는 것은 저장된 지표로 캐시를
다시 쓰는 것뿐이라 어느 묶음에든 안전하고, **문턱을 바꾸는** 것은 그 묶음이
"그때 그 문턱으로 낸 결과" 라는 사실을 깨므로 검토 중이 아니면 `--force` 를 받는다.

DB 로 옮기면서 세 가지가 달라졌다.

- 통과분·탈락분을 합치는 코드가 사라졌다 — 한 테이블에 `passed` 칼럼이라 **UPDATE 한 번**이다
- **문턱이 `ThresholdSet` 행으로 남는다.** 예전에는 결과마다 복사됐고 다시 거르면
  덮어써져서, "원형 669 → 514 가 언제 무슨 문턱으로 바뀌었나" 에 답할 수 없었다
- 실행이 `Run(kind=refilter)` 에 남는다

**주지 않은 문턱은 그 검출이 지금 쓰는 값 그대로다.** 하나를 바꾸려다 나머지 열
개가 조용히 초기화되면 안 된다(전부 기본값으로 되돌리는 것은 따로 요청해야 한다).

사람의 교정은 건드리지 않는다 — `mask_key` 로 붙어 있고 이것은 판정만 바꾼다.
지운 개체가 탈락분으로 옮겨가도 뷰어에서는 여전히 지운 것으로 보인다.

검출 대상은 **합성본이 원칙**이고, 싱글턴 시야(n=1)만 그 한 장을 쓴다.

## 스키마의 요점 셋

18개 모델의 자세한 모습은 `docs/20260810_db-specification.md` 와 `db-erd.md` 에 있다.
여기 적는 것은 **왜 그 모양인가**다.

```
Slide 1:N Viewpoint 1:N Image(kind = stack | frame | depth) 1:N Detection 1:N Candidate
                                    ↑
                           ObjectReview.image   UNIQUE (image, batch, mask_key)
                                    ↓ N:1
                              DiatomObject      개체 하나 = 사람이 하나로 보는 대상
```

**`batch` 가 열쇠에 들어간다** — 같은 이미지의 같은 마스크라도 **어느 검출을 보고
한 판단인지**가 다르면 다른 행이다. 사람이 그린 것은 `batch` 가 NULL 이라 그 제약이
안 잡으므로(SQLite 는 NULL 끼리 안 부딪힌다) 조건을 뒤집은 제약을 하나 더 둔다.

### 교정은 `Candidate` 가 아니라 `mask_key` 에 붙는다

FK 로 매면 재검출에서 사람의 판단이 조인 실패로 사라진다. **정규화가 덜 된 것이
아니라 소유 방향의 선택이다** — 재생성 불가한 것(교정)이 재생성 가능한 것(검출)의
자식이 되면 안 된다.

모든 교정 행이 `geom` 에 기하를 스스로 들고 있어 **검출기가 바뀌어도 읽힌다.**
지운 것도 학습의 음성 표본이다 — P04 에서 오검출 4,039건이 실제로 그렇게 쓰였다.

### `Image` 는 검출을 돌릴 수 있는 이미지 한 장이다 (P06)

열쇠는 `path` 다 — 파일 하나에 행 하나. 예전에는 합성본과 원본 프레임이 **테이블이
둘**이어서 `Detection` 이 `target`(`stack|frame`) + nullable `frame` 으로 다형 연관을
흉내 냈고, 그것이 교정의 열쇠까지 흔들었다. `(viewpoint, mask_key)` 는 시야마다 볼
이미지가 한 장일 때만 성립하는 열쇠다.

- **촬영·합성 메타는 `Frame`·`Stack` 에 그대로 있다.** `Image` 는 정체만 맡는다
- **`kind="depth"` 에는 검출이 안 붙는다** — 관행이 아니라 스키마에 적혀 있다
- **만드는 문은 `web/viewer/images.py` 하나다.** 파이프라인 네 자리와 재그룹핑이
  전부 여기를 지난다
- **`Image.viewpoint` 는 `SET_NULL`, `Image.stack` 은 `CASCADE`** — 시야를 가르면
  **프레임은 살아남고 합성본·깊이맵은 죽는다.** 방향이 반대인 것이 요점이다

이 정규화가 연 것이 **프레임별 검출을 검토할 자리**다.

### 개체와 판정은 다른 것이다 (P12 · 108)

프레임별 검출을 열어 놓으니 **같은 규조각이 초점면마다 따로 잡힌다.** 사람이 그것을
하나로 묶기 시작하면서(P11) 세 테이블이 반쯤 겹쳤고 — `ObjectReview`(판정) ·
`ObjectLink`(묶음) · `ObjectLinkMember`(멤버) — P12 에서 **둘로 모았다.**
**판정 행이 곧 멤버다.**

```
DiatomObject   이 규조각은 무엇인가        label · species · pose
   1:N
ObjectReview   이 판에서 무엇을 보았는가   removed · accepted · auto_confirmed
                                          · grade · note · geom · is_rep(대표)
```

가르는 기준은 **"초점을 옮기면 달라지는가"** 다.

- **개체의 것** — 분류·종명·자세. 같은 규조각이면 어느 판에서 보든 같다.
  묶으면 값이 하나로 합쳐지고, **엇갈리는데 사람이 안 고르면 서버가 409 로 거절한다**
  (개체가 값을 하나만 들 수 있어 "그대로 두기" 가 성립하지 않는다)
- **판정의 것** — 삭제·되살림·확인·등급·코멘트·기하. **"이 판에서는 초점이 안
  맞는다" 는 판마다 하는 말이다**

진실이 한 곳이라 **번지게 하는 코드가 없다** — 104 가 만들었던 전파 함수가 P12 에서
통째로 사라졌다. 읽는 자리 79곳은 `ObjectReview.label` 같은 **읽기 전용 통로**로
그대로 두었고, **쓰기는 `AttributeError` 다**(조용히 안 먹히는 것보다 낫다).

판정 행은 **개체 없이 설 수 없다**(NOT NULL). 그래서 행을 만드는 자리 셋(검토 저장 ·
그리기 · 카탈로그)이 **문 하나(`data.judgement_for`)를 지난다** — 규칙이 셋이면
하나만 빠뜨려도 `IntegrityError` 이거나, 더 나쁘게는 **대표 없는 개체**가 선다.

```
시야 목록      /d/<slug>/
시야 화면      /d/<slug>/g/<n>/   ← 사람이 교정하는 화면

관리 · 학습자료 /manage/dataset/   검토 결과에서 정답을 얼마나 뽑을 수 있는가
```

**엔진 비교는 검토 화면 안에서 한다** — 사진 위 탭줄의 `◉ SAM / ○ YOLO`
라디오(`?batch=<실행>`)다. 묶음을 한 표로 훑던 `/engine/` 화면은 075 에서 지웠다.

지도는 권역마다 투영이 다르다 — 남극 EPSG:3031(극구면), 한국 EPSG:5179. `전체` 탭에
지도가 없는 것은 **섞을 수 없기 때문이다.** 좌표가 없는 지역은 주황 마커 + 오차 원으로
대략값임을 드러낸다.

**목록의 "검출" 칸과 상세 화면의 검출 수는 다른 것을 센다.** 목록은
`ClassDef.counted` 가 켜진 분류만 더한다 — 파편을 개체로 세면 밀도가 부푼다(369cm
923 → 444). 상세 화면의 "검출 N → 검토 후 M" 은 검토가 얼마나 걸러 냈는가를 보는
줄이라 파편도 센다.

**목록의 마스크·배지·개수는 요청할 때마다 다시 계산한다** — 교정하고 목록으로 오면
그 자리에서 반영돼 있다. 다만 두 군데서 옛 화면이 남을 수 있어 막아 두었다:

- 이미지 주소에 원본 mtime(`v=`)을 박고 `Cache-Control: immutable` 로 보낸다.
  주소가 그대로면 합성본을 다시 만들어도 브라우저가 옛 그림을 붙잡는다. 반대로
  주소가 내용에 따라 바뀌면 마음껏 캐시해도 늘 맞고, 두 번째 방문이 빨라진다
  (`v=` 없이 들어온 주소는 `no-cache` 로 답한다)
- **뒤로 가기**로 돌아오면 브라우저가 캐시된 화면을 되살린다(bfcache). 그때는
  `pageshow` 에서 다시 받는다 — 교정·검토 표시가 옛것이면 안 된다

캐시된 값을 손대지 않는 것도 중요하다. `detection_for()` 는 후보를 **복사한 뒤**
교정을 얹는다 — 원본 dict 에 `removed`·`cls`·`note` 를 써 넣으면 그 값이 캐시에
남아, **교정을 되돌려도 옛 상태가 계속 따라붙는다.**

검출 레이어는 구운 오버레이 JPG 가 아니라 좌표에서 박스와 instance mask 를 SVG 로
직접 그린다.

시야 화면은 **검출 화면 / 개체 목록** 두 탭이고, 사진 아래 **캐러셀**에 합성본 ·
깊이 맵 · 원본 프레임이 모두 걸린다. 커서를 올리면 미리 보고 클릭하면 교체되는데,
**검출 레이어는 그대로 얹혀 있어 합성본이 아닌 원본에서도 검출이 맞는지 확인할 수
있다.** 다만 원본 프레임은 ECC 정렬 이전이라 마스크가 조금 어긋난다.

캐러셀은 `« ‹ [썸네일 목록] › »` 꼴이다. 썸네일에 붙은 파란 막대는 **선명도**
(그룹 내 최고 대비 비율)이고 원본 프레임에만 있다 — 합성본·깊이 맵에는 선명도가
없다. 막대 유무로 사진 위치가 어긋나지 않게 썸네일은 위에서부터 쌓는다(버튼의
기본 수직 중앙 정렬을 끈다).

캐러셀은 **← →** 로도 넘기고, **Ctrl+← →** 는 사진을 거치지 않고 곧바로 이웃
시야로 간다(`« »` 버튼과 같다 — 묻지 않는다). 마지막 사진에서 → 를 한 번 더 누르면 다음 시야로
넘어갈지 묻고(첫 사진에서 ← 도 대칭으로 동작한다), **다시 묻지 않기**를 고르면
이후로는 바로 넘어간다(localStorage). 이전 시야로 거슬러 갈 때는 그 시야의 마지막
사진에서 시작해 ← → 왕복이 끊기지 않는다. 시야를 옮기기 전에 **지연 저장 중인
교정을 먼저 밀어낸다** — 지우고 곧바로 → 를 눌러도 기록이 사라지지 않는다.

| 조작 | 동작 |
|---|---|
| 휠 / 우클릭 드래그 | 확대 / 이동 |
| hover | 개체 통계 팝업 |
| 클릭 · Shift+클릭 · 드래그 | 선택 · 추가/해제 · 범위 선택 |
| 같은 자리 반복 클릭 | **겹친 개체를 작은 것부터 돌려 가며 선택** (n/N 표시) |
| 우클릭 (정지) | 컨텍스트 메뉴 — 삭제 · **분류 지정** · **코멘트** |
| 빈 곳 클릭 | **마스크가 그 자리를 덮는** 탈락 후보를 잘라 보여줌 → 고르면 검출로 인정 |
| 좌상단 버튼들 | 선택 · 배율 초기화 · 삭제분 · 실행취소 · 교정 초기화 · **마스크 그리기** |
| **d** 또는 그리기 버튼 | 점을 찍어 마스크를 새로 그린다. **마지막 점에서 커서까지 점선이 따라온다** |
| 우클릭 → 모양 고치기 | 있는 마스크의 점을 끌어 옮긴다 (선분을 누르면 점이 는다) |
| 하단 가운데 **검토 완료** | 이 시야를 다 봤다고 표시 → **다음 시야로 이동** (목록에 ✓ 검토 배지) |
| 우상단 체크박스 | bbox · mask · **탈락** 표시 토글 (localStorage 에 남는다) |
| 캐러셀 hover / 클릭 | 그 사진 미리보기 / 교체 |
| **← →** 또는 **‹ ›** | 캐러셀 앞뒤 사진. **끝에서 한 번 더 누르면 이웃 시야로 넘어갈지 묻는다** |
| **« »** 또는 **Ctrl+← →** | 묻지 않고 바로 이웃 시야로 (없으면 비활성) |

교정 버튼은 사진 위에 얹혀 있다 — 좌상단에 도구, 하단 가운데에 **검토 완료**,
우상단에 레이어 토글, 우하단에 스케일바. 사진에서 눈을 떼지 않고 조작하려면
버튼이 사진 위에 있어야 한다(배율 표시는 남은 좌하단으로 뺐다).

**검토 완료**는 `ViewpointReview.done` 에 저장되고 시야 목록에 `✓ 검토` 배지로
나타난다. **묶음마다 따로다**(073) — `sam2-전수` 를 다 봤다고 `yolo-3차` 를 본
것이 아니기 때문이다. 시야 코멘트는 반대로 묶음과 무관해서 `batch=NULL` 인 줄에
따로 산다. **교정이 하나도 없어도 켤 수 있다** — 고칠 것이 없어서 기록이 빈 시야와
아직 보지 않은 시야는 전혀 다른 것이고, 그 구분이 재현율 실측과 학습 데이터 선별의
근거다.

완료로 표시하면 **곧바로 다음 시야로 넘어간다**(묻지 않는다 — 누른 사람의 뜻이
분명하다). 해제할 때는 한 번 더 묻는다 — 잘못 눌러 풀리면 "다 본 시야"라는
표시가 조용히 사라지기 때문이다.

#### 엔진 고르기는 이 화면 안에 있다

사진 위 탭줄의 `◉ SAM 0 ○ YOLO 3` 라디오다 — 누르면 **시야는 그대로 두고** 그림 위의
개체만 바뀐다. 이웃 시야로 넘어가도 고른 엔진을 들고 간다.

**묶음이 아니라 엔진으로 접는다.** 한 엔진에 묶음이 여럿이면 *지금 보는 것 → 현재
검출을 낸 것 → 나중 것* 순으로 대표를 세운다. 그래서 `yolo-4차` 를 쌓아도 칸이
늘지 않고 대표만 바뀐다.

#### 검출 결과만 보기 (`/d/<slug>/crops/`)

시야 목록의 **검출 결과만 보기** 링크. 검출된 개체만 bbox 로 잘라 썸네일로
늘어놓는다 — 시야를 하나씩 넘겨보지 않고 "이것들이 정말 규조각인가" 를 한 화면에서
훑기 위한 화면이다. **크기 내림차순이라 의심스러운 것(작고 밋밋한 것)이 뒤에 모인다.**
테두리 색이 판정(봉상·원형·수동복구)이고, 누르면 그 시야로 간다.
형태로 거를 수 있다(`?cls=rod|round|manual`).

**방향을 세워서 보여준다** — 마스크 폴리곤의 주축을 구해 **장축을 세로로** 돌린다.
방향이 통일되면 형태를 나란히 비교할 수 있다. 축 비율이 1.15 미만이면(원형처럼
방향이 뜻 없는 것) 돌리지 않는다 — 보간으로 흐릴 이유가 없다. `원래 방향` 칩으로
사진에 있는 그대로도 볼 수 있다(`?upright=0`).

주축은 **폴리곤의 면적 모멘트**를 닫힌 해로 풀어 구한다. 꼭짓점만 PCA 하면
`approxPolyDP` 로 단순화된 점 간격이 고르지 않아 결과가 치우친다. 회전과 자르기는
한 번의 affine 변환으로 함께 한다 — 잘라서 돌리면 모서리가 비고 두 번 보간하게 된다.
합성 타원(0·20·45·70·110·160°)으로 넣고 **결과 이미지를 다시 재서** 전부 90°(세로)로
서는 것을 확인했다.

썸네일마다 **스케일바**가 붙는다(1·2·5 눈금, 이미지 폭의 40%를 넘지 않게 내림).
바는 칸이 아니라 **이미지에 붙인다** — `object-fit` 여백만큼 길이가 어긋나기 때문이다.
감싼 요소가 이미지를 꼭 감싸므로 백분율이 곧 이미지 폭이 된다. 크롭이 몇 µm 폭인지
알 수 있는 것은 회전량과 결과 크기를 **자르기 전에 확정**해 두기 때문이다(여백까지
포함해서). 자르는 쪽에서 여백을 따로 더하면 그 값을 알 수 없다.

크롭은 서버가 잘라 `/data3/DiaRUGA/.thumbcache/` 에 캐시한다(개체마다 한 장, 여백 8%).
개체가 데이터셋마다 700~1,100개라 **한 페이지에 500개까지만 그리고** 나머지는
`?offset=` 으로 넘긴다.

화면에는 **1600 px 축소본**을 띄운다(원본 2752 px, 134 KB vs 606 KB). 그대로
확대하면 없는 화소를 늘리는 셈이라, **그려지는 폭이 지금 이미지의 실제 화소를 넘는
순간 원본으로 갈아 끼운다**(`naturalWidth` 로 재므로 축소본 폭을 코드에 박지 않는다).
요소도 배율도 그대로여서 화면은 흔들리지 않고 선명도만 올라간다. 캐러셀 hover
미리보기는 축소본을 쓴다 — 커서만 지나가는데 600 KB 를 받으면 무거워진다.

좌하단 **배율 표시는 원본 화소 기준**이다. 화면에 맞춘 상태를 100% 라고 하면 "지금
원본을 다 보고 있는가" 를 알 수 없다 — 2752 px 을 1460 px 폭에 맞춰 놓은 것이라 실제로는
`53%` 다. `100%` 는 원본 1화소가 화면 1화소라는 뜻이고, 원본을 받아 온 뒤에는 `· 원본`
이 붙는다. areolae 를 축소본을 늘린 화면으로 판단하면 안 되므로 무엇을 보고 있는지
드러나야 한다.

**선 두께는 확대해도 그대로다.** canvas 가 `scale(k)` 로 커지므로 두께를 쓰는 곳마다
`calc(2px * var(--inv))` 로 역수를 곱한다(`--inv` = 1/배율, `applyTransform()` 이 얹는다).
bbox 테두리·hover 후광·유령 ✕ 가 모두 여기 걸려 있다. 예전에는 JS 가 요소마다
`Math.max(1, 2/k)` 로 계산했는데, **2배를 넘으면 1px 하한에 걸려 오히려 배율만큼
두꺼워졌다**(12배에서 12px).

우하단 **스케일바**는 검출에 기록된 µm/px 로 그린다. 확대·이동에 상관없이 늘 같은
자리에 있고, 배율이 바뀌면 1·2·5 계열로 눈금을 다시 잡는다.

SAM2 는 한 자리에 여러 스케일의 마스크를 내므로 bbox 가 예사로 겹친다(후보의
84%가 더 큰 마스크 안에 든다). 맨 위의 것만 잡히면 아래 것을 고를 수 없으므로,
**같은 자리를 다시 클릭하면 다음 개체로 넘어간다** — 작은 것부터 돌고, 선택 정보에
`이 자리에 3개 겹침 (2/3)` 으로 몇 번째인지 나온다. Shift+클릭은 더하고 빼는
조작이라 순환하지 않는다(두 번 누르면 제자리로 돌아와야 한다).

bbox 를 끄면 화면에 보이는 것은 마스크뿐이므로 **클릭·hover 판정도 마스크(폴리곤)로
바뀐다** — 큰 물체의 빈 자리를 눌렀을 때 보이지도 않는 것이 잡히면 안 된다. bbox 가
보일 때는 bbox 로 잰다. 지운 것(점선 유령)은 마스크를 칠하지 않으므로 마스크 모드에서는
누를 수 없다 — 되살리려면 bbox 를 다시 켠다. 박스 요소 자체는 두 모드 모두 남긴다.

#### 분류 직접 지정과 코멘트

자동 판정은 **봉상 / 원형** 둘뿐인데, 조각난 규조각이 그 둘 중 하나로 잘못 들어가는
일이 있다. 개체를 고르고 우클릭하면 직접 지정할 수 있다.

| 분류 | 색 | 배지 | 키 | 센다 |
|---|---|---|---|---|
| 원형 `round` | 진한 초록 | `rnd` | `q` | ○ |
| 원형 파편 `round_frag` | 옅은 초록 | `rndf` | `q` (한 번 더) | ✕ |
| 봉상 `rod` | 진한 파랑 | `rod` | `w` | ○ |
| 봉상 파편 `rod_frag` | 옅은 파랑 | `rodf` | `w` (한 번 더) | ✕ |
| Eucampia | 분홍 | `euc` | `e` | ○ |
| Chaetoceros (`CRS`) | 연두 | `cha` | `r` | ○ |

**색상이 "무엇인가", 진하기가 "온전한가" 를 말한다.** 본체와 파편이 같은 색 가족이라
화면에서 관계가 읽힌다 — 축이 둘로 갈라져 분류가 늘어도 규칙이 선다. 단축키도 같은
모양이라 `q` 를 한 번 더 누르면 파편이다.

**형태 칸과 분류학 칸은 성격이 다르므로 메뉴에서 줄을 그어 나눈다**(`is_taxon`).
Eucampia 는 형태가 아니라 속(屬)으로 알아보는 것이고 남극 시료의 지시종이라, 형태
칸에 묶어 둘 수 없다.

**분류를 더할 곳은 `ClassDef` 테이블이다** — 코드가 아니다. 화면 규칙을 코드에서
테이블로 옮긴 목적이 "분류를 더할 때 배포가 필요 없게" 였다. 다만 **테이블에 행
하나로 끝나지 않는다**: `label`·`short`·`badge`·`color`·`hotkey`·`counted`·
`is_taxon`·`sort_order` 여덟에 `base.html` 의 CSS 까지다. 하나라도 비면 **예외는 안
나고 그 분류만 조용히 다르게 굴러간다** — 마스크가 투명해 "지정은 되는데 화면에 안
보이는" 상태가 될 뻔했다. `ops/check_db.py` 가 단축키·색 두 개는 잡아 준다.

**되돌릴 때는 행을 지우지 말고 `active=False` 로 끈다.** 지우면 그 분류로 붙인 교정이
이름 없는 분류가 되어 화면에서 안 읽힌다.

사람의 지정은 자동 판정을 덮어쓰지만 원래 값을 `cls_auto` 로 남긴다(툴팁에 `자동
판정: 원형` 으로 보인다). 사람이 지정한 것은 테두리가 점선이라 자동 판정과 구분된다.
`분류 지정 해제` 로 자동 판정으로 되돌린다. Ctrl+Z 도 듣는다.

**코멘트**는 개체마다 하나씩 달 수 있고(우클릭 → 코멘트, Ctrl+Enter 로 저장) **사진
오른쪽에 목록으로 나열된다.** 목록 항목에 커서를 올리면 그 개체가 선택되고, 반대로
개체를 고르면 그 코멘트가 강조된다 — 메모를 읽으면서 어느 것에 대한 말인지 바로
짚을 수 있어야 한다. 항목을 클릭하면 고칠 수 있다.

**시야 전체 코멘트**는 코멘트 칸 **아래쪽 고정 높이 자리에서 그 자리로 바로 적는다**
(팝업을 열지 않는다). 개체에 붙지 않는 이야기(초점 상태, 판정을 보류한 이유 같은 것)를
적는 곳이다. 빈 곳 우클릭 메뉴는 그 칸으로 커서를 보낸다. 타이핑하는 동안 저장이
흐르고, 칸을 벗어날 때 실행취소 한 칸으로 묶인다 — 글자마다 이력을 쌓으면 Ctrl+Z 가
쓸모없어진다. Esc·Ctrl+Enter 로 칸에서 빠져나온다.

개체 코멘트 칸과 시야 코멘트 칸은 **각각 스크롤되고**, 아래 칸은 높이가 고정이라
개체 코멘트가 길어져도 밀려나지 않는다. 시야 전체 코멘트는 `ViewpointReview.note` 에
저장된다.

교정은 **`mask_key` 로** 저장되므로 문턱을 바꾸거나 검출을 다시 돌려도 같은 마스크에
그대로 붙는다. 학습 데이터를 뽑을 때 이 값이 정답이 된다. **분류는 개체
(`DiatomObject`)에, 코멘트는 판정(`ObjectReview`)에 산다** — 위 "개체와 판정은
다른 것이다" 를 볼 것.

데이터셋 화면 두 번째 줄에 진척이 한 줄로 나온다 — **자동 검출 → 교정 후** 개수,
분류별 개수, 그리고 사람 손이 들어간 양(삭제·되살림·분류 지정·코멘트):

```
검출 811 → 교정 후 264개 (원형 38 · 원형 파편 31 · 봉상 119 · 봉상 파편 63 · Eucampia 8)
· 시야당 7.8 · 교정: 삭제 608 · 되살림 47 · 분류 지정 109 · 코멘트 2 (+시야 1)
```

자동 검출 수와 교정 후 수를 **함께** 보여야 뜻이 통한다 — 하나만 보면 문턱이 센 것인지
사람이 많이 지운 것인지 알 수 없다. 분류별 개수는 `ClassDef` 를 훑으므로 분류를 더해도
이 줄은 손댈 필요가 없다.

| `ObjectReview` 칸 (**판마다**) | 뜻 |
|---|---|
| `removed` | 오검출로 지운 개체 |
| `accepted` | 탈락분에서 **되살린** 개체 |
| `auto_confirmed` | 검토 완료가 남는 개체에 단 **확인 표시** (109). 되살림과 축이 달라 칸을 나눴다 — 뭉치면 "엔진이 놓친 것 몇 건" 을 못 센다. **마스크마다 누른 것이 아니라 이름이 `auto_` 다** |
| `grade` | 등급 `A`·`B`·`C` — **초점면마다 다르다** (파편에는 안 준다) |
| `note` | 개체별 메모 (최대 500자) — 판마다 하는 말이다 |
| `geom` | 기하를 스스로 들고 있다 — 검출기가 바뀌어도 읽힌다 |
| `is_rep` | 묶인 판들 중 **대표** (개체마다 하나) |

| `DiatomObject` 칸 (**개체마다**) | 뜻 |
|---|---|
| `label` | 사람이 지정한 분류 (자동 판정보다 우선) |
| `species` | 종명 — 자유 입력 + 자동완성 (개체 카탈로그 화면) |
| `pose` | 자세 `valve`·`girdle`·`other` — 초점을 옮겨도 안 변한다 |

시야 단위는 `ViewpointReview` 가 맡는다 — `note`(시야 전체 메모)와 `done`(다 봤다는
표시).

크롭 갤러리에도 `봉상 파편`·`원형 파편`·`사람 지정`·`코멘트 있음` 필터가 있다.

#### 탈락 후보는 마스크로만 판정한다

우상단 **탈락** 체크박스를 켜면 문턱에서 떨어진 후보가 **빨간 점선 테두리**로 보인다
(채우지 않는다 — 사진이 가려지면 정작 규조각인지 판단할 수 없다). 시야당 100개가 넘어
기본값은 꺼짐이다. 재현율을 눈으로 확인하거나 누락을 되살릴 때 켠다. 선 두께와 점선
간격은 `vector-effect: non-scaling-stroke` 라 확대해도 그대로다.

빈 곳 클릭으로 펼치는 후보도 **마스크가 그 지점을 덮는 것만** 고른다. bbox 로 재면
아무것도 없는 자리에서도 잔뜩 뜬다 — 실측으로 탈락 후보의 **bbox 합집합은 화면의
46.6%** 인데 **마스크 합집합은 19.5%** 다. 그 차이 25%p 가 "빈 곳인데 후보가 뜨는" 자리이고,
탈락분은 그려지지 않으니 왜 떴는지 알 수도 없다. bbox 는 폴리곤 판정 전의 값싼
1차 걸름망으로만 쓴다. (폴리곤이 없는 탈락 후보는 16,414개 중 0개라 잃는 것도 없다.)

**빈 곳을 클릭하면 그 자리의 탈락 후보를 펼쳐 보여준다.** 크롭은 서버(`/crop`)에서
잘라 오고 **원래 종횡비를 지킨다** — 칸에 억지로 맞추면 실측 종횡비 0.15~7.2 인 물체가
최대 9배까지 늘어나 형태를 보고 판단할 수가 없다. 그 위에 **마스크를 얹어** 무엇을
따온 것인지 보여준다(여백을 클라이언트가 계산해 `pad=0` 으로 넘기므로 폴리곤이 정확히
겹친다).

시야 목록의 표지 썸네일에도 **검출 마스크를 얹는다** — 목록에서 무엇이 잡혔는지 바로
보인다. 검출을 돌린 이미지와 표지가 같을 때만 그린다(다른 이미지의 좌표를 얹으면
조용히 어긋난 그림이 된다).

오검출로 지운 것은 점선으로 남아 클릭 한 번에 되살아난다(Ctrl+Z 도).

#### 사람이 지운 것이 문턱 변경으로 탈락분이 되면

`pipeline/refilter.py` 로 문턱을 올리면 사람이 이미 지워 둔 개체가 탈락분으로 옮겨갈 수 있다.
이때 **"사람이 지웠다"가 이긴다** — 지운 것이 조용히 되살아나는 것이 가장 나쁘다.
그런 개체는 여전히 빨간 점선 유령으로 남고, 툴팁에 `지금 문턱에서는 탈락분이다` 가
붙는다. 되살리면 수동 복구(`accepted`)로 저장되므로 문턱과 무관하게 유지된다.

같은 이유로 두 가지를 지킨다:

- 유령으로 이미 화면에 있는 것은 **"이 자리의 탈락 후보" 목록에서 뺀다** — 같은
  개체가 두 곳에 나오면 어느 쪽을 눌렀는지에 따라 결과가 달라진다
- 복구 목록(`accepted`)은 **서버가 준 것을 그대로 쓴다.** 예전에는 `manual` 표시로
  되짚었는데, 그러면 지워 둔 탈락분이 "복구된 것"으로 세어져 **다음 저장에서 지운
  것이 되살아났다**

#### 저장은 그 시야의 교정 **전체**를 갈아치운다

`/review` POST 는 받은 키 목록에 없는 교정을 지운다. **"뷰어는 늘 전체를 보낸다"**
가 전제이고, 깨지면 나머지를 지운다. 이것으로 **세 번 당했다** — 빈 키 목록을 운영
DB 로 보내 14건, "읽기 전용" 이라 적어 놓고 CSS 로 버튼만 감춘 화면에서 클릭 한 번에
37건, 그리고 저장이 **남의 시야로 가고 있어서** 138행이 노출됐다.

셋째가 가장 조용했다. 시야를 `stem` 하나로 찾았는데 **프레임 이름은 슬라이드끼리
겹친다**(카메라 일련번호라 같은 날 이어 찍으면 번호대가 이어진다 — 143종). 싱글턴
시야 135개 중 **12개가 다른 슬라이드의 시야를 열고 있었고**, 개체를 하나도 안
건드리고 **"검토 완료" 만 눌러도** 그쪽 교정이 통째로 지워졌다. 200 이 돌아오고
화면에는 "저장됨" 이 뜬다. 지금은 `(slug, gid)` 로 짚는다 — 이름은 겹쳐도 주소는
안 겹친다.

**그래서 화면을 눌러 보는 시험은 반드시 사본 DB 에 붙인다.**

`ALLOWED_HOSTS` 는 실제로 응답할 이름만 명시돼 있다. 인증이 없으므로 공개망에
그대로 올릴 물건이 아니다. 다른 호스트로 붙으려면 `DIARUGA_HOSTS` 환경변수를 쓴다.

### 문턱 조정 화면 (`/thresholds/`, `/d/<slug>/thresholds/`)

문턱을 만지는 일의 어려움은 **한 시야를 보며 정한 값이 시야 전부에 걸린다**는
것이다. 그 영향을 보지 못하면 적용하고 나서 시야를 하나씩 다시 확인해야 한다.

그래서 이 화면은 슬라이더를 움직이는 대로 **전체 영향**과 **영향받는 시야**를 함께
보여준다. 실측 근거가 있다(124 시야이던 때의 값이다).

| | |
|---|---|
| 전체 재판정 | **50 ms** (개체 18,936개) |
| 문턱을 바꿔도 판정이 뒤집히는 개체 | 전체의 **0.4~3.3%** |
| areolae 1500 → 2000 일 때 영향받는 시야 | **57/124** — 나머지 67개는 볼 이유가 없다 |

**볼 것은 그 차이뿐이다.** 시야를 2컬럼으로 늘어놓되 **영향 큰 순**으로 정렬하고,
빠지는 개체는 빨간 테두리, 들어오는 개체는 초록 테두리로 표시한다. 크롭만 보면
"이게 규조각인가" 를 판단할 맥락(주변 쇄설물, 다른 개체와의 대비)이 잘리므로 시야를
통째로 보여준다. 칸을 클릭하면 그 시야가 열린다.

**판정은 서버가 한다**(`pipeline/judge.py` 하나). 규칙을 JS 로 복사하면 두 곳이 어긋난다.
폴리곤은 시야마다 한 번만 받아 캐시하고, 슬라이더를 움직일 때는 판정
(`mask_key → cls`)만 다시 받아 색을 바꾼다 — 그래서 즉각 반응한다.

적용 범위는 **전역 또는 슬라이드**다. 시야마다 다른 문턱을 두지 않는다 — 같은
슬라이드 안에서도 시야별 텍스처 중앙값이 1,830~11,551 로 6배 넘게 벌어지는데, 그것은
**시료가 실제로 다른 것**이지 맞춰야 할 오차가 아니다. 시야마다 문턱을 맞추면 깊이별·
지역별 비교가 측정이 아니라 조정의 산물이 된다. 문턱이 갈라져 있으면 화면이 경고한다.

이력이 남고(`Run(kind=refilter)`) 항목을 누르면 그때 값을 불러온다. 탈락분을 지표째
보관하므로 문턱은 몇 번이든 왕복할 수 있다.

## 공통 부품

### zen_meta.py — 촬영 메타데이터 읽기

사진 옆의 `<파일명>.jpg_metadata.xml` 에서 **픽셀 크기(µm/px)** 와 촬영 시각을
읽는다. 픽셀 크기의 결정 순서는

```
XML (Scaling/Items/Distance)  >  사이드카 <파일명>_scale.json  >  기본값
```

합성본에는 ZEN XML 이 따라오지 않으므로 `pipeline/focus_stack.py` 가 원본에서 읽은 값을
`<tag>_focused.jpg_scale.json` 으로 물려준다(합성 단계에서 리사이즈했다면 그것도 반영).
기본값으로 물러날 때, 배율이 광학현미경 범위 밖일 때, X·Y 픽셀 크기가 다를 때,
**한 번의 실행에서 배율이 섞일 때** 각각 경고한다.

픽셀 크기를 명령줄에서 직접 지정하면 XML 을 읽지 않는다. 검출 행에는 쓰인 값과
함께 출처(`um_per_pixel_source`: xml/sidecar/default/cli)가 남는다.

`python3 test_zen_meta.py` — 합성 XML 로 파서를 검증한다. 촬영 데이터도 GPU도
필요 없고 표준 라이브러리만 쓴다.

### judge.py — 규조각 판정 규칙

**판정 앞에서 같은 bbox 를 접는다** (`collapse_boxes`, 077). DB 의 열쇠가
`mask_key`(= bbox 문자열)라 같은 자리는 한 행밖에 못 들어가는데, 예전에는
**판정한 뒤** 넣으면서 버렸다. 그러면 판정이 본 집합과 저장된 집합이 달라져
**저장된 판정을 다시 계산해도 안 맞는다** — `ops/check_db.py` 의 "판정 == 지표 + 문턱"
이 그것을 잡는다.

`pipeline/segment_diatoms.py`(검출 직후)와 `pipeline/refilter.py`(문턱 재조정)가 **같은 함수를 쓴다.**
두 곳에 적어 두면 어긋나고, 어긋나면 "다시 걸렀더니 결과가 달라졌다" 는 일이 조용히
생긴다. 문턱 기본값(`DEFAULTS`)도 여기가 유일한 정의다.

**torch·cv2 에 기대지 않는다** — 문턱 재조정은 GPU 가 필요 없는 일이고, 뷰어와 처리를
갈라 담을 때 이 규칙은 가벼운 쪽에 있어야 한다.

## 규조각 판정 기준

SAM2 는 클래스 무관이라 규조각·쇄설물·배경을 가리지 않고 잡는다. 시야당 후보가
150~350개 나오므로 선별 기준이 필요하다. 참조 도판(Plate 1~9) 실측을 근거로 잡았다.

```
크기      타원 장축 10 – 150 µm             도판 실측 13~95 µm 를 여유 있게 포함
텍스처    주기 구조 세기 ≥ 1000             ← 1차 관문
원형      신장비 < 1.4,  타원IoU ≥ 0.85,  볼록성 ≥ 0.92,  텍스처 ≥ 1500
봉상      신장비 2.0–20, 타원IoU ≥ 0.72,  볼록성 ≥ 0.85
집합체    자식 2개 이상 + 자식면적 > 자기 50% → 덩어리로 보고 제거
중복      상호 80% 이상 겹치면 텍스처 높은 쪽만
```

### 원형은 areolae 를 더 무겁게 본다

원형에만 `--round-texture-min`(기본 1500)을 따로 걸어 봉상보다 높은 텍스처를
요구한다. **형태로는 밋밋한 원반을 가려낼 수 없기 때문이다** — 원형 통과분을
텍스처 구간별로 갈라 보면 형태 지표가 거의 평평하다:

| 텍스처 구간 | 개수 | 타원 IoU 중앙 | 볼록성 중앙 | 장축 중앙 |
|---|---|---|---|---|
| 1000~1500 | 159 | 0.887 | 0.962 | 14.2 µm |
| 1500~2000 | 82 | 0.896 | 0.957 | 14.2 µm |
| 2000~3000 | 121 | 0.886 | 0.960 | 15.2 µm |
| 3000~5000 | 124 | 0.891 | 0.959 | 16.6 µm |
| 5000+ | 183 | 0.898 | 0.966 | 18.4 µm |

IoU 0.886~0.898, 볼록성 0.957~0.966 — 형태 문턱을 어디에 두어도 areolae 가 약한
원반과 뚜렷한 중심목이 갈리지 않는다. 그래서 areolae 세기 자체를 관문으로 둔다.
탈락분은 `원형areolae부족` 으로 남으므로 뷰어에서 되살릴 수 있고, 문턱은
`refilter.py --round-texture-min` 으로 2초에 다시 잡는다.

> **다만 텍스처는 크기와 같이 움직인다**(장축 중앙 14.2 → 18.4 µm). 작은 개체는
> areolae 를 담는 화소가 적어 점수가 낮게 나오므로, 이 문턱은 **작은 중심목을
> 먼저 떨어뜨린다.** 실물로 검증되지 않은 부분이다(TODOs 1순위).

### 왜 이렇게 되었나

**봉상과 원형은 하나의 기준으로 묶인다 — 타원.** 우상목은 길쭉한 타원, 중심목은
이심률 0인 타원이다. 마스크가 적합 타원과 얼마나 겹치는가로 둘을 함께 잰다.
퇴적물 덩어리도 잘린 조각도 타원이 아니므로 자연히 걸러진다.

**텍스처가 결정적이다.** 도판의 규조각은 예외 없이 규칙적 주기 구조를 갖는다 —
우상목은 조흔(striae), 중심목은 areolae 격자. 조흔 간격이 10 µm 당 8~20개이므로
주기 0.4~1.6 µm, 즉 약 4~14 픽셀이라 충분히 분해된다. FFT 로 이 대역의
피크/중앙값을 재면 **규조각 1,500~19,000 vs 구조 없는 티끌 12~240** 으로 세
자릿수가 갈린다. 대역을 픽셀이 아니라 µm 로 정의해서 `--scale` 을 바꿔도 같은
구조를 본다.

**둘 다 요구해야 한다.** 실측으로 확인했다.

| 조합 | 결과 |
|---|---|
| 형태만 | 밋밋한 원반·쇄설물 혼입 |
| 텍스처만 | 재현율↑, 정밀도 붕괴 (쇄설물 대거 유입) |
| **텍스처 AND 형태** | **전부 진짜 규조각** |

### 폐기한 접근 — 다시 시도하지 말 것

- **`box_nms_thresh` 조이기로 중첩 제거.** SAM2 는 격자 포인트마다 다중 스케일
  마스크를 내므로 최대 6단계까지 중첩되고 후보의 84%가 더 큰 마스크 안에 든다.
  그런데 포함관계 205쌍의 **IoU 중앙값이 0.07** 이다(작은 것이 큰 것 안에 들면
  IoU 는 오히려 작아진다). 문턱 0.8이 잡는 포함쌍은 **0개**, 0.5로 조여도 43/205
  뿐이다. IoU 기반 NMS 는 중첩을 구조적으로 못 잡는다.
- **원형도(circularity)를 테두리 매끈함 지표로 사용.** 원형도는 신장비에 지배된다.
  신장비 6인 봉상은 윤곽이 완벽해도 0.37이다. **볼록껍질둘레/실둘레**로 교체했다.
- **원형 문턱을 봉상에 그대로 적용.** 우상목은 피침형이라 타원 적합도가 구조적으로
  낮다(중앙값 0.789). 원형용 문턱을 쓰면 봉상 26개 중 1개만 통과한다.
- **중첩 정리에서 큰 쪽 남기기.** 덩어리가 내부 규조각을 전부 삼킨다(67 → 8개).
  집합체를 골라 버리고 개별 물체를 남기는 쪽으로 뒤집었다.

### 크기 관문은 타원 장축으로 본다

bbox 긴 변만 보면 비스듬히 누운 물체에서 실제보다 커져, 장축 4 µm 짜리가
10 µm 관문을 통과한다. 실제로 배치 후 집계에서 발견해 고쳤다.

## 성능

AMG는 격자 포인트마다 디코더를 돌리므로 비용이 `points_per_side^2` 에 비례한다.
게다가 포인트 배치마다 마스크를 **원본 해상도로 업샘플링**해서 메모리를 크게 먹는다.
64포인트 x 2208x2752 x float32 = 텐서 하나에 1.55 GB.

### Quadro RTX 8000 48 GB (현재 기준 장비)

**권장 설정: `--scale 1.0 --points-per-side 48 --points-per-batch 64`**

| 항목 | 값 |
|---|---|
| 장당 시간 | **약 21초** (124장 실측 평균, 20~30초 분포) |
| 픽셀 | 0.1126 µm/px (원본 해상도) |
| VRAM | 실행 중 약 20 GB 관측 |
| 124 시야 전체 | 합성 포함 **약 50분** (그때의 실측) |

Turing(cc 7.5)이라 `autocast_dtype()` 이 **fp16 autocast** 를 켠다. 48 GB 라
sysmem fallback 이 없다. 아래 1050 Ti 설정과 비교하면 **해상도 4배 + 포인트
2.25배를 올리고도 시간이 비슷하다.**

**텍스처 판정에는 원본 해상도가 사실상 필수다.** 원본에서 조흔 주기는 3.6~14.2 px
인데, `--scale 0.5` 로 줄이면 1.8~7.1 px 가 되어 **대역의 짧은 쪽이 Nyquist(2 px)
아래로 내려간다.** 이 구간의 스펙트럼은 앨리어싱이라 점수를 신뢰할 수 없다.
코드의 가드(`max_period_px < 2.5` 면 0 반환)는 scale 0.15 이하에서야 걸리므로
0.5 에서는 조용히 열화된 값이 나온다 — 문턱 1000 을 그대로 쓰면 안 된다.

### GTX 1050 Ti 4 GB (WSL2) — 소용량 VRAM 참고용

**권장 설정: `--scale 0.5 --points-per-side 32 --points-per-batch 16`** (장당 19s)

| 모델 | scale | pps | 시간 | 마스크 | peak VRAM |
|---|---|---|---|---|---|
| tiny | 0.5 | 32 | 19.3s | 123 | 1.16 GB |
| small | 0.5 | 32 | 19.6s | 101 | 1.23 GB |
| base-plus | 0.5 | 32 | 19.0s | 87 | 1.33 GB |
| base-plus | 0.5 | 48 | 140.9s | 129 | 2.09 GB |
| base-plus | 0.4 | 64 | 238.2s | 151 | 3.38 GB |

모델 크기는 시간에 거의 영향이 없다(비용은 포인트 수가 지배). pps를 48 이상으로
올리면 OOM 경고가 뜨며 sysmem fallback 이 시작돼 급격히 느려진다 — 4GB 카드에서
7.42 GB를 할당하려 하면 WSL2가 시스템 RAM으로 흘려보내 수십 배 느려진다.
입력을 0.5배로 리사이즈하고 `points_per_batch` 를 낮추면 peak VRAM 7.42 → 1.16 GB
로 떨어지면서, 포인트를 4배로 늘리고도 49s → 19s 가 됐다.

Pascal 세대라 bfloat16 미지원, fp16은 FP32 대비 1/64 속도여서 fp32로만 돌아간다.
`autocast_dtype()` 이 compute capability 를 보고 자동 판단한다(≥8 → bf16,
7.x → fp16, 그 이하 → fp32).

**이 설정에서는 텍스처 판정을 신뢰할 수 없다**(위 Nyquist 문제). `--no-shape-filter`
로 지표만 기록해 두고, 원본 해상도를 쓸 수 있는 장비에서 다시 검출하거나
`pipeline/refilter.py` 로 크기·형태 기준만 적용하는 편이 낫다.

## 배포

뷰어와 파이프라인이 **컨테이너 두 벌**로 돌고, 판이 따로다(`IMAGE_TAG` /
`PIPELINE_TAG`). 하나로 묶으면 뷰어 판을 올리는 순간 폴러가 없는 이미지를 가리킨다 —
그렇게 **4시간 반 멈췄다**.

**그런데 함께 올려야 하는 축이 둘 있다.**

- **스키마를 조이는 마이그레이션.** 칼럼을 걷었는데 옛 파이프라인 이미지가 그
  칼럼에 INSERT 하면 폴러가 선다. **조인 사본에 파이프라인 컨테이너를 붙여 먼저
  돌려 볼 것**
- **슬러그·경로 같은 "값의 모양" 규칙.** 그 규칙은 **파이프라인이 만들고 뷰어가
  쓴다.** 코드만 고치고 이미지를 안 올리면 옛 규칙이 계속 값을 만들고, 규칙을 어긴
  값이 DB 에 앉으면 **그 값을 읽는 화면이 전부 죽는다** — 괄호가 든 슬러그 하나로
  목록이 `NoReverseMatch` 를 내 뷰어 전체가 500 이었다(11분 36초). **들어오는 값이
  404 가 되는 것과 나가는 값을 못 만드는 것은 고장의 크기가 다르다**

밟은 자리 몇 개:

- **`/healthz` 의 `degraded` 는 503 이 아니라 200 이다.** 503 으로 바꾸면 배포
  스크립트의 기동 게이트가 200 을 기다리다 **배포가 스스로 멈춘다.** 배포를 세우는
  판단은 `smoke.sh` 가 `status != ok` 로 한다
- **`/healthz`·`smoke.sh` 는 링크를 안 만들어** 위의 슬러그 고장을 통과시킨다.
  200 은 "떴다" 일 뿐이다
- **`DiaRUGA.db` 는 파일이 아니라 디렉토리째로 마운트한다.** 파일 하나만 물리면
  WAL 이 만드는 `-wal`·`-shm` 형제가 컨테이너 안쪽에 생겨 호스트와 WAL 을 공유하지
  못한다 — 같은 DB 를 보는 줄 알았는데 아닌 상태가 된다
- **컨테이너는 `1000:1000` 으로, `TZ=Asia/Seoul` 로 돌린다.** root 로 돌면 DB 소유자가
  바뀌고, 시간대를 빠뜨리면 UTC 로 돌아 **백업 사본 이름이 아홉 시간 어긋나 정리
  규칙이 가장 새 사본을 지운다**

배포·백업 규약의 전문은 `.guides/web/README.md` 에 있다(형제 프로젝트들이 같은
사고를 겪고 도달한 표준). 이 저장소에는 커밋하지 않는다.

## 설치

**requirements 가 넷으로 갈라져 있다** (P03). 호스트 venv 는 `requirements.txt`
하나면 되고, 컨테이너가 나머지를 나눠 쓴다.

| 파일 | 누가 쓰나 |
|---|---|
| `requirements.txt` | 호스트 venv (`~/venv/DiaRUGA`) |
| `requirements-web.txt` | 뷰어 컨테이너 — Django · pillow · gunicorn |
| `requirements-pipeline.txt` | 파이프라인 컨테이너 — torch · SAM2 |
| `requirements-yolo.txt` | ultralytics. `--no-deps` 로 파이프라인 위에 얹는다 |

torch 는 CUDA 12.6 기준이다(`--extra-index-url https://download.pytorch.org/whl/cu126`).
드라이버가 더 낮으면 cu121 등으로 바꾼다. Python 3.12~3.14 에서 동작을 확인했다.

**사내망이 `download.pytorch.org` 의 TLS 를 가로챈다.** 파이프라인 이미지 빌드가
거기서 죽으면 `deploy/ca/` 를 볼 것 — `pip` 은 시스템 CA 저장소를 보지 않아
`PIP_CERT` 를 함께 줘야 한다.

## 알려진 한계

1. **SAM2 파이프라인의 재현율은 50~60% 추정.** 눈에 보이는 봉상 중 절반가량을
   놓친다. 원인은 판정 기준이 아니라 분할 단계다 — SAM2 AMG 가 조밀한 무리 속
   **투명한** 규조각을 온전한 하나로 분할하지 못한다. 불투명한 쇄설물은 깨끗하게
   따면서 정작 목표물에 약하다. **이것이 YOLO 로 간 이유다** — 사람이 검토한 시야로
   학습시키니 같은 재현율에서 정밀도가 1.7배였다. 다만 **아직 갈아타지 않았다.**
2. **원형(중심목) 문턱은 실물로 검증된 적이 없다.** 오검출을 걸러내며 잡은 값이라
   진짜를 놓치고 있을 수 있다. 특히 **텍스처는 크기와 같이 움직여** 작은 중심목을
   먼저 떨어뜨린다. 이제 표본이 충분하므로 검증할 수 있다 (TODOs 1순위).
3. **Plate 7·8 형태(뿔·원뿔)는 설계상 제외.** 윤곽이 오목해 타원 기준을 통과할 수
   없다. 텍스처는 통과하지만 형태 관문에서 걸린다.
4. **종 동정은 아직 사람 몫이다.** 자동 판정은 "규조각인가", "봉상인가 원형인가"
   까지고, 속(屬) 단위인 Eucampia·Chaetoceros 는 사람이 지정한다.
5. **깊이 맵의 정량화**는 Z 좌표가 기록된 z-stack 촬영이 전제다.
6. **SQLite 는 쓰기가 하나다.** 파이프라인이 도는 중에 검토를 저장하면 잠긴다 —
   프레임 229장을 그렇게 잃었다. 트랜잭션을 나눠 고쳤지만, 동시 작업이 일상이 되면
   다시 볼 문제다.
