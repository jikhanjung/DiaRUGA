# VPN 이 9090 을 막는다 — 뷰어를 80 의 /diatom/ 아래로 옮긴다

**작성일** 2026-08-02
**관련** `20260731_008_containerize.md` (포트를 나눈 그 결정)

---

## 증상

VPN 으로 붙은 상태에서 `172.16.116.98` 은 열리는데 `172.16.116.98:9090` 이 안 된다.
사내망 안에서는 둘 다 된다.

서버 쪽은 멀쩡했다.

```
호스트에서  curl :9090/healthz  →  200
```

VPN 이 80 만 통과시킨다. 뷰어가 9090 에 있는 한 VPN 사용자는 못 본다.

## 왜 9090 이었나

008 에서 포트를 나눈 이유가 있었다. 이 머신의 80 은 phyloserver 블록이
`server_name 172.16.116.98` 로 이미 잡고 있다. 그때 `diatom.conf` 머리말에
이렇게 적어 뒀다 — *"서브경로(/diatom/)로 얹으려면 FORCE_SCRIPT_NAME 에 더해
템플릿의 fetch() 5곳이 절대경로라 손봐야 한다."*

그 값을 치를 때가 됐다.

## 버린 방법 — 호스트명 기반 vhost

`server_name diatom.paleolab` 로 블록을 하나 더 두면 80 을 공유할 수 있다. 코드를
한 줄도 안 건드려도 된다.

**안 된다.** VPN 사용자는 **IP 로 들어온다.** Host 헤더가 `172.16.116.98` 이라
phyloserver 블록에 걸린다. 각자 hosts 파일을 고치게 하거나 내부 DNS 에 이름을
올려야 하는데, 둘 다 "뷰어 주소를 알려 주면 바로 볼 수 있다"를 깬다.

## 한 일

### 1. nginx — 80 의 /diatom/ 을 떼고 넘긴다

```nginx
location = /diatom { return 301 /diatom/; }
location /diatom/  { proxy_pass http://127.0.0.1:8090/; }
```

**끝의 슬래시가 핵심이다.** `proxy_pass` 에 URI 부분(`/`)이 있으면 nginx 가 매칭된
접두를 떼고 넘긴다. 없으면 앱이 `/diatom/d/…` 를 그대로 받아 전부 404 다 —
Django 는 `PATH_INFO` 로 URL 을 찾고, 거기에는 접두가 없어야 한다.

phyloserver 블록 안에 `include snippets/diatom-subpath.conf;` 한 줄로 얹었다.
같은 `listen 80` + 같은 `server_name` 으로 server 블록을 두 개 두면 nginx 가 앞의
것만 쓰고 뒤를 버린다 — location 으로 들어가는 수밖에 없다.

> phyloserver 의 저장소 사본(`~/projects/phyloserver/deploy/nginx/`)은 설치본보다
> 이미 두 블록 뒤처져 있었다(`/media/sp_photos/`·`/epma/`). 설치본을 기준으로
> 고쳤다. 그쪽 저장소는 건드리지 않았다.

### 2. Django — FORCE_SCRIPT_NAME

```python
FORCE_SCRIPT_NAME = os.environ.get("DIATOM_SCRIPT_NAME", "").rstrip("/") or None
```

`reverse()`·`{% url %}` 가 앞에 뿌리를 붙인다. 환경변수라 뿌리(/)에 붙이는 배포도
그대로 산다 — 비워 두면 `None` 이 되어 예전과 똑같다.

`STATIC_URL` 은 `"static/"` 그대로 뒀다. **슬래시로 시작하지 않으면 Django 가
`SCRIPT_NAME` 을 알아서 붙인다.** `"/static/"` 로 박아 두었으면 여기서 어긋났을 것이다
(이 뷰어는 정적 파일이 없어 실해는 없지만 주석을 달아 뒀다).

### 3. 절대경로를 걷어냈다 — 예고된 5곳이 아니라 20곳이었다

| 어디 | 몇 곳 | 어떻게 |
|---|---|---|
| 템플릿 `href="/"` | 7 | `{% url 'index' %}` |
| JS 안의 `fetch('/…')`·`src = '/…'` | 8 | `ROOT + '/…'` |
| **템플릿태그가 만드는 URL** | 3 | `reverse("image")`·`reverse("crop")` |

008 의 메모는 `fetch()` 만 셌다. **정작 놓친 것은 `viewer_extras.py` 였다** —
`thumb`·`cropurl`·`full` 이 `"/img?" + urlencode(...)` 로 문자열을 만든다.
템플릿만 훑어서는 안 보인다. 화면에는 `{% thumb f.rel %}` 라고만 적혀 있다.

JS 쪽은 `base.html` 이 `<head>` 에서 뿌리를 한 번 내보내고 쓰는 쪽이 이어 붙인다.

```js
window.ROOT = '{% url "index" %}'.replace(/\/$/, '');   // '' 또는 '/diatom'
```

`<head>` 에 두는 이유는 본문의 인라인 스크립트가 이것보다 먼저 돌기 때문이다.

### 4. 9090 은 리다이렉트로 남긴다

`FORCE_SCRIPT_NAME` 을 켜면 앱이 만드는 링크가 전부 `/diatom/…` 인데, 9090 블록은
접두를 떼지 않으므로 **9090 으로 들어와 아무 링크나 누르면 404** 다. 서빙하는 경로를
둘로 두면 한쪽이 조용히 반만 동작한다.

그래서 9090 을 **301 로 바꿨다.**

```nginx
return 301 http://$host/diatom$request_uri;
```

적어 둔 북마크가 새 주소로 넘어간다. 서빙은 한 곳이다.

## 또 `{# #}` 계열에 걸렸다

`base.html` 의 JS 주석에 태그 이름을 그대로 적었다가 템플릿이 죽었다.

```
// … {% url %} 는 FORCE_SCRIPT_NAME 을 알아서 붙이지만 …
   → TemplateSyntaxError: 'url' takes at least one argument
```

**Django 는 JS 주석 안이어도 태그로 읽는다.** CLAUDE.md 의 `{# #}` 항목과 같은
종류인데 방향이 반대다 — 그쪽은 "주석인 줄 알았는데 출력됐다", 이쪽은 "주석인 줄
알았는데 실행됐다". 주석에 태그 이름을 적지 말 것.

## 확인

이 머신에 **node 가 생겼다**(`/usr/bin/node`). HANDOFF 의 "node·브라우저가 없다"는
낡은 정보다. 렌더한 인라인 스크립트를 뽑아 `node --check` 로 실제 파싱했다.

| 무엇 | 결과 |
|---|---|
| 서브경로에서 화면 8종 × 슬라이드 3장 = 24 URL | 전부 200, **접두 없는 링크 0** |
| 뿌리 배포(`DIATOM_SCRIPT_NAME` 없음) 10 URL | 전부 200, **접두 붙은 링크 0** |
| 렌더한 JS 5종 `node --check` | 전부 통과 (`ROOT` 정의가 사용보다 앞) |
| 80 으로 실제 왕복 | 목록·시야·갤러리 200, 썸네일·크롭 JPEG, `POST /review` 400(도달), 문턱 이력 200 |

`POST /review` 가 400 인 것은 빈 payload 를 보냈기 때문이다 — 404 가 아니라는 것이
확인하려던 것이다.

## 남은 것

- 뷰어는 여전히 **인증이 없다.** 80 으로 나오면서 노출 면이 넓어졌다. 필요해지면
  스니펫에 `auth_basic` 을 걸면 된다 — Django 를 건드릴 필요가 없다
- phyloserver 저장소의 nginx 사본이 설치본보다 뒤처져 있다. 그쪽에서 배포하면
  이 `include` 한 줄이 날아간다
