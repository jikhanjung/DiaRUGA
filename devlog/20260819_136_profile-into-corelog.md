# 136 — 꺾은선을 코어 로그 안, 시료 표식 옆으로 옮긴다

2026-08-19 · `sclee` · [P17](20260819_P17_core-profiles.md) 4단계 고침 ·
앞의 것은 [135](20260819_135_core-profile-chart.md)

135 는 그림을 화면 **아래**에 따로 두었다. 사용자 지적(2026-08-19):
**"적어도 오팔 그래프는 시료 테이블 옆에서 볼 수 있어야 한다."** 맞는
지적이다 — 깊이와 나란히 읽는 그림인데 아래로 내려가 있으면 시료가 어느
값에 놓이는지를 눈이 두 번 움직여야 안다.

## 1. 왜 처음에 아래로 뺐었나

`.mark`(시료 표식)가 `left:146px` 에 `right:0` 으로 **절대 위치**로 깔려
있었다. 암상 띠 다음이 곧 그 자리라, 칸을 끼우면 표식이 **그림 위에 겹쳐
앉는다.** 135 를 쓸 때는 그것을 피해 아래로 뺐다.

**그때 새 코어 둘이 관찰 0개라 겹칠 일이 없었다는 것도 한몫했다.** 화면으로는
멀쩡해 보였을 것이다 — 관찰이 붙는 날 드러나는 종류다.

## 2. 자리를 값 하나로 모았다

```
[깊이 눈금][암상 띠][칸 × N][시료 표식 …]
```

`.corelog` 에 `--lane0`(첫 칸의 왼쪽)과 `--lanew`(칸 하나의 폭)를 두고,
화면이 `--lanes`(칸 수) 하나만 싣는다. 머리줄·그림·표식·발치가 **전부 그
값으로** 자리를 잡는다 — 한 군데만 맞으면 넷이 함께 맞고, 어긋나면 함께
어긋나서 눈에 띈다.

`.mark` 는 `right:0` 을 놓았다. 폭을 못 박아 두면 칸이 많을 때 **표식이
잘린다** — 안 보이면 이 지점에 없는 시료가 된다. 대신 `.logscroll` 이 가로로
넘긴다.

**깊이는 어긋날 수가 없다.** 칸이 `top:0; bottom:0` 이라 눈금과 같은 상자를
쓴다 — 135 에서는 축을 따로 그려서 여백을 손으로 맞춰야 했고, 머리글을 두
줄에서 세 줄로 늘릴 때 한 번 어긋났다. 그 계산이 통째로 없어졌다.

## 3. 확인

브라우저로 쟀다 (`getBoundingClientRect`).

```
RS14-GC04 (관찰 0)   칸 4 · 표식 0 · 겹침 없음 · 칸높이 620 = 본문높이 620
RS23-GC03 (관찰 4)   칸 2 · 표식 4 · 겹침 없음 · 선 길이 1,215
RS23-GC03 다 끔      칸 0 · 표식 4 · 표식이 예전 자리로 돌아온다
```

**`RS23-GC03` 으로 본 것이 핵심이다.** 관찰이 있는 코어라야 이 고장이 난다 —
새 코어 둘로만 보면 통과한다(086 이 말하는 "자료가 어느 갈래로 가는지").
사본 DB 의 `RS23-GC03` 에 시험용 항목 둘을 넣어 봤다(운영 자료가 아니다).

시험 둘을 더했다 — 칸 수가 화면에 실리는가 · 다 끄면 0 이 되는가.
전체 **691개 통과**.

## 4. 잃은 것 하나

칸 머리글이 좁아 **단위가 안 들어간다**(`자기감수율 …` 로 잘린다). 단위는
바로 아래 고르는 자리에 그대로 있고(`자기감수율 (Whole) SI(10-5)`) 칸에
마우스를 올리면 뜬다. 발치의 양 끝 값이 크기를 말하므로 그림을 읽는 데는
지장이 없다고 봤다.
