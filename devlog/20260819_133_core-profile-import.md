# 133 — 코어 자료를 반입하고, 관찰 없는 코어에도 축을 세운다

2026-08-19 · `sclee` · 계획은 [P17](20260819_P17_core-profiles.md) 2·3단계

`RS14-GC04`·`RS19-GC17` 두 코어의 물성·지화학 자료(xlsx 둘)를 DB 로 들이고,
**관찰이 하나도 없는 지점에도 깊이 축이 서게** 했다. 그림은 아직 아니다 —
지금 화면에 나오는 것은 무엇이 몇 점 들어와 있는가까지다.

## 1. 축의 근거를 넓혔다

깊이 축은 시료의 `depth_cm` 에서만 나왔다. 관찰이 없으면 `axis` 가 `None` 이라
화면이 "깊이가 적힌 시료가 없어 축을 그릴 수 없습니다" 를 냈고, **새로 들어온
코어 둘이 정확히 그 상태**였다 — 자료를 다 넣어도 화면이 빈다.

`bottom` 을 `max(시료 깊이, 항목의 최대 깊이)` 로 바꿨다. 실측으로
`RS14-GC04` 는 관찰 0개인 채 `bottom=400cm`(눈금 9개), `RS19-GC17` 은
`bottom=600cm`(눈금 7개)로 선다. 관찰이 나중에 붙으면 **같은 축에 얹힌다.**

안내 문구도 갈랐다. 관찰이 하나도 없는 코어에 "정보 편집에서 깊이를 채우세요"
라고 적으면 **고칠 관찰이 없는 사람을 편집 화면으로 보낸다** — 노두에 그 문구를
안 내는 것과 같은 이유다.

## 2. 표 둘 · 깊이는 mm 정수다

`CoreSeries`(항목) + `CorePoint`(점). 칼럼을 고정한 표로 두지 않은 이유는
P17 3절에 있다 — 코어마다 있는 항목이 다르다.

**계획에서 한 가지를 바꿨다.** 깊이를 `depth_cm` 실수로 두려던 것을
`depth_mm` 정수로 했다. `(항목, 깊이)` 가 유일 제약이라 **깊이가 열쇠**인데,
XRF 가 1 mm 간격이라 cm 로 두면 `0.1`·`0.3` 이 열쇠가 된다. 다시 반입할 때
계산 경로가 조금만 달라도 같은 점이 두 줄로 생긴다. 화면과 축은 cm 로 말하고
바꾸는 자리는 `data.core_series()` 하나다.

## 3. 반입을 두 단으로 갈랐다

```
xlsx  ──(호스트)──▶  <지역>-<지점>.series.csv + .points.csv  ──(dbrun.sh)──▶  DB
      tools/coredata_extract.py                    ops/import_coredata.py
```

앞단은 Django 를 안 부르고 DB 도 안 만진다. 뒷단은 CSV 만 읽으므로 웹 이미지에
`openpyxl` 이 안 들어간다 — `requirements.txt` 에만 적었다(`python-docx` 와 같은
자리, 호스트 전용).

**중간 CSV 는 커밋하지 않는다.** 사람이 확인한 판단은 `coredata/mapping.toml`
에 있고 CSV 는 거기서 나오는 산물이다(코어 하나에 9만 행). `.gitignore` 에 넣었다.

### 3.1 매핑표가 머리글을 대신한다

머리글이 틀린 자리가 셋인데 **전부 `RS14-GC04`** 다.

| 시트 | 머리글 | 실제 | 근거 |
|---|---|---|---|
| `MS` | `Depth(mm)` | **cm** | 값이 1~362, 코어가 362 cm |
| `Opal` | `depth(m)` | **cm** | 값이 0~362 |
| `Size` | `NO.` | **cm(깊이)** | 값이 0~356, 4 cm 간격. RS19 쪽은 `Depth(cm)` |
| `XRF` | `position (mm)` | mm (맞다) | 값이 1~3609 = 360.9 cm |

그래서 매핑표에 **열 번호로** 적었다. 이름으로 짚으면 안 되는 이유가 따로 있다 —
`MS` 는 `Point`/`Whole` 이, `Spectro` 는 `SCE`/`SCI` 가 **같은 머리글을
반복해서** 뒤엣것이 앞엣것을 덮는다.

매핑표에 `expect_max_cm`(코어 길이)을 함께 적고 **반입기가 그것으로 자기를
검사한다.** 단위를 잘못 읽으면 열 배로 어긋나므로 여기서 걸린다.

## 4. 원본에서 나온 것 셋

**(1) XRF 점 수를 잘못 셌었다.** 시트가 8,384행인데 **뒤 4,809행이 통째로
비어 있다.** 실제 측정은 3,575점(0.1~360.9 cm)이라 24원소로 85,800행이다 —
계획에 적은 209,450 이 아니다. 그래도 한 항목이 3,575점이라 화면으로 그대로
내보낼 수는 없고, 줄이는 층은 4단계에 남는다.

**(2) `MS` 에 같은 깊이가 40개 겹쳐 있다.** 221~260 cm 가 시트 아래쪽에 한 번
더 있는데, **값까지 글자 그대로 같다** — 재측정이 아니라 붙여넣기가 겹친 것이다.
그래서 반입기를 이렇게 갈랐다:

- 같은 깊이·**같은 값** → 한 번만 넣고 몇 개였는지 적는다
- 같은 깊이·**다른 값** → **멈춘다.** 어느 쪽이 맞는지 스크립트가 고를 수 없다

처음에는 무조건 "먼저 나온 것" 을 남기게 짰는데, 그건 조용히 사람의 판단을
대신하는 것이다.

**(3) 안 읽기로 한 것들.** `Opal (2)`(사용자가 편집하다 갈라 놓은 것) ·
`Opal 요약`(표가 아니라 문서) · RS19 `W.C` 6열(이름 없는 둘째 함수율 —
무엇인지 모르는 것을 이름 붙여 넣지 않는다) · RS19 `Size` 13열 이후(계량
원자료) · `TYPE`·`Munsell C Hue` 같은 글자 칸.
