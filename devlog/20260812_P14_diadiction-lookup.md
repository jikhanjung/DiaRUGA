# P14 — 뷰어에서 도감을 부른다 (Diadiction)

2026-08-12 · 계획 · `sclee`

**목표**: 검토·카탈로그 화면에서 속 이름을 짚으면 **그 자리에서 도감의 등록
정보와 도판을 본다.** 지금은 사람이 화면을 떠나 NAS 의 PDF 를 따로 열어야 한다.

아직 아무것도 안 만들었다. 여기 적는 것은 **무엇이 이미 있고, 어디에 붙일 수
있고, 무엇을 먼저 정해야 하는가**다.

---

## 1. Diadiction 이 무엇인가

NAS 공유에 따로 만들어 둔 규조 도감 자료 모음이다. 저장소 밖에 있다.

```
Windows  N:\DiaRUGA\Diadiction
리눅스   /nfs/temp-share/DiaRUGA/Diadiction        (172.16.112.125:/volume1/public)
```

2.7 GB · 파일 165개. 폴더 자체의 `README.md` 와 `skill/SKILL.md` 가 쓰는 법을
전부 적어 두었다 — **거기가 원본이고, 이 문서는 뷰어에 붙이는 쪽만 본다.**

| 도감 | 색인 | 규모 |
|---|---|---|
| 한국동식물도감 제9권 식물편(담수조류), 1968 | `md/한국동식물도감_규조_색인.md` | 항목 169–680 · **512종** · Plate 21–74 |
| A. Schmidt, *Atlas der Diatomaceenkunde* (1874–1959) | `md/Schmidt_Atlas_학명색인.md` | 학명 **1,504개** · 출현 1,968건 · Tafel 1–480 |
| 플라이스토세 중기 이후 동남극 규조 (도판집) | **없다** — `notes/03` 에 Plate별 종 목록 | Plate 1–9 + SEM |

그 밖에 `md/학명_유효성_기록.md` 가 있다. AlgaeBase·DiatomBase 로 확인한
**유효·이명 상태를 누적**하는 표다. 지금 3줄이다.

**세 번째 도감이 우리 자료와 직접 겹친다.** `notes/03` 의 Plate 1–9 는 남극
퇴적물 코어 규조이고, 거기 나오는 *Fragilariopsis kerguelensis* ·
*Thalassiosira lentiginosa* · *Actinocyclus ingens* 는 RS23 이 보는 것과 같은
얼굴이다. **색인이 없는 도감이 하필 제일 가까운 도감이다.**

---

## 2. 어디에 붙나 — `ClassDef.is_taxon`

뷰어에서 속을 아는 자리는 하나뿐이다. **`ClassDef` 중 `is_taxon` 이 참인 행**
(`data.py:159` 의 `taxon_keys()`). 형태 분류(원형·파편)는 도감에 없다.

그러니까 붙는 곳은 **분류를 보여주는 자리 전부**다 — 검토 화면의 분류 메뉴·
배지, 카탈로그의 속 열, 개체 화면. 여기서 도감으로 가는 문이 하나 뜨면 된다.

---

## 3. 갈래 셋

**(a) 링크만 건다.** 분류 배지 옆에 도감으로 가는 문을 하나 두고, 색인 md 의
해당 절을 그대로 띄운다. 가장 싸다. 대신 검색·조인이 안 되고, 도판은 여전히
사람이 PDF 를 열어야 한다.

**(b) 도감을 DB 에 넣는다.** `AtlasEntry`(도감·항목번호·학명·도판·쪽·생태·분포)
테이블을 세우고 `ClassDef` 와 맨다. 조인·검색이 되고 `check_db.py` 로 무결성도
본다. 대신 **재생성 가능한 것이 DB 로 들어온다** — 색인 md 가 원본이고 DB 는
사본이 되므로, 어느 쪽이 원본인지 규칙을 세워야 한다.

**(c) 파일로만 읽는다.** `outcrop.py` 가 이미 그 선례다 — 노두 현장 사진은 NAS
공유에 파일로만 살고 **DB 에 행이 없다.** 같은 자리에 `atlas.py` 를 두고 색인
md 를 읽어 dict 로 낸다.

**(c)를 먼저 본다.** 선례가 있고, 도감은 우리가 만드는 자료가 아니라 **읽기만
하는 남의 자료**라 소유 방향이 `outcrop` 과 같다. 색인이 md 라 파싱이 필요한데,
형식이 규칙적이다:

```
**240. *Actinocyclus Ehrenbergii RALFS***
<sub>pl. 31 · 책 p.176 · PDF p.77</sub>
- 생태: …
- 분포: …
```

느려지면 그때 (b)로 간다. **먼저 캐시를 놓지 않는다** — 512 + 1,504행이고
`data.py` 의 읽기 전용 약속 안에서 도는 크기다.

## 4. 먼저 정할 것

**4.1 이름이 안 맞는다.** 도감은 1874~1968년 간행물이라 **그때 이름으로 적혀
있다.** `ClassDef` 의 속명은 지금 이름이다. `학명_유효성_기록.md` 의 첫 줄이
바로 그 사례다 — 도감의 *Actinocyclus ehrenbergii* 는 지금 *A. octonarius* 다.
게다가 **AlgaeBase 와 DiatomBase 의 판단이 엇갈린다.**

속 층에서는 대체로 성립하지만(속명은 종소명보다 덜 바뀐다), **안 맞는 자리가
생기면 그것을 화면이 말해야 한다.** 조용히 빈 결과를 내면 사람이 "도감에 없는
속" 으로 읽는다 — 실제로는 이름이 다른 것뿐이다.

**4.2 도판을 어떻게 낼 것인가.** 지금 `plate/` 에 **크롭이 1장뿐이다.**
나머지는 2.5 GB PDF 안에 있다. 셋 중 하나다 — 미리 다 크롭해 둔다(사람 손이
많이 든다) · 뷰어가 그때그때 렌더한다(**컨테이너에 poppler 가 들어오고 2.5 GB
를 물어야 한다 — 안 하는 쪽이 낫다**) · 쪽 번호만 알려 주고 사람이 연다.

**시작은 셋째다.** 색인이 이미 `pl.`·`책 p.`·`PDF p.` 를 들고 있어 그것만 화면에
놓아도 사람이 바로 찾아간다. 크롭은 사람이 하나씩 늘리고, `plate/` 에 있으면
그것을 보여준다.

**4.3 남극 도판집에 색인을 만들 것인가.** 우리 자료와 제일 가까운데 md 색인이
없다. `notes/03` 을 색인 md 로 옮기는 일은 크지 않다(20쪽 · Plate 9장).

**4.4 뷰어 컨테이너가 이 공유를 볼 수 있는가 — 아직 확인 안 했다.** 지금
`/nfs/temp-share` 는 호스트에만 마운트돼 있다. 이것부터 본다. 못 보면 (a)~(c)가
전부 성립하지 않는다.

## 5. 함정

- ~~**파일 이름이 CP949 다.**~~ **치웠다** (2026-08-12, 아래 6절)
- **색인 텍스트를 그대로 인용하면 안 된다.** 한국 도감 항목 169–480 은 PDF
  텍스트 레이어라 한자가 깨져 있고, Schmidt 는 전량 tesseract OCR 이라 철자
  오류가 남아 있다. 화면에 낼 때 **어느 구간에서 온 것인지 함께 말한다**
- **`origin/dup/` 은 `Band1~3` 과 같은 책이다.** 1.2 GB 중복본이라 격리돼 있다
- **Schmidt 는 속명을 머리글자로 축약한다**(`S. robusta`). 색인에 복원했지만
  `(속명 추정)` 69건은 원문 대조가 필요하다
- **옛 도감은 종소명을 대문자로 쓴다**(*Actinocyclus Ehrenbergii*). 맞춰 볼 때
  소문자로 정규화한다

## 6. 한 것 — 파일 이름을 ASCII 로마자로 (2026-08-12)

뷰어가 이 경로를 열기 전에 치웠다. 나중에 하면 색인 안의 상호 참조와 `.skill`
꾸러미까지 따라 고쳐야 하는 양이 계속 는다.

**한글 이름 25개 · 문서 10개의 참조 53곳 · `.skill` 꾸러미 1개.** 파일 내용은
한 글자도 안 건드렸다 — 본문의 한글과 도감 제목은 그대로다.

**왜 UTF-8 이 아니라 ASCII 인가.** 디스크에 CP949 바이트가 앉아 있었다는 것은
Windows 가 이 공유를 **NFS 클라이언트로** 붙었다는 뜻이다(SMB 였다면 Synology
가 UTF-8 로 적었을 것이고, 그러면 `N:` 쪽이 이미 깨져 보였을 것이다). 그래서
UTF-8 로 바꾸면 **문제가 뒤집힐 뿐이다** — 리눅스가 성해지고 Windows 가 깨진다.
양쪽 다 성한 것은 ASCII 하나뿐이다.

바꾼 이름은 소문자 snake_case 이고 **학명은 원래 표기를 지켰다**
(`plate/plate_240_Actinocyclus_Ehrenbergii_pl31.png`). 규칙은 폴더의
`README.md` 와 `notes/04_method_and_history.md` 에 적어 뒀다 — **다음에 파일을
더하는 사람이 다시 한글로 짓지 않게** 하는 것이 이 기록의 목적이다.

확인: 남은 비ASCII 이름 0 · 파일 165개 · 2.7 GB (바뀐 것 없음) · 깨진 참조 0.
