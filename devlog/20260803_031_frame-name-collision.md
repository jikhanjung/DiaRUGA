# 프레임 이름이 슬라이드끼리 겹쳐 파이프라인이 매분 헛돌았다

**날짜** 2026-08-03
**앞선 문서** `20260731_P03_containerize-nas-ingest.md` (폴러), P02 (스키마)

NAS 로 새 슬라이드 세 장이 들어왔는데, 그중 하나가 **`processing` 에서 멈춰
매분 아무 일도 하지 않고 실행 기록만 쌓고 있었다.**

---

## 1. 증상

```
[19:46:03] --- 260803_gc03-c1_72cm (processing) ---
260803_gc03-c1_72cm: 검출 대상 61개
이미 검출한 시야 61개를 건너뛴다        ← 12개는 검출이 없는데?
검출할 것이 없다.
[19:46:07] 260803_gc03-c1_72cm: 끝
```

슬라이드 상태는 `검출 대기 시야 12개` 인데 검출기는 61개 전부를 "이미 했다" 고
건너뛴다. 매분 반복되고 슬라이드는 영영 `done` 이 되지 않는다.

## 2. 원인 — 카메라 일련번호는 슬라이드를 모른다

검출이 없는 12개는 전부 **싱글턴**(프레임 1장)이었다. 싱글턴은 합성본이 없어
프레임 파일을 그대로 쓴다. 그래서 `find_viewpoint()` 가 **프레임 이름**으로
시야를 찾는다.

```python
fr = Frame.objects.filter(name=stem).select_related("viewpoint").first()
```

**프레임 이름은 카메라가 매기는 일련번호다.** 같은 날 이어서 찍으면 번호대가
이어진다. 260803 의 두 슬라이드에서 **143종이 겹쳤다.**

```
Snap-22374 → 260803_bp09-0901(g51) · 260803_gc03-c1_72cm(g54)
Snap-22375 → 260803_bp09-0901(g51) · 260803_gc03-c1_72cm(g55)
```

`.first()` 가 먼저 들어온 `bp09-0901` 을 준다. 그쪽은 이미 검출이 끝나 있으니
"이미 검출함" 으로 건너뛴다. **12개 전부가 그랬다.**

260729·260731 때는 안 겹쳤다. 슬라이드가 하루에 하나씩 들어왔기 때문이다.

## 3. 순서가 반대였다면 더 나빴다

지금은 건너뛰기만 해서 **잘못 붙은 검출은 0건**이다(확인했다). 그런데
`gc03-c1_72cm` 이 먼저 처리됐다면 그 검출이 **`bp09-0901` 의 시야에 저장**됐을
것이다. 우연히 순서가 좋았을 뿐이다.

`Frame` 에는 이미 `(slide, name)` 유일 제약이 있었다. **DB 는 맞았고 조회만
틀렸다** — 제약이 있다는 것이 곧 "이름만으로는 못 찾는다" 는 뜻인데 그렇게 읽지
않았다.

## 4. 고친 것

### `find_viewpoint(stem, slide=None)`

슬라이드를 함께 받아 거른다. `--slide` 경로는 이미 슬라이드를 알고 있었고,
경로로 들어온 경우에는 **폴더로 슬라이드를 되찾는다**(`Slide.image_dir`).

**슬라이드를 못 정했는데 이름이 겹치면 건너뛴다.** 아무거나 고르지 않는다 —
조용히 틀리는 것보다 안 하는 것이 낫다.

```
슬라이드를 주면 제대로 찾는 것 12/12
슬라이드를 안 주면 건너뛰는 것 12/12
```

### 할 일이 없을 때 `Run` 을 닫는다

"검출할 것이 없다" 로 빠져나가면서 `Run` 을 안 닫았다. 폴러가 매분 부르는 동안
`running` 이 하나씩 쌓였고, 다음 실행의 `close_stale` 이 그것을 **`failed`** 로
닫았다. 실패한 것이 아니라 할 일이 없었을 뿐인데 **이력에는 실패로 남는다.**

25건이 그렇게 쌓여 있었다. `done` + `counts={"detections": 0}` 으로 정리했다.

## 5. 풀었다 — 그리고 빌드가 그것을 막고 있었다

**폴러는 배포된 파이프라인 이미지를 쓴다.** 고친 코드는 저장소에만 있으므로
이미지를 다시 굽기 전까지 `gc03-c1_72cm` 은 멈춰 있었다.

그런데 **그 빌드가 `ultralytics` 의존성 충돌로 실패했다**(`ResolutionImpossible`).
YOLO 를 운영 이미지에 넣으려던 것이 급한 고침을 막고 있었다. 그래서 ultralytics 를
빼고 `v0.1.1` 을 먼저 구워 배포했고 — 슬라이드가 곧바로 풀렸다.

```
Snap-22241 … Snap-22374    싱글턴 12개 검출 · 개체 1,416개
260803_gc03-c1_72cm: 자동 처리 완료 — 검토를 연다
```

**급한 고침이 새 기능을 기다릴 이유가 없다.** 둘을 갈라 낸 것이 맞았다.
의존성은 그 뒤에 따로 풀었다(032).

## 남는 것

- **`Viewpoint.tag` 도 같은 위험이 있다.** 지금은 안 겹치지만(`g001_Snap-...` 이
  프레임 이름을 품어서) 규칙이 바뀌면 겹칠 수 있다. `find_viewpoint` 의 합성본
  갈래도 슬라이드로 거르게 해 뒀다
- **이름으로 무언가를 찾는 다른 곳**을 훑어야 한다. `import_json.py`·`rebind.py`
  등이 같은 가정을 하고 있을 수 있다
- 슬라이드가 `processing` 에서 오래 머무는 것을 **아무도 알려 주지 않는다.**
  026 이 적은 "실패를 아무도 모른다" 와 같은 자리다
