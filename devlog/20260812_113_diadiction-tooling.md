# 113 — 도감을 실제로 쓸 수 있는지 확인하고, 규칙을 도구에 심는다

2026-08-12 · `sclee` · 계획은 [P14](20260812_P14_diadiction-lookup.md)

**뷰어 연동은 아직 아니다.** 이번에 물은 것은 그 앞의 것 하나다 —
**지금 이 자리에서 도감을 쓸 수 있는가.** 쓸 수 있다는 것을 말로 확인하지 않고
종 하나를 4단계로 끝까지 조회해서 확인했다.

---

## 1. 4단계가 각각 되는가

`Diadiction/skill/SKILL.md` 의 절차를 그대로 밟았다. 고른 종은
***Fragilariopsis kerguelensis*** — RS23 이 실제로 보는 종이고, 하필 **md 색인이
없는 도감**(동남극 도판집)이라 제일 어려운 갈래다.

| 단계 | 도구 | 결과 |
|---|---|---|
| ① 도감 정보 | grep + `pdftoppm` → 이미지 판독 | ○ `notes/03` → Plate 1 → PDF 2쪽 |
| ② 도판 | `pdftoppm -r 200` + PIL 크롭 | ○ `plate/` 에 저장 |
| ③ 교차검증 | DiatomBase/WoRMS REST | ○ **`curl` 로만** |
| ③ 주 출처 | AlgaeBase | **✗ 브라우저가 있어야 한다** |
| ④ 기록 | `md/name_validity_log.md` 편집 | ○ |

**`WebFetch` 가 안 된다.** 사내망이 도메인 확인을 막는다. WoRMS 는 정적 JSON 이라
`curl` 로 그냥 되므로 실질적인 손해가 없다. **AlgaeBase 는 다르다** — JS 렌더링
이라 `curl` 은 302·0바이트를 낸다(폴더 문서가 적어 둔 그대로였다). 주 출처가
막힌 자리라, 학명 판정은 **DiatomBase 만 본 것임을 기록에 밝혀야 한다.**

## 2. 조회하다 나온 것

DiatomBase 가 *F. kerguelensis* 를 `status: unassessed` 로 두면서 `valid_name`
에는 **기본명 *Terebraria kerguelensis* E.O'Meara, 1876** 을 싣고 있다. 남극
규조에서 가장 흔한 축에 드는 종인데 이 조합은 이상하다. **임의로 고르지 않고**
기록에 경고를 달았다 — 폴더의 규칙("두 DB 가 엇갈리면 양쪽을 모두 제시한다")이
바로 이런 자리를 위한 것이다.

> **이 건은 같은 날 §6 에서 결론이 났다.** 사용자가 AlgaeBase 를 직접 열었고,
> **관계가 정반대로 걸려 있었다.** 여기까지만 읽고 덮지 말 것.

## 3. 이름 규칙이 절반만 서 있었다

파일 이름 25개를 로마자로 바꾼 것은 P14 §6 이다. 그런데 **"이렇게 이름 지어라"
는 틀이 아직 한글이었다.**

```
README.md   plate/도판_<항목번호>_<학명>_pl<도판번호>.png   md/<도감명>_색인.md
SKILL.md    <D>/plate/도판_<번호>_<학명>_pl<도판>.png
```

**링크 검사가 이것을 못 잡는다** — 실재 경로가 아니라 틀이라 존재 확인에서
건너뛰기 때문이다. 그대로 뒀으면 **다음 크롭이 다시 한글 이름으로 저장됐을
것이고**, 규칙은 파일 25개에만 걸린 일회성 청소로 끝났을 것이다.

**값을 고치는 것과 값을 만드는 규칙을 고치는 것은 다르다.** 057 에서 슬러그로
겪은 것과 같은 모양인데, 거기서는 규칙이 코드에 있었고 여기서는 문서에 있다.

### 줄임말이 이름으로 바뀌었다

문서의 경로 참조를 전부 뽑아 실재를 짚는 검사를 짰더니 **진짜가 하나 걸렸다.**
`SKILL.md` 가 원래 이렇게 적고 있었다:

```
`Schmidt_Atlas_Band1_해설_OCR.md` ~ `Band4_해설_OCR.md`
```

뒷것은 **앞의 접두어를 생략한 줄임 표기**다. 한글일 때는 눈으로 이어 읽혔는데,
로마자로 바뀌자 `band4_notes_ocr.md` 라는 **없는 파일 이름처럼** 보이게 됐다.
치환은 정확했고 결과가 틀렸다 — **일괄 치환이 깨뜨리는 것은 맞춤법이 아니라
사람이 문맥으로 채우던 자리다.**

검사는 두 번 짜야 했다. 처음 것은 문서가 `origin/Band1.pdf` 를 문맥상
`Band1.pdf` 로만 적는 자리를 전부 "깨졌다" 고 냈다(38건). **파일 이름으로 트리
전체를 뒤지게 고치자 59곳 중 진짜는 1건이었다.** 거짓 양성이 38이면 아무도
안 본다.

## 4. Windows 부스러기 — 규칙은 "지우기" 가 아니다

작업 중에 `plate/`·`temp/` 에 `Thumbs.db` 와 `Thumbs.db:encryptable` 이 생겼다.
탐색기가 폴더를 열면서 만든 것이다(**그 덕에 `N:` 쪽이 성하다는 것이 우연히
확인됐다**).

지웠지만 **지우는 것은 규칙이 될 수 없다 — 폴더를 열면 그 자리에서 또 생긴다.**
그래서 이렇게 적었다: *어느 쪽이든 자료 수에는 넣지 않는다.*

그리고 목록을 훑는 쪽은 **블랙리스트가 아니라 화이트리스트**로 적었다 —
`.png`·`.pdf`·`.md`·`.xlsx` 만 본다. 뺄 것을 세면 **다음에 나올 새 부스러기를
못 막는다.** 이 프로젝트에 이미 같은 대응이 있다: `web/viewer/outcrop.py` 가
같은 공유를 보면서 같은 이유로 확장자를 못 박고, 머리말에 그 근거가 있다
(`…:Zone.Identifier` 를 이미지로 열려 들면 매 요청마다 예외가 난다).

## 5. 규칙을 어디에 심었나 — 세 자리다

| 자리 | 무엇 | 누구에게 걸리나 |
|---|---|---|
| `Diadiction/README.md` | 이름 규칙 · 부스러기 규칙 | 폴더를 여는 사람 |
| `Diadiction/skill/SKILL.md` | 같은 둘 + **0단계: `plate/` 를 먼저 본다** | 그 절차를 따르는 도구 |
| 세션 기억 | 폴더 위치 · 되는 것/안 되는 것 · 다시 만들지 않기 | 나 |

**기억에만 두면 나만 아는 규칙이 된다.** 도구가 읽는 자리(`SKILL.md`)에 넣어야
그 폴더를 쓰는 누구에게나 걸린다. `.skill` 꾸러미도 함께 다시 구웠다 — **꾸러미는
`SKILL.md` 의 사본이라, 고치고 안 구우면 설치한 쪽은 옛 절차를 계속 따른다.**

0단계를 넣은 이유는 사용자 지시다(*"만들어둔 종은 새로 만들지 않도록"*). 도판
하나에 렌더 → 번호 위치 확인 → 라벨 안 잘리게 크롭이 걸리고 실제로 경계를 두 번
다시 잡았다. 같은 종을 두 번 조회하면 그 값을 다시 치르고, **결과가 미묘하게
달라져 도판이 두 벌 생긴다.**

## 6. AlgaeBase 는 왜 자동이 안 되나, 그리고 엇갈릴 때 무엇을 쓰나

**처음 막은 것은 Cloudflare 가 아니라 TLS 였다.** 사내망이 TLS 를 가로채는데
그 CA 가 **크로미움 저장소에는 없다**(`curl` 은 시스템 저장소를 봐서 통했다 —
둘이 다른 저장소를 본다). 그걸 넘기고 나서야 진짜 벽이 드러났다:

> **"Click the box below to help us prevent automated scraping."**
> — Cloudflare Turnstile. **검색과 상세 둘 다** 걸려 있고, 통과 못 하면
> **오류 없이 첫 화면을 되돌려 준다.** 조용히 틀린 답이 나오는 종류다.

목적을 대놓고 적어 둔 문이라 뚫지 않는다. **자동으로 가는 길은 공식 API 하나
뿐이고 연 €500~1,000 짜리 유료 키다.** 그러니 지금 자동으로 서는 것은
DiatomBase/WoRMS 와 GBIF 뿐이고, **AlgaeBase 는 사람이 여는 자리로 남는다.**

**GBIF 는 세 번째 의견이 아니다** — 백본이 WoRMS 를 받아 쓴다. 같은 말을 두 번
들은 것이지 두 사람이 말한 것이 아니다. (Catalogue of Life 의 ChecklistBank
`3LR` 에는 규조가 사실상 없다 — *Fragilariopsis* 가 통째로 빠져 있다.)

### 엇갈림이 실제로 나왔다

사용자가 AlgaeBase 를 직접 열어 확인한 결과, ***F. kerguelensis*** 에서
**관계가 정반대로 걸려 있었다**:

```
AlgaeBase (2023)    F. kerguelensis = accepted
                    T. kerguelensis = synonym of F. kerguelensis
WoRMS(2018)/GBIF    F. kerguelensis → valid_name: T. kerguelensis
```

**이 저장소의 두 번째 엇갈림이고 방향이 반대다.** *Actinocyclus ehrenbergii*
는 AlgaeBase 가 이명, DiatomBase 가 accepted 였다. **그래서 "늘 더 새 쪽" 이나
"늘 WoRMS" 같은 규칙은 세울 수 없다.**

### 정한 것 — 판정과 기록을 가른다

**쓸 이름은 AlgaeBase 를 따른다**(사용자 방침 2026-08-12). 옛 규칙은 *"임의로
고르지 말고 양쪽을 제시하라"* 였는데, **그것은 기록의 규칙이지 판정의 규칙이
될 수 없다** — 화면과 보고서에는 이름이 하나 들어간다. 그 빈자리를 방침이
채웠다. **엇갈렸다는 사실 자체는 지우지 않고 그대로 남긴다.**

**갱신 시점을 함께 적는 것도 규칙으로 올렸다**(사용자 제안). 오래 손대지 않은
레코드는 그 사이의 재검토를 반영하지 못한다 — 위 사례가 2023 대 2018 이다.
**단서를 달았다: 최신이 곧 옳음은 아니다.** 근거로만 쓰고 판정은 방침이 한다.
