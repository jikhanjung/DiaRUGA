# 085 — 판을 내보내기 전에 눌러 볼 자리를 만든다 (`/DiaRUGATest/`)

2026-08-07

## 문제

v0.8.2 가 준비됐는데 **사람이 눌러 볼 자리가 없다.** 지금까지의 확인 수단은
셋인데 셋 다 이 일을 못 한다:

| | 왜 모자라나 |
|---|---|
| 시험 333개 | 통과했다. 그런데 통과하는 시험만 통과한다 (086 이 그 이야기다) |
| 미리보기 | **정지 화면**이다 (049·052) — 눌러 볼 수가 없다 |
| 배포 후 smoke | **이미 운영에 올린 뒤**다. 되돌리는 것이 확인보다 비싸다 |

**포트를 하나 더 여는 길은 없다.** 사내 VPN 이 80 만 통과시킨다 — 018 이
:9090 을 버리고 서브경로로 간 이유가 그것이고, 사람들이 VPN 으로 붙는 이상
그 제약은 그대로다. 그래서 **서브경로를 하나 더** 얹는다.

## 한 일

```
바깥 80  /DiaRUGA/      ──▶  127.0.0.1:8090   운영    v0.8.1
         /DiaRUGATest/  ──▶  127.0.0.1:8091   테스트  v0.8.2
```

- `deploy/nginx/DiaRUGATest-subpath.conf` — phyloserver 블록에 include 한 줄
- `/srv/DiaRUGA/test/` — `.env` · `docker-compose.yml` · `db/` · `outcrop/`
- `/srv/DiaRUGA/test/install-nginx.sh` — sudo 로 한 번 돌리는 설치·되돌리기

`^~` 를 붙였다. nginx 는 **접두 location 보다 정규식을 먼저 보는데**, 운영 조각의
`location ~* ^/(diaruga|diatom)(/.*)?$` 가 대소문자를 안 가린다. 지금 그 정규식은
`/DiaRUGATest/` 를 안 잡지만(`DiaRUGA` 뒤에 `/` 가 아니라 `Test` 가 온다), 저쪽이
느슨해지는 날 **테스트가 조용히 운영으로 301 되는 것**을 막아 둔다.

## 갈라 둔 것 넷

하나라도 운영과 같아지면 테스트가 운영을 만진다.

1. **DB** — `/srv/DiaRUGA/test/db/` 의 **사본**이다 (`backup_db.py --note
   before-testdeploy`, integrity=ok). 컨테이너에 운영 `db/` 를 **아예 마운트하지
   않았다** — 경로를 잘못 적어도 닿을 수 없게. 교정 7,472건은 재생성 불가다
2. **노두 사진** — 이것도 사본이다. 지점 페이지에서 지우면 **파일이 실제로
   지워지는** 자리라(`outcrop.py`), NAS 원본을 물리면 테스트에서 누른 것이
   진짜로 사라진다. `DIARUGA_OUTCROP_DIR` 로 갈랐다
3. **포트** 8091 (루프백만)
4. **프로젝트 이름** `diaruga-test` — 컨테이너 이름이 겹치면 `up -d` 하나가
   운영을 갈아 끼운다

**`SECRET_KEY` 도 다르다.** 오리진이 같아(`172.16.116.98:80`) 세션 쿠키를
공유하는데, 키까지 같으면 두 판의 세션이 서로 유효해진다.

**`.env` 에 `$` 를 넣지 않는다.** 이 파일은 compose 의 변수 치환에도 쓰여서,
`$` 가 있으면 compose 가 그 자리를 변수로 읽고 **조용히 다른 값**이 들어간다.
처음 만든 키가 그랬다.

## 함께 쓰는 것 하나 — `/data3/DiaRUGA`

사진은 읽기만 하고, 썸네일 캐시는 경로로 키를 잡아 두 판이 같은 것을 만든다.
**v0.8.2 가 썸네일 코드를 안 건드렸다는 것을 diff 로 확인하고** 함께 쓰기로 했다
— 건드렸으면 갈랐어야 한다. 갈라 두면 테스트가 캐시를 처음부터 다시 굽는다.

## 버린 것

- **운영 DB 를 함께 보기.** 검토 결과가 이어져 편하지만, 테스트 코드의 쓰기가
  운영 교정에 들어간다. v0.8.2 는 마이그레이션이 없어 이번엔 안전했겠지만
  **다음번에도 그러리라는 보장이 없고**, 안전한 판인지를 사람이 매번 기억해야
  한다. 규칙은 기억에 기대면 안 된다
- **파이프라인·dbtool 서비스.** 테스트 자리에 두지 않았다 — 거기서 GPU 작업이나
  DB 스크립트를 돌릴 일이 없고, 있으면 운영 자리와 헷갈린다

## 남은 것

- **두 화면이 똑같이 생겼다.** 어느 쪽을 보고 있는지 알려 주는 표시가 없다.
  `FORCE_SCRIPT_NAME` 을 보고 `base.html` 이 띠를 다는 식이면 작게 끝난다
- **`localStorage` 를 운영과 공유한다** — 오리진이 같기 때문이다.
  `diatom.layers`·`diatom.dsview`·`diatom.crossgroup` 셋이 걸린다. 테스트에서
  레이어를 끄면 운영 화면에도 꺼진 채로 보인다
- **테스트 자리의 `docker-compose.yml`·`.env` 는 저장소에 없다** (`/srv` 에만
  있다). 운영 쪽은 `deploy/srv/` 에 견본이 있는데 여기는 아직 없다 — 이 자리를
  계속 둘 것인지 정한 뒤에 옮긴다
