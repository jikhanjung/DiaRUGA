# 실행을 묶는다 — "전체를 한 번 훑었다" 가 흩어져 있었다

**날짜** 2026-08-03
**앞선 문서** `20260803_025_yolo-first-training.md`, P02 (스키마)

`/engine/` 에서 SAM2 와 YOLO 를 견주려는데 **한 번의 작업이 실행 여럿으로
흩어져 있어** 무엇과 무엇을 견주는지가 화면에 안 잡혔다.

---

## 1. 왜 흩어지나

파이프라인은 **슬라이드 단위로 돈다.** 폴러가 새 슬라이드 하나를 받으면 그것만
처리하기 때문이고, 그 단위가 맞다. 바꿀 이유가 없다.

그런데 "전체를 한 번 훑었다" 는 작업은 그 단위로 쪼개져 남는다.

```
YOLO 전수   #58 #59 #60 #61 #62 #63 #64      (슬라이드 7장)
SAM2 전수   #19 #37 #39 #43 #47 #50 #51~#55  (여러 날에 걸쳐)
```

## 2. `RunBatch` — 실행이 아니라 이름표

`Run` 에 부모를 다는 대신 따로 뒀다. 부모 `Run` 은 자기 `started_at`·`counts` 를
갖게 되어 뜻이 겹친다. **묶음은 실행이 아니라 이름표다.**

```python
class RunBatch:
    kind · label · note · started_at · finished_at
Run.batch = FK(RunBatch, null=True)
```

`null=True` 인 것이 중요하다 — 폴러가 슬라이드 하나만 처리하는 평소 실행에는
묶을 것이 없다. 묶음은 **여러 슬라이드에 걸친 작업에만** 붙는다.

앞으로 돌릴 것은 `segment_diatoms.py --batch <이름>` 이 알아서 묶는다.
슬라이드마다 명령을 나눠 불러도 같은 이름이면 한 덩어리가 된다.

## 3. 되돌아가 묶기 (`batch_runs.py`)

이미 흩어져 있는 것을 묶는 도구를 따로 뒀다. 한 번으로 끝나는 일 같지만,
앞으로도 "이건 저 작업이었다" 를 다시 정할 일이 생긴다.

```bash
python batch_runs.py --list
python batch_runs.py --auto --dry-run          # (종류·백엔드·날짜)로 묶어 본다
python batch_runs.py --label yolo-v1seg-전수 --runs 58-64 --note "…"
```

**`--auto` 는 규칙이지 진실이 아니다.** `(종류, 백엔드, 날짜)` 로 묶으면 지금
자료는 깔끔히 갈리지만, 같은 날 두 번 훑었으면 뭉쳐진다. 실제로 07-31 의 SAM2
에는 첫 시도(#37)와 그것을 밀어낸 재시도(#39)가 함께 있다.

**검출을 하나도 안 남긴 실행은 묶지 않는다** (#30~#33). 죽은 시도이고, 묶으면
묶음의 개수가 실제로 처리한 양과 어긋난다.

## 4. 두 묶음으로 정했다

`--auto` 는 SAM2 를 07-31 하루로만 잡았다. 그것이 **작업의 단위와 달랐다** —
SAM2 전수 처리는 여러 날에 걸쳐 있었고, 260729 세 슬라이드는 그보다 먼저
계산해 `#19`(`kind=ingest`, `part=detections`)로 들여왔다(P02 이전이라 `detect`
실행 기록이 없다).

그래서 손으로 묶었다.

| 묶음 | 실행 | 검출 | 슬라이드 |
|---|---|---|---|
| `sam2-전수-1차` | 11 | 349 | 7 |
| `yolo-v1seg-전수` | 7 | 892 | 7 |

**묶음에는 종류가 섞여도 되게 했다.** `sam2-전수-1차` 는 `detect` 실행 열 개와
`ingest` 실행 하나로 이루어진다. 갈라 두면 "SAM2 로 전체를 한 번 돌렸다" 를
한 화면에 못 본다. 묶음의 `kind` 는 **작업의 성격**이고 구성원의 종류가 아니다.

## 5. 화면이 잘못 세고 있었다

`/engine/` 은 **쌓인 검출(= `is_current` 가 아닌 것)만** 센다. 이미 현재로
올라간 것은 검토 화면에서 보이기 때문이다.

그런데 처음 판은 **쌓인 검출이 있는 실행만 세어** 묶음 크기를 냈다. SAM2 묶음이
11건인데 6건으로 보였다.

```
고치기 전   sam2-전수-1차  실행 6 · 쌓인검출 79
고친 뒤     sam2-전수-1차  실행 11 · 쌓인검출 79 (+270 현재)   ← 79+270 = 349
```

`+270 현재` 를 함께 내기로 했다. 이 화면의 숫자를 "이 묶음이 처리한 전부" 로
읽으면 SAM2 가 YOLO 의 10분의 1처럼 보인다 — **대부분이 현재로 올라가 있어서
여기 안 세일 뿐이다.**

## 남는 것

- `group`·`stack`·`refilter` 실행도 같은 문제를 갖는다. 지금은 `detect` 만
  묶었다 — 견주는 데 필요한 것이 그것뿐이라서다
- `RunBatch.finished_at` 을 아무도 채우지 않는다. 묶음이 언제 끝났는지는
  구성원 실행의 최대 `finished_at` 으로 알 수 있어 급하지 않다
