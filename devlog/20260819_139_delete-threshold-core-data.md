# 139 — 지점을 지울 때 코어 자료를 센다

2026-08-19 · `sclee` · [P17](20260819_P17_core-profiles.md) 뒤처리 ·
앞의 것은 [138](20260819_138_core-derived-series.md)

`v0.15.0` 을 내려고 예행을 하다 잡았다. **`CoreSeries` 를 `CASCADE` 로 달아
놓고 지우기 문턱에 안 넣었다.**

## 1. 무엇이 났나

`manage_data.deletable('locality', ...)` 는 **시료만 센다.** 그런데 이번에
들어오는 코어 둘은 **시료가 0개다** — 관찰이 아직 없고 코어 자료만 있다.
그래서 문턱이 그냥 열린다.

사본 DB 에서 눌러 봤다:

```
RS19-GC17: 시료 0개 · 항목 27개 · 점 10,795개
막는 이유: (없다 — 그냥 지워진다)
지우기: True  "RS19-GC17 을(를) 지웠습니다."
```

**예외도 경고도 없고, 성공 메시지가 사라진 것을 한 마디도 안 한다.** 063 이
적어 둔 "지우기 문턱은 눌러 보기 전에 보여야 한다" 의 다음 판이다. 그때는
`SET_NULL` 이라 관찰이 소속만 잃었는데, 이번엔 `CASCADE` 라 **자료가 없어진다.**

그리고 그중 `source='manual'` 인 것은 **사람이 손으로 넣은 것이라 다시 만들 수
없다.**

## 2. 고친 것

`deletable` 이 코어 자료를 세고 이유를 적는다.

```
코어 자료 43개 항목 · 점 88,664개가 함께 지워집니다 (그중 수동 1개는 다시 만들 수 없습니다)
```

**화면은 안 고쳤다.** `views.py` 가 이미 `block_why = deletable(...)` 로 받아
`_delbtn.html` 이 단추를 끄고 `title` 에 이유를 단다 — 서버 한 곳을 고치니 화면이
따라왔다. **문턱을 한 함수에 모아 둔 것이 값을 한 자리다.**

## 3. 반입 항목을 지울 수 있게 했다 — 막기만 하면 갇힌다

문턱이 코어 자료를 세기 시작하면, 반입 자료가 붙은 지점은 **영영 못 지운다.**
`delete_series` 가 반입 항목을 거절하고 있었기 때문이다.

그래서 갈랐다 — **지우는 것은 고치는 것과 다르다:**

| | 반입 항목 | 왜 |
|---|---|---|
| 고치기(이름·단위·점) | **막는다** | 다음 반입이 덮어 헛일이 된다 |
| 지우기 | **된다** | 다시 반입하면 그대로 돌아온다 |

확인 문구도 갈랐다 — 반입은 "다시 반입하면 돌아옵니다", 수동은 "되돌릴 수
없습니다". 코어 화면의 목록도 `직접 넣은 항목` 에서 `항목 지우기` 로 넓혔다
(파생은 저장돼 있지 않으니 안 낸다).

## 4. 시험

되살려서 잡히는 것만 적었다 — 시료가 0개인데 코어 자료가 있으면 막는가 ·
수동이 섞였을 때 그렇게 적는가 · 반입만 있을 때는 그 말을 안 적는가 ·
항목을 치우면 지워지는가 · 코어 자료가 없으면 예전 그대로인가.

전체 **891개**(브라우저 153 포함) 통과.

## 5. 남은 것

`Site` 쪽은 안 건드렸다 — 지역은 지점이 하나라도 있으면 이미 막히고, 지점이
코어 자료를 막으므로 두 겹이 된다.
