# 배율은 슬라이드마다 다를 수 있고, 시료 정보는 사람이 채운다

**작성일** 2026-07-31

---

## 검사가 정상을 문제로 잡고 있었다

`check_db.py` 에 "배율이 하나다"·"문턱이 하나다" 검사가 있었다. 슬라이드가 하나뿐일
때는 맞는 검사였는데, 대물렌즈를 바꿔 찍은 슬라이드가 들어오자 정상인 것을 문제로
보고하기 시작했다.

```
!! 배율이 2가지로 섞여 있다: [0.045039683, 0.112599206]
```

**전체를 한 덩어리로 보면 진짜 사고를 못 본다.** 슬라이드끼리 다른 것은 정상이고,
한 슬라이드 **안에서** 갈라지는 것이 사고다(사이드카가 어긋났거나 XML 이 섞였거나).
검사 단위를 슬라이드로 바꿨다.

```
슬라이드마다 배율이 하나다 (4개 슬라이드)
  260731_rs23-gc03_369cm       0.045039683 µm/px
  rs23                         0.112599206 µm/px
  ...
```

문턱도 같다. 배율이 다르면 텍스처 문턱이 같을 수 없으므로(015) **슬라이드마다
다른 것이 오히려 맞다.** 대신 한 슬라이드 안에서 갈라지면 시야 간 개수를 비교할
수 없으니 그때 알린다.

문턱 조정 화면에서 전역 적용을 고르면 경고도 띄운다 — 크기(µm)와 비율 지표는
배율과 무관하지만 텍스처는 딸려 간다는 것을 그 자리에서 알려 준다.

## 시료 정보를 채울 자리를 만들었다

`Site.region`·`lat`·`lon`, `Core.lat`·`lon`·`water_depth_m`·`kind`·`collected_at` —
이 칸들은 **P02 때 이미 만들어 두고 비워 뒀다.** 모델 머리말에 이유가 적혀 있다:
*"지역 코드의 정식 명칭은 사람이 채운다 — 코드만으로는 단정할 수 없다."*

이제 채울 화면이 생겼다(`/d/<slug>/edit/`).

| 묶음 | 편집 항목 |
|---|---|
| 슬라이드 | 이름 · 깊이(cm) · **배율** · **설명** |
| 코어 | 코드 · 채취 방식 · 위·경도 · 수심 · 채취일 · 메모 |
| 지역 | 코드 · 이름 · 해역 · 위·경도 · 메모 |

**자동으로 단정하지 않는다.** 폴더 이름에서 뽑히는 것(지역 코드·코어 코드·깊이)은
파이프라인이 이미 채워 뒀고, `RS = 로스해` 같은 것은 추천 목록과 힌트로만 보여
준다 — *"RS 는 로스해일 가능성이 큽니다 — 확인하고 채우세요."* 이 방침은 P02 가
정한 것이고 015 에서 자동 추론이 두 번 틀린 뒤라 더 그렇다.

**지역과 코어는 여러 슬라이드가 공유한다.** 여기서 고치면 같은 코어의 다른 깊이
슬라이드에도 반영되므로, 몇 개가 함께 바뀌는지 미리 알린다. 셋을 한 트랜잭션으로
저장한다 — 코어만 바뀌고 지역이 안 바뀌면 화면과 저장된 것이 어긋난다.

새로 만든 칸은 둘이다.

- `Slide.description` — 사람이 적는 설명. `state_note` 와 갈라 뒀다. 그쪽은
  자동 처리가 덮어쓰는 칸이다
- `Slide.um_per_pixel_override` — 배율을 못 박는다(015). 자동 파이프라인에는
  `--um-per-pixel` 을 줄 자리가 없어서 만들었다

## 밟은 것 — 파괴적 엔드포인트를 실데이터에 대고 시험했다

검토 차단(012)을 시험하려고 `/review` 에 POST 를 보냈는데 본문을 **빈 키 목록**
으로 만들었다. `save_review()` 는 설계상 키 목록에 없는 교정 행을 지운다("교정
전체 초기화"가 그렇게 동작한다). `rs23 g0` 의 교정 14건이 삭제되고 검토완료가
풀렸다.

30분 전 백업에서 그 시야만 골라 되돌렸고 `removed`·`accepted`·`label`·`note` 가
백업과 완전히 일치함을 확인했다.

**뷰어 동작을 시험할 때는 사본 DB 를 쓴다** (`DIATOM_DB=<임시>`). 복구 리허설(009)
에서 이미 쓰던 방식인데 여기 적용하지 않았다. 그 뒤 데이터셋 편집 화면의 POST
시험은 사본으로 했다.

이 사건이 백업 lane 을 세워 두길 잘했다는 증거이기도 하다. 30분 전 스냅샷이
없었으면 14건은 그대로 사라졌다.
