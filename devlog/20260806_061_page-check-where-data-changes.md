# 061 — 화면 검사를 자료가 바뀌는 자리에 붙인다 (그리고 정정 하나)

2026-08-06. 057 의 "남는 것" 에 **`smoke.sh` 에 목록 페이지 200 을 더한다** 고
적어 뒀고, 사용자가 그것을 해 달라고 했다. 열어 보니 **이미 있었다.**

## 정정 — smoke 는 목록을 보고 있었다

`smoke.sh` 의 5번 검사가 nginx 를 거쳐 `/DiaRUGA/` 를 친다.

```bash
site_code=$(curl ... "$SITE")     # SITE 기본값이 http://127.0.0.1/DiaRUGA/ 다
case "$site_code" in 200) ok ... ;; *) bad "nginx 경유가 200 이 아니다" ;;
```

**057 의 500 도 이것이 잡았을 것이다.** 사본에 괄호 슬러그를 심어 그 상황을
재현하고(목록 500 · `/healthz` 200) 지금 `smoke.sh` 를 걸어 봤다.

```
  ✓ /healthz 200
  ✓ status=ok
  ✗ nginx 경유가 200 이 아니다 (받은 것: 500) — http://127.0.0.1:8093/
smoke 실패 — 종료코드 1
```

**틀린 진단을 세 문서에 옮겨 적었다** — 057 · HANDOFF 9.8·9.10·10절 ·
6차 진척 보고서. 전부 고쳤다(보고서는 docx 를 다시 구워 NAS 공유에도 올렸다).
**026 의 교훈이 이것이었는데** — 원인을 짐작해 적으면 그 진단이 문서에 눌러앉아
다음 사람을 엉뚱한 곳으로 보낸다. 그때는 로그 524줄이었고 이번엔 문서 셋이다.

## 그러면 진짜 구멍은 어디였나

**`smoke.sh` 는 배포할 때만 돈다.** `deploy.sh` 가 마지막에 부르고, 그 밖에는
사람이 손으로 부를 때뿐이다 — cron 에 없다.

그런데 **057 은 배포와 무관하게 났다.** 자료가 들어오면서 났다. 폴러가 NAS 에서
슬라이드를 반입하는 순간 규칙을 어긴 슬러그가 DB 에 앉았고, 그때 아무 검사도
돌지 않았다. 11분 36초 동안 아무도 몰랐고, **사람이 화면을 열어 보고서야 알았다.**

    검사가 붙어 있던 곳:  배포 (판이 바뀌는 자리)
    고장이 난 곳:        반입 (자료가 바뀌는 자리)

## 자료를 바꾸는 자리에 붙였다

`poll_nas.sh` 가 처리를 끝내면 목록 페이지를 한 번 친다.

```
[10:49:32] !! 뷰어가 목록을 못 낸다 (HTTP 500) — 방금 반입·처리한 것을 볼 것
```

**로그에만 적지 않는다.** 로그는 읽는 사람이 없는 동안 꺼진 안전망이다
(`.guides/web/data-safety.md` §2 · 034 에서 같은 판단을 했다). `db_sentinel` 로
깃발을 세워 **`/healthz` 가 degraded 가 되게** 했다 — 뷰어의 상태에 뜨고,
그 다음 `smoke.sh` 도 실패한다. 사람이 이미 보고 있는 통로에 싣는다.

깃발을 세우는 것까지 실제로 돌려 확인했다(사본 DB 로).

```
2026-08-06T10:49:32  poll_nas  목록 페이지가 500 이다 (자동 처리 뒤). 새 슬라이드의 슬러그를 볼 것
```

**호스트에서 도는 것이 규약에 걸리지 않는다** — `db_sentinel.py` 는 Django 를
임포트하지 않고 DB 옆에 텍스트 파일 한 줄을 놓는다. `backup_db.py` 가 cron 으로
도는 것과 같은 자리다(CLAUDE.md 의 예외 조항).

## smoke 에는 한 걸음 더 — 링크를 따라가 본다

**200 은 "떴다" 일 뿐이다.** 목록이 멀쩡해도 상세가 죽을 수 있고, 목록이 200 을
내면서 링크를 하나도 못 만들 수도 있다. 그래서 목록에서 슬라이드 링크를 하나
뽑아 따라간다.

```
  ✓ nginx 경유 http://127.0.0.1/DiaRUGA/ 200
  ✓ 시야 목록 /DiaRUGA/d/260805_bp09-0901_1/ 200
```

링크가 하나도 없으면 그것도 실패다 — **단, 자료가 있을 때만**(`slide > 0`).
자료가 없는 경우는 4번 검사가 이미 잡으므로 여기서 또 울리면 한 원인이 두 줄로
번진다(그 함정도 이 스크립트가 이미 한 번 겪었다).

## 곁들여 — `/healthz` 의 깃발 문구

깃발을 세우는 주인이 백업만이 아니게 됐다. 그런데 `/healthz` 는 무슨 깃발이든
**"백업 실패 깃발"** 이라고 적고 있었다. 폴러가 세운 깃발에 그 말이 붙으면
읽는 사람이 백업을 보러 간다 — **원인을 짐작해 적지 않는다**(026). `무결성
깃발 [poll_nas …]` 로 바꿨다.

이 한 줄은 뷰어 이미지 안에 있어 **아직 안 나갔다** — 다음 판에 함께 간다.

## 남는 것

- **아무도 아무것도 안 할 때는 여전히 아무 검사도 안 돈다.** 자료가 안 들어오고
  배포도 없으면 화면이 죽어도 모른다. cron 으로 5분마다 때리는 것이 가장 싸지만,
  그건 "폴러가 멈춘 것을 아무도 안 알려 준다"(HANDOFF 9.10)와 같은 자리라
  **한 화면에 모아 보이는 쪽**이 낫다. 그 항목과 함께 판단한다
- **검사는 목록과 상세 한 장뿐이다.** 검토 화면·갤러리·코어는 안 본다. 늘리면
  느려지므로, 늘릴지는 고장이 한 번 더 난 뒤에 정한다
