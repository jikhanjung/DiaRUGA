# 105 — 개체 카탈로그: 카탈로그 번호와 동정

> "카탈로그 번호를 붙이고, 각각에 대한 동정 결과를 좀 채워넣어야 하는 시점이라고
> 생각해. 규조 객체 각각에 페이지를 만드는 것은 부적합해보이고, 관찰 하나당 카드
> 형태로 보여주는 페이지를 (…) 만들어주자."

## 없던 것 — 개체를 부르는 이름

검출된 개체는 지금까지 `mask_key`(bbox 를 이어 붙인 문자열)로만 짚었다. 그것은
**이미지 한 장 안에서만 유일한 내부 열쇠**다. 논문에 개체를 인용하거나 표본 목록을
만들려면 사람이 읽고 적을 수 있는 고정 번호가 있어야 하는데, 스키마에 그런 칸이
없었다.

동정(종명)을 적을 자리도 없었다. `ObjectReview.label` 은 `ClassDef` 가 정한 목록
(원형·봉상·Eucampia)에서 고르는 것이라 **종 수준을 담지 못한다** — 종은 목록으로
가둘 수 없다(`var.`·`f.`·명명자가 붙고, 검토 중에 이름이 바뀐다).

## 번호는 저장하지 않는다

```
<지역>-<지점>-<시료>[-<관찰>]-g<시야>[-f<프레임>]-<위치>-<묶음>

RS23-GC03-071-g03-1204_856_132_97-S1        남극 · SAM2 · 합성본
RS23-GC03-071-g03-f28-1198_861_130_99-Y3    남극 · YOLO 3차 · 프레임 28
BP-BP09-0901-g12-f27-843_1502_96_210-S1     육상 · 단독 프레임
RS23-GC03-369-100-g07-410_222_88_140-S1     관찰 100 (0 이면 생략)
RS23-GC03-071-g03-m1a2b3c4d-M               사람이 그린 개체
```

칼럼에 넣으면 층을 고치거나 재검출을 돌릴 때 저장된 값과 실제가 어긋나고, **어긋난
것은 예외가 안 나고 그냥 틀린다.** 파생이면 어긋날 수가 없다.

번호가 안정한 것은 **재료가 안정하기 때문이다.** `mask_key` 는 사람이 경계를 고쳐도
안 바뀌고(그래서 화면이 키를 늘 실어 보낸다) 지웠다 되살려도 그대로다. 규칙은
`web/viewer/catalog.py` 하나뿐이다 — `naming.py`·`judge.py` 와 같은 자리다.

### 위치를 줄이려다 세 번 걸렸다

짧게 만들려고 자른 후보가 전부 실측에서 부딪혔다. 이미지 한 장 안에서 같은 값을
받은 개체 수다.

| 후보 | 예 | SAM | YOLO |
|---|---|---:|---:|
| x,y | `1204x856` | 90 | 270 |
| x,y,너비 | `1204x856x132` | 10 | 30 |
| 중심 좌표 | `1270x904` | 0 | 30 |
| 해시 4자 | `K7QX` | 2 | 0 |
| **bbox 전체** | `1204_856_132_97` | **0** | **0** |
| 해시 5자 | `K7QX4` | 0 | 0 |

이미지 한 장에 개체가 최대 106개라 좌표를 자르면 붙어 있는 것들이 뭉개진다.
**해시 5자도 오늘 0 이지만 그것은 재 봐서 0 인 것이고**, bbox 전체는
`Candidate` 의 `(detection, mask_key)` 유일 제약이 **보장한다** — 4자 해시가 실제로
2건 부딪힌 것을 보면 자료가 늘면 5자도 언젠가 부딪힌다. 길이보다 이쪽을 골랐다.

실제 자료로 확인: 두 묶음의 통과 개체 **32,480건에 번호를 매겨 전부 서로 달랐고,
못 만든 것은 0건**이었다.

### 꼬리가 어느 검출인지 말한다

> "마지막 글자에 엔진하고 검출차수를 의미하는 글자를 끼우면 일련번호만 보고도
> 어디 검출인지 알 수 있지 않을까"

꼬리에 두면 앞쪽 `관찰-시야-위치` 가 엔진끼리 같은 모양이라 나란히 놓고 읽힌다.
코드는 `RunBatch.code` 가 들고 **사람이 정한다** — 라벨에서 자동으로 뽑으면
`yolo-3차`·`yolo-4차` 가 같은 글자로 눕고, 그때는 이미 번호가 적힌 뒤다. DB 가
유일 제약으로 막고, `M`(손그림 자리)은 CheckConstraint 로 막는다.

## 화면 — 관찰 하나당 카드

`/d/<슬러그>/catalog/`. 카드 하나가 개체 하나이고, 카드 자체가 두 열이다 — 왼쪽에
크롭(세워서 자른다: 방향이 통일돼야 형태를 비교한다), 오른쪽에 **번호 · 종명 ·
유형 · 코멘트**. 머리에 어느 엔진의 판인지와 동정 진행률, 오른쪽 위에 검색창
(번호·종명·코멘트), 아래에 거르개 칩(형태별 + 수동 복구·사람 지정·코멘트 있음·
**동정함·동정 안 함**).

**담기는 것은 통과분과 사람이 되살린 것이다.** 동정 대상이 그것이고, 지운 것까지
내면 카드가 몇 배가 된다. 어느 이미지의 개체를 낼 것인가(합성본이 있으면 합성본,
없으면 프레임)는 `candidate_rows` 가 이미 정하고 있어 그것을 재사용했다 — 규칙이
둘이 되면 크롭 화면과 카탈로그가 서로 다른 개체를 센다.

### 엔진마다 별개, 그런데 고르는 장치는 없다

> "한국 권역 시료들은 SAM으로, 남극 권역 시료들은 YOLO로 동정 결과를 채우게
> 될거야. 그러니 두 카탈로그 화면은 완전히 분리되어야 해."
>
> "정확히는 검토 대상 묶음에 따라 보여주는 페이지가 달라지는 게 더 좋겠지"

동정이 엔진에 종속되는 것은 **`ObjectReview` 의 열쇠에 `batch` 가 있어 이미
그렇다**(P09 5.1). 화면은 그 위에서 **검토 대상 묶음 하나만 따라간다.** 처음에는
`?batch=` 와 넘어다니는 버튼을 만들었다가 걷었다 — 관리 화면에서 검토 대상을 갈면
**검토·크롭·카탈로그가 함께** 옮겨 가고, 그러면 화면마다 다른 판을 보는 상태가
아예 안 생긴다. **051 이 그 상태에서 났다.**

두 엔진의 모양이 실제로 다르다(실측).

| | 시야당 이미지 | 검출 | 통과 개체 |
|---|---|---:|---:|
| `sam2-전수` | 합성본 1장(417) · 단독 프레임 1장(153) | 570 | 10,619 |
| `yolo-3차` | 합성본 1장 + **프레임 2~10장** | 2,247 | 21,861 |

YOLO 는 검출력의 대부분이 프레임에 있는데 합성본만 보면 4,444 만 남는다. 그래서
**일단 합성본으로 하고, 묶기(P11)가 채워진 개체는 가장 크게 보이는 프레임을 카드에
그린다.** 번호는 합성본 기준으로 고정한다 — 번호가 묶는 행위에 따라 움직이면 이미
적어 둔 번호가 무효가 된다.

## 밟은 것

### 검토 화면의 "검토 완료" 한 번이 동정을 지웠다

`/review` POST 는 **그 (이미지, 묶음) 의 교정 행 중 payload 에 없는 것을 지운다** —
"뷰어는 늘 전체를 보낸다" 가 전제다. 그런데 검토 화면은 종명을 모른다. 그래서
종명만 채운 행은 삭제·되살림·유형·코멘트가 전부 비어 있어, 사람이 **아무것도 안
하고 "검토 완료" 만 눌러도 통째로 사라졌다.**

017·027·053 이 전부 그 삭제 줄에서 났고 두 번은 운영 자료를 잃었다(14건·37건).
**시험으로 먼저 재현해 놓고** 막았다.

```
AssertionError: unexpectedly None : 종명만 있는 행이 지워졌다
```

`data.save_review` 가 삭제 범위를 정할 때 종명이 든 행의 키를 얹는다. `edits` 와
달리 **갈래 없이 늘** 얹는다: `/review` 는 어느 판에서도 종명을 보내지 않으니
"이 화면이 대표하지 않는 것" 이 조건 없이 참이다.

**그러면서 청소는 계속 된다.** 안전망을 넓게 잡으면 빈 교정 행이 쌓여 "교정 전체
초기화" 가 안 되고 그 행을 세는 자리가 어긋난다 — 되살려 확인했다(2개 실패).

### 응답이 방금 친 글자를 덮었다 — 브라우저로만 잡힌다

세 칸을 잇달아 채우니 **코멘트만 저장이 안 됐다.** 먼저 보낸 종명 저장의 응답이
돌아오면서, 그 사이에 친 코멘트를 서버가 아는 빈 값으로 되돌리고 있었다. 화면에는
"저장됨" 이 적혀 있고 새로고침하면 코멘트만 없다.

**3겹으로는 안 잡힌다** — 서버는 받은 것을 정확히 저장했고 200 을 냈다. 045 가
브라우저 겹을 만든 바로 그 종류다. 고친 것 둘: 요청을 한 줄로 세우고, **보낸 뒤로
사람이 더 친 칸은 응답이 안 건드린다.**

### 다른 묶음을 짚으면 조용히 빈 화면이었다

`_viewpoints_of(only_current=True)` 가 후보를 미리 당길 때 `reviewing()` 으로 못
박혀 있어서, 다른 묶음을 열면 **후보가 한 개도 안 올라오고 "검출이 없다" 로
보였다.** 예외도 404 도 없다. 시험 둘이 잡았다(`[] is not true`).

### 실패할 수 없는 시험을 하나 짰다가 고쳤다

"적다 말고 그림을 눌러 시야로 넘어가면 잃는가" 를 시험으로 짰는데, 되살려 보니
**그 코드를 빼도 통과했다** — 링크를 누르면 칸이 먼저 blur 되어 그때 이미
보내진다. 진짜 빈 자리는 **blur 가 안 나는 이동**(뒤로 가기·주소창·탭 닫기)이라
그쪽으로 다시 짰다. 이제 코드를 빼면 실패한다.

### 말풍선이 코멘트를 글자 그대로 심고 있었다

> "커서를 올리면 (…) 맨 위에 종명을 이텔릭체에 볼드체로 해서 보여주면 좋겠네."

붙이면서 알았다 — `c.note` 를 escape 없이 넣고 있어서 `<` 하나면 말풍선이 통째로
안 보인다. 종명도 자유 입력이라 같은 자리다. `esc()` 를 두고 둘 다 통과시켰다.

CSS 는 `getComputedStyle` 로 `italic 700` 을 확인했다 — `.dettip b` 가 이미 있어
선택자 이름을 잘못 고르면 HTML 은 멀쩡하고 화면에는 맨 글자가 나온다. `.tools`
(051) · `.nowrow`(083) · `.nowtag`(088) 에 이어 네 번째가 될 자리였다.

## 덤 — 검토 대상 묶음을 시야마다 다시 묻고 있었다

`current_detections` 가 시야마다 `review_batch_id()` 를 다시 물었다. 한 화면에
**390~560번**이고 값은 매번 같다. 한 번만 묻고 내려보내게 바꿨다.

| | 질의 | review_batch 조회 |
|---|---:|---:|
| `bp09-0901` (카드 373) | 1,177 → 789 | 390 → **1** |
| `369cm` (카드 1,788) | 1,686 → 1,128 | 560 → **1** |

**크롭 화면·계측 표도 같이 빨라진다** — 같은 함수를 지난다.

## 안전망

**`export_review.py` 가 종명을 싣는다.** `label`·`note` 와 같은 무게의 재생성
불가 자료다. **형식 번호는 안 올렸다** — 적은 개체에만 키를 실으므로(`source`·
`geom_edited` 와 같은 규칙) 종명이 없는 파일은 한 글자도 안 바뀐다. 6,700행을 뜻
없이 다시 쓰면 그 diff 에 그 사이의 진짜 변화가 묻힌다. 운영 DB 로 대조해 `species`
가 출력에 한 글자도 안 나오는 것을 확인했고, 칼럼이 없는 옛 백업도 그대로 읽는다.

**`check_db.py` 에 9번을 더했다** — 묶음 코드가 있는가·`M` 이 아닌가·층 코드가
번호에서 뭉개지지 않는가(`GC-03` 과 `GC03` 이 한 토막이 된다)·관찰이 층을 갖고
있는가·종명이 붙은 교정이 묶음에 들어 있는가. 다섯 다 사본을 망가뜨려 걸리는 것을
확인했다.

**여기에 축이 하나 있다** (057). 번호 규칙이 뷰어 코드(`web/viewer/catalog.py`)에
있어서 **9번은 뷰어 이미지를 올린 뒤에 돈다.** 그때 도구가 죽으면 안 되고(나머지
여덟은 그 코드와 무관하다) 조용히 건너뛰어도 안 되므로, 낡은 판에서는 **크게 적고
넘어간다**:

```
=== 9. 개체 카탈로그 (번호·동정) ===
!! 개체 카탈로그 검사를 못 돌렸다     <-- 이 이미지에 viewer/catalog.py 가 없다 (뷰어 판을 올릴 것)
```

## 버린 것

- **개체마다 페이지** — 사용자가 처음부터 뺐다. 3만 개체에 주소 3만 개는 만들 수도
  관리할 수도 없다
- **종 테이블** — `ClassDef` 처럼 목록으로 가두는 안. 자유 입력 + 자동완성으로
  갔다(이미 쓴 이름이 뜬다). 굳으면 그때 옮긴다
- **넘어다니는 버튼** (`?batch=`) — 만들었다가 걷었다. 위 "고르는 장치는 없다"
- **해시 번호** — 짧지만 보장이 아니다. 위 표
- **프레임 개체까지 카드로** — YOLO 를 다 살리지만 같은 규조각을 시야당 2~10번
  동정하게 된다. 묶기가 채워지면 묶음 단위로 가는 것이 옳은 길이다
