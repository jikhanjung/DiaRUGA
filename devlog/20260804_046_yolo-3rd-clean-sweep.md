# 046 — YOLO 묶음을 들어내고 한 조건으로 다시 뽑는다 (`yolo-3차`)

2026-08-04 저녁. 사람이 물었다: "지금 yolo 1, 2차 데이터를 모두 삭제하고 새로
만들어도 되지?" 확인해 보니 **안전했고, 새로 뽑는 편이 나았다.**

## 1. 왜 들어내는가 — 한 묶음에 두 조건이 섞여 있었다

이유가 셋 쌓였다.

- **`largest_body` 수정(033)이 절반에만 적용돼 있었다.** `yolo-1차` 는 수정 전
  (09:51~10:11 KST), `yolo-2차` 는 수정 후(10:31~)다. **2.8배 차이**가 나는 두
  조건이 "한 번 훑은 것" 이라는 이름 아래 섞여 있었다
- **어제의 잔재가 있었다.** `yolo-1차` 는 08-03(프레임만)과 08-04(합성본 추가)에
  걸쳐 있다. 합성본 검출이 아예 없는 시야가 3개 남아 있었고, 045 에서 시작 판
  규칙을 재던 통계가 그것 때문에 흐려졌다 — **오늘만으로 도는 `yolo-2차` 로 봐야
  깨끗했다**
- **`am22-gc10b_25cm` 은 이미 어긋나 있었다.** 044 에서 시야를 가르면서 그 아래
  YOLO 검출도 `CASCADE` 로 함께 지워졌다(26 → 30 시야). 그 슬라이드는 어차피
  불완전했다

여기에 OOM 재시도 수정(043)까지 들어가서, 다시 뽑으면 **처음으로 한 조건에서 나온
견주기 자료**가 된다.

## 2. 안전한지 먼저 셌다

```
지울 것          Candidate 74,521 · Detection 3,223 · Run 49 · RunBatch 2
is_current=True  0        ← 뷰어가 보는 것이 하나도 안 걸린다
딸린 교정        0건      ← ObjectReview.candidate 가 가리키는 것이 없다
```

교정은 `mask_key` 로 붙고 현재 검출(`sam2-전수`)에만 매여 있다. **견주기용으로
쌓은 묶음은 통째로 들어내도 검토 화면이 그대로다.**

## 3. `drop_batch.py`

묶음을 통째로 지우는 도구가 없었다 — `prune_detections.py` 는 묶음 *안*의 겹친
검출만 정리한다. 만들었다. `Candidate` → `Detection` → `Run` → `RunBatch` 순으로
지운다.

**`Run` 까지 지운다.** 검출이 사라진 실행만 남으면 `/engine/` 목록에 빈 묶음이
뜨고, 이력으로도 "무엇을 돌렸는가" 를 못 말한다.

막아 둔 것 둘 — 둘 다 **예외가 안 나고 그냥 틀린 상태**를 막는다.

- **`is_current=True` 인 검출이 하나라도 있으면 거부**한다. 그것은 사람이 교정을
  붙인 검출이다. 실제로 `sam2-전수 --apply` 를 줘 보고 거부되는 것을 확인했다
- **그 개체를 가리키는 교정이 있으면 거부**한다. `SET_NULL` 이라 행은 살아남지만
  (진짜 키는 `mask_key` 다) 바인딩이 조용히 끊긴다. `--force` 로만 넘어간다

`Candidate` 를 `Detection` 보다 먼저 지운다 — Detection 부터 지우면 Django 의
수집기가 74,000 행을 한 번에 끌어올린다.

지운 뒤 `check_db.py` 13개 검사 전부 OK · 교정 6,731건 그대로 · smoke 통과.

## 4. `yolo-3차` 의 조건

사람이 정했다: **하나만, conf 0.01, 판정 켬.**

```bash
segment_diatoms.py --slide <slug> --backend yolo --keep-current \
  --scale 1.0 --yolo-conf 0.01 --min-um 10 --max-um 150 --batch yolo-3차
```

**판정을 켜는 쪽이 정보가 많다.** `Candidate` 는 통과분과 탈락분을 한 표에 담고
`passed` 칼럼으로만 가른다 — 판정을 켜도 탈락한 것이 지워지지 않고 검토 화면처럼
"탈락" 레이어로 펼쳐 볼 수 있다. 끄면 전부 "통과" 가 되어 **무엇이 걸러졌을지가
사라진다**(`yolo-2차` 는 탈락 0이었다). 게다가 `passed` 가 칼럼 하나라 `refilter`
가 UPDATE 한 번으로 문턱을 다시 건다 — 재추론이 필요 없다.

밟을 뻔한 것 둘:

- **`--scale` 기본값이 0.5 다.** 빠뜨리면 절반 해상도로 검출되고 `um_per_px` 가
  2배로 기록된다. 폴러가 `--scale 1.0` 을 명시하는 이유가 그것이다
- **`--no-judge` 같은 인자는 없다.** 판정은 늘 돌고, "판정 끔" 은 문턱을 넓혀
  전부 통과시킨 것이었다. 기본 문턱이면 그대로 "판정 켬" 이다

`--keep-current` 는 "교정이 있는 시야를 건너뛰는" 관문을 **건너뛴다**. 관문이 있는
이유는 재검출이 `is_current` 를 옮기고 교정을 다시 맺기 때문인데 keep-current 는
둘 다 안 한다 — 여기서 걸러 버리면 정작 견주고 싶은 검토된 시야가 다 빠진다.

## 5. 결과

```
검출 1,624 = 합성본 314 + 프레임 1,310      (전체: 합성본 317 · 프레임 1,318)
개체 37,536 — 통과 15,992 · 탈락 21,544
실행 20 (done 16 · partial 4) · 13.4분 · 판당 0.50초
```

무결성 검사 13개 전부 OK.

**두 번에 나눠 돌았다.** `--slide` 는 **시야당 한 장**만 돈다 — 합성본이 있으면
합성본, 없으면 그 프레임. 프레임 하나하나를 보려면 **디렉토리를 줘야** 한다.
처음엔 그것을 모르고 `--slide` 만 돌려 452장으로 끝났다(3.2분). 옛 `yolo-1·2차`
가 1,600건대였던 것이 그 차이다.

- **시야당 훑기**(452장)는 `sam2-전수` 와 **정확히 같은 대상**이라 견주기의 기본이 된다
- **프레임 훑기**(1,318장)는 "이 규조각이 어느 초점면에서 잡혔나" 를 보는 자료다.
  `/engine/` 캐러셀이 프레임을 넘길 때 갈아 끼우는 것이 이것이라 **같은 묶음**에
  넣어야 한다

싱글턴 시야의 프레임이 두 훑기에 겹쳐 들어와 `prune_detections.py` 로 **135건**을
정리했다. 그 도구가 있는 이유가 정확히 이것이다.

### 못 돌린 11장 — 장비 한계다

빠진 것은 합성본 3장(`rs23 g2` · `369cm g72·g73`)과 프레임 8장인데,
**프레임 8장이 전부 그 세 시야의 사진들이다.** 개체가 유난히 빽빽한 자리라
합성본도 프레임도 8 GB 를 넘긴다. OOM 11건이 그대로 이 11장이고,
`Run.status='partial'` 로 남았다.

**`--scale 0.5` 로 우회하려다 스크립트에 막혔다.**

```
--backend yolo 는 --scale 1.0 이어야 한다 (지금 0.5).
가중치는 원본 해상도에 imgsz=1280 로 학습했다
```

**막은 쪽이 옳다.** 절반 해상도로 넣으면 학습 때와 물체 크기가 달라져 그 셋만
"조건이 다른 검출" 이 아니라 **비교가 성립하지 않는 값**이 된다. 처음엔 가볍게
"해상도만 다른 조건" 이라고 생각했는데 그게 아니었다. 그대로 두고 기록만 한다.

### 밟은 것 — `docker compose run` 이 목록을 먹었다

프레임 훑기를 `while IFS='|' read` 루프로 돌렸더니 **첫 슬라이드만 돌고 끝났다.**
`docker compose run` 이 **heredoc 목록을 stdin 으로 읽어치웠다.** `-T` 는 TTY 만
끄지 stdin 을 막지 않는다 — `< /dev/null` 이 필요했다.

조용히 틀리는 종류다. 실패도 오류도 없이 **"9장이 없는 채로 성공" 으로 끝났다.**
슬라이드별 검출 수를 세어 보고서야 알았다.
