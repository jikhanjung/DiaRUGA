# 096 — 그린 마스크가 묶이지 않던 것: 저장 실패가 조용히 눌러앉는다

2026-08-10 · 실사용 보고 (369cm g25 — "m3b6dc459 는 이 화면의 마스크가 아니다")

## 무엇이 났나

봉상 다섯을 지우고 새로 그려 가며 검토하다 묶기를 눌렀는데, 그린 마스크
하나(`m3b6dc459`)를 서버가 "이 화면의 마스크가 아니다" 로 거절했다. DB 를
보니 **그 마스크만 `ObjectReview` 에 없었다** — 화면에는 있는데 저장이 한
번도 성공한 적이 없는 상태다. 묶기 검증은 제 일을 한 것이다.

## 뿌리 — 실패한 저장이 "할 일 없음" 이 된다

```js
function postReview(keepalive) {
  savePending = false;          // ← 첫 줄에서 끈다
  ...fetch...
  .catch(() => saveState.textContent = '저장하지 못했습니다');  // 안 되살린다
}
```

저장이 한 번 미끄러지면(연결 순간 끊김 등) `savePending` 이 꺼진 채라
`flushSave` 는 그다음부터 **할 일이 없다고 판단한다.** 상태 줄의 작은 글씨
하나가 유일한 흔적이고, 사람은 계속 검토한다 — 그린 마스크는 화면에는 있는데
DB 에는 영영 없다.

## 고침 셋

1. **실패는 다시 저장할 것으로 남는다** — `!r.ok`·`catch` 에서
   `savePending = true`. 다음 동작(판 넘기기·팝업 열기·떠나기)이 재시도한다
2. **묶기 팝업이 열릴 때 밀린 저장부터 밀어낸다** — `flushSave()` 의 약속을
   들고, 묶기 POST 가 그 **뒤에** 선다. 400ms 지연 저장과의 경주도 함께 없어진다
3. **keepalive 는 정말 떠날 때만** — 판 넘기기·팝업 열기는 페이지가 남는다.
   keepalive 요청은 브라우저가 **본문 64KB 를 넘으면 보내 보지도 않고
   거절한다** — 교정·그린 폴리곤이 많은 시야가 정확히 그 크기라, 판을 넘길
   때마다 조용히 잃을 수 있는 자리였다

## 시험

route 로 `/review` 를 **한 번만 떨어뜨려** 사고를 그대로 재현했다 — 그리기 →
저장 실패 → 묶기 → 성공(재시도 덕에 그린 마스크가 DB 에 있다). 되살려 확인:
고침을 걷으면 정확히 "실패했던 저장이 재시도되지 않았다" 로 넘어진다.

일부러 떨어뜨린 요청의 콘솔 오류는 그 줄만 걸렀다 — 통째로 비우면 진짜 JS
오류까지 덮는다. 전체 377개 통과.

## 남는 물음

- 저장 실패를 상태 줄 말고 **더 크게** 알릴 것인가 — 지금은 "다시 시도합니다"
  로 문구만 고쳤다. 실패가 반복되면(서버가 내려가 있으면) 사람이 검토를
  계속하는 것 자체가 손실이다

## 덧 — 같은 날, 미리보기의 같은 뿌리 (사용자 보고 둘째)

> 캐러셀 썸네일에 커서를 올리면 그 프레임이 뜨는데, **이미 지운 마스크가 안
> 지운 것처럼** 그대로 보인다. 클릭하면 맞게 나온다.

미리보기(hover)가 `shotDets`(서버가 준 처음 상태)에서 직접 뽑고 **`removed`
를 안 갈아 끼웠다** — 지움 판정을 고른 판의 removed 로 하니 스친 판의 지운
마스크가 산 것처럼 그려졌다. `stateOf` 로 여섯(cands·rejects·removed·
accepted·labels·notes)을 다 갈아 끼우게 고쳤다 — 클릭과 같은 상태를 같은
길로 읽어야 hover 와 클릭이 같은 그림을 낸다.

**그 고침이 074 의 "못 짚는다" 던 창을 실제로 물었다.** 지연 저장(400ms)이
미리보기 도중에 나가면 `postReview` 가 전역(이제 스친 판의 것)을 읽어 고른
판의 이미지로 보낸다 — 고른 판의 삭제가 지워졌다. **기존 시험이 잡았다**
(스치며 판을 옮겨도 교정이 제 이미지로 간다 → 0 != 1).

뿌리를 고쳤다: `postReview` 는 **미리보기 중이면 갈무리한 고른 판의 상태**
(`shotState[curKey]`)로 payload 를 만든다. 074 가 남겨 뒀던 부분 위험(스친
판의 drawn·edits 가 payload 에 실리는 것)도 이것으로 함께 막힌다.

교훈: **전역을 그리기용으로 갈아 끼우는 화면에서, 저장이 전역을 읽으면
언젠가 어긋난다.** 저장은 "무엇의 상태인가" 를 스스로 물어야 한다.
