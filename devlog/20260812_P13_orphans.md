# P13 — 고아 화면 (`/orphans/`)

**P02 8단계의 마지막 조각이다.** `migrate/rebind.py` 는 011 에서 만들었는데
**그 결과를 볼 화면이 없다.** 이 문서는 **무엇을 고아라고 부를지**와 **화면이
무엇을 할 수 있는지**를 정한다. 근거는 [P02](20260730_P02_db-schema.md) §3 이고,
여기서는 그 사이에 달라진 스키마(P06 · P09 · P12)에 맞춰 다시 그린다.

> **보류다 — 만들기 전에 YOLO 4차를 돌린다** (2026-08-12 사용자 결정).
>
> 순서를 이렇게 잡았다: **`yolo-3차` 검토를 끝내고 → 그 결과로 학습 자료를 만들어
> → 4차를 돌리고 → 그때 고아가 얼마나 나오는지, 무엇에 쓸모가 있는지 본다.**
>
> **이 문서의 6절이 그 근거를 이미 적고 있다** — 지금 고아는 거의 0 이라
> **되살려서 잡히는 것을 볼 수가 없다.** 화면을 먼저 만들면 무엇이 유용한지
> 판단할 자료 없이 모양부터 정하게 되고, 접어 둔 C안(106)이 정확히 그 이유로
> 접혔다: **화면에 숫자를 내려면 그 숫자를 견줄 근거가 있어야 한다.**
>
> **계획은 여기 그대로 둔다.** 4차 뒤에 이 문서부터 다시 열면 된다 — 그때 달라질
> 것은 5절(안 정한 넷)과 6절(시험 자료)이지 1~4절이 아니다.

**담당** 미정 — 4차 뒤에 다시 정한다.

## 1. 고아는 무엇인가 — 스키마로 말하면

```
DiatomObject ──1:N── ObjectReview ──?──▶ Candidate
 (P12 뒤 NOT NULL)      판정 행         null 이면 고아
```

**`ObjectReview` 행은 있는데 그것이 가리킬 `Candidate` 가 없는 상태**다
(`candidate = NULL` · `bind_method = "orphan"`).

- **`DiatomObject` 는 이 정의에 안 들어간다** — P12 이후 판정 행마다 반드시
  하나씩 있어서 개체의 유무로는 갈리지 않는다. 갈리는 것은 **`candidate` 링크
  하나**다
- `candidate` 가 `SET_NULL` 인 것도 같은 이야기다 — **후보가 지워져도 판정은
  살아남는다.** 재생성 가능한 것(검출)이 재생성 불가한 것(교정)을 끌고 가면 안 된다

### 후보가 없는 데는 세 갈래가 있다

| 어떻게 생기나 | 상태 | 화면이 할 일 |
|---|---|---|
| **재검출·엔진 교체로 그 자리에 후보가 안 나왔다** | `orphan` · `candidate=NULL` · `source="engine"` | **이것이 진짜 고아다** |
| **사람이 그린 개체** (`source="manual"`) | 처음부터 `orphan` — 후보에서 나온 것이 아니다 (`data.py` `judgement_for`) | **목록에서 뺀다** |
| **거짓 고아** — 후보가 멀쩡히 있는데 코드가 안 맺어 줬다 | `orphan` 인데 사실 짝이 있다 | **일부러 남긴다** (아래) |

**그래서 목록 조건은 `bind_method="orphan"` 만으로 뽑으면 안 된다.**
`source="manual"` 을 빼야 한다 — 안 빼면 **사람이 그린 개체가 영영 안 줄어드는
할 일로 쌓인다**(맺을 상대가 원래 없다).

**거꾸로 거짓 고아는 남긴다.** 화면에서 *"이 자리에 새 후보 2개"* 로 보이는 것이
곧 그 버그의 증상이다 — 108 에서 묶기가 `judgement_for` 에 후보를 안 넘겨 두 건이
그렇게 앉아 있었고, **이 화면이 없어서 더 안 보였다.**

## 2. 왜 지금 만드나 — 지금은 고아가 거의 없다

지금 교정은 **전부 `exact`** 다. 그래서 이 길은 **한 번도 시험대에 오른 적이 없다.**

| 무엇을 바꾸나 | `exact` 로 붙는 비율 |
|---|---|
| 문턱만 (`refilter`) | 100% — 마스크를 안 건드린다 |
| 같은 설정 재검출 | 100% (실측 · P02 §2.7) |
| `--scale`·`--points-per-side` 변경 | 크게 떨어진다 |
| **엔진 교체 (YOLO)** | **거의 0** |

**하필 그때가 교정이 학습 정답으로 쓰이는 시점이다.** 화면이 없으면 사람의 판단이
조용히 버려지고, **버려졌다는 사실조차 안 보인다.** 4차 회차를 돌리기 전에
세워야 하는 이유가 그것이다.

## 3. 화면

P02 §3 의 그림을 그대로 가져간다.

```
┌ 고아 교정 47개 ─ [삭제 31] [되살림 9] [분류 5] [코멘트 2] ─ 크기순 ┐
│ ┌──────────┐  사람: 오검출로 삭제        이 자리의 새 후보 2개      │
│ │ geom 크롭 │  22.4 µm · 봉상            ┌────┐ ┌────┐             │
│ │  (세움)   │  "조각난 것"               │ A  │ │ B  │  [연결]      │
│ └──────────┘                            └────┘ └────┘             │
```

- **크롭은 `/crop` 엔드포인트를 그대로 쓴다** — 방향 세움과 스케일바가 공짜로
  따라온다. 기하는 `ObjectReview.geom` 에서 오고, 없으면 `mask_key` 에서 푼다
  (`rebind.key_to_bbox`). **둘 다 없으면 그릴 수 없다** — 그 상태는
  `check_db` 가 따로 센다
- **오른쪽은 그 자리의 새 후보**다. 검토 화면의 "빈 곳 클릭 → 후보 펼쳐 보기" 와
  같은 방식이라 조작이 낯설지 않다. 고르는 기준은 `rebind.bbox_iou` — **규칙을
  두 벌 만들지 않는다**
- 엔진 교체 직후엔 고아가 **2,000개 규모**다 → 필터·정렬·페이지네이션이 필수

### 이 화면이 곧 엔진 비교 화면이다

P02 §3 이 말하는 진짜 값은 이쪽이다.

| 숫자 | 뜻 |
|---|---|
| `orphan` 중 `accepted`·`label` 이 붙은 것 | **새 엔진이 놓친 것** (사람이 규조각이라 한 자리) |
| `orphan` 중 `removed` | 새 엔진이 애초에 안 낸 오검출 — **좋은 신호다** |
| 새 후보 중 아무 교정도 안 붙은 것 | 새로 생긴 것 → 사람이 봐야 할 대상 |

## 4. 동작 셋과 그 문

| 동작 | 무엇을 바꾸나 |
|---|---|
| **이 후보에 연결** | `candidate` · `bind_method="manual"` · `bind_score` |
| **그대로 두기** | 아무것도 안 바꾼다 (다음 회차에 다시 걸린다) |
| **교정 폐기** | `ObjectReview` 행을 지운다 — **재생성 불가 자료를 지우는 문이다** |

**`/review` 를 지나면 안 된다.** 그 길은 *"그 (이미지, 묶음)의 교정 전체를
갈아치운다"* 이고, 이 화면은 한 번에 한 행만 만진다 — `save_catalog` 처럼
**좁은 문**을 따로 둔다(105 가 같은 이유로 그렇게 했다).

- **서버가 다시 검사한다** — 그 고아와 그 후보가 같은 (이미지, 묶음)인가 ·
  그 후보에 이미 다른 판정이 붙어 있지 않은가(**같은 개체를 둘이 가져가지
  않는다** · `rebind` 의 규칙과 같아야 한다) · 검토 대상 묶음인가
- **`manual` 은 기계가 다시 풀지 않는다** — `rebind.py` 가 이미 그렇게 되어 있다.
  화면에서 맺은 것이 다음 재검출에서 조용히 풀리면 안 된다
- **폐기는 되돌릴 수 없다.** 눌러야 지워지고, 무엇이 지워지는지(삭제/되살림/분류/
  코멘트/종명·등급이 붙어 있는지)를 **버튼에 미리 적는다**(063 의 규칙)

## 5. 아직 안 정한 것

1. **URL 이 슬라이드별인가 전역인가.** P02 는 `/d/<slug>/orphans/` 이고
   TODOs·HANDOFF 는 전역 `/orphans/` 로 적혀 있다. **슬라이드별이 맞다고 본다** —
   크롭·`um_per_px`·검토 대상 묶음이 전부 슬라이드에 매여 있다. 전역은 "어느
   슬라이드에 몇 개" 한 줄로 목록 화면에 얹으면 된다
2. **묶음 축을 어떻게 두나.** 교정은 `(image, batch, mask_key)` 에 매여 있어
   고아도 묶음마다 따로다. 검토 대상 묶음만 볼지, 묶음을 고르게 할지
3. **폐기에 확인 한 겹을 더 둘지** — 지금 안은 "버튼에 적고 서버가 다시 검사"
   까지다
4. **`rebind.py` 를 화면에서 돌릴 수 있게 할지.** 지금 안은 **아니다** — 재바인딩은
   회차를 돌릴 때 스크립트로 돌고, 화면은 **그 결과를 보는 자리**다. 몇 시간짜리
   작업을 버튼 하나로 조용히 시작하지 않는다(084 와 같은 판단)

## 6. 시험 자료가 없다 — 이것이 이 작업의 절반이다

**지금 고아는 (거의) 0 이다.** 그래서 **되살려서 잡히는 것을 볼 수가 없고**,
그런 시험은 없는 것보다 나쁘다(064 에서 한 번 그렇게 짰다).

- **유닛·브라우저 시험**은 픽스처로 `orphan` 을 세운다 — `source="engine"` 인
  진짜 고아 · 사람이 그린 것(목록에서 빠져야 한다) · 거짓 고아(후보가 있는데
  `orphan`) 셋을 다 만든다
- **실물 확인**은 조인 사본에 `rebind.py` 를 돌려 만든다. `--scale` 을 달리해
  재검출한 묶음이 있으면 그것으로, 없으면 `yolo-3차` 를 상대로 맺어 본다
- **운영 DB 에 붙여 눌러 보지 않는다** — 폐기가 있는 화면이다

> **이 계정(`jikhanjung`)은 DB 를 직접 못 본다** — `dbrun.sh` 가
> `open /srv/DiaRUGA/.env: permission denied` 로 서고 docker 소켓도 막혀 있다.
> 지금 고아가 몇 건인지 세려면 `paleoadmin` 쪽에서 `check_db.py` 3번을 봐야 한다.

## 7. 순서

1. 목록 조건과 조회를 `data.py` 에 만든다 (`source="manual"` 을 뺀다)
2. 화면 — 목록 · 필터 칩 · 페이지네이션. 크롭은 `/crop` 재사용
3. 그 자리의 새 후보 (`rebind.bbox_iou` 로 고른다)
4. **좁은 문** — 연결 · 폐기. 서버가 다시 검사한다
5. 시험 셋 (6절) · `check_db` 와 숫자가 맞는지
6. 목록 화면에 "고아 N" 줄
