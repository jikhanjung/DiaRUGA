## 3단계 — 묶인 것이 보인다

- **사슬 배지** — 묶인 개체의 상자 오른쪽 위에 ⛓. 마스크 색은 안 건드린다:
  색은 분류가 말하고, 묶임은 정체에 대한 다른 축이다
- **말풍선** — "⛓ 4장 묶음 · 대표: 합성본" 한 줄
- **캐러셀 따라가기** — 묶인 개체를 고른 채 판을 넘기면 다음 판의 짝이 1.4초
  밝아진다. "지금 보는 이것이 아까 그것" 을 눈이 따라간다
- **저장 직후 배지가 선다** — 팝업의 저장 성공 갈래가 `build()` 를 다시
  부른다. 새로고침을 기다리게 하면 "저장이 됐나" 를 묻게 된다

**`?batch=` 읽기 전용 화면에는 안 붙였다 — 안 붙는 것이 맞아서다.** 묶음은
검토 대상 묶음의 마스크에 열쇠(`mask_key`)로 붙는데, 그 화면은 **다른 묶음의
마스크**를 그린다 — 열쇠가 달라 보여 줄 것이 애초에 없다. 화면 갈래를 하나
줄이는 결정이 아니라 자료 구조가 내리는 결정이다.

## 4단계 — `export_review.py` FORMAT 4

묶음은 사람이 프레임마다 골라 만든 **재생성 불가 자료**다 — 교정과 같은 무게로
git 감사 기록에 실린다.

- 파일 머리에 `n_links`, 꼬리에 `links` 절. 멤버 하나가 한 줄(개체와 같은 규칙)
- **id 가 아니라 이름·경로다** — 묶음은 `batch` 라벨, 이미지는 `path`. 감사
  기록은 두 DB 를 견주는 물건이라 저장소마다 달라지는 id 를 적으면 diff 가
  거짓말을 한다 (형식 3 이 교정에 대해 세운 규칙 그대로)
- **차례를 못 박는다** — 멤버는 합성본 먼저 경로순, 묶음은 첫 멤버의 (경로, 키)
  순. `--check` 가 문자열 대조라 렌더가 결정적이어야 한다
- **옛 DB(0030 이전 백업)는 표가 없어 조용히 빈 목록** — `image_id` 칸 처리와
  같은 갈래다. `--db <백업>` 으로 두 시점을 견주는 쓰임이 살아 있다
- 묶음이 없는 파일은 `"links": []` 한 줄 — 대부분의 파일에 두 줄을 보탤 이유가
  없다
- **교정 없이 묶음만 있는 시야도 내보낸다** — 빈 시야 판정에 `links` 를 넣었다

확인: 옛 백업 읽기(묶음 0) · 사본에 묶음을 심고 내보내기 · `--check` 왕복 통과 ·
DB 만 대표를 옮기고 `--check` → **달라짐 1 을 잡는다**.

운영 `review/` 를 형식 4 로 다시 내보냈다(508 파일 — 검토가 진행 중이라 교정도
7,472 → 7,587 로 함께 실렸다. 감사 기록은 지금 DB 의 모습을 담는 것이 맞다).
