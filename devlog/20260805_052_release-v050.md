## 판 번호 — MINOR 는 사람이 정했다

`v0.4.0 → v0.5.0`. **PATCH(`v0.4.1`)를 기본으로 제안하고 물었고, MINOR 가
답이었다.**

물어본 이유가 기록에 있다. 지난 두 번 다 자릿수 규칙(`MINOR = feature add`)을
근거로 올렸다가 정정받았다 — 목록 화면 1.3초→0.3초를 `v0.2.0` 으로 올리려다
`v0.1.10` 이 됐고, 권역 갈래 + 남한 지도 + 새 모델 칸을 `v0.2.0` 으로 올렸다가
`v0.1.15` 로 되돌렸다. 08-04 에는 **새 화면·새 엔드포인트·새 CLI 를 더하고도
`v0.3.1`** 이었다.

그래서 이번에도 물었다. 이번 답이 MINOR 인 근거로 든 것:

- 새 화면 + 새 URL (`/core/<지역>/<코어>/`)
- **DB 스키마가 바뀐다** (`Slide.sample_kind`)
- 목록 화면의 구조 자체가 바뀐다 (평평한 목록 → 코어로 묶인 목록)

**규칙이 바뀐 것이 아니다.** 판 번호는 프로젝트의 단락을 사람이 어떻게 보는지를
담는 값이고, 그 크기는 사람이 정한다. 다음에도 묻는다.

## 굽는 태그 이름을 한 번 틀렸다

`IMAGE_TAG=v0.5.0 docker compose … build web` 로 구웠더니
**`honestjung/diaruga:latest` 가 나왔다.** `deploy/docker-compose.yml` 이 보는
변수는 `DIARUGA_TAG` 다(`image: honestjung/diaruga:${DIARUGA_TAG:-latest}`).
`IMAGE_TAG` 는 **`/srv/DiaRUGA/.env` 쪽 이름**이고 `deploy.sh` 가 그것을 고친다.

같은 것을 가리키는 이름이 안팎으로 다르다 — 굽는 쪽은 `DIARUGA_TAG`, 도는
쪽은 `IMAGE_TAG`. **틀려도 예외가 안 난다.** `latest` 라는 멀쩡한 이름이
나오고, 그것을 배포하면 무엇이 도는지 알 수 없는 상태가 된다. 다시 구워
`v0.5.0` 으로 올렸다.

## 병행 세션이 도는 중에 구웠다

이 저장소는 **여러 Claude 세션이 같은 작업 트리에서 동시에 돈다.** 이미지는
`COPY . .` 라 **구운 시점의 트리가 그대로 들어간다** — 남의 미커밋 변경이
섞일 수 있다.

이번에는 확인했다. 구운 시각이 `11:22:07`, 바로 앞 커밋이 `aee969f`(11:16:06),
그다음 커밋이 `fab71d9`(11:36:32)다. 그 사이 옆 세션이 만지고 있던 것은
P05 계획 문서였고 뷰어 코드가 아니다. 050(peewee)·051(엔진 고르기)의 코드는
**11:45 이후라 이 이미지에 없다.**

굽기 전에 `git log --format='%h %ad' --date=format:'%H:%M:%S'` 로 시각을 맞춰
보는 것이 이 판에서는 실효가 있다. `git status` 가 깨끗한 것만으로는 모자란다 —
**깨끗한 것은 그 순간이고, 굽는 데 걸리는 몇십 초 사이에 늘어난다.**
