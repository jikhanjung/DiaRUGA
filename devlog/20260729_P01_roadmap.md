## 1. NAS 연결 (NFS)

NAS 의 특정 디렉토리에 폴더별(viewpoint)로 사진이 올라오면, 그것을 가져와
현재와 같은 흐름으로 합성·검출한다.

```
NAS (NFS) ─→ 로컬 복사 ─→ [그룹핑?] ─→ 합성 ─→ 검출 ─→ 뷰어
```

### 착수 전 확정할 것 — "폴더별(viewpoint)" 이 폴더 하나 = 시야 하나인가?

이 답에 따라 파이프라인의 첫 단계가 달라진다.

| 경우 | 그룹핑 | 영향 |
|---|---|---|
| **폴더 = 시야** | 불필요 | `group_focus_series.py` 를 건너뛰고 폴더 전부를 한 그룹으로 합성 |
| 폴더 = 시료 | 필요 | 현재와 동일 |

현재는 한 폴더에 여러 시야가 섞여 있어 이미지 내용으로 묶는다. XML 에 스테이지
좌표가 없어서 그렇게 할 수밖에 없었다. 폴더가 시야 단위로 온다면 그 제약이
촬영 단계에서 해소되는 셈이라 상당히 단순해진다.

부수 효과로, 116cm 의 단독 시야 26개가 촬영 문제였는지 임계값 문제였는지도
자연히 무의미해진다.

### 할 일

- NFS 마운트. **읽기 전용 권장** — 원본을 건드리지 않는다.
  재부팅 후에도 붙어 있게, NAS 가 내려갔을 때 hang 하지 않게(`soft`, `timeo`)
- 새 폴더 감지 → 복사 → 처리 트리거.
  **NFS 에서 inotify 는 신뢰할 수 없으므로 폴링이 무난하다**
- **업로드 완료 판정** — 촬영 중인 폴더를 건드리면 안 된다. 파일 개수·mtime 이
  일정 시간 변하지 않으면 완료로 보는 방식이 단순하다
- **폴더 단위 상태 관리.** `run_batch.sh` 는 산출물 존재 여부로 건너뛸 뿐
  폴더 상태 개념이 없다. 대기/복사중/처리중/완료/실패 + 재시도 정책

### 유의

**디스크.** 원본이 345장에 994 MB 였다. 지속적으로 쌓이면 정책이 필요하다.
현재 `/` 가 84% 사용 중이다. 원본을 계속 둘지, 처리 후 지울지. 산출물은
재생성 가능하지만 시야당 1분이 든다. **`review/` 는 재생성 불가 — 백업 대상.**

**스케일 하드코딩.** `UM_PER_PIXEL` 이 0.112599 로 박혀 있다. 지금 데이터는
345장이 모두 같은 촬영 조건이라 문제가 없었지만, **조건이 바뀌면 계측값이
통째로 틀어진다.** 사진마다 동반되는 XML 의 `Scaling/Items/Distance` 에서
읽도록 바꿀 것. 자동 수집을 붙이는 시점이 적기다. 광학계 구성이 이전과 다르면
경고하는 것도 함께.

## 2. 데이터셋 + 학습 파이프라인

뷰어로 모은 교정 결과를 정답으로 삼아 YOLO11 등을 커스텀 학습한다.
**지속적으로 재학습이 가능한 파이프라인**을 만드는 것이 목표.

```
뷰어 교정 ─→ 데이터셋 내보내기 ─→ 학습 ─→ 평가 ─→ (교체는 3번)
     ↑                                        │
     └──────────── 부족한 부분 보강 ←──────────┘
```

### 이미 갖춰진 것

- `out/*_candidates.json` — bbox, **외곽선 폴리곤**, 분류(rod/round), 지표 일체
- `review/*_review.json` — 사람이 지운 것(오검출)과 되살린 것(누락)
- 폴리곤이 있으므로 **YOLO detection(bbox) 과 segmentation 양쪽 다 뽑을 수 있다**

### 할 일

- **내보내기 스크립트** — `out/` + `review/` → YOLO 형식(images/labels, data.yaml)
- **정답의 신뢰도 구분.** 사람이 검토한 시야와 그렇지 않은 시야를 섞으면 안 된다.
  현재는 교정 기록 유무로 간접 판단할 수밖에 없다 → 뷰어에 **"검토 완료" 표시**가
  필요하다(6번과 연결)
- 학습/검증 분할은 **시야 단위로.** 같은 시야의 개체가 양쪽에 섞이면 성능이
  부풀려진다
- 클래스 정의. 지금은 rod / round 둘뿐이고 Plate 7·8 형태는 아예 빠져 있다.
  학습 데이터에 포함할지 결정
- 재학습 트리거와 버전 관리 — 데이터셋 스냅샷 + 모델 + 평가 결과를 함께 남긴다

### 유의 — 재현율이 라벨 품질의 상한이다

**현재 검출의 재현율이 50~60% 로 추정된다(육안).** 놓친 개체는 라벨에도 없으므로,
이 데이터로 학습하면 **같은 것을 놓치는 모델**이 된다.

뷰어의 누락 복구로 메울 수 있지만, 그것도 **SAM 이 후보로라도 잡아 준 것**에
한한다. SAM 이 아예 못 잡은 개체는 현재 UI 로 추가할 방법이 없다
→ **수동 박스 그리기 기능이 필요할 수 있다**(6번).

그래서 착수 순서는 재현율 실측 → 필요하면 분할 개선 → 데이터셋 구축이 맞다.

또 하나, 학습 데이터가 특정 시료에 쏠리지 않게 할 것. 현재 밀도가 시료마다
크게 다르다(그룹당 12.3 ~ 27.4개).

## 3. 검출 엔진 교체

커스텀 학습이 완성되면 SAM + 형태·텍스처 필터를 커스텀 모델로 바꾼다.

### 이미 갖춰진 것

`segment_diatoms.py` 에 `--backend` 인자가 있다(현재 sam2 / sam3 자리).
`load_generator()` 만 확장하면 된다.

### 유의

- **출력 스키마를 유지할 것.** `out/*_candidates.json` 형식을 그대로 내면
  뷰어·`refilter.py`·내보내기 스크립트가 수정 없이 동작한다
- **형태·텍스처 지표는 계속 계산해 남기는 편이 낫다.** 판정에 쓰지 않더라도
  계측값(장·단축 µm, 조흔 주기)은 그 자체로 결과물이다
- 교체 전후 **같은 시야로 비교.** 재현율·정밀도를 실측해 두어야 판단이 선다
- **SAM 경로를 지우지 말 것.** 새 시료·새 형태에서는 클래스 무관 검출이
  여전히 쓸모 있다

## 4. Identification (종 동정)

2·3번과 **별개 트랙으로 병행**한다. 논문·handbook 등의 이미지를 모아 학습
데이터로 공급할 예정. 구체적인 방안은 차차 정한다.

### 현재 상태

시스템은 "규조각인가", "봉상인가 원형인가"까지만 판정한다. 속·종 수준은
다루지 않는다. 판정 기준을 세울 때 참조 도판 9장(Plate 1~9)을 썼고, 그것이
이 트랙의 씨앗이 될 수 있다.

### 미리 생각해 둘 것

- **도메인 격차.** 논문 도판은 대개 고배율·고대비로 정리된 이미지고, 우리 사진은
  명시야 투과광에 배경 대비가 낮으며 쇄설물과 겹쳐 있다. 그대로 학습하면
  실제 사진에서 안 맞을 수 있다
- **라벨 체계.** 어느 분류 체계를 따를지, 속 수준까지인지 종까지인지
- **개체 수 불균형.** 흔한 종과 드문 종의 차이가 크다
- **이미지 출처와 이용 조건** 확인
- **이미지 외의 특징을 함께 쓸 것.** 조흔 밀도(현재 FFT 로 측정 중), 장·단축 µm,
  형태 지표는 실제 동정에 쓰이는 형질이다. 이미지만 넣는 것보다 나을 수 있다

## 5. 컨테이너화

Docker 이미지를 만들어 컨테이너로 돌린다.

### 갈라야 할 것

뷰어와 처리 파이프라인은 성격이 달라 한 이미지에 묶지 않는 편이 낫다.

| | 필요한 것 | 크기 |
|---|---|---|
| **뷰어** | Django, Pillow — GPU 불필요 | 작다 |
| **처리** | torch+cu126, SAM2, 모델 가중치 — GPU 필요 | 크다 (venv 가 6.3 GB) |

뷰어만 상시 띄우고 처리는 필요할 때 돌리는 형태가 자연스럽다.

### 유의

- **Docker 는 포트 publish 시 ufw 를 우회한다.** iptables 에 직접 규칙을 넣기
  때문이다. 실제로 이 서버의 8080 이 ufw 와 무관하게 열려 있다. 뷰어에 인증이
  없으므로 `127.0.0.1:9090:9090` 으로 바인딩하거나 앞에 nginx + basic auth 를
  두어야 한다. 지금은 ufw 로 사내망만 열어 두었지만 컨테이너로 옮기면 그 규칙이
  무의미해진다
- 데이터는 전부 볼륨 마운트 — `260729/`(또는 NAS 마운트), `stacked/`, `out/`,
  **`review/`**. 특히 `review/` 는 재생성 불가라 컨테이너 안에 두면 안 된다
- GPU 는 `--gpus` / nvidia-container-toolkit
- **모델 가중치를 이미지에 굽지 말 것.** `~/.cache/huggingface` 를 캐시 볼륨으로
- 개발 서버(`runserver`)가 아니라 gunicorn 등으로. `DEBUG=0`,
  `DIATOM_SECRET_KEY` 지정. 설정은 이미 환경변수로 빠져 있다

## 6. UI · 편의성 개선 (지속)

기능이 아니라 쓰는 맛에 관한 것. 계속 다듬는다.

지금 눈에 띄는 것들:

- **검토 완료 표시** — 어느 시야를 다 봤는지 알 수 없다. 2번의 전제이기도 하다
- **수동 박스 그리기** — SAM 이 후보로도 못 잡은 개체는 현재 추가할 방법이 없다.
  2번의 라벨 품질과 직결된다
- **문턱 조정 UI** — `refilter.py` 를 명령줄로 돌리는 대신 뷰어에서 값을 바꿔
  즉시 결과 보기. 재추론이 없어 124 시야 재적용이 2초면 된다
- **필터 · 정렬** — 크기·형태·텍스처로 후보를 걸러 보기, 표 정렬
- **계측 결과 내보내기** — CSV. 지금은 뷰어에서 눈으로 보는 것뿐이다
- **시야 간 키보드 이동** — 지금은 갤러리 안에서만 ← → 가 듣는다
- 데이터셋 전체 크기 분포 그래프
- 작업 진행 상황 표시 (1번과 연결)

## 당면 과제 (2026-07-29 작업에서 이어짐)

위 여섯 가지에 앞서, 또는 병행해서 정리할 것들. 배경은 devlog 003 §8 참조.

1. **원형(중심목) 판정 기준 검증** — 668개가 잡혔으나 실물로 확인된 적이 없다.
   오검출을 걸러내며 정한 값이라 진짜를 놓치고 있을 수 있다. **1순위**
2. **재현율 실측** — 50~60% 는 육안 추정치다. 뷰어에 교정 기능이 갖춰졌으므로
   시야 몇 개를 전수 교정하면 실측할 수 있다. **2번 항목의 전제**
3. **분할 단계 개선** — 재현율 문제의 근본 원인. SAM2 AMG 가 조밀한 무리 속
   투명한 규조각을 온전히 분할하지 못한다. 엣지·임계값으로 씨앗을 찾아 SAM2 에
   점·박스로 물려주는 방향. **3번으로 엔진을 갈아치우면 무의미해질 수 있으므로
   투자 판단이 필요하다**
4. **텍스처 가드 방향 수정** — `texture_score` 의 가드가 `max_period_px` 만 보는데
   앨리어싱은 짧은 쪽에서 먼저 생긴다. 현재 장비(원본 해상도)에서는 실害 없음
5. **116cm 그룹핑 임계값** — 단독 시야 26개가 촬영 문제인지 임계값 문제인지 미확인.
   1번에서 폴더=시야로 확정되면 무의미해진다
