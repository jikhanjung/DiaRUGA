## 한 줄인데 왜 판을 냈나

깃발을 세우는 주인이 **백업만이 아니게 됐기 때문이다.** 061 에서 폴러가 자동
처리 뒤에 화면이 안 뜨면 같은 깃발을 세우게 했고, **폴러 쪽은 저장소에서 돌아
이미 살아 있다.** 그 상태로 두면 폴러가 세운 깃발에 뷰어가

    백업 실패 깃발 [poll_nas …] 목록 페이지가 500 이다

라고 적는다. **읽는 사람이 백업을 보러 간다.** 026 에서 정확히 그 값을 치렀다 —
파이프라인 이미지 태그가 틀린 것을 "NAS 가 내려갔는가" 라고 4시간 반 동안
524번 적었다. **원인을 짐작해 적으면 그 진단이 사람을 엉뚱한 곳으로 보낸다.**

고장 나 있는 상태가 아니라 **고장 났을 때 잘못 말하는 상태**라 급하지는 않다.
그래도 안전망이 우는 날은 이미 나쁜 날이고, 그날 한 줄 때문에 사람이 다른 데를
파게 만들 이유가 없다.

## 확인 — 깃발을 실제로 세워 보고 읽었다

문구를 바꿨다고 적기만 하면 그 문구가 **그 상황에서 나오는지**는 모른다.
새 이미지에 **사본 DB 를 물려** 깃발을 세우고 `/healthz` 를 읽었다.

```
status: degraded
note:   무결성 깃발 [poll_nas 2026-08-06T12:14:55] 목록 페이지가 500 이다
        (자동 처리 뒤). 새 슬라이드의 슬러그를 볼 것
```

`status` 가 `degraded` 로 넘어가는 것까지 같이 봤다 — 문구만 고치다 깃발이
상태를 안 바꾸게 되면 그게 더 나쁘다. **운영 DB 옆에는 깃발을 세우지 않았다**
(`/data3/DiaRUGA/.flagtest/` 에 사본을 두고 끝나고 지웠다).

> **`docker compose run --rm web python -` 으로는 안 됐다.** 5분을 기다리다
> 끊었다 — 이 서비스의 entrypoint 가 gunicorn 을 띄우는 자리라 stdin 으로 준
> 스크립트가 안 돌아간다. **도는 컨테이너에 `exec` 로 붙고 `-e` 로 DB 만 갈아
> 끼우는 쪽**이 맞다(설정을 임포트할 때 환경변수를 읽으므로 새 프로세스면 된다).
