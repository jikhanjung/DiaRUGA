# 068 — 사람이 마스크를 그린다 (P09 3단계)

2026-08-06. 계획은 [P09](20260806_P09_mask-editing.md), 앞 단계는
[065](20260806_065_review-belongs-to-batch.md)·[066](20260806_066_review-per-image.md)·
[067](20260806_067_orphan-objects-on-screen.md).

**엔진이 마스크를 아예 안 낸 자리**에 사람이 개체를 만들 수 있게 됐다. 거기가
재현율의 나머지 절반이고, 학습으로 보면 **가장 값진 양성 표본**이다.
시험은 194개다.

---

## 1. `shape.py` — 임포트가 `math` 뿐이다

사람이 그린 폴리곤은 **잰 사람이 없다.** 그렇다고 화면을 빈칸으로 두면 고장으로
읽힌다.

| 재는 것 | 방법 |
|---|---|
| 면적 · 둘레 | 신발끈 · 변의 합 |
| 원형도 | 4πA/P² |
| solidity · convexity | 볼록껍질(단조 체인) 대비 |
| 장축·단축 · 신장비 | **면적 모멘트**로 맞춘 타원 |
| 긴 변·짧은 변 | 주축으로 돌린 외접 상자 |
| 타원 IoU | Sutherland–Hodgman 클리핑 |

안 재는 것은 `texture`(픽셀의 주파수)와 `predicted_iou`·`stability_score`(SAM 이
자기 마스크에 매긴 점수)다. 뒤 둘은 **애초에 사람이 그린 것에 뜻이 없다.**

### numpy·cv2 를 안 들인 근거 — 재 봤다

사용자가 "크기가 얼마나 되지?" 라고 물어서 잰 값이다.

| | 크기 |
|---|---|
| `numpy` + `numpy.libs` | **70 MB** |
| `cv2` + `opencv_python_headless.libs` | **153 MB** |
| 지금 뷰어의 Django | 50 MB · PIL 7 MB |

뷰어 이미지가 200 MB 대인데 둘을 넣으면 **2배가 넘는다.** 그리고 진짜 선택지는
"numpy 만" 이 아니었다 — numpy 만으로는 볼록껍질·타원 맞춤·클리핑이 없어
`shape.py` 의 대부분이 남고, 개체 하나에 점 13~19개라 속도가 문제인 자리도
아니다. **cv2 를 넣고 230줄을 지우느냐, 200 MB 경계를 지키느냐**가 진짜 물음이고,
지키는 쪽을 골랐다:

- **뷰어는 화면을 고칠 때마다 굽는다** (파이프라인은 알고리즘이 바뀔 때만).
  자주 굽는 쪽이 2배가 되는 비용은 배포마다 낸다. 그리고 `/` 가 86%다
- `requirements-web.txt` 가 "torch·opencv·numpy 가 여기 없는 것은 실수가
  아니다" 라고 못 박아 뒀다 — cv2 가 들어오면 **판정·계측이 뷰어로 새어 들어올
  길**이 생긴다

### 아는 값으로 잰다

정사각형의 원형도 π/4, 원의 타원 IoU > 0.99, 오목한 ㄷ 자의 solidity < 0.8,
**기울인 타원의 긴 변이 안 바뀌는 것**(축정렬 상자로 재면 부푼다 — 봉상 개체의
축정렬 상자는 중앙값 52%가 배경이다). 지금 나오는 값을 베껴 적으면 계산을 잘못
고쳐도 시험만 함께 틀어져 통과한다.

## 2. 지표를 저장하지 않는다

`ObjectReview` 에 칸을 더해 넣어 둘 수도 있었다. **안 했다** — 폴리곤이 원본이고
지표는 거기서 나오는 값이라, 넣어 두면 **4단계에서 기하를 고쳤을 때 낡는다.**
개체 하나에 점 13~19개라 그때그때 재는 값이 싸다.

대가는 계측 표가 매번 다시 잰다는 것이다. 사람이 그린 개체는 전체의 일부일
것이므로 지금 걱정할 자리가 아니다 — 비싸지면 그때 캐시를 본다.

---

## 3. 없는 것과 빈 것이 다르다

`drawn` 이 payload 에 **아예 없는 것**과 **빈 목록**은 다른 말이다.

- 없다 → **그리기를 모르는 옛 화면**이다. 손대지 않는다
- 비었다 → "그린 것이 하나도 없다". 지운다

둘을 같이 다루면 **배포 중에 열려 있던 탭**의 저장 한 번이 그린 개체를 전부
지운다. 판을 올리는 동안 그런 탭은 반드시 있고, "검토 완료" 한 번이면 저장이
나간다.

**지우는 것은 행을 지우는 것이다.** 엔진이 낸 것은 `removed=True` 로 남겨 음성
표본이 되지만, 사람이 그리다 만 것을 그렇게 남기면 **"여기 규조각 없다" 를 다음
회차에 가르친다** (P09 5.10).

## 4. 한 번 그리면 저장이 막히는 갈래

가장 고약한 것이 이것이었다.

화면은 서버가 준 `labels` 지도를 그대로 되돌려 보낸다. 그린 개체의 분류가 거기
실리면 그 키가 서버로 돌아오는데, **`batch=NULL` 이라 엔진 쪽 `known` 집합에
없다** → 409. **한 번 그리고 분류를 주면 그 시야를 더 저장할 수 없게 된다.**

분류·코멘트는 `drawn` 이 통째로 나르는 것이 맞다. 갈라야 하는 자리가 넷이었다.

```
data.py           labels·notes 지도에서 source="manual" 을 뺀다
_detection.html   setLabel · setNote · 실행취소 두 갈래
```

**3겹 시험이 처음에 이것을 못 잡았다.** "화면이 받은 것을 그대로 되돌려 보낸다"
는 시험을 따로 쓰고서야 잡혔고, 브라우저 시험에서는 **콘솔의 409 까지** 함께
드러났다.

## 5. 그리는 중은 다른 층이다

점 찍기 상태 기계가 기존 마우스·키보드 배선 위에 얹힌다. 새는 자리가 셋이었고
셋 다 시험으로 막았다.

| 새면 | 무슨 일이 나나 |
|---|---|
| 클릭이 **선택**으로 | 그리다가 개체가 골라지고 그 상태에서 분류 단축키가 먹는다 |
| Backspace 가 **`history`** 로 | **저장된 교정을 무른다** |
| 분류가 **`labels`** 로 | 위 4절 |

그 밖에 배운 것:

- **닫기 거리는 화면 화소로 잰다.** 이미지 좌표로 재면 확대할수록 닫기가
  어려워진다. 배율은 svg 의 실제 폭에서 얻는다 — `k` 를 따로 곱하면 두 번 센다
- **그리는 층은 늘 svg 의 맨 위에 둔다.** `build()` 가 마스크를 다시 붙이면
  문서 순서상 뒤로 가고, SVG 는 나중 것이 위에 그려져 **점이 마스크에 묻힌다**
- **커서 CSS 는 `.detview` 자신에 붙는다.** `.detview .view` 라고 적었는데
  그런 요소가 없다(`#dv-<uid>` 가 곧 `.detview` 다) — 아무 일도 안 일어난다

## 6. 집계에 넣었다

`_SUMMARY_SQL` 에 UNION 을 더해 사람이 그린 개체를 센다. 안 넣으면 **화면에는
보이는데 목록 숫자에는 없는** 상태가 된다 — 사람이 찾아낸 규조각이 밀도에서
통째로 빠지고, 그 숫자가 보고서에 실린다.

**`n_auto` 에는 안 섞는다.** 엔진이 낸 것이 아니라 사람이 만든 것이라, "자동
검출 몇 개" 에 섞이면 엔진 성적을 잘못 읽는다.

세는 것은 **대표 이미지에서만** 이다(엔진 개체와 같은 규칙). 프레임에 그린 것은
안 세어진다는 뜻이고, 그것이 밀도의 정의(시야 하나에 판 하나)와 맞는다.

## 7. 남은 것

- **4단계 — 기존 마스크 고치기.** 점 끌기 · `geom_edited` · "엔진 것으로
  되돌리기". 키는 이미 기하에서 떼어 뒀다(067 §2)
- **5단계 — 전환.** 그 앞에 운영 반영이 있다: 0~3단계가 코드로만 있고
  마이그레이션은 사본에서만 돌렸다 (065 §9)
- `data.polygon_axis` 와 `shape._centroid_moments` 가 같은 계산을 두 번 적고
  있다. 주석으로 묶어 뒀지만 **규칙이 둘인 것은 이 저장소가 싫어하는 모양**이라,
  4단계 뒤에 `shape` 로 모은다
