# 검출 구분 라디오의 `?` 를 고친다 — 실행 #19 에 backend 를 채운다

2026-08-09. 검토자가 wap13-gc47 화면에서 라디오가 `◉ ?` 로 나오는 것을 보고
일시적인 것인지 물었다. 일시적이 아니었다.

## 왜 그랬나

검출 구분 라디오(◉ SAM / ○ YOLO)의 이름은 `Run.params["backend"]` 에서 온다
(`data.py` 의 `ENGINE_LABELS`, 없으면 `?`). P02 이전에 계산된 260729 세
슬라이드의 검출은 **ingest 실행 #19**(`params={"part": "detections"}`)로
들어와 backend 가 기록된 적이 없다 — sam2-전수 묶음에 소속만 되어 있었다.
그래서 그 실행이 대표로 잡히는 **wap13-gc47 116cm · 450cm · rs23** 셋에서만
라디오가 `?` 였다. 1차 검토 때부터 그랬을 것이나, 2차 검토가 이 슬라이드들을
다시 여느라 이제 눈에 띄었다.

## 무엇을

`backfill_run_backend.py` 를 만들어 규약대로 갔다 — 백업
(`manual/DiaRUGA_20260809_202019_before-backend-backfill.db`) → dbsync →
dry-run(대상이 #19 하나뿐임을 확인) → `--run 19 --backend sam2 --apply`.
채우고 나서 backend 없는 묶음 실행이 0 임을 확인했다.

값이 sam2 인 근거는 묶음 설명이다 — "260729 세 장은 07-30 에 계산해
#19(ingest)로 들여왔다" 고 sam2-전수 묶음 자신이 적고 있다.

## 버린 것

- **코드 폴백(묶음 이름에서 backend 추정)** — 화면에서 "모르는 것" 과
  "아는 것" 이 같아 보이게 된다. `?` 는 기록이 없다는 정직한 표시이고,
  기록이 실제로 있는 자리(사람이 안다)는 데이터를 채우는 것이 맞다.
  같은 이유로 `ENGINE_LABELS` 의 "여기 없는 것은 대문자로 그대로" 도 그대로 둔다
