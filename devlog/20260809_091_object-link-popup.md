# 091 — 같은 개체 묶기: 팝업과 저장 (P11 2단계)

2026-08-09 · [090](20260809_090_object-link-schema.md) 에 이어

## 한 일

마스크 우클릭 → **[⛓ 동일 개체 묶기]** → 팝업. 판(합성본·프레임)마다 닻 근처의
살아 있는 후보를 거리순 3개까지 펼치고, 하나씩 고르고(또는 "(없음)"), 별로
대표를 세우고 저장한다. 이미 묶인 마스크에서는 **[묶음 열기 (N장)]** 로 고치고
풀 수 있다.

- **후보 계산은 화면이 한다** — 새 조회 API 없음. 검토 화면이 프레임마다의
  검출을 이미 들고 있다(P09 캐러셀). 서버가 더한 것은 `_review_shot.rel`
  (다른 판의 크롭을 `/crop` 에 청하려면 경로가 필요하다) 하나다
- **`stateOf` 를 본다** (사용자 지적) — 서버가 준 초기 상태가 아니라 화면의
  지금 상태다. 방금 지운 마스크는 후보에서 빠지고, 방금 그린 마스크는 든다
- 저장은 `POST /d/<slug>/g/<gid>/link` — 묶음 하나 단위. `/review` 에 안 실은
  이유는 P11 §6 그대로다
- **서버가 다시 검사한다**: 시야 밖 이미지 · 없는 마스크 · **오검출로 지운
  마스크** · 대표 0/2개 · 멤버 1개 · 이미 다른 묶음에 속한 마스크(409).
  기하는 서버가 스스로 뜬다 — 화면이 보낸 것을 믿지 않는다
- 판이 하나뿐인 화면(`canLink`)과 읽기 전용 갈래에는 항목 자체가 없다

## 브라우저 시험이 잡은 것 — 미리 고르기가 되살아났다

미리 고르기(IoU ≥ 0.5 · 간격 ≥ 0.3)를 `render()` 안에 두었더니 **"(없음)" 으로
뺀 판을 다음 그리기가 도로 찍었다.** 고르기 상태가 바뀔 때마다 다시 그리는
화면에서, 그리기가 상태를 만들면 사람의 선택이 진다 — **그리기는 상태를 읽기만
해야 한다.** 열 때 한 번만 계산하는 것으로 옮겼다.

3겹(endpoint 시험 11개)은 이것을 못 잡았다 — 서버는 화면이 무엇을 보냈는지만
본다. 눌러 보는 시험이 아니면 안 잡히는 종류다(045 의 그 이야기).

## 시험 (이번에 15개 · 전체 372)
