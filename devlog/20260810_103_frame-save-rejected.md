# 103 — 프레임 판을 보고 한 교정이 통째로 거절되고 있었다

실사용 보고로 시작했다.

> "22119 프레임에서 같은 자리의 검출 둘을 오검출로 지웠어. 그 자리의 탈락분
> 하나를 되살려서 다른 프레임의 탈락분들과 묶었는데, 묶은 것은 잘 보이지만
> **맨 처음에 지운 두 개가 여전히 살아 있네.**"

## 무엇이었나

`/review` 저장이 **409 로 거절되고 있었다.** 서버가 한 말:

```
화면과 저장 대상이 어긋난다 — g0 의 현재 검출은 g000_Snap-22117-22119_focused
인데 Snap-22119 을 보냈다
```

`find_viewpoint` 는 `(slug, gid)` 로 시야를 짚고, `stem` 은 **덧문**으로만 쓴다 —
"이 화면이 이 시야의 것인가". 그 검사가 이렇게 생겼었다:

```python
cur = next((d for d in vp.detections.all() if d.is_current), None)
if cur is not None and Path(cur.image_path).stem != stem:
    return None, "화면과 저장 대상이 어긋난다 …"
```

**시야 하나에 현재 검출이 여럿이다** (P09 1단계 · 055) — 합성본에 하나,
프레임마다 하나. 그런데 그중 **아무거나 하나**를 집어 견줬다. 053 의 `.first()`
와 정확히 같은 자리다: *제약이 있다는 것과 조회가 그걸 쓴다는 것은 다르다*
를 이번엔 **"판이 여럿이라는 것과 검사가 그걸 아는 것은 다르다"** 로 다시 밟았다.

화면이 어느 판으로 서는지는 `group_detail` 이 정한다 — **합성본에 개체가 있으면
합성본, 없으면 개체가 가장 많은 판.** 그 규칙 자체는 옳다(빈 판이 먼저 열려
"검출이 없는 줄" 알게 되는 것을 막으려고 실측으로 정했다). 다만 그렇게 열린
**프레임 판의 stem** 이 검사에 걸렸다.

세어 봤다: 판이 여럿인 시야 **417개 중 11개가 프레임 판으로 열린다.** 그 열한
화면에서는 **어떤 교정도 저장된 적이 없다.**

| 슬라이드 | 시야 |
|---|---|
| `260805_bp09-0901_1` | g25 · g35 · g36 · g47 · g55 |
| `260803_bp09-0901` | g36 · g64 · g80 |
| `260731_am22-gc10b_261cm` | g7 |
| `260803_gc03-c1_816cm` | g11 |
| `260731_rs23-gc03_231cm` | g9 |

## 왜 아무도 몰랐나 — 고장이 셋이다

**1. 서버가 갈래를 안 밟았다.** `test_review_image.py` 는 "시야에 현재 검출이
여럿" 을 일부러 세워 두고 열두 가지를 확인하는 시험인데, **전부 `stem=합성본`
으로만 보냈다.** 086 과 같은 이야기다 — *URL 을 덮는 것과 갈래를 덮는 것은
다르다*. 화면이 실제로 보내는 값의 종류를 시험이 안 만들었다.

**2. 화면이 실패를 조용히 흘렸다.** 회색 글씨 한 줄:

```
아직 검토를 열지 않았습니다 — 저장하지 않았습니다
```

두 가지가 틀렸다. **크기** — 마스크는 화면에서 지워진 채로 남아 사람은 검토를
이어 갔다. 051 에서 배운 것과 같다: *되는 것처럼 보이는 것이 안 되는 것보다
나쁘다*. 그리고 **내용** — 409 를 전부 "아직 검토를 열지 않았습니다" 로 적고
있었는데 실제 이유는 다른 이야기였다. 사람은 안 겪은 문제를 찾으러 간다.

**3. 묶기는 그 문을 안 지난다.** `save_object_link` 는 제 검증을 따로 하고
`review_blocked`·`find_viewpoint` 를 안 거친다. 그래서 **한쪽은 거절, 한쪽은
200** 이 됐다 — 되살리기까지 정상으로 돌아서, 남은 화면은 "묶기는 됐는데 지운
것이 살아 있는" 모양이 됐다. 그 상태가 보고의 문장 그대로다.

## 고친 것

**서버** — 견줄 것은 **그 시야가 가진 판들**이다.

```python
stems = {Path(d.image_path).stem
         for d in vp.detections.all() if d.is_current and d.image_path}
if stems and stem not in stems:
    return None, "…"
```

덧문의 뜻은 그대로다("이 시야를 보고 보낸 것인가"). 어느 판에 앉힐지는 `image`
가 따로 짚고, 그 이미지에 현재 검출이 없으면 `save_review` 가 거절한다 —
**짚는 일과 확인하는 일이 갈려 있다.**

**화면** — 실패는 크게, 서버의 말로.

- 성공할 때까지 **안 사라지는 띠**(`.errbar.savefail`)를 세운다
- 서버가 준 `error` 를 그대로 옮긴다
- 저장에 성공하면 띠를 거둔다

> 띠를 **`.detview` 앞에 끼웠다가 096 시험이 잡았다** — 그 부모 `.detrow` 는
> 사진과 코멘트를 나란히 두는 flex 행이라, 띠가 한 칸을 차지해 사진을 밀어냈고
> 우클릭이 사진 밖으로 떨어졌다. 저장 상태 줄 다음의 **블록 자리**로 옮겼다.
> *브라우저 겹이 없었으면 "메뉴가 가끔 안 열린다" 로 남았을 종류다.*

**묶기** — 밀린 저장이 실패한 상태에서는 **묶지 않는다.**

```js
if (savePending) {
  throw new Error('앞선 교정이 저장되지 않았습니다 — 그 상태로 묶으면 …');
}
```

096 에서 팝업이 열릴 때 지연 저장을 밀어내게 했는데, **밀어낸 것이 거절당했을
때**를 안 봤다. 묶기는 "화면의 마스크가 DB 에 있다" 를 전제로 서므로, 그 전제가
깨졌으면 서지 않는 것이 맞다.

## 시험

**3겹** (`test_review_image.py`) — 프레임 판의 stem 으로 보낸 저장이 통하는가 ·
합성본 쪽이 여전히 통하는가 · **이 시야에 없는 판이면 여전히 거절하는가**.
첫 번째는 옛 코드로 되돌리면 선다.

**4겹** (`browser/test_save_failure.py`) — `/review` 만 409 로 막아 놓고(묶기는
안 막는다 — 실사용이 그 모양이었다) 셋을 본다: 띠가 서는가 · 서버의 말이
나오는가 · **그 상태에서 묶기가 거절되는가.** 고침을 걷으면 셋 다 선다.

전체 400개 통과.

## 남은 것

지금 열한 시야의 검토 기록은 **비어 있는 것이 맞다** — 사람이 무엇을 했든 서버가
받은 적이 없다. 되살릴 방법은 없고, 다시 검토하는 수밖에 없다.

`save_object_link` 가 `review_blocked` 를 안 보는 것은 그대로 뒀다. 지금은 화면
쪽에서 막고 있고(읽기 전용·저장 실패), 서버 쪽 문을 하나로 모으는 것은 **문
자체를 다시 그리는 일**이라 따로 세운다.
