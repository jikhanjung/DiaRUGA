# 146 — AlgaeBase 300종을 더 먹인다 (19~24일차)

901~1200번이 50종씩 여섯 벌로 들어왔다. 누적 **1,254/1,845** 이고 **1~1200 은
빈 자리가 없다**(그 위 54개는 148건이 순번을 건너뛰며 골라 간 것이다).
남은 것 **591**.

전과 같이 파일 이름이 CP949 라 이 자리에서 깨져 보여서, ASCII 로마자 이름으로
`names/algaebase/` 에 옮겼다(`algaebase_day19_0901-0950.md` ~
`day24_1151-1200.md`). 내용은 UTF-8 그대로다.

## 1. 학명 자리에 독일어 낱말이 있다

이 구간에서 **`검색 안 함` 이 다섯 몰렸는데 전부 같은 꼴이다.**

```
# 906  Hantzschia vermochte    "~할 수 있었다"
# 909  Hemiaulus eingereiht    "편입된"
# 910  Hemiaulus gerechnet     "계산된"
# 940  Liradiscus erinnere     "기억하다"
# 950  Mastogloia bildet       "형성한다"
```

속명은 멀쩡하고 **종소명 자리에 독일어 동사가 앉아 있다.** Schmidt Atlas 가
독일어 도감이라 본문 낱말이 색인의 종소명 자리로 흘러든 것이다 — OCR 이 글자를
틀리게 읽은 것(`Cyrosigma`·`troplca`)과 **갈래가 다르다.** 앞엣것은 교정하면
이름이 나오지만 이것은 **처음부터 이름이 아니다.**

`#910 Hemiaulus gerechnet` 은 15일차 `#730 Denticula gebracht` 와 같은 낱말
꼴이고, `#1023 Melosira pegs` 는 영어다. 적어 오는 쪽이 이것을 알아보고
**조회를 안 하고 사유를 적어 왔다** — 없는 이름을 등록부에 묻는 헛일을 막았다.

**지우지는 않았다.** `index_remove` 의 규칙이 넓어 진짜 학명 일곱을 지울 뻔한
자리가 121 에 있다(종소명이 짧다고 지우지 않기로 한 것과 같은 줄이다). 색인
표제어는 그대로 두고 **대조표가 "이름이 아니다" 라고 말한다.**

## 2. `확인 필요` 가 늘어나는 이유는 하나다

55 → **69** 로 열넷 늘었고 **그중 열둘이 동명이종**이다. 저자마다 목적지가
갈리는데 도감이 저자를 안 적어 판단을 못 하는 자리다.

**이것은 AlgaeBase 에 다시 물어도 안 풀린다.** 같은 답이 온다 — 필요한 것은
도감 원문의 저자 표기이거나 **어느 판을 택할지 정하는 규칙**이다. 한 줄은 이미
그렇게 추론해 뒀다("Schmidt Atlas 출처면 그 판").

134 에서 "변종만 걸리는 자리를 그대로 넘기고 있다" 고 적었는데 **한 겹 아래가
이것이었다.** 적는 사람의 문제가 아니라 자료에 없는 것을 묻고 있는 것이다.

## 3. 발음부호는 이번에 안 걸렸다

134 가 901번 뒤에 일곱이 남았다고 적었고 이 구간에 `#1069 Navicula aérophila`
가 들어 있었는데, **표가 `é` 를 그대로 적어 왔다**(비고에 "도감 표기의
accent(é)는…" 이라고 짚기까지 했다). `restore_diacritics` 가 되돌린 것은
#637 하나뿐이고 그것은 지난번 것을 다시 먹인 것이다.

여섯이 남았다 — #1381 · #1436 · #1607 · #1608 · #1774 · #1804.


같은 이름을 두 표가 다르게 말한 것은 누적 47건인데 **이번 구간에서 난 것은
둘뿐이다**(#986 · #1106). 148건과 겹치는 자리를 이미 대부분 지났다.

번호 검산은 통과했다. 대조표는 `AlgaeBase`·`AlgaeBase비고` 두 칸에서 295줄이
바뀌었고 **나머지 27개 칸은 한 글자도 안 건드렸다** — 사본
(`worms_master_20260814.tsv.bak-20260823-algaebase`)과 대조해 확인했다.

색인 표시(`annotate_index.py`)를 다시 붙였고 `〔…〕` 를 걷어 낸 본문이 사본과
같은 것을 확인했다. `atlas/*.json` 은 **`source_sha256` 세 줄만 바뀌었다** —
표시가 달라져도 항목이 안 달라지면 그렇다. DB 반입은 안 걸린다.

## 5. `temp/` 를 비웠다

꾸러미가 오는 자리라 CP949 이름이 열둘 쌓여 있었다. **내용이 같은 사본이
`names/algaebase/` 에 있는 것만** 지웠다(sha256 대조). 윈도우가 남긴
`*:Zone.Identifier` 도 걷었다 — 자료가 아니다.

`names/worms/*.bak-*` 와 `names/index_backup_*` 는 **그대로 뒀다.** 되돌릴 때
쓰는 자리이고, 이름으로 정렬해 앞에서부터 자르는 실수를 CLAUDE.md 가 이미
한 번 적어 두었다.
