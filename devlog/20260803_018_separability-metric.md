# 그룹핑 신뢰성 지표를 두 번 고쳤다 — 꼬리를 재고 있었다

**작성일** 2026-08-03
**앞선 기록** [012](20260731_012_grouping-to-db-and-review-gate.md) (지표를 처음 만든 곳)

## 판정이 두 번 뒤집혔다

같은 슬라이드를 두고 판정이 이렇게 움직였다.

| | AM22 25cm | AM22 261cm |
|---|---|---|
| 처음 기준 (`gap ≥ 0.05`) | 통과 | 통과 |
| 올린 기준 (`gap ≥ 0.2`) | **미심쩍음** | 통과 |
| **사람이 눈으로 확인** | **정상** | — |
| 고친 기준 (겹침) | **정상** | **표본 부족** |

가운데 두 줄이 이 기록의 이유다. **지표가 정상인 것을 잡았고, 사람이 그것을
바로잡았다.**

## 무엇을 재고 있었나

처음 만든 지표는 이랬다.

```
여유 = min(그룹 안 상관) - max(경계 상관)
```

"같은 시야로 묶인 사진끼리는 닮고, 시야가 바뀌는 경계에서는 안 닮는다. 두 무리가
벌어져 있어야 임계값 0.55 가 뜻이 있다" — 취지는 맞다. 문제는 **양 끝값으로 쟀다는
것**이다.

최솟값·최댓값은 꼬리다. **표본이 많을수록 나빠진다.**

```
AM22 261cm   그룹 안 쌍  1개  →  여유 0.664  (만점)
AM22 25cm    그룹 안 쌍 34개  →  여유 0.100  (걸림)
RS23 369cm   그룹 안 쌍 338개 →  여유 0.554
```

261cm 은 27개 시야 중 26개가 단독이라 **검증할 쌍이 하나뿐**인데 만점을 받았다.
25cm 은 34개 중 최악 하나로 판정됐다. 지표가 거꾸로 상을 주고 있었다.

## 실제 분포를 보니 겹침이 없었다

```
AM22 25cm
  그룹 안 34쌍:  0.594 0.623 0.629 0.723 │ 0.986 …… 0.998   ← 30쌍이 0.986 이상
  경계   25쌍:   …… 0.423 0.475 0.494
                              └─ 0.494 ~ 0.594 사이는 완전히 비어 있다
```

**겹치는 쌍이 하나도 없다.** 두 무리가 깨끗하게 갈려 있고, 그 사이 어디에 임계값을
둬도 결과가 같다. 내가 양 끝만 빼서 "여유 0.1" 이라 부른 것이다.

낮은 네 쌍(0.594~0.723)이 있긴 하다. 초점을 크게 돌린 장이거나 스테이지가 살짝
흔들린 장일 것이다. 그래도 경계(최대 0.494)보다는 확실히 높다 — 같은 시야가 맞다.

## 고친 기준 — 판정과 정보를 가른다

**판정은 겹침으로만 한다.**

```python
overlap = (그룹 안인데 어떤 경계보다 낮은 쌍) + (경계인데 어떤 그룹 안보다 높은 쌍)
```

`overlap > 0` 이면 임계값을 어디에 둬도 잘못 묶이는 쌍이 생긴다. 그때만 사람을
부른다. **여유(margin)는 기록만 한다** — 좁아도 겹치지 않으면 정상이다.

여기에 하나를 더했다. **표본이 모자라면 모른다고 말한다.**

```
AM22 261cm: 그룹 안 쌍 1개 → "판단할 표본이 모자란다"
```

정상일 수도 있지만 *정상임을 확인했다* 고는 할 수 없다. 모르는 것을 통과로
처리하면 지표가 있으나 마나다. 이건 처음 기준에서도 놓치고 있던 구멍이다.

새 기준으로 다시 판정한 결과:

| 슬라이드 | 겹침 | 여유 | 그룹 안 쌍 | 판정 |
|---|---|---|---|---|
| AM22 25cm | 0 | 0.044 | 34 | 정상 (여유 좁음) |
| AM22 261cm | 0 | 0.219 | **1** | **확인 필요 — 표본 부족** |
| RS23 231cm | 0 | 0.182 | 28 | 정상 |
| RS23 369cm | 0 | 0.204 | 338 | 정상 |

## 무엇을 배웠나

**꼬리 통계는 표본 수에 딸려 간다.** 슬라이드마다 시야 수도 장수도 다른데 최솟값
하나로 비교하면, 적게 찍은 슬라이드가 유리해진다. 지표를 만들 때 "표본이 두 배면
이 값이 어떻게 움직이나" 를 먼저 물었어야 했다.

**"좁다" 와 "틀렸다" 는 다르다.** 여유가 적은 것은 임계값을 옮길 여지가 적다는
뜻이지 결과가 틀렸다는 뜻이 아니다. 둘을 한 기준으로 묶으면 정상인 것을 세운다.
자동 처리가 정상인 것을 자꾸 세우면 사람이 경고를 안 읽게 되고, 그러면 진짜
문제도 놓친다.

**사람의 확인이 지표를 고쳤다.** 015 의 배율 사고와 같은 모양이다 — 그때는 사람이
"조흔이 안 보인다" 고 했고 계측이 틀렸다. 이번에는 사람이 "그룹핑 잘 됐다" 고 했고
기준이 틀렸다. 두 번 다 화면을 본 쪽이 맞았다.

  것부터** 새 기준이 걸린다

  검토하면서 보면 드러난다
