# 121 — 학명 대조를 한 표로 모으고, 색인에 붙인다

2026-08-14 · `work/20260814-sclee` · P15(도감을 DB 에 넣는 계획)의 앞 단계

08-13 에 색인 학명을 WoRMS 에 물어 둔 것을 정리해 색인까지 반영했다. 도구 넷이
생겼다 — `triage_worms.py`·`worms_db.py`·`annotate_index.py`·`ingest_algaebase.py`.
**세 번 "근거 없이 지우려던 것" 을 잡았고, 그때마다 규칙을 근거로 바꿨다.**

## 1. 조회 결과가 두 벌이었다 — 도감 출처를 잃은 쪽이 있었다

같은 폴더에 두 갈래가 있었다. `harvest_worms.py` 가 낸 `worms_20260813.json`
(색인 이름 1,845개, **이름마다 `atlases` 로 도감 출처를 들고 있다**)과, 그것을
신뢰도로 가른 **표 다섯**(4,003개)이다. 겹치는 것은 1,784개뿐이고 **표 다섯에는
도감 출처 칸이 없었다.** 색인에 없는 이름이 2,219개 섞여 있어(속 단위 훑기의
산물) 그대로는 반입 수를 못 센다.

**출처를 다시 만들지 않고 JSON 에서 이었다.** `species_1845.tsv` 도 같은 정보를
갖고 있지만 그것도 JSON 에서 나온 사본이라 한 겹 멀다 — 원본을 본다.

나온 것이 `worms_master_20260814.tsv` 4,064줄(4,003 ∪ 색인 61)이다. **아무것도
안 버렸다.** 지울 것으로 판정된 것도 줄이 남고 `재판정` 칸이 왜 그런지를 말한다.
지운 뒤에 되돌아보려면 **지운 것이 어디 있는지부터** 알아야 한다.

## 2. 지우는 규칙 둘이 넓어 진짜 학명 7건을 지울 뻔했다

`index_remove` 196건이 "눈으로 한 번에 확인된다" 고 적혀 있었는데, 전수를 WoRMS
에 다시 물었더니 일곱이 실재했다.

```
Amphora schmidtii      Grunow                  accepted    418256
Campylodiscus schmidtii · Cymbella schmidtii · Auliscus schmidtii
Aulacodiscus schmidtii · Triceratium schmidtii
Planktoniella sol      (C.G.Wallich) Schütt    unassessed  196815
```

규칙 둘이 원인이었다.

- **`schmidt` 가 들어가면 저자명 조각으로 봤다.** `-ii` 로 끝나는 것은 Schmidt 를
  기린 정당한 종소명이다. OCR 부스러기는 `sehmidt`·`schmidts`·`scamidt` 쪽이다
- **종소명이 짧으면 잘린 낱말로 봤다.** `sol`·`ovum`·`flos`·`major` 가 전부
  정당하다 (사용자 지적)

**같은 실수를 내가 반복하고 있었다.** `absent` 315건을 가를 때 "5자 이하" 를 그대로
베껴 써서 77건을 쓰레기로 밀어 놨었다. 길이를 근거에서 뺐다 — **잘렸다고 말하려면
무엇이 잘렸는지 짚어야 한다.** 같은 속에 그 종소명으로 시작하는 **실재하는** 더 긴
이름이 있을 때만 세우고, 근거 칸에 그 이름을 적는다.

```
Aulacodiscus marg  → Aulacodiscus margaritaceus, Aulacodiscus marginatus 의 앞부분이다
```

증거가 잡힌 것은 31건뿐이고 61건이 사람에게 돌아왔다(`Brightwellia major`·
`Epithemia curta`·`Navicula ovum`). 변종 18건도 지울 것이 아니라 판단 대상으로 옮겼다.

**세 번째로 같은 실수를 할 뻔했다.** "종소명이 다른 속에 있으면 속 표기를
의심한다" 를 넓게 잡아 57건이 걸렸는데 `Brightwellia major` → `Melosira/Navicula/
Pinnularia major` 같은 것이었다. `major`·`vulgaris`·`affinis` 는 흔한 라틴어라
근거가 못 된다 — **다른 속 하나에만 있을 때**로 좁혀 26건이 됐다.

## 3. "담수·화석이라 빠졌다" 는 실측으로 안 선다

`absent` 의 245건을 왜 없는지로 가르려 했다. 처음 세운 가설이 서식지였는데
도감별 적중률이 **Schmidt 89.1% · 한국(담수조류 도감) 90.5% · 동남극 93.9%** 로
거의 같다. DiatomBase 가 담수를 덮고, 화석은 `extant_only=false` 로 들어온다(119).
**서식지로는 못 가른다.**

가르는 것은 속이었다. 속 62개를 묻고(없으면 TAXAMATCH 로 되짚어) 넷으로 갈랐다.

| | |
|---|---|
| 속은 있는데 종이 없다 | 180 |
| 화석속이라 종이 덜 담겼다 | 34 |
| 속 표기를 의심한다 | 26 |
| **속 표기가 어긋난다** | **5** — `Raphoneis`→`Rhaphoneis`[phonetic] · `Terpsinoe`→`Terpsinoë`[exact] |

`Raphoneis`→`Rhaphoneis` 는 `harvest_worms.GENUS_FIX` 에 **이미 손으로 적혀
있던 것**이다 — 표 다섯을 만든 쪽이 그 보정을 안 걸었다. 손으로 적어 두는 대신
물어서 얻게 바꿨다.

**화석은 절반만 성립한다.** 종은 들어오지만 화석속은 종까지 다 등재돼 있지 않다.
그래서 속의 `isExtinct` 를 근거로만 쓰고 **그 이름이 진짜라는 뜻으로는 안 쓴다** —
같은 칸에 `Trinacria halb`(독일어) 같은 부스러기가 들어온다.

## 4. 내려받은 WoRMS 는 규조의 38% 만 담고 있다

사용자가 허가받아 DwC-A(2026-07-01, 64 MB)를 받아 왔다. 596,103줄 중 규조가
11,529줄이고 **변종 1,712 · 품종 377** 이 함께 있다 — REST 는 종까지만 답했다.

**그런데 REST 로 확정한 3,153건의 38.1% 밖에 없다.** 처음에 `eml.xml` 의
*"catalogue of marine names"* 를 보고 "해양 전용판" 이라 적었는데 **틀렸다** —
덤프에 담수 전용 규조가 175건 있다(*Asterionella formosa*·*Fragilaria construens*).
내려받기 안내의 한 줄이 실제 이유였다(사용자 확인):

> data originating from AlgaeBase is excluded, since the license does not allow redistribution

규조는 그 비중이 큰 분류군이다. **다시 신청해도 이 자리는 안 채워진다** — 그
레코드에 자동으로 닿는 길은 REST 하나뿐이다. 그래서 `--against` 는 **걸린 것만
적고 안 걸린 것은 빈칸으로 둔다.** 판정을 뒤집지 않는다.

**칸 이름을 `덤프(해양판)` → `덤프(20260701)` 로 고쳤다.** 사실과 어긋나는 이름을
두면 나중에 그 칸을 잘못 읽는다.

얻은 것 셋 — 변종 13건은 REST 가 답한 적이 없고, 되살린 7건 중 5건이 독립으로
확인되며(못 걸린 둘은 담수라 빠진 것이다), **"색인 쓰레기" 238건은 덤프에도
0건**이라 지우기 전 교차 확인이 됐다.

## 5. 색인에는 붙이기만 한다

도감 셋의 표제어 **2,059개 전부**에 `〔WoRMS 20260814 · …〕`를 달았다.
**지우거나 갈아치우지 않았다.** 이유가 셋이다.

- `Diadiction/README.md` 가 **색인 텍스트를 그대로 인용하지 말라**고 못 박고 있다
- 이 파일은 **119 에서 속명 복원 버그가 나온 파일이다.** 후보가 33개 더 남아 있다
- 이 문서의 2절이 그대로 이유다 — 근거 없이 지우는 규칙을 오늘만 세 번 봤다

이름을 뽑는 규칙은 `harvest_worms.read_names` 에서 **가져다 쓴다.** 두 벌이 되면
붙는 자리가 어긋난다.

**이명법이 안 나오는 표제어 11개도 표시했다.** 조용히 건너뛰면 성격이 아주 다른
둘이 똑같이 "안 붙은 줄" 로 보인다 — 도판집의 **속 수준 동정** 10개
(`Delphineis sp.`)는 정상이고, `389. Synedra cyclopиm` 은 종소명에 **키릴 문자
`и`** 가 섞인 OCR 손상이라 고쳐야 할 자리다. 이런 것은 이름으로 조회하면 영영
안 걸린다.

**`--strip` 왕복을 검사하다 둘을 잡았다.** 표시를 `\s*` 로 걷으면 **한국 색인이
줄바꿈으로 쓰는 줄 끝 공백 두 칸**까지 사라지고, 머리말 블록은 넣을 때와 뺄 때
모양이 달라 빈 줄이 남았다. 지금은 세 파일 모두 사본과 바이트 단위로 같아진다.

## 6. AlgaeBase 300종이 들어왔다 — 앞으로도 300종씩

사람이 브라우저로 조회해 온 표 여섯 벌(50종씩)이다. AlgaeBase 는 Turnstile 때문에
자동으로 못 연다(`harvest_worms.py` 머리말). **앞으로도 같은 양식으로 온다.**

| 그대로 유효 | 이명 → 갈아탄다 | AlgaeBase 에 없다 | 그 밖 |
|---|---|---|---|
| 178 | **81** | 19 | 22 |

**번호를 검산하고 어긋나면 멈춘다.** 표는 `species_1845.tsv` 의 줄 번호로 적혀
오는데 그 파일이 다시 만들어지면 번호가 밀린다 — 엉뚱한 이름에 판정이 붙는 쪽이
안 들어가는 것보다 나쁘다.

**통용명 칸을 정확히 일치시키려 들면 샌다.** `(그대로 유효, 단 循環 이명 구조)`·
`미확인(OCR 오독)`·`검색 안 함`·`—` 처럼 꼬리가 붙어 온다. 낱말이 들어 있는지로
가르고 **원문은 언제나 비고에 남긴다.**

**AlgaeBase 가 주 출처라 색인 표시도 그것을 앞세운다**(방침 08-12). 다만
**엇갈렸다는 사실은 지우지 않는다** — 17건이 그렇고, `Actinoptychus undulatus` 는
AlgaeBase 가 `Actinoptychus senarius`, WoRMS 가 `Actinocyclus senarius` 로 **속이
다르다.**
