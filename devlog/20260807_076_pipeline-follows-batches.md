# 076 — 파이프라인을 묶음의 뜻에 맞춘다 (배포 전)

2026-08-07 · v0.8.0 / 파이프라인 v0.5.0 을 굽기 직전

배포하려다 물음 하나에서 멈췄다 — **"파이프라인도 관련 수정 끝난 거지?"**
안 끝나 있었다. P10 이 `is_current` 의 뜻을 좁혔는데(그 묶음 안에서 최신)
`segment_diatoms.py` 는 옛 뜻(뷰어가 볼 것) 그대로 돌고 있었다.

`refilter.py`·`batch_runs.py`·`prune_detections.py` 는 P10 때 함께 고쳤다.
**검출을 만드는 쪽만 남았다.**

## 고친 것 넷

### 1. `is_current` 인계가 묶음을 안 가렸다 — **파괴적이다**

```python
old = vp.detections.filter(is_current=True)          # 옛 코드
Detection.objects.filter(pk__in=…).update(is_current=False, superseded_by=det)
```

이행(0027) 뒤에는 `yolo-3차` 의 검출 1,799개도 `is_current` 다. 그 상태에서
SAM2 를 한 번 더 돌리면 **그 시야의 YOLO 현재 표시가 꺼지고 `superseded_by` 가
묶음을 가로질러 걸린다.** 나중에 그 묶음으로 갈아타는 날 화면이 빈다.

같은 묶음 안에서만 인계하도록 고쳤다. 뷰어가 무엇을 보는지는
`RunBatch.for_review` 가 정하므로 **다른 묶음을 건드릴 이유가 애초에 없다.**

### 2. "이미 검출한 시야" 관문도 묶음을 안 가렸다

`vp.detections.filter(is_current=True).exists()` 로 걸렀다. 이행 뒤에는
YOLO 가 덮은 시야가 전부 "이미 했다" 가 되어 **새 묶음으로 전수 재검출이 아예
안 돈다.** 앞으로 하려는 일이 정확히 그것이다.

**이미지마다, 그리고 이 묶음 안에서** 보도록 고쳤다. 이미지 단위로 바꾼 것은
3번 때문이다 — 합성본 하나가 되어 있다고 프레임 여섯 장이 통째로 빠지면 안 된다.

### 3. 사람의 교정이 있는 시야를 통째로 건너뛰었다

관문이 있는 이유는 재검출이 `is_current` 를 옮기고 교정을 다시 맺기 때문인데,
**둘 다 묶음 안의 일이 됐다.** 다른 묶음으로 돌리는 것은 사람의 판단을 건드리지
않는다 — 오히려 그것이 회차의 목적이다(교정을 정답 삼아 새 회차를 견준다).

안 가리면 **검토를 마친 시야일수록 새 회차에서 빠진다.** 가장 값진 자리가
빠지는 것이다. 이 묶음의 교정만 보도록 고쳤다.

### 4. `--slide` 가 시야마다 이미지를 한 장만 골랐다

합성본이 있으면 합성본, 없으면 가장 선명한 프레임. **SAM2 의 모형이다.**
YOLO 는 원본 프레임을 보므로 합성본 + 프레임 전부에 돌려야 하는데 그 길이
없었다 — 070 에서 파일 목록을 손으로 만들어 돌린 이유가 이것이다.

`--all-images` 를 뒀다. 기본은 지금까지와 같다(폴러가 그 길로 돈다).

## 가중치

두 가지를 함께 고쳤다.

- **기본값이 없는 경로를 가리키고 있었다** — `runs/segment/…/weights/best.pt`
  는 학습 산출 자리이고 이 기계에 없다. 실제 자리는
  `/data3/DiaRUGA/models/11m-v1seg-1280.pt` 다. `--backend yolo` 를 그냥
  부르면 "가중치가 없다" 로 죽었다. 상대경로를 **자료 뿌리 아래**에서 찾도록
  했다(작업 디렉토리가 `/app` 이라 저장소 안을 가리켰다)
- **무엇이 이 묶음을 냈는지를 `Run.params.weights` 에 남긴다** — 경로·크기·
  mtime·sha256(앞 16자). 회차를 돌리면 가중치가 여럿이 되고, 이름만 남기면
  같은 이름으로 다시 학습한 파일을 못 가른다

**이름 규칙**: `<모형>-<자료판>-<입력크기>[-<날짜>].pt`. 새로 학습할 때마다
날짜를 붙여 **덮어쓰지 않는다** — 덮어쓰면 옛 묶음의 근거가 사라진다.
지금 있는 `11m-v1seg-1280.pt` 는 그대로 두었다(이름을 바꾸면 그것을 가리키는
기록이 어긋난다). 다음 회차부터 날짜를 붙인다.

## 확인

시험이 못 잡는 자리다 — `segment_diatoms.py` 는 `cv2`·`torch` 를 최상위에서
임포트해 뷰어 시험 안으로 못 들어온다. **CLAUDE.md 가 정한 방법으로 했다:
이행한 사본에 파이프라인 컨테이너를 붙여 먼저 돌려 본다.**

오늘 백업 → 0025~0028 → 검토 대상을 `sam2-전수` 로(운영 이행 직후와 같게) →
저장소를 `/app` 에 물려 새 코드로 실행.

```
검출 대상 77개 (합성본+프레임)        ← 시야 30개. 한 장씩이면 30개였다
검출 4개 · 개체 24개 · Run #259

묶음별 is_current
   sam2-전수      508   for_review=True    ← 안 건드렸다
   yolo-3차     1,799   for_review=False   ← 안 건드렸다
   yolo-연습        4   for_review=False   ← 새 묶음이 제 안에서 current

superseded_by 가 묶음을 가로지르는 행: 0건
교정: 7,472 행 그대로
Run.params.weights: {path, bytes, mtime, sha256:d9e20a2654705659}
```

다시 돌리니 `이 묶음에서 이미 검출한 이미지 4개를 건너뛴다` — 이어 돌리기가
이미지 단위로 선다. `check_db.py` 도 사본에서 "앞뒤가 맞는다".

**옛 코드가 실제로 깨지는 것은 안 돌려 봤다.** 옛 관문(3번)이 먼저 걸러 인계
자리까지 가지도 않는다 — 되살려 보이려면 교정 없는 시야를 따로 만들어야 하는데,
새 동작을 사본에서 직접 확인했으므로 거기서 멈췄다. 못 본 것을 봤다고 적지 않는다.
