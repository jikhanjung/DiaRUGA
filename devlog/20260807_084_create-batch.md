# 084 — 묶음을 화면에서 만든다

2026-08-07 · 083 의 남은 자리

## 문제

묶음은 **파이프라인이 `--batch` 로 처음 쓸 때** 생겼다. 그래서 순환이 하나
있었다:

```
조리법을 적으려면  →  묶음이 있어야 하고
묶음을 만들려면    →  검출을 한 번 돌려야 한다 (몇 시간)
```

"다음 회차를 이렇게 돌리겠다" 를 **미리 적어 둘 수가 없었다.** 083 이 조리법
폼을 만들었지만 그것을 적을 대상이 아직 없는 묶음에는 못 붙였다.

## 한 일

운영 화면(`/manage/ops/`)에 **새 묶음** 칸을 뒀다. 이름 · 메모 · 그리고
**조리법을 베껴 올 묶음**.

**베끼기가 요점이다.** 새 회차는 대개 지난 회차에서 **가중치만 바뀐 것**이다.
빈 칸에서 시작하면 배율·크기 문턱 같은 것을 옮겨 적다가 틀리고, 틀린 값은
검출이 다 끝난 뒤에야 드러난다.

**`weights_guessed` 는 안 물려준다.** 0029 이행이 추측으로 채운 가중치에 붙는
표시인데, 베낄 때 함께 가면 **경고가 영영 따라다닌다.** 새 묶음의 가중치는
사람이 다시 보는 것이 맞다.

## 만드는 것으로 자료가 생기지는 않는다

이것을 화면과 응답에 **둘 다** 적었다.

- 새 슬라이드는 폴러가 채운다 (079 의 조리법 순서대로)
- **이미 있는 슬라이드는 사람이 한 번 돌려야 한다**

전수 실행을 화면에서 시작하게 만들지 않은 이유는 하나다 — **몇 시간짜리 GPU
작업이라 버튼 하나로 조용히 시작하면 안 된다.** 진행 상황을 보여줄 자리와
멈추는 길이 함께 있어야 하고, 그것은 이 화면이 아직 갖고 있지 않다. 대신
**돌릴 명령을 화면이 적어 준다.**

## 시험

333개 전부 통과. 이번에 7개 추가.

- 만들어진다 · **조리법을 갖고 태어나지 않는다** · 만들자마자 검토 대상이 되지 않는다
- 이름이 없거나 겹치면 거절한다
- 베껴 온다 · **추측 표시는 안 물려준다**
- **만들었다고 검출이 생기지는 않는다** (응답이 그렇게 말하는지까지)
- 조리법을 적으면 실행 계획에 오른다

되살려 확인했다 — 같은 이름 막기를 빼면 1개, 추측 표시 걷기를 빼면 1개가 깨진다.

그리고 미리보기에서 **실제로 눌러** 만들어 봤다: `yolo-3차` 의 조리법을 베낀
`yolo-4차` 가 조리법 폼과 실행 계획에 함께 나타났고, 순서는 검토 중인
`yolo-3차` → `yolo-4차` → `sam2-전수` 였다(최근 것부터).

## 남은 것

- **지우는 길은 안 뒀다.** 묶음을 지우면 그 아래 검출이 통째로 간다 —
  `drop_batch.py` 가 명령줄에 있고, 그 정도의 문턱이 맞다
- 새 묶음을 **기존 전체에 돌리는** 것은 여전히 손으로 한다 (위 이유)
