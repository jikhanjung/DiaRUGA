# 039 — 파편을 제 본체와 같은 색 가족으로

2026-08-04

038 에서 색을 "빈 색상환 자리를 찾아 채우는" 방식으로 골랐다. 그렇게 여섯이
되고 나니 문제가 드러났다 — **색이 분류 체계를 반영하지 않는다.**

```
봉상      파랑 217°     원형      초록 150°
봉상 파편 보라 258°     원형 파편 청록 180°
```

넷을 따로 외워야 했다. 화면에서 마스크를 보고 "이건 봉상 쪽인가 원형 쪽인가"
가 안 읽힌다 — 본체와 파편은 **같은 것의 온전한 것과 깨진 것**인데 색은 그
관계를 하나도 말해 주지 않았다.

## 색상은 본체를 따르고, 진하기로 가른다

```
봉상       70,140,255   진한 파랑
봉상 파편  120,195,255  옅은 파랑   ← 같은 217°
원형       60,220,120   진한 초록
원형 파편  140,235,170  옅은 초록   ← 같은 150°
```

이제 **색상이 "무엇인가", 진하기가 "온전한가"** 를 말한다. 축이 둘로 갈라져서
분류가 늘어도 규칙이 그대로 선다.

**너무 옅게는 안 잡았다.** 마스크는 밝은 규조각 위에 42% 로 얹힌다. 흰색에
가까워지면 *마스크가 안 걸린 것*과 구분이 안 된다 — 파스텔로 밀었다가 그
지점에서 되돌렸다. 가장 어두운 성분을 120·140 위로 두어 색은 확실히 남기되
본체보다 연하게만 했다.

## 배지도 마스크 색을 따라간다

파편 둘이 배지 키 `frag` 하나를 같이 쓰고 있었다 — **색으로 가를 수가 없다.**
`rodf`·`rndf` 로 갈랐다.

**원형의 배지 키가 `on` 이었던 것도 고쳤다.** `on` 은 "합성됨"·"N개 검출" 이
쓰는 일반 배지다. 원형이 거기 얹혀 초록으로 나오던 것이 우연히 맞아 보였을
뿐, 일반 배지 색을 바꾸면 원형이 따라 바뀌는 상태였다. `rnd` 로 떼어냈다.

봉상 배지도 `var(--accent)`(하늘색)여서 제 마스크(파랑)와 달랐다. 넷 다
마스크 색으로 맞췄다 — **사진에서 파랗던 것이 목록에서도 파랗다.**

## 표와 CSS 가 어긋나지 않는지 기계로 본다

색이 `ClassDef.color` 와 `base.html` 두 곳에 있다(038 의 미해결 항목).
손으로 맞추는 값이라, 키마다 CSS 규칙에서 rgb 를 긁어 표의 값과 대조했다:

```
OK round        color=60,220,120   CSS=['60,220,120']   badge=.rnd
OK round_frag   color=140,235,170  CSS=['140,235,170']  badge=.rndf
OK rod          color=70,140,255   CSS=['70,140,255']   badge=.rod
OK rod_frag     color=120,195,255  CSS=['120,195,255']  badge=.rodf
OK eucampia     color=255,110,190  CSS=['255,110,190']  badge=.euc
OK chaetoceros  color=150,225,75   CSS=['150,225,75']   badge=.cha
```

**이 대조를 손으로 한 번 하고 마는 대신 `check_db.py` 에 넣을 자리다** —
색을 표에서 뿜어내기(TODO) 전까지는 어긋날 수 있는 값이다.

## 덤: 색상환이 넓어졌다

보라 258°·청록 180° 가 비었다. 038 에서 "색이 여덟을 넘으면 짜내는 일이 된다"
고 적었는데, 가족으로 묶으면서 오히려 자리가 늘었다 — 새 속은 색상 축에서
고르고, 그 파편이 생기면 진하기 축으로 내려가면 된다.
