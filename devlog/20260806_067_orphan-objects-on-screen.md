# 067 — 후보 없이 교정만 남은 개체를 그린다 (P09 2단계)

2026-08-06. 계획은 [P09](20260806_P09_mask-editing.md), 앞 단계는
[065](20260806_065_review-belongs-to-batch.md)·[066](20260806_066_review-per-image.md).

화면이 그리는 근거를 `Candidate` 에서 **`Candidate ∪ ObjectReview`** 로 넓혔다.
시험은 155개다.

---

## 1. 화면 기능인 줄 알았는데 자료 보호였다

P09 를 쓸 때는 이 단계를 **3단계(그리기)의 전제**로만 적었다 — 사람이 그린
마스크는 후보가 없으니 그리는 길을 먼저 내야 한다는 것이었다. 그리고 "지금 고아가
0이라 당장 보여줄 것이 없다" 고 5.1 에 적어 두었다.

**틀렸다.** 고치기 전에 갈래를 재현해 보니 이렇다.

```
FAIL test_화면이_보낸_그대로_저장해도_고아가_남는다
     AssertionError: False is not true : 검토 완료를 누른 것만으로 고아 교정이 사라졌다
```

`_apply_review` 가 후보만 도니까 고아가 안 그려지고 → 화면은 자기가 아는 키만
보내고 → `save_review` 의 마지막 줄이 payload 에 없는 키를 지운다.
**사람이 아무것도 안 해도 사라진다.**

017·027·053 과 같은 자리인데 다른 점이 하나 있다 — **엉뚱한 화면이 아니라 제
화면에서 난다.** 지금 고아가 0이라 안 밟힐 뿐이고, 재검출 한 번이면 생긴다
(실측: 재검출에서 exact 26 · iou 40 · 고아 1).

**그래서 순서가 이것이 맞았다.** 그리기(3단계)를 먼저 만들었으면 사람이 그린
개체가 첫 저장에 사라지는 것을 보고서야 알았을 것이다.

---

## 2. 키를 기하에서 다시 만들면 안 된다

화면의 `keyOf(c)` 는 `bbox_xywh` 를 이어 붙여 키를 만든다. 서버의 `cand_key()` 도
같다. **지금까지는 맞았다** — `mask_key` 가 곧 bbox 문자열이라 기하에서 다시
만들어도 같은 값이 나왔다.

그 등식이 깨지는 자리가 둘이다.

- **4단계** — 사람이 경계를 고치면 bbox 는 바뀌고 키는 그대로여야 한다(P09 5.4)
- **고아** — `geom` 이 원래 후보의 것이라 지금은 맞지만, 맞는다는 보장이 없다

기하에서 키를 만들면 그 순간 **다른 개체가 된다.** 옛 행은 payload 에서 빠져
지워지고 새 키로 행이 하나 선다 — 분류·코멘트·이력이 끊긴다.

**둘 다 `key` 를 먼저 본다.** 서버가 실어 보내면 그것을 쓰고, 없으면 예전처럼
기하에서 만든다. 규칙이 갈라지면 화면이 보내는 키와 서버가 아는 키가 어긋나고,
`/review` 는 모르는 키를 지운다.

---

## 3. 색을 빌리지 않는다

고아는 엔진이 낸 것과 **달라 보여야 한다.** 같아 보이면 사람이 지표가 있는
개체로 읽는다 — 이 개체는 `Candidate` 가 없어 **잰 적이 없다.**

그런데 분류 색을 바꾸면 안 된다. **색은 "무엇인가", 진하기는 "온전한가" 를
말하는 자리다**(039). 빌려 쓰면 규조각 종류를 잘못 읽는다.

→ **테두리로만 가른다.** `border-style: dashed` + 굵기 + 흰 그림자, 그리고 `?`
표식. 분류 색은 그대로 둔다.

```css
.detview .box.orphan { border-style: dashed; border-width: 2px; … }
```

**`.detview` 를 붙인다** — `.box` 만 적으면 `.detview .box.<분류>` 가 특이도에서
이겨 아무 일도 안 일어난다. 051 에서 그렇게 도구를 감춘 줄 알고 계속 내보였다.
브라우저 시험이 `getComputedStyle` 로 그것을 본다.

**말풍선이 지표가 빈 이유를 적는다.** 표를 감추지는 않았다 — 칸이 사라지면
"이 개체는 다르게 생겼다" 가 아니라 **"화면이 덜 그려졌다"** 로 보인다.

---

## 4. 내 시험이 약했다

브라우저 시험 다섯을 붙이고 되살려 봤더니 **넷만 섰다.** "검토 완료만 눌러도
고아가 남는다" 가 안 잡혔다.

이유는 이랬다 — 픽스처의 고아에 분류와 코멘트가 붙어 있었는데,
`_apply_review` 의 반환에는

```python
"labels": {k: o.label for k, o in reviews.items() if o.label},
"notes":  {k: o.note  for k, o in reviews.items() if o.note},
```

가 있다. **후보와 무관하게 교정 전부에서 만든다.** 그래서 분류가 붙은 고아는
안 그려도 `labels` 를 타고 payload 에 실려 **살아남는다.**

진짜로 사라지는 것은 **표시가 `removed` 뿐인 고아**다. 지운 것 목록(`gone`)은
후보에서만 만들어지므로 안 그리면 키가 통째로 빠진다. 픽스처에 그런 고아를 하나
더해서야 잡혔다.

```
FAIL test_검토_완료만_눌러도_고아가_남는다
     AssertionError: False is not true : 표시가 removed 뿐인 고아가 사라졌다
```

**통과하는 것을 보고 "있다" 고 말하지 않는다**(P08 §1). 이번에는 되살려 보는
절차가 그 약한 시험을 잡았다 — 절차가 없었으면 "다섯 개나 붙였다" 로 끝났다.

---

## 5. 남은 것

- **사람이 그린 개체는 아직 집계에 안 잡힌다.** `Candidate` 가 없어 후보 기반
  SQL(`_SUMMARY_SQL`)이 못 본다. 고아도 마찬가지다 — 화면에는 보이는데 목록의
  숫자에는 없다. **3단계에서 함께 본다**
- 지표를 순수 파이썬으로 재는 것도 3단계다 (P09 5.8). 지금은 비어 있고, 왜
  비었는지 말풍선이 적는 것으로 갈음한다
- 운영 반영은 여전히 안 했다 — 0~2단계가 코드로만 있다 (065 §9)
