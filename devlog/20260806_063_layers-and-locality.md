2026-08-06 · 배포 `v0.7.0` (뷰어) · `v0.4.0` (파이프라인)

## 1. 사고 — `(1)` 은 읽혔는데 소속이 없었다

사용자가 `BP09-0901 (1)` 을 올렸고, 그것이 `BP09-0901` 과 같은 시료의 관찰로
서기를 기대했다. **안 그랬다.**

```
id  slug                     name             core_id  depth  obs_no
 8  260803_bp09-0901         BP09-0901          5(BP09)  None    0
12  260805_bp09-0901_1       BP09-0901 (1)      None     None    1   ← 소속 없음
```

`obs_no=1` 은 제대로 들어갔다. **빠진 것은 지점 연결이었다.**

원인은 `parse_sample_name` 이다. 정규식이 `<지역>-<지점> <깊이>cm` 를 요구하는데
`BP09-0901` 은 노두라 `cm` 이 없어 **매치가 안 된다.** 슬라이드 8 의 지점은
파서가 붙인 것이 아니라 사람이 속성 편집 화면에서 넣은 것이었고, 새 관찰은
물려받을 데가 없었다.

목록·지도·지점 페이지는 전부 `지점 → 위치 → 관찰번호` 로 묶으므로 소속이 없는
관찰은 **어느 화면에도 안 선다.** 500 도 404 도 아니다 — 그냥 사라진다.

### 덤으로 나온 것 둘

**하나.** `save_grouping` 과 `ingest_nas` 가 `update_or_create` 의 `defaults` 에
`core=None` 을 그대로 실었다. 즉 슬라이드 8 을 **다시 그룹핑하거나 다시 반입하면
사람이 넣은 지점이 지워진다.** `obs_label` 은 "사람 것이라 defaults 에서 뺀다" 고
해 놓고 `core`·`depth_cm` 는 안 그랬다.

**둘.** 사용자가 속성 편집으로 고치려다 실패했는데, 그 화면이

- 지역 코드를 비우면 **지점을 찾는 갈래가 통째로 건너뛰어져** 아무 일도 안
  일어나는데 "저장했습니다" 가 떴고
- 만약 성공했다면 **폼의 빈 칸으로 기존 BP09 지역·지점을 덮어썼을** 것이다.
  북평분지·좌표·`outcrop sample` 이 다 지워지고 슬라이드 8 도 함께 당한다

두 번째는 실제로 일어나진 않았다(사용자가 지역 코드를 안 채웠다). 하지만
**성공했으면 더 나빴을 종류의 실패**다.

## 2. 용어 정리 — 사용자가 층을 말해 주었다

여기서 방향이 바뀌었다. 사고를 막는 것보다 **왜 이런 사고가 가능한 구조인가**가
문제였다.

```
권역   한국 · 남극                       Site.area
 └ 지역   BP(북평분지) · RS23            Site
    └ 지점   BP09(노두) · GC03(시추코어)  Locality   ← 예전 Core
       └ 시료   0901 · 71cm              Sample     ← 없던 층
          └ 관찰   (1) · (2)             Slide
```

사용자가 정한 것 넷:

1. **"코어" 를 지점으로 넓힌다.** 북평분지는 육상이라 시추한 것이 아니다.
   지점은 시추코어와 노두를 함께 담는 말이고, 어느 쪽인지는 유형이 말한다
2. **유형은 지점의 성질이다.** 한 지점이 코어이면서 노두일 수 없다
3. **육상은 지점 = 노두 = 단면이 하나다.** 단면 층을 따로 두지 않는다
4. **관찰끼리는 동등하다.** "대표 관찰" 을 두지 않고 이름표로 구분하며,
   통계에 무엇을 넣을지는 숨김·집계 제외로 사람이 고른다

그리고 시료 코드를 읽는 법:

```
BP09-0901
└┬─┘ └┬┘
 │    └ 09 = 지점 번호가 되풀이된 것 · 01 = 그 노두의 첫 시료
 └ 지역 BP + 노두 번호 09
```

### 두 체계의 폴더 규칙이 다르다

| | 폴더가 담는 것 | 지역을 아는 법 |
|---|---|---|
| 남극 | `<지역>-<지점> <깊이>cm` | 폴더에 있다 |
| 육상 | `<지점>-<시료>` | 폴더에 없다 — 지점 코드의 앞 글자(`BP09` → `BP`) |

**가르는 표시는 `cm` 이 있느냐다.** 이 규칙을 `viewer/naming.py` 하나로 모았다 —
예전에는 같은 정규식이 `group_focus_series` 와 `import_json` 에 두 벌 있었다.

> **육상의 지역을 숫자를 떼어 얻는 것은 짐작이다.** 노두 코드가
> `<지역문자><번호>` 꼴이라는 전제이고, 어긋나면 없는 지역이 만들어진다.
> 그래도 비워 두는 쪽이 더 나쁘다 — 지역이 없는 관찰은 어느 권역 탭에도 안
> 나와 화면에서 사라진다(이 사고가 정확히 그것이었다). 대신 **관리 화면에서
> 사람이 고칠 수 있게** 했다.

## 3. `Sample` 이 없던 것이 뿌리였다

`Slide` 하나가 시료와 관찰을 겸했다. `core`·`depth_cm`·`sample_kind` 가 **관찰
행마다** 앉아 있었고, 그래서 같은 시료의 관찰 둘이 **서로 다른 소속을 가질 수
있었다.** 그것이 이 사고다.

시료 행이 있으면 관찰은 그것을 가리키기만 하므로 애초에 어긋날 수가 없다.
덤으로 "같은 시료의 다른 관찰" 이 **이름 짐작이 아니라 조인 한 번**이 된다 —
아침에는 `name__startswith` 로 좁히고 접미사를 떼어 비교해야 했고, 이름이 규칙에
안 맞으면 그대로 못 찾았다.

### 시료의 위치 칸이 둘이다

| 지점 유형 | 시료가 서는 값 | 칸 |
|---|---|---|
| 시추코어 | 깊이 71 cm | `depth_cm` (실수) |
| 노두 | 단면상의 위치 1 | `sample_no` (정수) |

한 칸에 몰지 않는 이유는 `depth_cm` 을 문자열로 안 바꾼 것과 같다 — "369cm" 와
"단면 9번" 을 같은 축에 그리게 된다. 지점은 코어이거나 노두이거나 둘 중 하나라
정렬할 때는 어차피 한 칸만 본다(`Sample.position`).

**노두에는 cm 축을 아예 안 그린다.** 단면상의 위치는 "몇 번째로 딴 것" 이지
거리가 아니다. 축에 얹으면 없는 간격을 지어내게 된다.

### 마이그레이션 — 자동 생성본을 그대로 쓰면 안 됐다

Django 는 이런 순서를 냈다:

```
CreateModel Locality → RemoveField slide.core → DeleteModel Core
```

**`Core` 를 지우고 `Locality` 를 빈 채로 만든다.** 그대로 돌리면 지점 다섯과
모든 관찰의 소속이 통째로 날아간다. 손으로 순서를 잡았다:

```
1. 새 표를 만든다 (Locality · Sample · Slide.sample)
2. **자료를 옮긴다**  ← RunPython 이 여기 있어야 한다
3. 그 다음에 옛 칸을 걷는다
4. 제약·인덱스는 자료가 다 앉은 뒤에 건다
```

되돌리기(`reverse`)도 함께 적었다. 배포 게이트가 막히면 판을 되돌려야 하는데,
그때 자료가 없으면 되돌린 판이 빈 화면을 낸다.

> **SQLite 가 한 번 물었다.** 칼럼을 지울 때 표를 통째로 다시 만드는데
> `uniq_core_code` 가 아직 `site` 를 가리키고 있어
> `NewCore has no field named 'site'` 로 죽었다. 제약을 먼저 뗀다.

지점 유형은 그 지점에 달린 관찰들의 `sample_kind` 에서 올렸다. **실측에서 지점
다섯 곳 전부 한 가지로 모여** 그대로 갔다.

## 4. 딸려 온 화면 넷 (사용자 제안)

층을 고치는 동안 검토 흐름을 짧게 하는 것 넷이 함께 들어왔다.

- **검토 완료 숨기기** (데이터셋). 카드가 이미 표시를 달고 있어 화면에서 거른다
  — 서버에 안 묻는다. 새로고침이 있으면 검토하다 말고 켜고 끌 수가 없다
- **다음 미검토** (검토 화면). 옆 시야로 한 칸 가는 것과 다른 일이다 —
  `bp09-0901` 이 86 중 53 완료라 한 칸씩 눌러 이미 본 것을 계속 지나야 했다.
  뒤에 없으면 앞으로 돌아가되 **돌아갔다고 말한다**
- **밝기·대비** (우측 패널). `filter` 를 `<img>` 에만 건다 — 마스크는 형제
  `<svg>` 라 안 물든다. **마스크 색이 분류를 나타내는 판정 근거**여서 사진과
  함께 어두워지면 무엇으로 지정했는지가 안 읽힌다
- **전체를 검토로 / 미검토로** (POST 전용). `done` 만 뒤집고 **행은 안 지운다**
  — 같은 행의 `note`(시야 코멘트)가 사람의 판단이라 지우면 함께 날아간다

## 5. 관리 화면 (`/manage/`)

지역·지점·시료를 만들고 지운다. **관찰은 만들지도 지우지도 못한다** — 폴더가
만드는 것이고 그 아래에 재생성 불가한 교정이 달려 있다.

**이 화면이 있어야 하는 첫째 이유는 소속 없는 관찰이다.** 그것은 다른 어느
화면에도 안 나온다. 여기서는 붙일 곳까지 추천해서 낸다.

**지우기에 문턱이 있다.** `Slide.sample` 이 `SET_NULL` 이라 시료를 지우면 관찰이
조용히 소속을 잃는다 — 딸린 것이 있으면 막고, **무엇이 몇 개 걸려 있는지 버튼에
미리 적는다.** 눌러 보고 "지울 수 없습니다" 를 만나면 무엇을 먼저 치워야 하는지
알 수 없다. 서버가 다시 검사한다: 화면에서 막는 것은 막는 것이 아니다.

## 6. 노두 현장 사진 (사용자 제안)

시추코어 지점에는 암상 띠가 들어올 자리가 잡혀 있는데 **노두 쪽은 그 자리가
통째로 비어 있었다.** 거기에 현장 사진을 넣는다.

**파일이 곧 자료다.** DB 에 행이 없고 이름이 `<지점코드> (n).jpg` 인 것이 지점과
사진을 잇는 유일한 근거다 — 사람이 탐색기로 NAS 에 직접 올려도 화면에 나타나고,
새 노두 지점을 만들고 사진만 두면 저절로 붙는다.

화면에서도 올린다(끌어다 놓기·파일 고르기). **이름은 서버가 짓는다** — 화면이
준 이름은 확장자조차 안 쓴다. 주소에도 이름이 없다: 서빙·삭제가
`(지점, 순번)` 으로만 짚어서 `../` 로 바깥을 가리킬 방법이 애초에 없다.

**세 장까지다**(사용자 방침 — 용량 관리). 여럿이 쓰는 NAS 공유라 올릴 때 긴 변
2400px·q85 로 줄여 다시 쓴다.

```
5568x3712  12.5 MB  →  2400x1600  0.97 MB   (8%)
```

있던 사진 셋도 `shrink_outcrop.py` 로 줄였다(37.4 → 2.9 MB). 원본 사본은
`backup/outcrop-original/` 에 있다.

**NAS 가 없어도 죽지 않는다.** 읽기가 `OSError` 를 삼키고 빈 목록을 낸다 —
사진이 안 보이는 것과 지점 페이지가 500 이 되는 것은 고장의 크기가 다르다.

## 7. 눌러 보는 시험이 잡은 것 넷

**전부 예외도 경고도 없었다.** 코드를 읽어서는 하나도 안 걸렸을 것들이다.

**`.tile` 의 `display: block` 이 `[hidden]` 을 이겼다.** 브라우저 기본
`[hidden] { display: none }` 은 특이도 (0,0,1) 이라 (0,1,0) 에 진다. 감추라고 해
놓고 그대로 보였다 — `.tools` 에서 한 번 밟은 자리다.

**관리 폼에 `kind` 가 둘이었다.** 숨은 칸이 층 이름을 `kind` 로 나르는데 유형
셀렉트도 같은 이름이라 Django 가 뒤엣것을 집었다. 지점이 "모르는 층" 이 되어
조용히 안 만들어졌다.

**끌어다 놓기 스크립트가 `{% block title %}` 안으로 들어갔다.** 마지막
`{% endblock %}` 을 찾는다는 것이 첫 번째를 집었고 — `<title>` 안이라 JS 가 한
번도 안 돌았다. CLAUDE.md 의 "block 바깥에 적은 것은 렌더되지 않는다" 와 같은
결이다.

**Django 의 `{# #}` 를 여러 줄로 썼다.** CLAUDE.md 에 적혀 있는데도 밟았다.

> 그리고 **서버가 템플릿을 캐시한다.** `--noreload` 로 띄운 개발 서버는 템플릿을
> 고쳐도 안 바뀐다 — 두 번 헛다리를 짚었다. 템플릿을 고치면 다시 띄울 것.

## 8. 배포

**뷰어와 파이프라인을 함께 올렸다.** 스키마를 조이는 마이그레이션이라 갈라
놓으면 옛 파이프라인이 없는 칼럼에 INSERT 한다(055 의 교훈).

**폴러 락을 잡은 채로 했다.** 마이그레이션이 도는 동안 옛 파이프라인이 돌면
폴러가 선다.

```bash
flock /tmp/DiaRUGA-poll.lock bash -c '
    sed -i "s|^PIPELINE_TAG=.*|PIPELINE_TAG=v0.4.0|" /srv/DiaRUGA/.env
    /srv/DiaRUGA/bin/deploy.sh v0.7.0'
```

**굽고 나서, 배포 전에 새 파이프라인 이미지를 조인 사본에 붙여 봤다** — 새 판
DB 를 읽고 시료를 제대로 찾는 것까지 확인한 뒤에 올렸다.

확인:

```
smoke 통과 — 판 v0.7.0 · 슬라이드 11 · 교정 7,472 · nginx 경유 200
django_migrations 최신: 0024_locality_and_sample

노두 현장 사진 3장이 운영에서 그려진다 · 콘솔 오류 0
```

사본 셋을 남겼다: `before-locality` · `before-v070` · `pre_deploy-v0.7.0`.
