# 040 — 분류 단축키, 그리고 "분류를 더할 때 채울 것" 목록

2026-08-04

검토는 개체를 고르고 우클릭 → 메뉴에서 분류를 고르는 방식이었다. 시야 하나에
개체가 수십이라 **메뉴를 여닫는 왕복이 곧 검토 속도다.** 개체를 고른 채 키
하나로 지정되게 했다.

```
q → 원형 → 원형 파편 → 원형 …        w → 봉상 → 봉상 파편 → 봉상 …
e → Eucampia                          r → Chaetoceros
```

## 본체와 파편이 한 키를 나눠 가진다

`q` 를 누르면 원형, 한 번 더 누르면 원형 파편. **손가락을 옮기지 않고 누른
횟수로 온전한 것과 깨진 것을 가른다.** 039 에서 색을 그렇게 묶었으니(색상은
본체, 진하기는 온전한가) 조작도 같은 모양이어야 한다.

순환 차례는 `sort_order` 다. 여럿을 고른 채 눌렀을 때는 **전부 같은 분류일 때만**
다음으로 넘어가고, 섞여 있으면 처음 것으로 모은다 — 여럿을 한 번에 눌렀는데
결과가 개체마다 다르면 그건 도구가 아니다.

키는 q·w·e·r 다. 왼손이 안 움직이고, 이미 쓰는 것들(화살표=사진·시야 이동,
Ctrl+Z=실행취소, Esc=닫기)과 겹치지 않는다.

## 배정을 표에 두고, 빠뜨리면 걸리게

`ClassDef.hotkey` 다. **코드에 목록을 적지 않았다** — 분류를 더하면서 한 자리만
옛 목록으로 남는 일이 이미 두 번 있었다(038 의 개수 줄, 목록의 분류 열).

키를 안 준 분류는 화면 안내에도 안 나온다. 그것이 곧 "아직 배정 안 했다" 는
표시고, `check_db.py` 의 "4. 분류" 가 같은 것을 잡는다:

```
활성 분류에 단축키가 있다      OK
활성 분류에 색이 있다          OK
```

그리고 `ClassDef` 머리말에 **분류를 더할 때 채울 것**을 목록으로 적었다.
label · short · badge · color · hotkey · counted · is_taxon · sort_order,
그리고 `base.html` 의 CSS. 하나라도 비면 예외는 안 나고 **그 분류만 조용히
다르게 굴러간다** — 이번에 겪은 것이 정확히 그것이다.

## 읽기 전용 화면에서는 키가 안 듣는다

`/engine/` 은 다른 엔진의 검출을 보는 시험용 화면이고, 여기서 저장하면 교정이
엉뚱한 검출에 붙는다. 예전에 CSS 로 버튼만 감췄다가 37건을 잃었다. 그래서

- 핸들러가 `readOnly` 면 그 자리에서 돌아서고,
- **안내 줄도 감춘다.** 있는 기능인 줄 알고 눌러 보다 "안 되네" 가 되는 쪽이
  아예 안 보이는 것보다 나쁘다.

## 약칭 (`short`)

속명은 길다. `Chaetoceros` 하나가 목록 표의 열을 두 배로 넓히고 개수 줄을
밀어낸다. `ClassDef.short` 를 두고 `Chaetoceros → CRS` 로 넣었다. 비면 전체
이름을 쓰므로 원형·봉상은 그대로다.

**자리가 좁은 곳만 줄인다.** 목록 표의 열 머리·카드 칸·개수 줄·개체 목록
배지·단축키 안내가 약칭, **말풍선과 분류 지정 메뉴는 전체 이름**이다. 고르는
자리에서까지 줄이면 무엇을 지정하는지가 흐려진다. 줄인 자리에는 `title` 로
전체 이름을 달아 두었다.

Eucampia 는 두지 않았다. 지금 자리에 들어가고, 줄일 이름이 늘수록 화면에서
무엇을 보는지가 흐려진다. 필요해지면 표에서 채우면 된다.

## 확인 — 브라우저 없이 순환 규칙을 시험한 방법

키 순환은 조건이 갈리는 코드라 "200 이 뜬다" 로는 못 본다. 브라우저가 없으니
**렌더한 페이지에서 그 조각을 그대로 떼어 내** node 에서 돌렸다. 손으로 옮겨
적으면 시험이 아니라 사본을 시험하는 것이 된다.

```
OK  q · [round] -> round_frag          OK  w · [rod] -> rod_frag
OK  q · [round_frag] -> round          OK  w · [rod_frag] -> rod
OK  q · [] -> round                    OK  w · [round] -> rod
OK  q · [rod] -> round                 OK  e · [eucampia] -> eucampia
OK  q · [round,round] -> round_frag    OK  e · [round] -> eucampia
OK  q · [round,round_frag] -> round    OK  r · [round,] -> chaetoceros
```

`e` 처럼 혼자인 키는 다시 눌러도 제자리다(`ring[(0+1) % 1]`). 나머지 화면은
전부 200, `makemigrations --check` 로 모델과 마이그레이션이 어긋나지 않은 것도
봤다.

**실제로 키를 눌러 본 것은 아니다** — 이벤트 배선(활성 패널 판정, 입력칸에서
안 듣기)은 브라우저에서 한 번 확인해야 한다.
