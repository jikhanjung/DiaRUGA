| | 전 | 후 |

| 카드 하나 | **후보** 하나 (시야마다 판 하나만) | **개체** 하나 (모든 판) |

## 2. 마이그레이션 `0040` 은 사본에서 먼저 돌렸다

`/data3/DiaRUGA/backup` 의 최근 사본(108 MB)에 붙여 2.2초. 개체 **11,061** 개가
전부 앵커를 받았고 **남의 판정을 가리키는 것 0 · 가장 오래된 멤버가 아닌 것 0**
이다. **되돌리기도 확인했다**(`migrate viewer 0039` → 다시 `migrate`).

## 3. 붙이면서 잡은 것 — 프레임마다 디스크를 짚고 있었다

`candidate_rows(all_images=True)` 를 `_frames()` 로 짜 놓았는데, 그 함수는
프레임마다 `exists()` 를 부른다(캐러셀이 없는 판을 흐리게 그리려고). 카탈로그는
그것을 쓸 일이 없는데 **시야 570 × 프레임 넷이면 한 판에 `stat` 이 2천 번**이다.

**이 계정이 사진을 못 읽어서 드러났다** — 운영 컨테이너는 읽을 수 있으니
`PermissionError` 대신 **조용히 느려졌을** 자리다. 카탈로그용 갈래는 `Frame`
행만 보고 디스크를 안 짚는다.

## 4. 시험 — 픽스처가 운영과 다른 모양이 되어 있었다

940 → **954**. 고친 것이 많은데, 대부분 **한 가지 이유**다: 카드가 개체 단위가
되면서 **판정이 없는 픽스처는 카드가 0** 이 됐다.

`fx.review_done(vp, batch)` 를 새로 두었다 — 운영이 쓰는 `confirm_kept` 를
그대로 부르고 `(시야, 묶음)` 에 완료도 적는다. **하나만 하면 카탈로그는 차는데
화면은 "덜 봤다" 고 말한다**(실제로 그렇게 짰다가 시험이 잡았다).

`add_review`·`new_review` 는 **이미 있는 줄을 고치도록** 바꿨다(운영의
`judgement_for` 가 get-or-create 인 것과 같다). 그러면서 **유일 제약을 보는
시험 셋이 아무것도 안 보게 됐다** — 그쪽은 모델을 직접 쓰도록 고쳤다.
*제약은 DB 의 사실이지 팩토리의 성질이 아니다.*

`fx.link_reviews` 도 앵커를 **가장 오래된 멤버**로 세운다. 운영에서 새로 묶으면
그릇이 빈 개체라 `reanchor` 가 그렇게 세우는데, 픽스처가 `rep` 을 따라가고 있어
**`rep` 을 무엇으로 주느냐에 따라 번호가 달라졌다.**

## 5. 되살려서 잡히는가

| 되살린 것 | 잡혔나 |
|---|---|
| 판 하나만 훑던 옛 규칙 | ○ |
| 번호를 앵커가 아니라 그 줄에서 뽑는다 | ○ |
| 개체 없는 후보도 카드로 낸다 (두 겹 다 걷고) | ○ |
| 검색이 멤버 번호를 안 본다 | ○ (시험을 고친 뒤에) |

**또 이빨 없는 시험을 둘 만들었다** — 둘 다 원인이 같다:
**`<style>` 에 있는 글자로 셌다.** `assertIn("catcard", html)` 은 결과가 0건
이어도 통과하고(그 클래스가 CSS 에 있다), `assertIn("vpdone", html)` 도 그렇다.
**속성(`class="vpdone"`)이나 그 개체의 열쇠로 짚는다.**

149·150·151 에 이어 **다섯 번째**다. 원인이 매번 같다 — *시험이 만든 상태나
세는 대상이 그 갈래를 안 지난다.*
