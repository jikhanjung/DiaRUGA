# 데이터셋 목록에 표/카드 전환을 둔다

**작성일** 2026-08-03

---

## 카드가 표가 된 이유 (앞 커밋)

슬라이드가 3장일 때는 카드가 읽혔다. 7장이 되자 같은 항목을 카드마다 눈으로 찾아
옮겨 다니게 됐다. **같은 코어의 깊이별 변화를 보는 것이 목적**이라 세로로 줄이
맞아야 비교가 된다. 줄 순서도 지역 → 코어 → 깊이로 바꿨다.

## 그런데 카드도 쓸모가 있다

표는 비교에 좋고 카드는 하나씩 훑는 데 좋다. 둘 중 하나를 고를 이유가 없어서
**전환을 붙였다.** 탐색기의 "자세히 / 큰 아이콘" 과 같은 자리(오른쪽 위), 같은
모양으로 뒀다.

```
▤  줄이 그어진 것   → 표
▦  네모 넷          → 카드
```

글자를 안 붙여도 읽히는 모양이라 아이콘만 두고, 무엇에 좋은지는 툴팁에 적었다.
고른 쪽은 강조색으로 채운다 — 테두리만으로는 어느 쪽이 켜져 있는지 한눈에 안
잡힌다.

## 둘 다 그려 두고 CSS 로 감춘다

서버를 다시 부르지 않으므로 즉시 바뀌고 스크롤 위치도 남는다. 슬라이드가 수백
장이 되면 다시 볼 문제지만, 지금 7장에 그 값을 치를 이유가 없다.

고른 방식은 `localStorage` 에 기억한다. **매번 고르게 하면 도구가 아니라 일거리가
된다.** 기본은 표다 — 지금 상황(7장, 깊이별 비교)에 그쪽이 맞다.

## 되살리면서 표와 맞춘 것

옛 카드는 표보다 먼저 만든 것이라 용어가 어긋나 있었다.

| 옛 카드 | 지금 |
|---|---|
| "그룹" | **"시야"** (`Viewpoint` 로 통일) |
| "그룹당 검출 · 검출 합계" | **"검출 · 시야당"** (표와 같은 이름·순서) |
| 부분 검출 표시 없음 | `*` 와 아래 설명 |

같은 값을 두 화면이 다르게 부르면, 어느 쪽이 맞는지 사람이 따져 봐야 한다.

## 죽어 있던 스타일을 살렸다

앞 커밋의 템플릿 주석이 짚어 둔 것이다 — **부모를 `extends` 한 템플릿에서 `block`
바깥에 적은 것은 렌더되지 않는다.** 옛 `index.html` 의 `<style>` 이 `{% endblock %}`
뒤에 있어서 `.dsmeta`·`.dsstate`·`.dsdesc` 가 **한 번도 먹은 적이 없었다.**

이번에 카드를 되살리면서 그 스타일도 `base.html` 로 옮겼다. 화면에 안 나오던
것이라 아무도 이상하다고 느끼지 못했다 — 예외도 경고도 없는 종류의 고장이다.

## 확인

브라우저가 없어 렌더된 결과로 봤다.

- 인라인 JS 구문 통과 (`node --check`)
- CSS 규칙 3개가 실려 있음 (`.dsview .asCards` 등)
- 마크업 중첩: `dsview` > `asTable` · `asCards`
- 카드 stat 63개 = 슬라이드 7 × 항목 9
