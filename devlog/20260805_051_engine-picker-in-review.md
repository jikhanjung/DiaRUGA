# 051 — 엔진 고르기를 검토 화면 안으로 들였다. YOLO 는 읽기 전용

2026-08-05. 검출 엔진을 고르는 일이 `/engine/` 이라는 **다른 화면**에만 있었다.
견주려면 검토 화면을 나갔다 들어와야 했고, 그때마다 어느 시야를 보고 있었는지
잃었다. 견주기는 같은 자리를 번갈아 보는 일이다 — 화면이 바뀌면 안 된다.

같이 고친 것: **지금 무엇을 보고 있는지가 화면에 없었다.** 탭 이름이 "합성본"
한 마디였고 캐러셀에서 프레임을 골라도 그대로 남았다.

## 1. 무엇을 만들었나

`/d/<슬라이드>/g/<시야>/?batch=<실행번호>`. 쿼리 하나로 갈린다.

| | 현재 검출 (SAM2) | 다른 묶음 (YOLO 등) |
|---|---|---|
| 주소 | `…/g/1/` | `…/g/1/?batch=215` |
| 교정 | **저장된다** | 안 된다 |
| 그리는 것 | 검출 + 사람의 교정 | 엔진이 낸 그대로 |
| 도구·완료단추 | 있다 | 감춘다 |
| 시야 가르기 | 있다 | 감춘다 |

화면에 더한 것 셋:

1. **탭 이름이 끝까지 말한다** — `검출결과 검토 - 합성본` · `검출결과 검토 - 22119`.
   앞머리(화면 이름)는 서버가 `data-prefix` 에 넣고, 뒷부분(지금 띄운 판)은
   `paint()` 가 판을 갈 때마다 다시 쓴다.
2. **엔진 드롭다운** — 탭 이름 바로 옆, `개체 목록` 앞. 칸마다 그 묶음이 문턱을
   통과시킨 개체 수를 함께 낸다(`SAM2 · sam2-전수 (1)`). 읽기 전용인 것은
   그렇게 적힌다.
3. **사진 가운데 위 `Read only`** — 빨갛게, 크게. 도구가 감춰진 화면이라 그
   자리가 비어 있고, 좌상(도구)·우상(레이어)이 이미 찬 자리다.

## 2. 저장을 막는 겹은 셋이다 — 화면은 그중 하나도 아니다

027 이 정확히 이 자리에서 났다. "읽기 전용" 이라 적어 놓고 CSS 로 버튼만
감췄더니 마스크 클릭 한 번이 교정 37건을 지웠다. **`/review` POST 는 그 시야의
교정 전체를 갈아치운다.**

1. **JS** — `ro-stack` 표식이 있으면 `save()` 가 타이머조차 걸지 않고
   `postReview()` 가 fetch 전에 빠져나간다. 표식 하나로 저장 차단과 화면의
   `Read only` 표시가 **함께** 갈린다. 따로 두면 한쪽만 켜진 화면이 나온다.
2. **서버** — `data.save_review` 가 현재 검출에 없는 키를 거절한다(409).
   엔진이 다르면 `mask_key`(bbox 문자열)가 거의 전부 어긋난다.
3. **화면** — 도구·완료단추·시야 가르기를 감춘다. **이건 세 번째다.** 앞의 둘이
   없으면 아무것도 아니다.

브라우저로 눌러 확인했다(045 의 playwright, 사본 DB `:8091`). 읽기 전용 화면에서
마스크를 클릭하고 판을 갈아 끼우는 동안 **`/review` 로 나간 요청은 0건**이고,
현재 검출 화면에서는 삭제·되돌리기가 여전히 200 으로 저장된다.

## 3. 눌러 보고서야 나온 고장 셋

셋 다 **읽어서는 안 보이는** 종류다.

### 3.1 `.tools { display: none }` 이 한 번도 먹은 적이 없다

`base.html` 이 `.detview .tools { display: flex }` 로 잡고 있다. 특이도가
`0,2,0` 대 `0,1,0` 이라 **감추는 쪽이 진다.** `/engine/` 은 도구를 감춘 줄 알고
여태 그대로 내보이고 있었고(저장은 `ro-eng` 가 막아 왔다), 검토 준비 중 화면도
"검토 도구만 잠가 두었습니다" 라고 적으면서 도구를 보이고 있었다.
세 자리 모두 `.detview` 를 붙여 고쳤다.

**예외도 경고도 없는 종류의 고장이다.** 렌더 결과를 브라우저에 물려
`getComputedStyle` 로 보기 전까지는 안 보인다.

### 3.2 이전 시야로 거슬러 가면 고른 엔진이 조용히 풀렸다

`?shot=last` 를 지우는 코드가 `location.pathname` 으로 주소를 갈아치웠다 —
**쿼리를 통째로 버린다.** 그때는 쿼리가 그것뿐이라 티가 안 났는데, `?batch=` 가
생기자 한 칸 뒤로 갈 때마다 현재 검출로 돌아갔다. `shot=last` 만 정규식으로
걷어내게 고쳤다.

### 3.3 `{{ prev_url }}?shot=last`

주소에 이미 `?batch=215` 가 붙어 있으면 `?batch=215?shot=last` 가 되어 둘 다
죽는다. 템플릿에서 `?`/`&` 를 가려 붙인다.

## 4. 버린 것

- **개체 자료를 판마다 미리 실어 두고 JS 로 갈아 끼우기.** 폴리곤이 시야당
  29 KB 다. 무엇보다 **교정을 얹을지 말지가 검출마다 다르다** — 서버가 그리게
  두는 편이 안전하다. 드롭다운은 주소만 바꾼다.
- **`?batch=` 로 현재 검출을 보는 것.** 그리로 오면 같은 것을 교정만 뗀 채 보게
  되고, 거기서 고친 것은 저장되지 않는다. 서버가 맨 주소로 되돌려보낸다
  (모르는 묶음 번호도 마찬가지).
- **`/engine/` 을 없애기.** 여러 묶음을 한 표로 훑는 화면은 다른 일을 한다.
  그대로 두고, 검토 화면의 "엔진 비교" 링크만 걷었다 — 이제 드롭다운이 같은
  일을 제자리에서 한다.

## 5. 남은 어긋남 하나

드롭다운의 개체 수는 **엔진이 낸 그대로**(문턱을 통과한 것)이고, `개체 목록` 의
수는 **사람의 교정을 얹은 뒤**다. 사람이 탈락분을 되살린 시야에서는 둘이 다르다
(첫 시야가 `SAM2 · sam2-전수 (0)` 인데 `개체 목록 1` 이다). 둘 다 맞는 수인데
재는 것이 다르다 — 드롭다운은 **엔진끼리 견주는** 자리라 사람의 손을 빼고
세는 편이 맞다. 말풍선에 그렇게 적어 두었다.
