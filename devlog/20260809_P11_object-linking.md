# P11 — 여러 프레임에서 검출된 같은 개체를 하나로 묶는다

2026-08-09. **계획과 결정** 문서다. 실제로 한 일은 번호 devlog 에 따로 적는다.

사용자 요청(2026-08-09)이 TODOs 의 "여러 프레임에서 잡힌 같은 개체를 하나로
묶는다"(2026-08-05 제안)를 구체화했다 — **자동 매칭이 아니라 사람이 고르는
흐름**이다:

> 마스크를 우클릭해 **[동일 개체 묶기]** 를 고르면 팝업이 프레임마다 그 자리
> 근처의 후보를 펼쳐 보여주고, 프레임마다 가장 적합한 것을 골라 묶는다.
> 그중 하나를 **대표**(별 토글)로 세운다. 후보는 프레임마다 한둘, 많아야
> 두셋 — 가까운 것 위주로.

## 1. 왜 지금 이것인가

YOLO 는 프레임마다 검출을 낸다. 같은 규조각이 초점면 3~5장에 세 번, 다섯 번
잡혀 있는데 **그것이 하나라는 것을 아무도 모른다.** 프레임별 검토(P06 5b)로
가면 사람이 같은 개체를 프레임 수만큼 다시 보게 된다 — 묶어 두면 한 번 판단해
묶음 전체에 퍼뜨릴 수 있고, 다음이 열린다:

- **정확한 개체 수** — 프레임 검출을 세면 같은 개체가 여러 번 세어진다.
  묶음이 있어야 "이 시야에 규조각 N개" 가 선다
- **가장 잘 잡힌 초점면** — 대표가 그것이다. 학습 자료로 뽑을 때 프레임마다
  다 내보내는 대신 대표만 내보내는 길이 생긴다
- **검출 신뢰도** — 여러 프레임에서 반복해 잡힌 것은 진짜일 확률이 높다
- (나중) **3차원 형태** — 초점면마다의 마스크를 쌓으면 두께 방향이 생긴다

**실측 (yolo-3차, 시야 508):**

```
프레임 검출 1,444 (통과 후보 13,747) · 합성본 검출 355 (3,501)
시야당 프레임 검출 수: 1장 153 · 2장 98 · 3장 101 · 4장 74 · 5장+ 82
프레임당 통과 후보: 중앙 7 · 평균 10.1 · 최대 76
```

프레임당 후보가 중앙 7개라, **"그 자리 근처만"** 으로 좁히면 사용자가 말한
"하나씩, 많아야 두셋" 이 실제로 성립한다 (같은 시야는 스테이지가 안 움직여
좌표가 거의 같다 — 초점만 다르다).

## 2. 핵심 결정 — 이것은 교정과 같은 무게다

TODOs 의 원안은 "IoU 로 자동 계산하는 층, 재검출하면 다시 계산"이었고, 그래서
`Candidate` FK + CASCADE 로 충분했다. **사람이 고르는 순간 그 전제가 무너진다.**
사람이 프레임마다 "이것이 그 개체다" 를 고르고 대표를 세운 것은 **재생성 불가
자료**다 — 재검출이 그것을 지우면 안 된다.

그래서 스키마는 `ObjectReview` 의 규약을 그대로 따른다:

- **FK 로 `Candidate` 를 가리키지 않는다.** 검출이 다시 돌면 조인 실패로
  사람의 판단이 사라진다 — 열쇠는 `(image, batch, mask_key)` 다
- **`geom` 을 스스로 든다.** 검출기가 바뀌어도 읽힌다
- **git 감사 기록으로 나간다** — `export_review.py` 형식을 올린다 (아래 §6)

## 3. 스키마 (1단계)

```python
class ObjectLink(models.Model):
    """같은 개체 묶음 — 한 시야 안에서 여러 이미지의 마스크가 한 개체다.

    **사람이 만든 것이라 재생성 불가다** (ObjectReview 와 같은 무게).
    """
    viewpoint = FK(Viewpoint, CASCADE)          # 묶음은 시야를 못 넘는다
    batch = FK(RunBatch, PROTECT, null=True)    # 어느 묶음의 검출을 보며 묶었나
    note = CharField(blank=True)
    created_at / updated_at

class ObjectLinkMember(models.Model):
    link = FK(ObjectLink, CASCADE, related_name="members")
    image = FK(Image, CASCADE)                  # 어느 프레임(또는 합성본)의
    batch = FK(RunBatch, PROTECT, null=True)    # 어느 검출의 마스크인가
                                                # (NULL = 사람이 그린 것, P09 5.2)
    mask_key = CharField                        # ObjectReview 와 같은 규약
    is_rep = BooleanField(default=False)        # 대표 (별)
    geom = JSONField                            # 기하 스냅샷 — 스스로 든다

    제약:
      (link, image) 유일           # 한 프레임에서 한 개만 고른다
      (image, batch, mask_key) 유일 # 한 마스크는 한 묶음에만 속한다
      (link) 조건부 유일 is_rep=True # 대표는 정확히 하나
```

**`batch` 가 `PROTECT` 인 이유** — 묶음(RunBatch)을 지우려면 그 검출을 보며
만든 사람의 묶음부터 지워야 한다는 뜻이다. 조용히 NULL 이 되면 "어느 검출을
보고 한 판단인지" 를 잃는다 (`drop_batch.py` 가 이미 지우기의 문이다 — 거기에
개수 경고를 더한다).

**합성본 마스크도 멤버가 된다.** 지금 검토 대상(`sam2-전수`)은 합성본 검출만
있어서, 묶음의 닻이 대개 합성본 마스크이고 프레임 쪽이 YOLO(또는 다음 엔진)의
검출이 된다 — 합성본↔프레임을 잇는 것 자체가 이 기능의 절반이다.

## 4. 후보 제안 (2단계) — 서버가 아니라 화면이 계산한다

검토 화면은 **이미 프레임마다의 검출을 다 들고 있다** (P09 캐러셀 —
`_frames(vp, by_path)` 가 프레임별 검출을 실어 보낸다). 새 API 없이 화면이
계산할 수 있다:

1. 우클릭한 마스크의 bbox 를 기준으로, **다른 이미지들**(합성본 + 프레임)의
   통과 후보 중 **중심이 기준 bbox 의 1.5배 상자 안**에 드는 것을 모은다
2. 중심 거리로 정렬해 **이미지마다 최대 3개**
3. 1위가 뚜렷하면(IoU ≥ 0.5 같은) **미리 골라 둔다** — 사용자는 확인만 한다
4. 사람이 그린 마스크(`batch=NULL`)도 후보에 든다

문턱(1.5배·IoU 0.5)은 **실측으로 정한다** — 3단계 전에 yolo-3차 자료로 같은
자리 후보의 IoU·중심거리 분포를 재는 일회성 스크립트를 먼저 돌린다.
크롭 썸네일은 기존 `/crop?p=…&b=…` 을 그대로 쓴다 (이미 bbox 를 받는다).

**탈락 후보는 1판에서 뺀다.** "그 프레임에서 가장 좋은 마스크가 문턱에서
떨어져 있다" 는 경우가 실제로 있겠지만, 탈락 후보를 고르는 것은 "되살린다" 는
판단과 섞인다 — 묶기(정체)와 되살리기(판정)를 한 팝업에서 겹치면 저장 의미가
복잡해진다. 필요해지면 "탈락까지 보기" 토글로 더한다.

## 5. 화면 (3단계)

**들어가는 길** — 마스크 우클릭 메뉴에 **[동일 개체 묶기]** 항목. 이미 묶인
마스크에서는 **[묶음 열기]** 로 바뀐다(고치기·풀기).

**팝업** — 탈락 펼침판·캐러셀과 같은 결의 모달:

```
동일 개체 묶기 — g012                                  [저장] [묶음 풀기] [닫기]
──────────────────────────────────────────────
합성본      [크롭✓]                       ← 우클릭한 마스크 (기준, 별 ★)
Snap-22117  [크롭1✓] [크롭2] (없음)       ← 미리 고른 것에 ✓
Snap-22118  [크롭1✓] (없음)
Snap-22119  (없음)✓                       ← 근처에 후보가 없는 프레임
──────────────────────────────────────────────
크롭 클릭 = 선택 · 별 클릭 = 대표 지정 · 프레임마다 하나 또는 없음
```

- 이미지마다 **라디오처럼 하나만** 고른다. "(없음)" 이 늘 있다 — 그 프레임에는
  이 개체가 안 잡혔다는 것도 정보다
- **별(★)** 은 멤버 중 하나에만 붙는다. 기본은 우클릭한 마스크
- 크롭 옆에 프레임 선명도(`sharp_pct`)를 작게 적는다 — 대표를 고를 때 근거가 된다

**읽기 전용 갈래를 함께 센다** (051 의 교훈 — 반응하는 자리를 전부 센다):
`?batch=` 비교 화면에서는 메뉴 항목 자체를 안 내고, 서버도 거절한다.

## 6. 저장·내보내기 (3·4단계)

**저장은 `/review` POST 에 싣지 않는다.** 그 길은 "그 시야의 교정 전체를
갈아치운다" 는 전제 위에 있고 두 번 사고 낸 자리다 — 전제가 다른 자료를 같은
길에 실으면 세 번째가 된다. **묶음 하나 단위의 전용 endpoint**
(`POST /d/<slug>/g/<gid>/link`)로 간다:

- 서버가 다시 검사한다: 멤버가 검토 대상 묶음(또는 `batch=NULL`)의 실제
  마스크인가 · 이미지가 그 시야의 것인가 · 대표가 정확히 하나인가 ·
  마스크가 다른 묶음에 이미 속해 있지 않은가
- 풀기는 명시적 `act=unlink` 다

**감사 기록** — `export_review.py` 를 FORMAT 4 로 올려 `links` 절을 더한다.
사람이 만든 것은 전부 git 으로 나간다는 규약 그대로다. `--check` 도 함께.

**`check_db.py` 에 8번(묶음) 절을 더한다**: 멤버의 이미지가 묶음의 시야에
속하는가 · 대표가 하나인가 · 멤버가 가리키는 마스크가 실재하는가(현재 검출
또는 교정의 geom).

## 7. 묶인 것이 화면에 어떻게 보이나 (4단계 — 최소로)

1판은 **표시만** 한다:

- 묶인 마스크에 작은 사슬(⛓) 배지 — hover 말풍선에 "N개 프레임과 묶임 · 대표: …"
- 캐러셀로 프레임을 옮기면 **같은 묶음의 멤버가 반짝** — "지금 보는 이것이
  아까 그것" 을 눈이 따라간다

개체 수 집계·학습 자료 내보내기에 묶음을 반영하는 것은 **다음 계획**이다 —
집계가 바뀌면 목록·통계의 뜻이 함께 바뀌므로 따로 결정하고 간다.

## 8. 단계 (실행 순서)

| 단계 | 무엇 | 크기 |
|---|---|---|
| 0 | **문턱 실측** — yolo-3차로 같은 자리 후보의 IoU·중심거리 분포 | 스크립트 하나, 반나절 |
| 1 | 스키마 + 마이그레이션 + `check_db.py` 8번 | 마이그레이션 1개 |
| 2 | 후보 제안 + 팝업 (화면) + 저장 endpoint | 이번 일의 몸통 |
| 3 | 표시(배지·캐러셀 반짝) + 읽기 전용 잠금 + 시험 | |
| 4 | `export_review.py` FORMAT 4 + `--check` | |

시험은 늘 하던 기준 — **되살려서 잡히는 것을 보고 나서 "있다" 고 말한다.**
브라우저 겹: 우클릭 → 팝업 → 고르기 → 별 → 저장 → 새로고침 후 남아 있는가,
그리고 읽기 전용 화면에서 메뉴가 **없는가**.

## 9. 미리 답해 둔 것 · 열어 둔 것

**답해 둔 것** (이 문서의 결정):

- 사람이 고른 묶음은 재생성 불가 → `ObjectReview` 규약(§2·§3)
- 합성본 마스크도 멤버다 (§3)
- 후보 계산은 화면에서, 새 API 없이 (§4)
- 저장은 전용 endpoint, `/review` 에 안 싣는다 (§6)
- 탈락 후보는 1판에서 뺀다 (§4)
- 집계 반영은 다음 계획으로 (§7)

**열어 둔 것** (구현 중 실측·사용감으로 정한다):

- 근접 문턱의 실제 값 (0단계가 정한다)
- 자동 미리 고르기의 IoU 문턱 — 너무 낮으면 틀린 것을 골라 두고, 사람은
  미리 골라진 것을 의심하지 않는다 (자동값이 사람 판단을 오염시키는 자리)
- 묶기 단축키를 줄 것인가 (지금은 우클릭 메뉴만 — 040 의 전례로는 자주
  쓰이면 키가 생기는 쪽으로 갔다)
