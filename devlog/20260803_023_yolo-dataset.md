# 전수 표시를 포기하고, 검토 264 시야를 그대로 학습 자료로 만든다

**날짜** 2026-08-03
**앞선 문서** `20260803_P04_yolo-training.md` (이 작업으로 개정됐다)

P04 는 "0단계에서 10~15 시야를 전수 표시해 재현율 기준선을 만든다" 로 시작했다.
그것이 뷰어로 되는지 확인한 결과 **0단계를 버렸고**, 대신 이미 끝난 264 시야로
YOLO 자료 꾸러미를 만들었다. 판단의 경위를 적는다.

---

## 1. 전수 표시가 되는가 — 부분적으로만

뷰어(`_detection.html`)의 도구는 이것뿐이다.

```
data-act = all | none | reset | ghosts | undo | clear
<input type="checkbox" data-layer="reject">  탈락
```

**되는 것.** `탈락` 층을 켜면 문턱에서 떨어진 후보가 빨간 점선으로 보이고 클릭해
되살릴 수 있다. 실제로 그렇게 **376건을 되살렸다** — 탈락 풀에 진짜 규조각이
들어 있다는 증거다.

**안 되는 것 둘.**

1. **새로 그릴 수 없다.** 되살리기는 SAM2 가 마스크를 만든 것 중에서만 된다
2. **크기 관문이 DB 이전에 자른다**

```
SAM2 원시 마스크        58,389
크기 관문(10~150 µm) 통과 34,250  (59%)   ← Candidate 가 되는 것
관문에서 사라진 것       24,139           ← DB 에 없어 되살릴 수 없다
```

## 2. 그래도 하지 않기로 했다

전수 표시를 하려면 **시야당 탈락 후보 107개**(90%는 166개)를 훑어야 한다.
통과분 17개의 6배다. 15 시야면 1,600여 개를 하나씩 판단하는 일이다.

그 비용을 치러도 위 두 구멍 때문에 얻는 것은 "진짜 재현율" 이 아니라
**"SAM2 의 상한 대비 재현율"** 이다. 완전한 기준선이 아니다.

판단 근거는 사용자의 것이었고, 옳다.

> 지나치게 fragmented 된 규조각을 놓치는 건 어쩔 수 없다고 생각해. 그리고
> 처음부터 YOLO 가 완벽하게 다 잡아낼 수 있다고 생각하지도 않고. 어느 정도
> 되는 걸 만들어 놓고 iteration 을 계속 돌아야지.

- 파편까지 세는 기준선은 실제 분석 목적(개체 세기·군집 조성)에 필요하지 않다
- 첫 모델이 완벽할 것이라 보지 않는다면, 기준선의 정밀함보다 **비교 가능성**이
  중요하다. SAM2 와 YOLO 에 같은 자를 대면 "나아졌나" 는 답할 수 있다

**남는 빚을 문서에 못 박았다.** 이렇게 재는 재현율에는 "SAM2 후보 범위 안에서"
라는 한정이 붙는다. `MANIFEST.json` 의 `recall_caveat` 에도 넣었다 — 자료 꾸러미만
들고 다른 기계로 가도 따라가게.

## 3. 확인한 것 — 검토가 지금 검출에 유효한가

스케일 정정(015) 뒤 재검출이 검토를 무효로 만들었을 수 있어 시각을 대조했다.

```
슬라이드 7장 전부   검출 7/30~7/31   <   검토 7/30~8/3
```

**모든 슬라이드에서 현재 검출이 검토보다 앞선다.** 재검출은 검토 *전*에 끝났다.
`rebind.py` 를 거친 라벨이 아니라는 뜻이라 신뢰도가 균일하다.

이 대조는 **재검출을 할 때마다 다시 해야 한다.** P04 §유의에 넣었다.

## 4. 타일링을 버렸다

P04 초판은 "원본 2752×2208 에 개체 중앙값 199 px 이니 640 타일로 자른다" 였다.
전제가 **"YOLO 는 640 으로 줄여 학습한다"** 였는데, `imgsz` 는 그냥 인자다.

| imgsz | 축소비 | 중앙 개체 | 작은 쪽 10% |
|---|---|---|---|
| 640 | 0.23 | 39 px | **20 px — 뭉개진다** |
| **1280** | **0.47** | **79 px** | **40 px** |

`imgsz=1280` 이면 작은 쪽 10% 도 40 px 라 충분하다. 타일링은 **경계에 걸친 개체**
라는 새 문제를 만드는데(최대 1331 px 짜리는 640 타일 어디에도 안 들어간다),
겹침·면적 기준·중복 제거가 전부 내가 새로 정하고 새로 틀릴 수 있는 규칙이다.
RTX 8000 은 48 GB 라 1280 을 감당한다 — 치를 이유가 없는 대가였다.

부수 효과로 이미지가 7,000 타일이 아니라 **264 장**이 됐다. 344 MB 라 옮기기 쉽다.

## 5. `export_yolo.py`

```bash
python export_yolo.py --out /data3/diatom/datasets/yolo-v1 --dry-run
python export_yolo.py --out /data3/diatom/datasets/yolo-v1
python export_yolo.py --out /data3/diatom/datasets/yolo-v1-seg --seg
```

### 판정을 다시 쓰지 않는다

`viewer.data.detection_for_viewpoint()` 를 그대로 부른다. `(passed and not
removed) or (not passed and accepted)` 를 여기 옮겨 적으면 언젠가 갈라지고,
**갈라진 것은 눈에 띄지 않는다.** 화면에 보이는 것이 곧 라벨이어야 한다.

이미 같은 이유로 데인 적이 있다 — `data.py:542` 의 주석("판정 규칙은
`_apply_review` 와 같아야 한다")이 목록 화면을 빠르게 만들면서 붙은 것이다.

### 음성을 따로 내보내지 않는다

사람이 지운 4,039건은 **라벨을 안 쓰는 것으로 충분하다.** YOLO 는 라벨 없는
자리를 배경으로 배운다. SAM2 가 실제로 헷갈린 자리에 사람이 "아니다" 를 붙인
것이라 무작위 배경보다 값어치가 크고, 그것이 이미지 안에 그대로 들어간다.

개체 0인 시야 29개도 빈 라벨 파일로 낸다 — YOLO 가 권하는 배경 비율(10% 안팎)과
정확히 맞는다(29/264 = 11%).

### 검증을 둘로 나눈다

```
train      시야 177  개체 1,046   빈 시야 23
val        시야  44  개체   256   빈 시야  6     ← 학습이 되고 있나
val_slide  시야  43  개체   201   빈 시야  0     ← 슬라이드를 외웠나
```

`val` 이 좋은데 `val_slide` 가 나쁘면 염색·조명·쇄설물 같은 **슬라이드 고유의
특징을 외운 것**이고, 새 슬라이드에는 안 듣는다는 뜻이다.

**빼는 슬라이드를 고르다 한 번 되돌렸다.** 처음에는 가장 큰
`260731_rs23-gc03_369cm`(847개, 56%)을 뺐는데 결과가 이랬다.

```
train 513   val 143   val_slide 847      ← 검증이 학습보다 크다
```

뒤집힌 모양이다. `wap13-gc47_450cm` 으로 바꾸니 1,046 / 256 / 201 로 셋 다 쓸 만하고,
**학습은 RS 에 쏠려 있는데 검증은 다른 해역**이라 "새 슬라이드에 듣는가" 라는
실제 질문에 더 가깝다. 그림으로 확인해 보니 WAP 슬라이드는 광물 쇄설물이 훨씬
많아 배경이 눈에 띄게 다르다 — 고르길 잘했다.

시야는 슬라이드 위의 서로 다른 자리라 같은 개체가 양쪽에 들어가지 않는다.
남는 누출은 표본 준비·촬영 조건이 같다는 것뿐이고, `val_slide` 가 정확히
그것을 잰다.

### 단일 분류로 시작한다

```
rod 506 · round_frag 420 · rod_frag 256 · round 218 · eucampia 68 · 미분류 35
```

`rod`/`round`/`frag` 는 **`judge.py` 가 이미 신장률에서 계산한다.** YOLO 가 상자를
내면 거기서 그대로 나오므로 모델에게 배우게 할 이유가 없고, 1,503개를 나누면 각
분류의 표본만 줄어든다. `eucampia` 는 68개뿐이다.

**모델이 새로 배워야 하는 것은 "규조각인가 아닌가" 와 (나중에) "무슨 속인가" 뿐이다.**

## 6. 검증 — 숫자만 믿지 않았다

**형식.** 라벨 1,503줄 = DB 개체 수와 정확히 일치. 좌표가 전부 0~1 안, 상자가
이미지 밖으로 나간 것 0건, 넓이 0 인 것 0건, 이미지·라벨 파일 짝이 전부 맞음.
체크섬 표본 20개 불일치 0.

**그런데 형식이 맞아도 좌표가 맞다는 뜻은 아니다.** 지도를 그릴 때 SVG 속성
길이만 보고 넘겼다가 해안선이 통째로 빈 화면이 됐던 일이 있다(021). 그래서
내보낸 라벨을 이미지에 **되그려서 눈으로 봤다.**

`train`(369cm, 32개) · `val_slide`(WAP450, 11개) 둘 다 상자가 규조각 위에
정확히 앉았다.

### 그러다 발견한 것 — 상자의 절반이 배경이다

되그린 그림에서 **대각선으로 누운 봉상**의 축정렬 상자가 눈에 띄게 비어 보였다.
재 봤다(개체 면적 ÷ 상자 면적).

| 분류 | n | 중앙 | 10% |
|---|---|---|---|
| **rod** | 506 | **0.52** | 0.26 |
| rod_frag | 256 | 0.54 | 0.34 |
| eucampia | 68 | 0.50 | 0.34 |
| round_frag | 420 | 0.67 | 0.54 |
| round | 218 | 0.77 | 0.67 |
| 전체 | 1,503 | 0.62 | 0.34 |

**상자의 절반 이상이 배경인 개체가 409개(27%)다.** 봉상은 중앙값이 0.52 —
절반이 배경이다. 축정렬 상자로는 어쩔 수 없는 일이고, 이것이 분할(`-seg`) 학습을
해 볼 이유가 된다.

폴리곤이 이미 전부 있으므로 `--seg` 로 두 번째 꾸러미를 함께 냈다. 같은 1,503개,
점 개수 중앙 18(최소 7, 최대 46), 검증 문제 0건.

꾸러미는 `/data3` 에 둔다. 저장소에 넣지 않는다(344 MB, 재생성 가능).
