# 125 · 축소본을 미리 굽는다 — "검토 화면이 느려졌다" 를 재 본 결과

2026-08-18 · sclee (UI·배포 파트)

## 신고와 실측

"검토 페이지 불러오는 게 조금 느려진 것 같다."

**서버는 느려지지 않았다.** 재 본 것을 먼저 적는다.

| 잰 것 | 값 |
|---|---|
| 검토 화면 렌더 (570 시야 전수, 테스트 클라이언트) | 중앙값 20ms · 최대 122ms · 질의 35~56개 |
| 운영 TTFB (`curl`, nginx 거쳐) | 가벼운 시야 19ms · 무거운 시야 76~102ms |
| 헤드리스 크로미움 `load` | 78 · 162 · 188ms (콘솔 오류 0) |

**08-14 사본과 08-18 사본이 같은 숫자를 낸다** (합 12.4s vs 12.6s, 중앙값 둘 다
20ms). DB 파일 크기도 그 사이 한 바이트도 안 늘었다 — 자료가 늘어 느려졌다는
갈래는 성립하지 않는다.

## 그러면 무엇이 느렸는가 — 찬 축소본

`views._thumbnail` 은 `경로|mtime|폭` 으로 캐시하고 **지우지 않는다.** 있으면
**2ms**, 없으면 **w=220 이 97ms · w=1600 이 146ms** 다. 검토 화면 한 장이
축소본을 열 개 남짓 부르고 워커가 셋이라, **한 번도 안 연 시야는 처음 여는
사람이 1초 가까이 대신 기다린다.**

합성본 421장 중 **171장(41%)이 w=1600 축소본이 없었다.** 갑자기 식은 것이
아니다 — 합성본 mtime 을 대조해 재생성 흔적이 없음을 확인했다. 그냥 **아직 아무도
안 연 시야들**이고, 검토가 새 슬라이드로 넘어가는 중이면 여는 화면마다 그렇다.
"느려졌다" 는 여기서 나온다.

342자리(합성본 × 폭 둘)를 구웠다. 146ms → 1.7ms 가 됐고 캐시는 379M → 413M 이다.

## 앞으로 — 폴러가 굽는다

`deploy/warm_thumbs.sh` 를 새로 두고 `poll_nas.sh` 가 **합성이 끝난 직후** 부른다.

**검출을 기다리지 않는다.** 화면이 부르는 축소본은 합성본과 프레임에만 달려
있고 그것은 그때 다 있다 — 검출은 그 위에 그리는 것이라 주소를 안 바꾼다.
검출 한 바퀴가 슬라이드마다 한 시간 반이라, 여기서 굽지 않으면 그 사이에 화면을
연 사람이 대신 기다린다.

**실패해도 폴러를 멈추지 않는다.** 굽는 것은 빠르게 만드는 일이지 자료가 서는
조건이 아니다 — 여기서 멈추면 검출이 통째로 안 돈다.

## 버린 길 셋

**1. 호스트에서 PIL 로 직접 굽기.** 캐시 열쇠가 **두 벌**이 된다(`_thumbnail`
과 굽는 쪽). 한 글자만 갈려도 굽는 쪽은 "구웠다" 고 하고 뷰어는 계속 새로
만든다 — 아무 예외 없이. 소유자도 갈린다(`.thumbcache` 는 컨테이너의
`1000:1000` 것이고 호스트에서 만들면 다른 uid 가 된다). **뷰어에게
`/img?p=…&w=…` 로 청한다** — 열쇠는 그 함수 하나에만 있다.

**2. 폭 목록을 스크립트에 적기.** `{% thumb %}` 이 부르는 폭은 지금 300·220·
1600 인데, 이것을 스크립트에 베껴 두면 템플릿이 바뀐 날 조용히 갈린다.
**화면을 열어 화면이 부르는 주소를 그대로 다시 부른다** — 폭이 바뀌거나 판이
하나 늘면 굽는 것도 따라간다. 시야 번호도 목록 화면의 링크에서 읽는다(세는
자리를 둘로 두지 않는다).

**3. 따로 도는 크론.** `poll_nas.sh` 의 그 자리가 이미 뷰어를 HTTP 로 눌러 보는
자리다(057 의 목록 검사). 자료가 들어오는 자리와 굽는 자리가 같아야 한다.

## 함정 하나 — 404 가 "구울 것이 없다" 로 지나갔다

처음 판은 `curl` 의 종료 코드만 봤다. 없는 슬러그를 주면 404 본문에 축소본
주소가 없으니 **"구울 축소본이 없다" 를 내고 0 으로 끝났다** — 굽는 일이 안
됐는데 됐다고 말하는 자리다(CLAUDE.md "화면이 아무 일도 안 하고 됐다고 말하는
것"). **HTTP 코드를 본다.** 시야 화면이 500 이면 나머지는 계속 굽되 **못 연
시야 수를 세어 말하고 종료 코드를 1 로 낸다.**

## 남은 것 — 이번에 안 고친 것

재 보다 나온 것들이다. 지금 사람이 느끼는 것은 아니라 손대지 않았다.

- **무거운 시야는 HTML 이 1 MB 다.** 915 KB 중 591 KB 가 `shot_dets` 이고 그
  절반 넘는 **320 KB 가 탈락 후보**다. 판 9개마다 통과 438 + 탈락 480개를 지표
  21칸과 폴리곤까지 통째로 싣는다. localhost 에서는 안 보이고 사내망 너머에서만
  드러난다
- **그린 개체의 지표를 열 때마다 다시 잰다.** `_orphan_dict` → `shape.measure`
  (`_clip_convex`)가 판마다·개체마다·요청마다 돈다. 전체로는 4% 지만 교정이
  많이 쌓인 시야에서 42ms 다(최대 페이지 84 → 122ms). `_orphan_dict` 주석의
  "재는 값이 싸다" 는 개체 하나 기준으로는 맞는데, **106 번지기가 그린 마스크를
  판 전부에 퍼뜨리므로 판 수만큼 곱해진다** — 검토를 할수록 그 시야가 느려진다
- **옛 자료의 프레임 축소본은 아직 차다** (필름스트립 220 · 판 교체용 1600).
  사용자 판단으로 지금은 두고 새 자료만 굽는다 — 필요하면
  `warm_thumbs.sh <slug>` 를 손으로 부르면 된다
- **운영 DB 의 빈 페이지가 27.9%(30 MB)다.** 질의 시간은 0에 가까워 지금 문제는
  아니지만 VACUUM 할 자리는 된다
