# 116 — 완료 표시가 서버에 안 가는 갈래와, 번지기가 옮겨 놓은 대표

검토자가 아침에 `AM22-GC10B 25cm` 를 검토하고 **"제대로 저장되지 않는 사례가
있다"** 고 했다. 이 문서는 그 이력을 읽어 무엇이 실제로 났는지 가른 기록이고,
고침 셋과 이미 앉은 값을 치우는 스크립트가 함께 있다.

## 1. 먼저 — 잃은 것은 없었다

`sclee` 계정에는 docker 가 없고 운영 DB 는 WAL 이라 `mode=ro` 로도 못 읽는다
(`-shm` 을 못 쓴다). 그래서 **시간별 사본 둘을 행 단위로 대조**했다.

| | 10:20 사본 | 11:20 사본 |
|---|---|---|
| ObjectReview | 7,924 | 8,195 (새 271 · **사라짐 0** · 바뀜 16) |
| DiatomObject | 7,913 | 8,044 (새 131 · 사라짐 0) |
| ViewpointReview | 523 | 556 (새 33 · 사라짐 0) |

**사라진 행이 없다** — 017·027·053 계열의 "그 시야의 교정을 통째로 갈아치웠다"
가 아니다. 10:47~10:59 에 시야 1→29 가 순서대로 저장됐고 삭제 44건과 분류
재지정이 전부 들어가 있다. 살아 있는 판은 HTTP 로 확인했다(`/healthz` 와
`api/d/<slug>.json` 은 읽기 전용이라 규약에 걸리지 않는다).

**테스트 인스턴스로 잘못 들어간 검토도 없었다.** `/DiaRUGATest/` 는 11:02 에
사본으로 갈렸고 그 슬라이드가 1/30 인 10:20 상태 그대로였다 — 115 의 워터마크가
막으려던 사고는 이번에 안 났다.

## 2. 이상 하나 — 시야 하나만 미검토로 남았다

`g028` 만 `done=0` 이었다. `ViewpointReview` 의 id 가 생성 순서를 말해 준다:

```
id 553  g027  done=1  10:56:08
id 554  g028  done=0  10:59:28   ← 555 보다 먼저 생겼다 = 10:57:25 에 생성
id 555  g029  done=1  10:58:52
```

즉 **g028 에서 저장 → g029 완료 → g028 로 되돌아와 다시 저장**이고, 마지막이
`done=0` 이다. 검토자는 **"완료를 푼 적이 없다"** 고 했다. 해제에는 `confirm()`
이 걸려 있어 모르고 풀 수는 없으므로, 누른 것이 서버에 안 갔다는 뜻이다.

### 어디가 샜나

완료 버튼은 켜고 · 칠하고 · 저장하고 · 곧바로 다음 시야로 넘어간다.

```js
reviewDone = !reviewDone;
paintDone();
save();
if (reviewDone) { leave(url); }
```

`save()` 에는 **`savePending` 을 안 세우고 돌아가는 갈래**가 있다 — 커서가
캐러셀의 옆 판을 스치는 중(`previewing`)이면 지나가는 판에 판단이 앉는 것을
막으려고 눌린 것을 버린다(074). 그러면 `leave()` 가 부르는 `flushSave()` 는
`if (!savePending) return` 으로 빠지고 곧바로 `location.href` 가 돈다.

**버튼은 완료로 바뀌고 화면은 다음 시야로 넘어가는데 서버는 요청을 한 번도 못
받는다.** 저장 실패 띠도 안 뜬다 — 실패한 요청이 없기 때문이다. 051 에서 배운
것과 같은 이야기이고, 이번에는 **읽기 전용이 아니라 정상 화면**에서 났다.

`previewing` 은 썸네일 위로 커서가 지나가기만 해도 켜지고
(`swapDet(s, commit=false)`), `strip` 의 `mouseleave` 가 푼다. 그래서 **마우스를
움직여 누르면 안 나고, 커서가 판 위에 남은 채로 눌릴 때만 난다** — 브라우저
시험도 `page.click` 으로는 통과했고 `el.click()` 으로 바꾸고서야 잡혔다.

`g028` 은 판이 넷이고 그린 마스크가 여섯이라 **캐러셀을 가장 많이 오간 시야**다.
`done=0` 인데 교정은 들어가 있는 시야가 DB 에 넷 있는데 **전부 판이 여럿이다**
(판이 하나뿐인 시야에는 한 건도 없다).

**거르는 조건이 무엇을 위한 것이었나가 요점이다.** 074 가 막으려던 것은 *판에
앉는 판단*(분류 키)이고, 완료는 **시야에 붙는 표시**다. 지나가는 판을 걱정할
일이 애초에 없었는데 같은 문을 지나면서 함께 걸렸다.

### 덧 — `leave()` 가 안 기다렸다

같은 자리에서 하나 더 나왔다. `flushSave()` 는 **약속을 돌려주는데**(묶기 POST
가 그 뒤에 서려고 그렇게 만들었다) `leave()` 는 그것을 안 기다리고 곧바로
떠났다. keepalive 가 붙어 있어 대개는 나가지만, 그 함수의 주석이 이미 적어 둔
대로 **본문이 64 KB 를 넘으면 브라우저가 보내 보지도 않고 거절한다** — 교정과
그린 폴리곤이 많은 시야가 정확히 그 크기다.

**실패하면 안 떠나게 했다.** 떠나면 그 판단이 화면에서도 사라져 실패 띠를 볼
사람이 없다. 저장이 계속 실패하면 시야를 못 옮기는데, 그쪽이 맞다 — 잃는 것보다
막히는 편이 낫고 띠가 이유를 말한다.

## 3. 이상 둘 — 번지기가 개체의 얼굴을 옮겼다

`is_rep` 은 *"학습 자료로 뽑을 때, 목록에 보일 때 이 판을 쓴다"* 이다. 오늘
아침 그린 개체 아홉의 대표가 **합성본에서 단일 프레임으로** 옮겨갔다.

```
7811~7816  stacked/g024_..._focused.jpg   is_rep 1 → 0
8427,8430,…  Snap-22174.jpg               is_rep = 1   ← 새로 생김
```

`_spread_drawn` 의 머리말은 **"대표는 그린 판이다"** 라고 적어 놓았는데, `src`
는 그린 판이 아니라 **저장할 때 열려 있던 판**이다. 08-09 에 합성본에 그린
마스크를 오늘 프레임 판을 열어 둔 채 저장하니 그 프레임이 `src` 가 되고,
합성본이 target 으로 밀려 대표를 잃었다. 새 대표는 **가장 선명한 프레임도
아니다**(g028 의 sharpest 는 `Snap-22175` 인데 대표는 `Snap-22174` 가 됐다).

**예외도 경고도 안 난다.** 대표는 개체당 하나라는 제약을 계속 지키므로
`check_db` 8번에 안 걸리고, 화면은 그냥 다른 크롭을 보여줄 뿐이다. 엔진 개체는
판이 여럿인 43개 중 1개뿐인데 손그림은 13개 중 9개였다 — 번지기를 탄 것만 걸린다.

**고를 기준을 바꿨다.** *어디서 눌렀나* 가 아니라 **어느 판이 이 규조각을 가장
잘 보여주나** 여야 한다. 합성본이 그것이다(all-in-focus 로 합친 그림이고, 판
넷 중 하나를 고르는 문제가 아니다). 합성본이 없는 시야는 `src` 를 그대로 쓴다.

## 4. 고친 것

| 자리 | 무엇 |
|---|---|
| `_detection.html` 완료 버튼 | 상태를 바꾸기 전에 `previewing` 을 걷는다 |
| `_detection.html` `leave()` | `flushSave()` 를 기다리고, 실패하면 안 떠난다 |
| `data._spread_drawn` | 대표를 **합성본**으로 고른다 (없으면 `src`) |
| `migrate/refix_drawn_reps.py` | 이미 앉은 아홉을 되돌린다 (기본 dry-run) |

## 5. 시험

`tests/browser/test_done_lost.py` 넷과 `tests/test_drawn_spread.py` 둘을 더했다.
**넷 다 고치기 전 코드에서 실패하는 것을 보고 나서 넣었다** — `leave()` 만 옛
모습으로 되돌려 돌려 보고, `_spread_drawn` 의 대표 고르기만 되돌려 돌려 봤다.

대조군을 함께 뒀다. "판을 안 스치면 저장된다" 와 "저장이 되면 넘어간다" 가
없으면, 아예 못 넘어가게 만들어 놓고도 통과한다.

`test_대표는_그린_판이다` 는 규칙이 바뀌었으므로 **이름을 `test_대표는_합성본이다`
로 고쳤다** — 이름과 뜻이 어긋나면 둘 중 하나를 고친다.

679개 전부 통과 (브라우저 130개 포함, 175초).
