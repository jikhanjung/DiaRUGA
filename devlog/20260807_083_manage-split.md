# 083 — 관리 화면을 셋으로 가른다 (자료 · 운영 · 학습 자료)

2026-08-07

## 왜 가르나

`/manage/` 하나에 층 편집(지역·지점·시료)과 검토할 묶음 고르기가 함께 있었다.
**묻는 것이 다르고 쓰는 때가 다르다.**

| 화면 | 무엇을 묻는가 | 얼마나 자주 |
|---|---|---|
| **자료** | 이 관찰이 어느 지점·시료의 것인가 | 새 슬라이드가 들어올 때 |
| **운영** | 지금 무엇을 보고 있고 새 자료를 어떻게 채우는가 | 회차를 돌릴 때 |
| **학습 자료** | 검토한 것에서 정답을 얼마나 뽑을 수 있는가 | 다음 회차를 준비할 때 |

한 화면에 다 있으면 **자주 쓰는 것이 드물게 쓰는 것에 묻힌다** — 실제로 층
편집표 셋 아래에 묶음 고르기가 있었다.

## 운영 — 조리법을 화면에서 적는다

079 가 `RunBatch.recipe` 를 만들었지만 **DB 를 직접 고쳐야** 했다. 그 나머지
절반이다.

- **새 자료를 채우는 순서** — `data.batches_to_run()` 이 정한 그대로. 검토 중인
  묶음 먼저, 나머지는 최근 것부터. 못 돌리는 묶음도 **이유와 함께** 남긴다
- **조리법 폼** — 엔진·가중치·배율·크기·`--all-images`. 이름을
  `segment_diatoms.py` 의 인자와 **같게** 뒀다: 화면에서 고친 값이 그대로
  명령줄이 되므로 이름을 바꾸면 `batch_plan.py` 와 갈라진다

**엔진을 비우면 조리법을 통째로 비운다** = 그 묶음은 자동으로 안 돈다. 끝난
회차를 그대로 두는 것이 기본이다.

**가중치 파일이 없어도 저장은 받는다.** 아직 학습이 안 끝났는데 조리법을 먼저
적어 둘 수 있어야 한다 — 대신 목록에 "못 돌림" 으로 뜨고 저장할 때도 그렇게
말해 준다. 저장을 막으면 파일을 만들 때까지 아무것도 적어 둘 수 없다.

**화면이 보여주는 명령은 폴러가 실제로 먹는 것과 같아야 한다.** 다르면 사람이
화면을 믿고 틀린 명령을 만든다 — 시험이 `--backend yolo`·`--weights`·
`--all-images` 가 화면에 그대로 나오는지 본다.

## 학습 자료 — 가중치를 만드는 화면이 아니다

이름을 정확히 해 두었다(사용자, 2026-08-07): 여기서 하는 일은 **검토가 끝난
결과에서 정답을 뽑는 것**이고 **학습은 그다음 별도의 일**이다. 이 구분이
흐려지면 "학습이 왜 안 좋지" 를 자료 문제와 학습 문제로 가를 수 없다.

보여주는 것:

- 검토완료 시야 · 정답 개체 · **오검출로 지운 것**
- 슬라이드별 시야·개체와 **비중** — 한 슬라이드가 절반을 넘으면 그것을 빼고
  검증해야 "새 슬라이드에 듣는가" 를 물을 수 있다(P04)
- 내보내는 **명령** (돌리지는 않는다)

**세는 기준이 `export_yolo.py` 와 같다.** 다르면 화면이 말한 수와 내보낸 수가
달라지고, 그때 어느 쪽이 맞는지 알 수가 없다.

**화면에서 내보내기를 돌리지 않는다.** 이미지 수천 장을 복사하는 일이라 요청
하나가 몇 분씩 걸리고 그동안 웹 일꾼 하나가 묶인다. 무엇을 돌릴지 정확히
적어 주고 사람이 붙여 넣는 편이 정직하다.

### 오답은 어디로 가나

사람이 지운 것은 **라벨을 안 만드는 것으로 쓰인다** — YOLO 는 라벨 없는 자리를
배경으로 배우고, 엔진이 실제로 헷갈린 자리라 무작위 배경보다 값어치가 크다
(`export_yolo.py` 머리말). 화면에 수를 적어 그것이 버려지는 것이 아님을 보인다.

## 밟은 것 둘

### `export_yolo.py` 가 073 에서 조용히 깨져 있었다

```python
Viewpoint.objects.filter(review__done=True)     # FieldError
```

073 이 검토 완료를 묶음마다로 가르면서 `review`(OneToOne)가 `reviews`(FK)가
됐는데 이 스크립트가 안 따라갔다. **화면이 아니라 명령줄이라 아무도 안 밟았을
뿐**이고, 다음에 자료를 뽑으려는 순간 죽었을 것이다.

`(viewpoint, batch)` 로 고쳤다 — **검토 중인 묶음에서 끝낸 시야**만 쓴다. 다른
묶음에서 끝낸 것을 섞으면 "이 묶음이 낸 검출을 사람이 봤다" 가 아니게 되고,
그러면 정답이 아니다.

### 표 CSS 가 한 번도 안 먹었다

묶음 표를 운영 화면으로 옮겼는데 `.mtab`·`.nowrow`·`.nowtag` 는 자료 화면의
`<style>` 안에 남아 있었다. **"검토 중" 줄이 보통 줄과 똑같아 보였다** —
051 의 `.tools` 와 같은 종류다.

`getComputedStyle` 로 배경색을 견주는 시험이 그것을 잡았다. 세 화면이 함께
쓰는 조각(`_managenav.html`)으로 옮겼다.

## 남은 것
