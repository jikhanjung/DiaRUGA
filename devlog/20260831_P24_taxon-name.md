# 학명 유효성 판정을 DB 에 넣는다 — `TaxonName` (계획)

P15(20260813_P15_atlas-db.md) §8.1 이 "방침이라 admin 이 정한다"며 미뤄 둔
`TaxonName` 을 이제 만든다. 계기는 사용자가 `/atlas/` 에서
`Actinocyclus ehrenbergii`(옛 이름)를 찾다가 "찾은 것이 없습니다" 를
보고 "이명으로 검색해도 최신화한 학명을 같이 보여줘야 한다" 고 한 것
(2026-08-31) — 그 이름의 판정은 **이미 `worms_master_20260814.tsv`
첫 줄 부근에 있었다**(사람이 지운 적 없다, 아래 "자료" 참고).

## 자료 — 세 벌 다 살아 있다 (확인함, 2026-08-31)

| 자리 | 무엇 | 크기 |
|---|---|---|
| `Diadiction/names/worms/worms_master_20260814.tsv` | 도감 1,845종 전체의 판정 마스터 표(4,064행, 08-14~08-26 37일치 배치) | **`AlgaeBase` 칼럼 채워진 것 1,845 · 그중 새 이름으로 갈아탄 것 668** |
| `Diadiction/md/name_validity_log.md` | 위 표의 서사식 요약(근거 문헌·비고까지) | 21건 표 + 산문 |
| `Diadiction/temp/paper_plates_156_result.json` | 논문 도판 8편(P22·P23) 캡션 학명 156종의 AlgaeBase 조회 결과(2026-08-31 사용자가 직접 조회) | **매칭 103 · "synonym of X" 41** |

**세 자료의 열쇠가 갈린다.** worms_master 는 `harvest_worms.binomial()` 이
뽑는 정규화된 이명법("Genus species")과 같은 모양이라 `AtlasEntry.binomial`
과 바로 맞는다. `paper_plates_156_result.json` 은 `plate_figs.py` 의
"짐작한 전체 학명"(사람이 캡션에서 손으로 옮긴 것)이 키라 **`binomial()`
을 통과시켜 다시 정규화해야 한다** — 이미 정규화된 것도 있고
(`Actinocyclus octonarius`) `var.`가 붙은 것도 있다(`Actinocyclus
ehrenbergii var. tenella`, 이 경우 `binomial()` 은 두 낱말만 보므로
그대로 "Actinocyclus ehrenbergii" 가 된다 — **변종 표시가 떨어진다는
것을 반입기가 알아야 한다**, 종 단위로 뭉뚱그려도 되는지는 8절에서 정함).

## 스키마 — `Atlas` 와 같은 자리다 (P15 8.1 이 권장한 쪽)

md/tsv 가 **원본**이고 DB 는 **사본**이다 — 지우고 다시 만들어도 안전하다
(사람의 판단 자체는 NAS 의 파일에 git 밖에서 영구히 남는다, `Atlas` 의
"언제든 통째로 지우고 다시 만들 수 있어야 한다" 와 같은 논리).

```python
class TaxonName(models.Model):
    """학명 하나의 AlgaeBase 유효성 판정 (P15 8.1 · P24).

    원본은 NAS(worms_master_20260814.tsv · paper_plates_*_result.json 류) —
    사람이 브라우저로 AlgaeBase 를 열어 내린 판단이라 재생성 불가지만,
    **그 판단 자체는 여기가 아니라 NAS 파일에 있다.** 이 표는 거기서
    뽑은 사본이라 Atlas 처럼 통째로 갈아치울 수 있다.
    """
    binomial = models.CharField(max_length=120, unique=True)  # harvest_worms.binomial() 정규화 값
    status = models.CharField(max_length=16, choices=[
        ("accepted", "유효"), ("synonym", "이명"),
        ("absent", "AlgaeBase 에 없다"), ("unassessed", "확인 필요/미확인"),
    ])
    valid_name = models.CharField(max_length=120, blank=True, default="")  # synonym 일 때만 채운다
    source = models.CharField(max_length=64)   # 'worms-master-20260814' | 'paper-plates-20260831' 등 원본 파일
    note = models.TextField(blank=True, default="")   # AlgaeBase비고·근거 문헌
    checked = models.CharField(max_length=32, blank=True, default="")  # 확인일/갱신일 원문 그대로
```

**`AtlasEntry` 에 FK 를 매달지 않는다** — `Occurrence.source`(P20)와 같은
이유다. 도감 반입이 `AtlasEntry` 를 통째로 갈아치우므로 FK 를 매면 CASCADE 로
사라진다. `binomial` 문자열로 느슨하게 잇고, 맞추는 것은 질의가 한다
(`atlas_search` 가 이미 이 자리에 `_occurrences_by_binomial()` 패턴을
가지고 있다 — `_taxon_names_by_binomial()` 을 그 옆에 만든다).

## 반입 — 2단계, 도감과 같은 문

```
1) NAS(tsv·json) → taxon_names.json   호스트에서 돈다, 저장소에 커밋
2) taxon_names.json → DB              dbrun.sh 로 컨테이너 안에서 (ops/import_taxon_names.py)
```

`tools/parse_taxon_names.py`(새로 만든다)가 1단계를 한다 — 두 소스를
읽어 `binomial()` 로 열쇠를 맞추고 **충돌하면(두 소스가 같은 이름에
다른 판정을 냈으면) 최신 확인일 쪽을 우선하되 그 사실을 `note` 에
남긴다**(엇갈렸다는 사실을 지우지 않는다 — `name_validity_log.md` 의
규칙 그대로). `ops/import_taxon_names.py` 가 2단계 — `ops/import_atlas.py`
와 같은 멱등·통째로 갈아치우는 패턴.

## 화면 — 검색 결과에 "현재 학명" 을 얹는다

**두 방향이 다 필요하다** (사용자의 "이명으로 검색해도" 를 읽으면):

1. **옛 이름으로 찾았을 때** — 결과 카드에 이미 뜬 항목의 `binomial` 이
   `TaxonName` 에서 `synonym` 이면 "→ 현재 학명: *X*" 를 얹는다
   (`_occurrences_by_binomial()` 과 같은 자리에 `_taxon_names_by_binomial()`)
2. **새 이름으로 찾았는데 도감엔 옛 이름으로만 있을 때** — 지금
   `atlas_search()` 는 `AtlasEntry.name/binomial/genus` 만 본다. 검색어가
   `TaxonName.valid_name` 과 맞으면 그 `binomial`(들, 이명이 여럿일 수
   있다)로 **한 번 더 찾아 합친다.** 이게 실제로 사용자가 겪은 자리다 —
   `Actinocyclus octonarius` 로 찾았는데 한국 도감은 `Actinocyclus
   Ehrenbergii` 로만 있어 못 찾았을 것이다(668건 중 이런 자리가 더
   있을 수 있다 — 8절에서 실측)

빈 결과 안내문(`atlas.html` "찾은 것이 없습니다")도 이 두 번째 검색까지
하고도 없을 때만 뜨게 고친다.

## 8. 구현 전에 확인할 것

- **`paper_plates_156_result.json` 의 `var.` 달린 이름을 종 단위로
  합쳐도 되는가** — `harvest_worms.binomial()` 은 두 낱말만 보므로
  자동으로 그렇게 되지만, `AtlasEntry.binomial` 도 같은 규칙을 쓰는지
  확인한다(다르면 안 붙는다)
- **`Actinocyclus octonarius` 로 검색했을 때 실제로 몇 건이 새로
  걸리는지** 실측 — 668건이 전부 "도감에 옛 이름만 있다" 는 아니다
  (애초에 도감에 그 속·종이 없을 수도 있다)
- **논문 8편(P23)도 `harvest_worms.binomial()` 을 거쳐 `AtlasEntry.binomial`
  이 채워져 있다** — `paper_plates_156_result.json` 의 열쇠가 그것과
  실제로 맞는지 대조 필요(짐작한 전체 학명이라 `var.`·`sp.` 처리가 갈릴 수 있다)
