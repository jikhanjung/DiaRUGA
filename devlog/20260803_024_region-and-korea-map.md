# 데이터셋에 권역을 넣고, 남한 지도를 굽는다

**날짜** 2026-08-03
**앞선 문서** `20260803_021_antarctic-map.md` (남극 지도)

데이터셋 목록에 **[한국 | 남극]** 상위 갈래를 넣고, 한국 쪽에 쓸 남한 지도를
EPSG:5179 로 새로 구웠다.

---

## 1. `region` 을 겸할 수 없었다

사용자의 말은 "region 을 상위 카테고리로" 였지만 `Site.region` 은 이미 차 있었다.

```
WAP13 · region = "Bigo Bay"      ← 세부 지명이다
```

`region` 은 "로스해"·"웨델해"·"Bigo Bay" 처럼 **해역·만 이름**을 담고 있고 지도
마커의 이름표로도 쓴다(`data.py:309`). 여기에 "한국/남극" 을 겸하게 하면 둘 다
망가진다.

**`Site.area` 를 새로 만들었다.** 모델 머리말에 둘이 다른 칸이라는 것을 적어 뒀다 —
이름이 비슷해서 나중에 반드시 헷갈린다.

```python
AREA = [("kr", "한국"), ("ant", "남극")]
area = models.CharField(max_length=8, choices=AREA, default="ant")
```

기본이 `ant` 인 것은 지금 자료가 전부 남극이라서다(마이그레이션 0007).

## 2. 서버에서 거른다

보기 방식(목록·카드·지도)은 셋 다 그려 두고 CSS 로 감춘다. 권역은 그렇게 하지
않고 **서버에서 거른다.** 이유가 둘이다.

- **합계 줄이 맞아야 한다.** 화면에서 줄만 감추면 표 아래 합계가 감춘 것까지 센다
- **지도 마커도 함께 걸러야 한다.** 남극 지도에 한국 시료가 찍히면 안 된다

즐겨찾기가 되는 것은 덤이다(`?area=kr`).

### 고르는 일을 한 곳에 둔다

```python
area = data.area_tabs(request.GET.get("area"))    # 없는 값이 와도 여기서 정해진다
```

`?area=zzz` 를 그대로 믿으면 빈 목록이 나오고 **왜 비었는지가 화면에 안 보인다.**
`area_tabs()` 가 목록에 없는 값을 걸러 내고, 기본값은 **"자료가 있는 첫 권역"** 으로
정한다 — 지금은 남극이지만, 한국 자료만 들어온 상태에서 빈 남극 탭이 열리는 일도
없다.

### 조용히 사라지는 것을 막는다

권역은 `Site` 에 붙는데 **`Slide.core` 는 null 이 될 수 있다.** 그런 슬라이드는
`core__site__area` 로 거르면 어느 탭에도 안 나온다. 지금은 0개지만 `datasets()`
주석이 "지역·코어가 아직 안 붙은 슬라이드도 있어서" 라고 적어 둔 상황이다.

세어서 화면 위에 알린다. **조용히 사라지는 것이 가장 알아채기 어렵다.**

## 3. 남한 지도 (EPSG:5179)

### 왜 해안선이 아니라 국가 경계인가

`ne_*_land` 는 육지 덩어리라 **한반도가 통째로 하나**다. 남한만 그리려면 휴전선이
필요하고, 그것은 국가 경계 자료(`ne_10m_admin_0_countries`)에만 있다.

10m 를 쓴 것은 남극과 사정이 달라서다. 남극은 대륙 전체를 한 화면에 담아 50m 로
충분했지만, 남한은 훨씬 작아 50m 로는 남해안 섬들이 뭉개진다.

### 검산을 먼저 했다

`proj_kr.py` 의 `__main__` 이 검산이다. 남극 지도(021)에서 **검산 없이 넘겼다가
백지가 됐던** 일이 있어 이번에는 순서를 바꿨다.

```
1. 투영 원점이 가원점(1000000, 2000000)으로 정확히 떨어지는가   ·
2. 왕복 오차                                                  ·
3. 중앙자오선 위 축척이 k0=0.9996 인가                          ·
4. 서울시청이 그럴듯한 자리에 오는가                             ·
```

**2번이 처음에 실패했다.** 허용치를 1 mm 로 잡았는데 5 mm 가 나왔다. 어디인지
찾아보니 전부 한 곳이었다.

```
가장 나쁜 다섯 곳 (오차 · 중앙자오선에서)
   4.980 mm   38.7N 131.9E   4.4도     ← 전부 독도
   4.874 mm   37.5N 131.9E   4.4도
   ...
중앙자오선 ±3도 안쪽만: 0.0985 mm
```

계열 전개라 중앙자오선에서 멀수록 벌어지는 것이고, 지도에서 1 px 이 약 756 m 이므로
상관없는 크기다. **통과시키려고 느슨하게 잡은 것이 아니라 실제 오차가 이만큼이라는
기록**이 되도록 허용치를 1 cm 로 두고 주석에 근거를 적었다.

### 독도를 두 번 놓칠 뻔했다

**한 번은 면적 문턱.** 작은 섬이 먼지처럼 보이는 것을 막으려고 3 km² 미만을
버렸는데, NE 자료의 독도는 0.03 km² 라 여기 걸렸다.

**문턱을 0.01 km² 로 낮췄는데도 여전히 사라졌다.** 이번에는 단순화였다 — 독도는
가로 200 m 남짓이라 허용오차 400 m 로 Douglas-Peucker 를 돌리면 두 점으로 뭉개지고
`len(s) < 4` 에서 버려진다. **작은 고리는 단순화를 건너뛰게** 고쳤다.

```
고리 52개 → 53개
가장 동쪽 고리 → 131.8625°E 37.2431°N   (독도 실제 131.8656E 37.2429N)
```

화면에서는 1 px 미만이라 채우기로는 안 보인다. `.krmap .land` 의 획 굵기(1400)가
그것을 점으로 만든다 — **굵기를 줄이면 독도가 사라진다.** CSS 에 적어 뒀다.

### 그려서 확인했다

래스터라이저가 없는 머신이라 **최종 path 문자열을 직접 파싱해 PIL 로 그렸다.**
오히려 이쪽이 확실하다 — 템플릿이 실제로 내보낸 문자열을 그대로 쓴다.

첫 그림에서 **눈금 글자가 가장자리에서 잘렸다**(38°N, 130°E). 위경도로 눈금 자리를
잡은 것이 원인이다. 자료를 한 축만 갖게 바꾸고(`("34°N", y)`), 나머지 한 축은 뷰가
viewBox 안쪽에서 정하게 했다 — **이제 벗어날 수가 없다.**

## 4. 단위가 달라 마커가 안 보일 뻔했다

```
남극  EPSG:3031  viewBox 7600      단위 km
한국  EPSG:5179  viewBox 680654    단위 m
```

마커 그림은 남극 기준으로 그려져 있다(`r="70"`). 한국 지도에 그대로 쓰면 **70 m,
화면에서 0.1 px** 이다. SVG 쪽에서 `scale(89.6)`(= 680654/7600)으로 키워 남극과
**같은 눈에 보이는 크기**가 되게 했다. 글자(`.sealabel` 등)는 CSS 에서 같은 비로
덮었다.

한국 SVG 에 `class="antmap krmap"` 을 함께 걸어 마커·판형 규칙을 그대로 쓰고,
**단위 때문에 달라지는 것만** `.krmap` 으로 덮는다.

## 5. 식이 두 곳에 생겼다 — 확인했다

지도는 굽는 시점에(`tools/proj_kr.py`), 마커는 요청마다(`data._korea_xy`) 계산한다.
남극도 같은 구조다(021). **식이 갈라지면 마커가 육지를 벗어난다.**

```
지도 식과 마커 식의 최대 차이: 0.000000000 m
```

두 파일 모두에 "고칠 일이 생기면 함께 고쳐야 한다" 를 적었다.

## 6. 지나가다 찾은 버그 — 남극 지도 툴팁

템플릿을 가르면서 회귀를 확인하다 발견했다. 마커에 마우스를 올리면 나오는 툴팁이
**dict 를 통째로 뱉고 있었다.**

```
아문젠해 · {&#x27;code&#x27;: &#x27;GC10B&#x27;, &#x27;n_slides&#x27;: 2, &#x27;slides&#x27;: [{...
```

`{{ p.cores|join:", " }}` 인데 `cores` 는 021 에서 코어 목록을 나무로 만들면서
dict 목록이 됐다. 같은 자료의 `core_codes` 를 쓰면 된다.

**HTML 이스케이프 때문에 눈에 안 띄었다** — 소스에서 `{'code':` 를 찾으면 안 나오고
`&#x27;code&#x27;` 로 찾아야 나온다. 처음 검사에서 "누출 없음" 이 나왔던 이유다.

```
아문젠해 · GC10B · 슬라이드 2장 · 시야 53개
```

## 7. 확인

| | |
|---|---|
| 탭 순서 | 한국 · 남극 (요청대로) |
| `?area=` 없음 / 엉뚱한 값 | 둘 다 남극으로 (자료가 있는 첫 권역) |
| `?area=kr` | 표 0줄 · 빈 목록 안내 |
| 지도 | 남극 → `antmap` EPSG:3031 · 한국 → `krmap` EPSG:5179 |
| 권역 저장 | **사본 DB** 로 시험 — 정상값은 저장, 엉뚱한 값은 무시 |
| 회귀 | 목록·데이터셋·문턱·속성편집 전부 200 |
| `check_db.py` | 통과 |

**권역 저장은 사본 DB(`DIATOM_DB=…/test.db`)로 시험했다.** 예전에 `/review` POST 를
운영 DB 에 때려 교정 14건을 지운 적이 있다. 시험 전에 `assert` 로 사본인지 확인하는
줄을 넣었다.

## 8. 빈 권역에서 무엇을 남길 것인가

권역 갈래는 `pagehead` 안, 목록 유무를 따지는 `{% if %}` 바깥에 있어 **자료가
0건이어도 보인다.** 그래야 한다 — 그것이 다른 권역으로 건너가는 유일한 길이다.

반면 **보기 방식(목록·카드·지도) 버튼은 감춘다.** 목록이 비면 `{% else %}` 블록
전체가 안 그려져 바꿀 화면 자체가 없는데 버튼만 셋 남아 있었다. 눌러도 아무 일이
없는 버튼은 "눌렀는데 안 되네" 로 읽힌다.

버튼과 그것을 다루는 스크립트가 **함께 나오고 함께 사라지는지**도 확인했다 —
스크립트만 남으면 없는 요소를 만져 죽는다.

```
한국(0건)  권역=[한국, 남극]  보기방식 0개  JS 없음  보기영역 없음
남극(7건)  권역=[한국, 남극]  보기방식 3개  JS 있음  보기영역 있음
```

## 남은 것

- **한국 자료가 0건이라 지도를 화면에서 볼 수 없다.** 목록이 비면 `{% else %}` 블록
  전체가 안 그려진다. 템플릿을 직접 렌더해 확인했고 그림도 남겼다
- 마이그레이션이 둘이다(0007 칸 추가, 0008 choices 순서). 0008 은 DB 를 바꾸지
  않지만 이미 적용돼 있어 합치지 않았다
- `Site.lat/lon` 이 AM22·RS23 에 없어 여전히 대략 위치다. **투영 문제가 아니라
  자료 문제**다 — 좌표가 들어오면 그대로 정확해진다
- zoom/pan 은 `viewBox` 를 JS 로 바꾸면 된다. 해안선이 허용오차 400 m(남극 10 km)로
  구워져 있어 많이 확대하면 각진 것이 보이고, 획·글자에 `non-scaling-stroke`
  처리가 필요하다
