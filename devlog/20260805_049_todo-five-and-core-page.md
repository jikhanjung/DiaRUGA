## 1. 오검출 삭제에 스페이스바

**가장 많이 하는 조작이었는데 키가 없었다.** 교정 6,753건 중 삭제가 5,467이다.
040 에서 분류에는 키를 줬는데 삭제만 우클릭 메뉴로 남아 있었다 — 시야 하나에
개체가 수십이라 메뉴를 여닫는 왕복이 곧 검토 속도다.

지난번에 이 제안이 나왔을 때 "스페이스를 단축키로 두면" 의 문제들을 짚었고,
그 목록이 그대로 TODO 에 남아 있었다. 넷 다 처리했다.

| 밟을 곳 | 어떻게 |
|---|---|
| `ClassDef.hotkey` 에 못 태운다 (`hotkey_groups` 가 `.strip()` 을 걸어 공백이 사라진다) | 분류 갈래와 나눠 제 핸들러를 뒀다 |
| 스페이스는 브라우저가 스크롤에 쓴다 | 이 갈래에서 `preventDefault()` — 분류 갈래는 `HOTKEYS` 에 걸린 키만 막는다 |
| `e.key` 는 `'Space'` 가 아니라 `' '` | 그렇게 본다 (`e.code` 쪽이 `'Space'`) |
| 버튼에 초점이 있으면 스페이스가 그 버튼을 누른다 | 거르는 목록에 `BUTTON` 을 더했다. **막지 않고 돌려보낸다** — 브라우저가 제 일(버튼 누르기)을 해야 한다 |

### 되살리기가 닿지 못하는 코드였다

만들고 보니 **"이미 지운 것에 다시 누르면 되살림" 이 성립할 수 없었다.**
유령(지운 개체)을 `sel` 에 넣을 방법이 아예 없었기 때문이다:

- 범위 선택이 지운 것을 걸러 낸다 (`if (removed.has(keyOf(c))) return;`)
- 유령을 왼클릭하면 **Shift 여부와 상관없이** 곧바로 되살아난다 — 그 갈래가
  `d.shift` 보다 위에 있었다

그래서 순서를 바꿨다. **Shift+클릭이 유령 되살리기보다 먼저다.** 그냥 클릭은
그대로 되살린다(잃은 것이 없다) — 새로 생긴 것은 "유령을 골라 둘 수 있다" 는
것뿐이다.

곁들여, 고른 것이 지운 것뿐일 때 `선택 없음` 이라고 하던 것을
`지운 개체 N개 선택 · Space 로 되살립니다` 로 고쳤다. 골라 놓고도 아무 일이
없는 것처럼 보이면 새로 생긴 길이 안 보인다.

### 지운 뒤 선택은 비운다

`removeKeys()` 가 원래 그렇게 한다(우클릭 메뉴가 쓰던 함수다). 남기면 분류
키(`q q q`)와 같은 모양이 되지만, **지운 개체는 기본적으로 화면에 안 그려져서**
"보이지 않는 것이 선택된" 상태가 된다. 되돌리기는 이미 `Ctrl+Z` 가 맡고 있다.

## 2. 노두 시료의 깊이 칸

노두(outcrop) 시료에는 깊이가 없다. `Slide.depth_cm` 을 비워 두는 수밖에
없었는데, 화면에 `—` 로 나와 **"깊이가 없는 시료" 와 "아직 안 채운 시료" 가
구별되지 않았다.**

**`depth_cm` 을 문자열로 바꾸지 않았다.** 슬라이드 정렬이 이 값으로 서고
(`Slide.Meta.ordering` · `data.py` 두 곳) `(core, depth_cm)` 인덱스가 걸려 있다.
시료 종류를 따로 두고(`Slide.sample_kind`) 화면이 그것을 읽는 쪽으로 갔다.
`NOT NULL` 이라 `db_default` 를 함께 줬다 — Django 의 `default` 는 파이썬 쪽이라
판이 다른 옛 이미지의 INSERT 에는 칼럼이 안 들어간다.

칸 이름은 **"깊이" 가 아니라 "위치"** 다. 시추코어는 `cm`, 노두는 `OC` —
좁은 칸만 줄이고 말풍선은 전체 이름이다(`ClassDef.short` 가 `Chaetoceros → CRS`
를 쓰는 것과 같은 규칙). 네 화면이 같은 규칙으로 읽도록 `_depth.html` 하나로
모았다(목록 표 · 목록 카드 · 시야 목록 머리 · 지도 범례).

편집 화면에서 노두를 고르면 **깊이 칸을 잠그되 비우지 않는다.** 잠긴 칸은
브라우저가 안 보내므로 서버도 노두면 깊이를 건드리지 않는다 — 종류를 잘못
골랐다가 되돌릴 때 값이 이미 사라져 있으면 안 된다.

## 3. 카드의 두 줄을 축으로 가른다

윗변 선이 `평균 장수` 와 `검출` 사이를 지나 아랫줄이 "분류별 + 규모 둘 +
진행률" 잡탕이었다. **첫째 = 얼마나 있고 얼마나 봤나 · 둘째 = 무엇이 있었나**
로 갈랐다.

그러면 둘째 줄이 정확히 `ClassDef.counted` 만 남아 **분류를 더하면 저절로 한 칸
는다** — 038~040 과 같은 방향이다.

덤으로 하나 고쳤다. `검토` 는 검출과 무관한 값인데 `mean_counted` 의 `if` 안에
있어서 **검출이 없는 슬라이드는 검토 수가 아예 안 보였다.**

첫째 줄이 여섯 칸이 되어 좁은 카드에서 한 칸이 접혀 내려갔다. 카드에서만
간격을 18 → 13 px 로 좁혀 한 줄에 들어가게 했다(표는 이 규칙을 안 쓴다).

## 4. 목록을 코어로 묶고 접는다

지금까지는 **정렬만 되어 있고 묶여 있지 않았다** — `data.py` 가 지역→코어→깊이
순으로 내주니 같은 코어의 깊이들이 이웃해 있을 뿐이었다.

- **묶는 열쇠는 지역이 아니라 코어다.** 지금 지역↔코어가 거의 1:1(5:5)이라
  어느 쪽으로 묶어도 화면은 같지만, **먼저 오는 것은 한 코어에서 슬라이드가
  여럿이 되는 일이다** — 이미 RS23-GC03 이 셋이다
- **이름이 아니라 코드로 묶는다.** 지역 이름은 사람이 고칠 수 있는데, 그것을
  열쇠로 삼으면 이름을 고치는 순간 접어 둔 것이 풀린다
- **표 안에서는 `<details>` 가 안 먹는다.** 코어마다 `<tbody>` 를 두고 머리
  `<tr>` 이 토글한다. 카드는 `<details>/<summary>` 로 그대로 된다 —
  **둘이 같은 열쇠를 써서** 보기 방식을 바꿔도 접힘이 따라온다
- 머리줄은 `datasets_total()` 을 묶음마다 불러 사진·시야·검출·검토 합을 든다.
  **평균은 넣지 않는다** — 분모가 슬라이드마다 달라 다시 더할 수 없다
- **접은 것만 기억한다.** 편 것을 적으면 새 코어가 들어왔을 때 목록에 없어
  접힌 채로 열린다 — 그러면 첫 화면이 빈 목록이다
- 구분은 ▶ 와 들여쓰기가 낸다. 옅은 면은 `--group-bg` 로 **테마마다** 준다.
  `--panel` 은 `tr:hover` 가 쓰고 있어 보통 줄과 구별이 안 되고,
  `--accent`·`--warn` 은 이미 다른 것을 말한다
- 한 코어에 100장이 오는 날을 위해 표는 **처음 열 줄 + "나머지 N장 더 보기"**
  로 끊는다(`<tbody>` 는 스크롤 상자가 못 된다 — 그러려면 `table-layout: fixed`
  로 열 너비를 못 박아야 한다). 카드만 `max-height` 로 스크롤한다

표의 `코어` 열은 이제 줄마다 같은 값을 되풀이하지만 **둔다.** 묶음을 접어 두면
머리줄만 보이는데, 그때 속 줄에 코어가 없으면 편 뒤에 어느 코어인지 다시
올려다봐야 한다.

## 5. 배경에 로고 워터마크

`_logo.html` 의 마크(1 KB)를 `position: fixed; z-index: -1` 로 깐다.
**PNG 을 쓰지 않는다** — `docs/assets/logo/` 의 PNG 은 281 KB 이고, 이 배포에는
정적 파일을 내보내는 길이 없어(`STATIC_ROOT` 도 nginx 의 static 자리도 없다)
data URI 로 심어야 하는데 base64 면 ~375 KB 가 모든 페이지에 붙는다.

- **테마가 둘이라 투명도도 둘이다** — 어두운 바탕의 밝은 획과 밝은 바탕의
  어두운 획은 같은 알파로 같게 안 보인다 (`--wm-op`: `.045` / `.06`)
- **`pointer-events: none`** — 검토 화면이 캔버스 전체에 클릭·드래그를 건다
- **검토 화면 위로 새지 않는다** — `.detview` 가 `background: #000` 이라 사진
  뒤에는 아무것도 안 보인다. 현미경 사진 뒤의 무늬는 구조로 오독될 수 있다

**TODO 는 "워드마크는 넣지 않는다" 였는데 넣었다.** 그때의 근거는 원본의
Montserrat 이 서버에 없다는 것이었다 — 그런데 머리글의 워드마크가 이미 같은
이유로 SVG 가 아니라 HTML 글자다. 기기마다 글꼴이 달라지는 것은 맞지만
**여기는 읽는 글이 아니라 배경이라** 그 차이가 드러날 자리가 아니다.
`text-transform` 은 얹지 않았다 — DiaRUGA 의 대소문자가 곧 약자다.

`body::before` 가 아니라 요소인 것은 그림을 `include` 로 가져오려면 실제
요소여야 해서다. 하는 일은 같다.

## 6. 코어 페이지 — 깊이 축과 암상 자리

묶기를 만들고 나니 **머리줄의 속성 칸이 비어 있었다.** 거기에 `보기` 를 두고
`/core/<지역>/<코어>/` 로 보낸다.

### 왜 지금인가 — TODO 의 판단을 뒤집은 것이 아니다

`TODOs.md` 는 코어 페이지를 "지금 가면 손해" 라고 적었다. 그 근거는
**목록을 대체할 때** 였다 — "코어 다섯 줄만 내고 나머지를 페이지 뒤로 보내면
지금 되는 일이 클릭 다섯 번이 된다". 목록을 그대로 두고 **덧붙이는** 것은 그
손해가 없다.

그리고 같은 항목이 세운 조건 — **"코어 페이지가 값을 하려면 목록의 부분집합
이상이어야 한다"** — 을 암상이 정확히 채운다. 목록은 암상을 못 보여준다.

### 암상은 모델을 만들지 않았다

구간 상·하한 · 암상 코드 · 색 · 조직 · 화석 함량 같은 칸이 정해져야 표가 서는데
**그 기재 규칙이 아직 없다.** 지금 스키마를 박으면 나중에 이미 붙은 자료를
옮겨야 한다. 축과 자리만 잡고 띠는 빗금으로 비워 뒀다 — 그럴듯한 가짜 암상을
그리지 않는다.

### 축은 진짜다

깊이가 DB 에 있어 눈금도 시료 위치도 실제 값이다.

- **위가 얕고 아래로 깊어진다** — 코어 로그의 관례
- **축은 늘 0 에서 시작한다** — 가장 얕은 시료부터 그리면 그 위 구간이 없는
  것처럼 보인다
- 눈금 간격은 1·2·5 계열에서 고른다(`_nice_step`). `span / want` 를 그대로 쓰면
  137 cm 같은 간격이 나와 축이 안 읽힌다
- **깊이가 없는 슬라이드(노두)는 축에 못 놓는다** — 버리지 않고 따로 낸다.
  안 보이면 이 코어에 없는 시료가 된다

### 속성은 읽기만 한다

`/d/<slug>/edit/` 이 슬라이드·코어·지역을 한 트랜잭션으로 저장한다. 여기에
폼을 하나 더 두면 **같은 `Core`·`Site` 행에 쓰는 문이 둘**이 된다 — 이 저장소가
두 번 당한 종류다. 그 화면의 해시 탭(`#core`·`#site`)으로 곧장 보낸다.

**코어 코드는 지역마다 겹칠 수 있다**(`Core` 의 unique 가 `(site, code)`). 주소도
그 짝이다 — `/core/AM22/GC03/` 은 404 다. "코어 미지정" 묶음에는 `Core` 행이
없어 `보기` 를 내지 않는다.

## 7. 확인한 것

전부 **사본 DB**(`test.db`)에 붙인 `runserver` 위에서 playwright 로 확인했다.
운영 DB 는 건드리지 않았다.

| 무엇 | 결과 |
|---|---|
| 스페이스 삭제·되살림·스크롤·버튼 초점·안내 줄 | 10/10 |
| 노두 저장 왕복(깊이 안 지워짐 · 모르는 값 무시) | 6/6 |
| 코어 묶음 접기(표↔카드 동기 · 새로고침 · 키보드 · 합계) | 12/12 |
| 코어 페이지(축 위치 계산 · 폼 없음 · 404 두 갈래) | 14/14 |
| 콘솔 오류 (`pageerror`) | 없음 |

**미리보기는 80 포트로 내야 한다.** 사내 VPN 이 80 말고는 안 통과시킨다 —
:9090 이 그래서 `/DiaRUGA/` 로 옮겨진 것과 같은 이유다(018). runserver 를
8099 에 띄우고 nginx `snippets/DiaRUGA-preview.conf` 로 `/DiaRUGA-preview/`
아래에 얹었다. **임시다** — 붙는 곳이 runserver 라 그 프로세스가 없으면 502 다.
배포가 끝나면 그 파일과 `include` 한 줄을 지운다.

**눈으로 봐야 남는 둘**(HANDOFF 3.3): 워터마크의 진하기가 실제 화면에서
적당한가, 묶음 머리줄의 옅은 면이 두 테마에서 다 읽히는가. 배포 뒤 한 번
열어 볼 것.
