## 판이 셋이 된 이유 — 쓰면서 드러났다

**v0.5.1 을 내보내고 사용자가 바로 눌러 봤다.** "read only 일 경우에도 화면에서
작동은 하는 것처럼 보이네." 저장은 막혀 있는데 우클릭 메뉴가 살아 있어서,
누르면 마스크가 지워지고 분류가 바뀌었다. **되는 것처럼 보이는 것이 안 되는
것보다 나쁘다** — 그렇게 한 시야를 검토하고 새로고침하면 판단이 사라진다.
v0.5.2 로 막았다(051 §7).

**v0.5.2 를 내보낸 뒤 "합성본은 `frame` 이 NULL 인데 어떻게 처리하나" 를 물었고,
그 칸을 따라가다 v0.5.3 이 나왔다.** `save_review` 가 `stem` 하나로 시야를
찾는데 프레임 이름은 슬라이드끼리 겹친다 — **싱글턴 시야 12개가 다른 슬라이드의
시야를 열고 있었다.** 사본에서 재현했고, 교정 7행이 200 응답과 함께 사라졌다.

**기능을 만든 devlog(051)보다 그 길에 나온 사고 devlog(053)가 더 중요하다.**

## 이미 터진 적은 없었다

교정은 재생성 불가라 **백업 이력으로 확인했다.** 노출됐던 시야 10개의 교정 수를
08-04 11:44 부터 백업 아홉 판에서 훑었다.

```
diatom_20260804_114433.db   120   [7, 12, 13, 9, 18, 11, 21, 6, 13, 10]
…                           120   (전부 같음)
DiaRUGA.db (지금)           120   [7, 12, 13, 9, 18, 11, 21, 6, 13, 10]
```

한 번도 변한 적이 없다. 노출된 화면 20개에 "검토 완료" 표시가 하나도 없는 것과도
맞는다 — 아직 그 시야들에 손이 닿지 않았다. **027 을 알아챈 것도 백업 숫자였다.**

## 운영에서 확인한 것 (v0.5.3)

컨테이너 안에서 **질의만** 돌렸다 — 운영 DB 에 POST 는 보내지 않는다.

```
① stem 만      -> 거절 · "이 이름의 시야가 2개다 … 저장하지 않았다"
② slug+gid     -> 260803_gc03-c1_72cm g1   (자기 시야)
③ 어긋난 stem  -> 거절 · "화면과 저장 대상이 어긋난다"
④ 검출 있는 시야 452개 전부 자기를 짚는다 — 어긋난 것 0
```

화면(nginx 경유)도 확인했다 — `data-slug`·`data-gid` 가 실려 있고, 저장이 보낼
것은 `{stem: g001_…_focused, slug: 260731_am22-gc10b_25cm, gid: 1}` 이다.
읽기 전용 화면은 여전히 `/review` 를 하나도 안 보내고 우클릭 메뉴가 잠겨 있다.
콘솔 오류 없음.

**현재 검출 화면은 열어서 읽기만 했다.** 운영 DB 라 클릭 하나가 교정을 바꾸는
자리이고, 저장 경로는 사본에서 이미 확인했다(053 §4).
