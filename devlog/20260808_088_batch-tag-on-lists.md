# 088 — 목록과 시야 목록이 지금 검토 중인 묶음을 말한다

2026-08-08 · 사용자 요청

## 문제

P10 부터 **화면에 보이는 검출이 어느 회차의 것인지를 `RunBatch.for_review` 하나가
정한다.** 그런데 그 사실이 관리 화면에만 있었다.

목록(`/`)의 "검출" 칸도, 시야 목록(`/d/<slug>/`)의 썸네일에 그려지는 마스크도
전부 검토 대상 묶음에서 나온다(`Detection.objects.reviewing()`). 묶음을 갈면
**같은 슬라이드의 숫자가 통째로 달라지는데** 화면에는 아무 표시가 없다 —
자료가 변한 것인지 묶음이 바뀐 것인지 **가릴 수가 없다.**

검토 화면(`/d/<slug>/g/<n>/`)에는 이미 `◉ SAM / ○ YOLO` 라디오가 있어 알 수
있었다. 그 앞의 두 화면만 말이 없었다.

## 한 일

`.batchtag` 표시를 두 화면의 머리줄에 뒀다. 조각 하나(`_batchtag.html`)를 둘이
함께 include 한다.

```
데이터셋  문턱 조정 →  관리 →   ( 검토 중  sam2-전수 )
```

**다른 묶음은 여기 안 낸다** (사용자 방침). 비교는 검토 화면의 라디오가 하는
일이고, 목록에서까지 고르게 하면 "지금 보는 것" 이 화면마다 달라진다. 여기는
**읽는 표시**이지 고르는 자리가 아니다 — 누르면 고치는 자리(`/manage/ops/`)로 간다.

**묶음이 하나도 안 켜져 있으면 경고 모양으로 "검토할 묶음 없음"** 을 낸다. 그
상태에서 뷰어는 검출을 **하나도** 안 그리는데(P10 3.6), 아무 표시가 없으면
"자료가 없다" 로 읽혀 사람이 파이프라인을 돌리러 간다. **없는 것과 안 고른 것은
다른 말이고 할 일이 다르다** — 071 이 빈 시야에 대해 한 것과 같은 이야기다.

## 밟을 뻔한 자리 — `.nowtag` 를 그냥 쓰면 안 된다

관리 화면에 **이미 같은 뜻의 딱지가 있다**(`.nowtag`, "검토 중"). 그대로
가져다 쓰고 싶었는데, 그 규칙은 `_managenav.html` 안에 있고 그 조각은
**관리 화면 셋만 include 한다.**

목록에서 `.nowtag` 라고 적었으면:

- HTML 은 멀쩡하다
- 3겹 시험도 통과한다 (`assertIn("nowtag", html)`)
- 화면에는 **테두리도 색도 없는 맨 글자**가 나온다

`.tools` 가 세 화면을 그렇게 속였고(051), `.nowrow` 가 관리 화면에서 같은 일을
했다(083). **세 번째다.** 그래서 `base.html` 에 따로 정의했다 — 모양은 일부러
`.nowtag` 와 같게 뒀다(같은 것을 가리키는 표시가 화면마다 다르면 같은 것으로 안
읽힌다).

## 시험

**3겹 4개** (`tests/test_batch_tag.py`) — 두 화면이 이름을 내는가 · 묶음을 갈면
따라가는가 · 안 켜져 있으면 그렇게 말하는가 · 누르면 고치는 자리로 가는가.

**4겹 3개** (`tests/browser/test_batch_tag.py`) — **CSS 가 먹는가**를 여기서만
볼 수 있다. `getComputedStyle` 로 테두리 두께·모서리 반경·`display` 를 본다.

`base.html` 의 `.batchtag` 규칙을 걷어 내고 돌려 확인했다:

```
3겹  Ran 4 tests  OK        ← 통과한다. 이것만 있으면 그냥 나갔을 것이다
4겹  AssertionError: '0px' == '0px' : 데이터셋 목록: 테두리가 없다 — CSS 가 안 먹었다
     AssertionError: '0px' == '0px' : 시야 목록: 테두리가 없다
     AssertionError: 경고 갈래가 보통 갈래와 같아 보인다
```

### 시험을 한 번 고쳤다

처음에 "묶음을 갈면 옛 이름이 페이지에 없어야 한다" 를 **페이지 전체 문자열**로
봤는데 실패했다. 썸네일 배지의 `title` 에 **다른 묶음 이름**이 들어 있었다 —
`"sam2-시험 에는 검출이 있습니다"`, P10 4단계가 "이 시야가 왜 비었는지" 를 말하는
자리다. 목적이 다르고 내가 더한 것도 아니다.

**시험이 틀렸다.** 표시 하나만 뽑아서 보게 고쳤다(`self.tag(url)`). `base.html`
의 CSS 주석에도 `batchtag` 가 들어 있어 문자열 검색은 어차피 성립하지 않았다.

### 브라우저가 `inline-flex` 를 `flex` 로 바꾼다

`display: inline-flex` 를 그대로 기대했다가 `flex` 가 나와 한 번 넘어졌다.
이 표시는 `.pagehead`(flex 컨테이너)의 자식이라 **블록화되는 것이 표준 동작**이고,
규칙은 먹은 것이다. `<a>` 의 기본값 `inline` 이 아닌 것을 보는 쪽으로 고쳤다.
