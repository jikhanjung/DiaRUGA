**마이그레이션(`0037`)으로 넣는다** — 손으로 INSERT 하면 운영 DB 에만 있고 새로
만든 DB(시험·복구)에는 없다. 되돌리기는 **지우는 것이 아니라 `active=False`**
다(`0014` 와 같다): 지우면 그 분류로 붙인 교정이 이름 없는 분류가 된다.

**이미 붙은 교정은 안 건드린다.** 봉상으로 적어 둔 것을 기계가 Rhizosolenia 로
옮기면 **사람이 안 한 판단이 사람의 판단으로 앉는다.** 옮기는 것은 검토 화면에서
사람이 한다.

## 2. 색을 고른 방법

색은 **아직 표에서 뿜어내지 않는다** — `ClassDef.color`("R,G,B")와 `base.html`
의 CSS 가 따로 있다. 그래서 고를 때 두 가지를 봤다.

**첫째, 색상환의 빈자리.** 분류가 쓰는 색(연두 90 · 초록 145 · 파랑 217 ·
분홍 327)에 **화면이 쓰는 색까지** 놓고 봐야 한다 — 빨강 0(`--danger`·지운 것) ·
주황 36(`--warn`) · 초록 130(`--good`) · 하늘 197(`--accent`) · 금색 51(고른 개체).
전부 늘어놓으면 **파랑 217 과 분홍 327 사이 108° 가 가장 큰 빈자리**이고 그
한가운데가 **보라 266°** 다.

**둘째, 실제로 놓이는 네 자리를 그려서 봤다** — 배지 · 사진 위 마스크(45%) ·
윤곽만 보기 · 크롭 테두리. 견본만 보면 안 되는 이유가 있다: 후보로 놓았던
하늘색(120,200,255)은 **봉상 파편(120,195,255)과 사실상 같은 색**이라 견본에서만
갈렸다.

보라 셋(연보라 `#b982ff` · 차분한 `#a78bfa` · 밝은 `#c878ff`) 중 **연보라**를
골랐다(사용자). 밝은 쪽은 분홍으로 기울어 Eucampia 와 헷갈릴 여지가 있고,
차분한 쪽은 기존 여섯이 다 진해 혼자 가라앉는다.

## 3. 행 하나로 안 끝난다 — CSS 여덟 자리

`ClassDef` 머리말이 "`base.html` 의 CSS 도 함께" 라고만 적어 두었는데, **세어
보니 여덟이다.** 배지 하나만 보고 끝내면 나머지 일곱에서 마스크가 투명해진다.

    .badge.rhi                              배지
    .tile .thumbwrap polygon.rhizosolenia   목록 타일
    .vpimg polygon.rhizosolenia             시야 그림
    .crop.rhizosolenia                      크롭 갤러리 테두리
    .detview svg.masks polygon.…            검토 화면 마스크
    .detview.hide-fill svg.masks polygon.…  윤곽만 보기
    .detview .box.rhizosolenia              상자 테두리
    .detview.hide-box .box.rhizosolenia     상자 감추기

## 4. 그러다 찾은 것 — Chaetoceros 가 개수 줄에 없었다

개수 줄(`후보 12개 (rod 5, round 3…)`)을 만드는 자리가 **분류 다섯을 손으로 박아
두고 있었다**: `rod`·`round`·`rod_frag`·`round_frag`·`eucampia`.

**Chaetoceros 는 표에 든 뒤로 한 번도 그 줄에 안 나왔다.** 040 이 표에 행을
넣으면서 이 자리를 안 고쳤고, **예외도 경고도 없어서** `v0.10.x` 부터
`v0.13.0` 까지 그대로였다. `ClassDef` 머리말이 말하는 "그 분류만 조용히 다르게
굴러간다" 가 정확히 이것이다.

같은 목록이 **두 군데**에 있었다(`data.py` 의 두 자리). `_count_parts` 하나로
모으고 **표의 차례를 그대로 따르게** 했다 — 다음 분류는 코드를 안 고쳐도 낀다.

## 5. 시험

`test_new_class_wiring.py` 를 새로 뒀다. **분류 목록을 손으로 적어 둔 자리**를
보는 곳이고, 배지 CSS 는 `test_classdef_css.py` 가 계속 본다.

**시험을 어느 표에 대고 보느냐가 갈린다** — 이것 때문에 두 번 헛돌았다.

| 무엇을 보나 | 어느 표 | 왜 |
|---|---|---|
| 마이그레이션이 채운 여덟 칸 | **마이그레이션만 돈 DB** | 픽스처가 덮어쓰면 마이그레이션을 안 보게 된다 |
| 단축키 겹침·예약키 | **픽스처 표**(운영을 옮겨 적은 것) | 마이그레이션 DB 에는 `round`·`rod`·`eucampia` 가 **없다** — 그것들은 초기 반입으로 들어왔다 |

처음에는 겹침 시험을 마이그레이션 DB 에 대고 짰다. **`Eucampia` 와 같은 키를 줘
봐도 통과했다** — 표에 둘밖에 없어 겹칠 것이 없었다. 064 가 적어 둔 "실패할 수
없는 시험" 이고, 되살려 보지 않았으면 못 봤다.

**픽스처와 마이그레이션이 어긋나는 것**도 본다(`test_픽스처_표와_같은_값이다`).
CSS 시험이 픽스처 색을 보는 동안 운영에 다른 색이 앉는 갈래를 막는다.

고장 여섯을 내 보고 각각 잡히는 것을 확인했다 — 개수 줄 되돌리기 · 마이그레이션의
단축키/약칭 빼기 · 색 어긋내기 · 픽스처에 겹치는 키 · 픽스처에 예약키 `d`.

전체 754개 통과(브라우저 포함).
