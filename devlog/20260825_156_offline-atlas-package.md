# 156 · 도감을 오프라인 꾸러미로 내보낸다

2026-08-25 · sclee · `tools/build_offline_atlas.py` · `tools/offline_assets/`

## 무엇을 청했나

"세 권의 도감 색인 및 뷰어와 종 검색 자료를 **오프라인에서도** 볼 수 있게
HTML 로 내보낸다. 판을 달고, `Diadiction/offline/` 에 모은다."

지금 이것을 보려면 사내망에서 뷰어(`/DiaRUGA/atlas/`)에 붙어야 한다. 배 위나
현장, 남의 노트북에서는 그 자리가 없다.

## 크기를 먼저 쟀다 — 그것이 설계를 갈랐다

| | 크기 |
|---|---|
| 색인 셋 `atlas/*.json` (항목 2,059) | 1.3 MB |
| 학명 대조표 `worms_master_20260814.tsv` (4,064행) | 1.1 MB |
| 쪽 PNG 1,336장 (300 dpi) | **2.4 GB** |

**글자는 무료고 도판이 전부다.** 그래서 도판을 어떻게 실을지가 유일한 결정이었고,
표본 16장을 실제로 변환해 재 봤다:

| | 예상 총량 |
|---|---|
| PNG 그대로 | 2.30 GB |
| JPEG 300 dpi q80 | **1.11 GB** |
| WebP 210 dpi q75 | 0.43 GB |
| JPEG 150 dpi q80 | 0.42 GB |
| WebP 150 dpi q75 | 0.28 GB |

**해상도를 줄이는 쪽을 안 골랐다**(사용자 결정). Schmidt 도판은 규조 미세구조를
보는 그림이라 150 dpi 로 내리면 세선(striae)이 뭉갠다 — 꾸러미를 만드는 뜻이
"현장에서 종을 짚는 것" 인데 짚을 수 없는 그림이면 크기를 아낀 값이 없다.
**해상도를 지키고 압축만 바꿔 2.4 GB → 1.1 GB.**

## 단일 HTML 은 못 한다 — 대신 둘로 낸다

사용자가 "USB 로 단일 파일 하나" 를 청했다. **1.1 GB 를 HTML 하나에 담을 수
없다** — base64 는 4/3 로 부풀어 1.5 GB 짜리 문서가 되고, 그 크기의 DOM 을
브라우저가 파싱하다 죽는다. 확인하고 물러선 것이 아니라 **규격이 그렇다.**

그래서 둘이다:

- **완전판** — `index.html` 하나가 옆의 `data/`·`pages/`·`thumbs/` 를 참조한다.
  들고 다닐 때는 폴더째, 또는 zip 하나(`diadiction-offline-v1.0.0.zip`)
- **글자만 단일 HTML** — `diadiction-index-v1.0.0.html` 2.4 MB. 자료를 통째로
  안에 박아 **진짜 파일 하나**다. 도판이 필요 없을 때 이것만 보내면 된다

## `fetch` 를 쓸 수 없다

`file://` 에서 브라우저는 로컬 파일을 서로 다른 출처로 본다 — `fetch('data/x.json')`
이 CORS 로 막힌다. 웹서버 없이 열리는 것이 이 꾸러미의 존재 이유라 여기서
물러설 자리가 없어서, 자료가 **`data/*.js` 로 나가 전역에 값을 놓는다**
(`<script src>` 는 막히지 않는다). 자료 안의 `</` 는 `<\/` 로 막는다 —
문자열 하나가 문서를 닫으면 그 뒤가 통째로 안 돈다.

## 규칙을 다시 만들지 않았다

쪽 파일 이름과 권 코드(`Band4` → `band4`)는 **`web/viewer/atlas.py` 하나뿐이라고
못 박아 둔 자리다**(129 · `vol_code` 머리말). 굽는 도구가 `.lower()` 를 한 번 더
쓰면 넷째 도감에서 갈린다 — 그래서 `sys.path` 에 `web/` 을 넣고 **그 모듈을
임포트해서 쓴다**. `settings` 를 건드리는 것은 `_root()` 뿐이라 Django 설정 없이
임포트만으로 돈다.

화면 쪽 규칙도 뷰어에서 그대로 가져왔다 — 검색 셋(표제어·이명법·속) · 한 판
50줄 · 격자 60칸 · 펼침의 좌우 판정(`left_parity`) · **PDF 쪽이 없으면 링크를
안 낸다.**

## 뷰어와 갈린 자리 하나 — 링크가 실제로 열려야 한다

뷰어는 **링크마다 디스크를 안 짚는다**(한 판에 수백 번이 된다 · 105). 그래서
안 구운 쪽도 링크로 나오고, 눌러야 404 를 만난다.

오프라인은 다르다. **굽는 자리는 무엇이 실렸는지 이미 안다**, 그리고 파일이
없는 링크는 사람이 **꾸러미의 고장**으로 읽는다. 그래서 쪽을 먼저 훑어
`have` 를 만들고, 색인이 짚는 자리가 거기 없으면 **번호는 남기되 링크를 안
낸다**(`<span class="chip">해설 p.174</span>`). 라벨까지 지우면 색인이 짚어 준
번호가 화면에서 사라져 **"안 적혀 있다" 로 읽힌다** — 안 실린 것과 색인이 안
적은 것은 다른 말이다(한국 도감 201건이 뒤엣것이다).

## 화면 넷

`index.html` 하나가 해시로 갈린다(`#/` · `#/book/…` · `#/page/…` · `#/names`).

- **색인 검색** — 뷰어 `/atlas/` 를 옮겼다. 도감 칩·속 칩·미리보기까지
- **쪽 보기** — 한 장/두 쪽 · 휠 확대 · 끌어 옮기기 · `←→` `g` `s` `+-0`
- **종 검색** — 학명 대조표를 통째로. **칸을 안 골랐다** — 오프라인에는 되물을
  곳이 없다. 이름을 누르면 그 이름으로 색인 검색으로 건너간다
- **안내** — 판·출처·인용 규칙

## 확인

헤드리스 크로미움으로 `file://` 을 열어 확인했다(045 의 자리). **콘솔 오류 0 ·
실패한 요청 0**, 검색 393건(`Navicula`) · 격자 → 쪽 → `←→` → `s` 두 쪽 →
휠 확대 → `g` 격자가 다 돌았고, 이미지가 실제로 붙는 것을 `naturalWidth` 로
확인했다(2880). **200 이 "떴다" 일 뿐인 것과 같은 줄이다** — 화면이 자료를 진짜
물었는지를 본다.

## 다시 굽는 법

```bash
python tools/build_offline_atlas.py --version 1.0.1            # 이미 구운 쪽은 건너뛴다
python tools/build_offline_atlas.py --version 1.0.1 --limit 8  # 눌러 볼 때 (권마다 8쪽)
python tools/build_offline_atlas.py --version 1.0.1 --no-images # 글자만
```

**색인이나 대조표가 바뀌면 판을 올려 다시 굽는다.** 꾸러미는 사본이라
`MANIFEST.json` 에 출처 해시(`atlas/*.json` 셋 · TSV)와 `git` 커밋을 적어 둔다 —
손에 든 꾸러미가 무엇에서 나왔는지 되짚을 수 있어야 한다.
