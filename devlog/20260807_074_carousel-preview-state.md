# 074 — 커서가 스치고 지나간 판이 고른 판의 자리에 앉는다

2026-08-07 · 미리보기에서 사람이 잡은 것

## 무엇을 봤나

> 합성본이 떠 있고, 첫 프레임(21712) 썸네일에 커서를 올리면 그 프레임 검출이
> 뜬다. 다시 합성본 썸네일에 커서를 올리면 합성본 검출이 뜬다. 그런데
> **합성본을 클릭하면 첫 프레임의 검출이 뜬다.**

말한 그대로 짚어 보니 한쪽만이 아니었다. **두 판의 상태가 통째로 뒤바뀐다.**

```
처음         합성본 30개        ✓
프레임 클릭   프레임 3개         ✓
합성본 hover  합성본 30개        ✓
합성본 클릭   합성본 30개        ✓
프레임 hover  프레임 3개         ✓
프레임 클릭   합성본 30개        ← 프레임 자리에 합성본이 앉았다
합성본 클릭   프레임 3개         ← 사람이 본 그것
```

## 왜 그런가

미리보기(`swapDet(s, false)`)는 **그리기만** 바꾸려고 전역(`cands`·`rejects`)을
갈아 끼운다. 그런데 판을 옮길 때 부르는 `stash()` 는 그 전역을 **고른
판(`curKey`)의 것**으로 알고 담는다.

```
커서가 옆 판을 스친다   → 전역 = 옆 판의 개체
그 상태에서 판을 고른다 → stash() 가 그것을 **고른 판의 상태로** 저장
```

`swapDet` 의 `key === curKey` 갈래에는 "커서가 지나가며 그리기만 바꿔 놓았을 수
있다" 는 주석과 되돌리기가 이미 있었다. **그런데 판이 바뀌는 갈래(`stash()` 로
가는 쪽)에는 없었다.** 알고 있던 문제인데 한쪽만 막혀 있었다.

## 더 나쁜 자리

같은 뿌리에서 하나가 더 나온다. 지연 저장(400 ms)이 걸린 채로 옆 판을 스치고
다른 판을 누르면 `flushSave()` 가 **스쳐 지나간 판의 개체를 고른 판의 이미지로**
보낸다. `/review` 는 그 이미지의 교정을 **통째로 갈아치우므로**(017·027·053
계열) 본 적 없는 판단이 앉고 있던 것이 지워진다.

## 한 일

**`previewing` 하나를 둔다** — 지금 전역이 고른 판의 것인지, 지나가는 판의
것인지.

- 미리보기를 **시작하기 전에 `stash()`** 로 고른 판의 것을 담는다. 사람이 방금
  만진 것이 전역에만 있을 수 있고, 미리보기가 그것을 덮어쓴다
- 판을 고를 때는 `unpreviewState()` 로 전역을 고른 판의 것으로 되돌린 **다음에야**
  `flushSave()`·`stash()` 로 간다
- `save()` 는 미리보기 중이면 **보내지 않는다.** 저장 대상(`curImage`)은 고른
  판인데 전역은 옆 판이라, 그대로 나가면 본 적 없는 이미지에 판단이 앉는다

세 번째는 오늘의 화면에서는 닿기 어렵다(교정 키들이 전부 선택을 요구하는데
미리보기가 선택을 비운다). **닿는 길이 생길 때를 막는 것**이고, 그래서 시험도
없다 — 없는 것을 있다고 적지 않는다.

## 시험

288개 전부 통과. 이번에 더한 것 4개(`browser/test_carousel_preview.py`).

**처음 쓴 시험은 고치기 전 코드에서도 통과했다.** 썸네일을 곧바로 눌러서다 —
미리보기가 사진을 내려받는 동안에는 전역이 아직 안 바뀌어 있어 **고장이 그
사이로 빠져나간다.** 사람이 하는 대로 **커서를 얹고 기다렸다가 누르도록** 고치니
되돌린 코드에서 깨진다.

이번 것도 그렇고 072 의 어긋남 비율도 그렇고, **재는 쪽을 먼저 의심해야 하는
일이 이틀에 두 번 났다.** 브라우저 시험은 "눌렀다" 와 "사람이 누르는 것과 같은
순서로 눌렀다" 가 다르다.
