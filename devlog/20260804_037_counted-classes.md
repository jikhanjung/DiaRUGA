# 037 — 목록의 "검출" 은 세는 분류만 더한다

2026-08-04

첫 화면(`/diatom/`)의 **검출** 칸은 검토 후 남은 개체를 전부 세고 있었다.
파편도 미분류도 한 개다. 그런데 이 숫자를 실제로 쓰는 자리는 "이 슬라이드에
규조가 몇 개 있나" 이고, 거기서 파편 하나를 개체 하나로 세면 밀도가 부푼다.
RS23-GC03 369cm 는 923 → **444** 다. 두 배 넘게 차이 난다.

**세는 것은 봉상·원형·Eucampia 셋이다.** 파편(봉상 파편·원형 파편)과 미분류는
뺀다.

## 왜 표에 넣었나 — 코드에 셋을 박지 않은 이유

가장 짧은 길은 `data.py` 어딘가에 `("rod", "round", "eucampia")` 를 적는 것이다.
그러지 않았다. `ClassDef` 를 표로 둔 이유가 **분류를 더할 때 배포가 필요 없게**
하려는 것이었는데(models.py 머리말), 세는 목록을 코드에 박으면 새 속을 넣을
때마다 다시 배포해야 한다. 넣고 나서 "왜 검출 수가 안 늘지" 로 한 번 헤맬 자리다.

그래서 `ClassDef.counted` 를 뒀다. 기본값은 `True` — 새로 넣는 분류는 세는 것이
보통이고, 안 세는 쪽이 예외다. 마이그레이션(0013)이 기존 행 중 `rod_frag`·
`round_frag` 만 내린다. 키로 찾는 것은 이 한 번뿐이다.

미분류는 `counted` 를 볼 것도 없다 — 분류 자체가 없어 어느 칸에도 안 들어간다.

## 열도 표가 정한다

봉상·원형 두 열이 템플릿에 박혀 있었다. 검출 수가 셋의 합이 된 이상 셋이 다
보여야 한다 — 안 그러면 화면의 숫자가 **분해되지 않는다**(합만 있고 무엇이
얼마인지가 없다). Eucampia 열만 손으로 더하는 대신 `counted_classes()` 로
열 머리부터 합계 줄까지 한 줄기로 만들었다.

**0 인 분류도 자리를 남긴다.** 상세 화면의 `class_counts` 는 0을 빼는데(한 줄로
늘어놓는 자리라 그게 맞다), 목록은 표다. 줄마다 열 수가 달라지면 세로로 안 맞고,
세로로 맞추려고 표로 바꾼 화면이다.

## 시야당도 같은 분자로

`mean_detected` 를 그대로 두면 "검출 ÷ 시야" 가 "시야당" 과 안 맞는다. 두
숫자가 나란히 있는 표에서 그건 어느 쪽이 틀렸는지 알 수 없다는 뜻이다.
`mean_counted` 를 따로 냈다.

## 건드리지 않은 것

**상세 화면(`/d/<슬라이드>/`)의 "검출 N → 검토 후 M" 은 그대로다.** 그건 개체
수가 아니라 검토가 얼마나 걸러 냈는가를 보는 줄이라 파편도 세어야 뜻이 맞는다.
목록의 검출 칸에는 `title` 로 전체 개체 수를 함께 달아 두어, 두 화면의 숫자가
다른 것이 어긋남이 아니라는 것이 그 자리에서 읽히게 했다.

`n_detected`·`mean_detected` 는 남겨 뒀다 — 지우면 상세 화면과 API 가 따라
바뀐다. 목록만 `n_counted`·`mean_counted` 를 본다.

## 싱글턴 열을 뺐다

Eucampia 열이 들어오면서 표가 한 칸 넓어졌다. 대신 **싱글턴을 뺐다.**

싱글턴 수는 "초점 시리즈를 덜 찍었나" 를 보는 값이다 — 촬영을 손볼 때 쓰는
숫자이지 슬라이드끼리 견줄 숫자가 아니다. 표는 세로로 견주려고 만든 화면이라
거기 있을 이유가 약하다. 상세 화면에는 그대로 있고, 10개를 넘으면 거기서
경고까지 뜬다(`dataset.html`). 진단이 필요한 자리에 남겨 두고 목록에서만 뺐다.

열 수는 15 → 14 로, 원래대로 돌아왔다.

## 확인

배포 DB 사본으로 마이그레이션을 돌리고 테스트 클라이언트로 첫 화면을 때렸다.

