# 097 — 폴러 3단계가 사흘째 조용히 죽어 있었다 (heredoc 과 </dev/null)

2026-08-10 · 실사용 보고: "RS23-GC03 369cm (100) 이 슬라이드만 만들어지고
사진은 딸려오질 않았어"

## 증상과 실제

증상은 "사진이 안 왔다" 로 보였지만 사진은 **와 있었다** (774개 파일, 1.3 GB,
로컬 반입 완료). 슬라이드가 `pending` 에서 멈춰 **그룹핑부터가 안 돈 것**이다 —
시야 0 · 프레임 0 이라 화면에는 빈 슬라이드만 보였다.

poll.log 는 8-09 22:42 "다음: group_focus_series.py 로 시야를 묶는다" 를
마지막으로 조용했다. cron 은 매분 돌고 있었고, 잠금도 정상, 걸린 프로세스도
없었다 — **폴러가 매분 "할 일 없음" 으로 조용히 끝나고 있었다.**

## 뿌리 — 079 의 `</dev/null` 이 heredoc 을 굶겼다

079(8-07 15:33, `v0.8.1`)가 `run()` 에 `</dev/null` 을 붙였다:

```sh
run() { timeout "$1" docker compose run --rm -T pipeline "${@:2}" </dev/null; }
```

묶음 while 루프 안에서 docker 가 루프의 stdin 을 삼키는 것을 막으려던 것인데 —
**3단계의 밀린 일 조회가 heredoc(stdin)으로 파이썬을 먹이고 있었다:**

```sh
TODO=$(run "$T_SCAN" python - <<'PY' 2>/dev/null ...
```

`python -` 이 빈 stdin 을 받아 **조용히 성공(빈 출력)** 하고, 빈 TODO 는
"할 일 없음" 이다. `2>/dev/null` 이라 어긋난 흔적도 없다. 8-07 오후부터
3단계(그룹핑·합성·검출)가 통째로 죽어 있었고, **그 뒤 첫 새 슬라이드가
8-09 라 이제야 드러났다** — 죽은 날과 드러난 날 사이가 이틀이다.

026 과 같은 모양이다: 판을 갈라 폴러를 고치던/개선하던 변경이 폴러 자신을
물었고, 아무도 알려 주지 않았다.

## 고침

- **조회를 `-c` 인자로** — stdin 의존이 아예 없다
- **조회 실패는 소리를 낸다** — 성공한 빈 목록만 "할 일 없음" 이다. 실패면
  로그에 stderr 를 적고 그 주기를 세운다. (명령 치환 안의 PIPESTATUS 는
  밖에서 안 보인다 — 파일로 받아 갈랐다. 한 번 그렇게 짰다 고쳤다)

cron 이 저장소의 스크립트를 직접 부르므로 고침은 커밋으로 곧 적용이다.

## 교훈

- **전역 리다이렉트를 더할 때는 그 함수의 호출자를 전부 센다.** `</dev/null`
  은 루프 안 호출을 고치고 heredoc 호출을 죽였다 — 같은 함수의 두 쓰임이
  반대 것을 원했다
- **"조용히 성공한 빈 결과" 와 "실패" 를 한 갈래로 접으면 며칠을 모른다.**
  9.10절의 "폴러가 멈춘 것을 아무도 알려 주지 않는다" 가 또 물었다 — 마지막
  정찰 시각을 뷰어에 띄우는 일의 우선순위가 이것으로 한 칸 올라야 한다
