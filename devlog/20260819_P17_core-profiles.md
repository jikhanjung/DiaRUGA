# P17 — 코어 페이지에 깊이별 측정 항목을 그린다

2026-08-19 · 계획 · `sclee` · 앞의 것은 [063](20260806_063_layers-and-locality.md)(층·지점)·
[084](20260807_084_locality-page.md)(깊이 축)·[105](20260810_105_object-catalog.md)(카탈로그)

**목표**: 지점 화면(`/loc/<지역>/<지점>/`)의 깊이 축 옆에 **y축이 깊이, x축이
값인 꺾은선**을 놓는다. 기본으로 켜는 것은 **MS · 함수율 · Opal · TOC** 넷이고
나머지는 체크로 꺼 둔다. 자료가 있는 코어는 자동으로 불러오고, 없는 것은 사람이
넣는다 (사용자 방침 2026-08-19).

아직 아무것도 안 만들었다. 여기 적는 것은 **자료가 어떤 모양으로 왔고, 그것을
어디에 어떤 꼴로 앉히며, 무엇을 안 하는가**다.

## 1. 온 자료

`N:\DiaRUGA\coredata` (이 호스트에서는 `/nfs/temp-share/DiaRUGA/coredata`) 에
xlsx 둘이 들어왔다. **둘 다 지금 DB 에 없는 코어다** — `RS14-GC04` · `RS19-GC17`.

| | RS14-GC04 | RS19-GC17 |
|---|---|---|
| 코어 길이 | ~362 cm | ~599 cm |
| W.C (함수율) | 177행 · 2 cm | 598행 · 1 cm |
| CN (TN·TC·TIC·CaCO₃·TOC·C/N) | 178행 · 2 cm | 320행 · 2 cm |
| Size (입도) | 90행 · 4 cm | 149행 · 4 cm |
| MS (자기감수율) | 400행 · Point/Whole 두 벌 | 600행 · Point/Whole 두 벌 |
| XRF | **8,378행 × 25원소** · 1 mm | — |
| Opal | 587행 | — |
| Spectro (Munsell · L\*a\*b\*) | — | 599행 · SCE/SCI 두 벌 |

공통은 **W.C · CN · Size · MS** 넷이고 나머지는 코어마다 있고 없다.

단위는 사용자가 확인했다 — **Opal 은 %, MS 는 SI**.

### 1.1 머리글을 믿으면 안 되는 자리가 셋

**전부 RS14 다.**

- `MS` 머리글이 `Depth(mm)` 인데 값이 `1~362` 다. 코어가 362 cm 이니 **cm 다**.
  같은 파일 `XRF` 는 `position (mm)` 이 `1~3609`(= 360.9 cm)로 **진짜 mm** 이고,
  RS19 쪽 `MS` 는 `Depth(cm)` 로 맞게 적혀 있다. 그대로 믿으면 프로파일이 코어
  맨 위 36 cm 에 뭉친다.
- `Opal` 머리글이 `depth(m)` 인데 값이 `0~362` 다. 이쪽도 cm.
- `Opal (2)` 는 **사용자가 편집하다 갈라 놓은 것이라 안 읽는다**.
  `Opal 요약` 은 표가 아니라 사람이 읽는 문서다(제목·개요 문단 + 깊이 블록 세
  벌이 가로로) — 반입 대상이 아니다.

그래서 **반입기는 머리글의 단위를 근거로 삼지 않는다.** 시트마다 어느 칼럼이
무엇이고 깊이 단위가 무엇인지를 **사람이 확인한 매핑표**가 따로 있고, 거기 없는
시트는 **안 읽는다**(조용히 넘기지 않고 그렇게 말한다). 머리글에서 짐작하는
갈래를 두면 다음 코어에서 같은 침묵이 돌아온다.

### 1.2 한 시트에 표가 둘인 것

`MS` 는 `Point` 와 `Whole` 이 빈 열을 사이에 두고 가로로 붙어 있고, RS19
`Spectro` 는 `SCE`/`SCI` 두 블록이 **같은 머리글을 반복한다**(`Munsell C Hue` 가
두 번). 열 이름으로 짚으면 뒤엣것이 앞엣것을 덮는다 — 매핑표는 **열 번호로**
짚는다.

### 1.3 그 밖에

- 머리글 행 위치가 파일마다 다르다 (RS14 `W.C` 는 2행, RS19 `Spectro` 는 1행).
- 이름 없는 칼럼에 값이 있다. RS19 `W.C` 는 6열인데 머리글이 5개다 — 함수율이
  두 벌인데 이름은 하나다. RS19 `Size` 오른쪽에는 계량 원자료가 딸려 있다.
- 깊이 간격이 코어 안에서 바뀐다 (RS14 는 `0-340cm 4cm, 340-366cm 8cm`).
  **등간격을 전제로 그리면 어긋난다** — 점의 깊이를 그대로 좌표로 쓴다.
- `:Zone.Identifier` 는 Windows 찌꺼기라 무시한다.

## 2. 정한 것 · 남은 것

**정했다** (사용자 2026-08-19):

- **`MS` 는 `Whole` 을 기본으로 켠다.** `Point` 도 함께 반입하고 체크로 둔다.
- **`TOC` 는 wt% 다** (사용자 확인).
- **XRF 는 반입까지 함께 간다.** 기본은 꺼 둔다.
  **점 수를 잘못 셌다** — 시트가 8,384행이지만 **뒤 4,809행이 통째로 비어
  있다**(엑셀이 남긴 자리). 실제 측정은 3,575점이라 24원소로 **85,800행**이다.
  20만 행이 아니다. 그래도 한 항목이 3,575점이라 화면으로 그대로 내보낼 수는
  없고, 줄이는 층은 4단계에 그대로 둔다.
- **지점 둘은 운영의 시스템 설정 화면에서 사람이 만든다.** 코드는 안 고쳐도
  된다 — `manage_data.create()` 가 이미 `Site`·`Locality` 를 만든다.

**아직 남았다**:

1. **화면에서 이것을 뭐라 부르는가.** `지표` 와 `계열` 은 이미 다른 뜻으로
   쓰고 있다(`shape.py` 의 형태 지표 · `_detection.html`) — 겸하면 안 된다.
   **구역 제목은 "코어 자료", 하나를 가리킬 때는 "측정 항목" 으로 두고 간다.**
   더 나은 말이 나오면 그때 바꾼다.
2. **`RS14`·`RS19` 를 새 `Site` 로 세우는가.** 규칙대로면 그쪽이 지역이고
   `GC04`/`GC17` 이 지점이다. 지금 `Site` 는 `RS23`·`WAP13`·`AM22`·`GC03`·`BP` 다.
3. **XRF 의 단위.** 매핑표에 빈칸으로 두었다 — 모르는 것을 적지 않는다.
4. **`RS14-GC04` 의 자기감수율(Whole)이 한 점에 축을 다 먹힌다** (135 8절).
   구간을 잘라 보는 기능이 필요한지.

## 3. 스키마 — 긴 테이블 하나

**칼럼을 고정한 테이블로 잡으면 안 된다.** 코어마다 있는 항목이 다르다(RS14 만
XRF·Opal, RS19 만 Spectro) — 칼럼을 박으면 절반이 빈 채로 남고, 코어가 하나 더
들어올 때마다 마이그레이션이 붙는다.

```
CoreSeries   (locality, key, label, unit, source, sort_order, default_on, note)
  └ CorePoint (series, depth_cm, value)      unique (series, depth_cm)
```

- `key` 는 기계가 쓰는 이름(`ms_point`·`wc`·`opal`·`toc`), `label` 은 화면 글자,
  `unit` 은 화면에 그대로 뜬다(`SI(10⁻⁵)` · `%`).
- `depth_cm` 은 **언제나 cm 다.** mm 로 온 것은 반입할 때 나눈다 — DB 안에 두
  가지 단위가 섞이면 질의하는 쪽이 매번 그것을 알아야 한다.
- `default_on` 이 체크의 기본 상태다. **DB 가 들고 있어야 코어마다 다르게 켤 수
  있다** — 템플릿에 이름 넷을 박으면 항목 이름이 바뀔 때 화면이 조용히 빈다.
- **XRF 처럼 점이 많은 항목은 화면으로 그대로 안 나간다.** 내려보내기 전에
  줄인다 — 어디서 줄이는지는 4단계에서 정하되, **줄인 것을 화면이 그렇게
  말한다**(몇 점 중 몇 점인지). 조용히 줄이면 안 잰 구간과 구별이 안 된다.
- `unique (series, depth_cm)` 를 둔다. **제약이 있다는 것과 조회가 그걸 쓰는
  것은 다르다**(053) — 질의도 이 짝으로 짚는다.

### 3.1 `source` 를 가르는 이유

`source` 는 `import` 와 `manual` 둘이다. **자동 반입은 자기 출처의 항목만
갈아치운다.** 이것이 없으면 xlsx 를 다시 반입할 때 사람이 넣은 값이 지워진다 —
063 에서 `update_or_create` 의 `defaults` 에 `None` 을 실었다가 사람이 채운
소속이 날아간 것과 같은 줄이다.

### 3.2 검출 수는 저장하지 않는다

규조 검출 수는 **이미 DB 에 있다**. 관찰마다 `n_counted` 가 있고 시료마다
`depth_cm` 이 있으니 깊이 축에 그대로 얹힌다 — 테이블에 또 넣으면 두 벌이 되고
어긋난다. **파생 항목으로 만든다**(`source='derived'` 를 하나 더 두거나, 아예
저장하지 않고 화면이 계산한다 — 4단계에서 정한다).

`Chaetoceros` 개체수도 같은 자리다. 카탈로그의 동정에서 세어지므로 **종명이
채워지는 만큼 저절로 는다.** 다만 **g당 개체수 같은 환산값은 시료 무게가 있어야
나오므로 그것은 수동 항목이다.**

## 4. 반입 — 두 단으로 가른다

xlsx 를 컨테이너 안에서 바로 읽으면 웹 이미지에 `openpyxl` 이 들어가야 하고,
`/nfs/temp-share` 를 컨테이너가 보게 해야 한다. 둘 다 이 일 하나 때문에 늘리기엔
넓다. **그리고 1.1 의 매핑표는 눈에 보이는 파일로 남아야 한다.**

```
xlsx  ──(호스트, Django 안 씀)──▶  coredata/<지점>.csv + mapping.toml
                                        │
                                        └──(dbrun.sh)──▶  DB
```

- 앞단(`tools/coredata_extract.py`)은 **`ops/export_review.py` 와 같은 자리**다 —
  Django 를 안 부르고 DB 도 안 만진다. 호스트 venv 로 돈다.
- 뒷단(`ops/import_coredata.py`)은 CSV 만 읽으므로 `dbrun.sh` 로 컨테이너 안에서
  규약대로 돈다. **`ops/check_db.py` 의 머리를 베껴 온다**(`DIARUGA_APP`).
- 중간 CSV 와 매핑표는 **저장소에 커밋한다.** 사람이 확인한 판단이 거기 있고,
  다음 코어가 들어올 때 견본이 된다. 원본 xlsx 는 커밋하지 않는다(1.8 MB · NAS 에
  있다).
- `openpyxl` 은 **앞단에만** 필요하다. `requirements.txt` 에 적는다
  (이번에 호스트 venv 에 3.1.5 를 넣었는데 아직 안 적었다).

## 5. 화면 — 축을 나눠 쓴다

지금 `core.html` 의 `logbody` 는 `--bottom` 을 놓고 눈금·시료를 **% 로** 앉힌다.
프로파일도 **같은 좌표계를 써야** 눈금과 어긋나지 않는다.

- 인라인 SVG 로 그린다. **바깥 라이브러리를 안 쓴다** — 이 저장소에 그런 것이
  없고, 축이 이미 CSS 로 서 있어 섞을 이유가 없다.
- `viewBox="0 0 100 {{ axis.bottom }}"` + `preserveAspectRatio="none"` 로 **깊이를
  그대로 y 좌표로 쓴다.** 값만 0–100 으로 정규화하면 축 계산이 한 군데로 모인다.
- 항목마다 폭이 좁은 칸 하나씩, 가로로 정렬한다. 켜진 것만 자리를 차지한다.
- **색을 박지 않는다**(107). 테마가 둘이라 `#…` 을 적으면 어두운 쪽에서 덩어리가
  된다 — `base.html` 에 이미 갈려 있는 토큰을 빌린다.
- 값이 없는 깊이는 **선을 잇지 않는다.** 이어 버리면 안 잰 구간이 잰 것처럼 뜬다.
- 체크는 주소에 남긴다(`?series=ms_point,wc,opal,toc`). 링크로 남길 수 있어야
  "이 조합으로 보라" 를 주고받는다.

**노두 지점에는 이 자리가 안 뜬다.** 노두의 시료 위치는 거리가 아니라 순서이고
(`locality_detail` 머리말), cm 축이 없는 곳에 프로파일을 얹으면 없는 간격을
지어낸다. 그 자리는 지금대로 현장 사진이 쓴다.

## 6. 관찰이 없는 코어에도 축이 서야 한다 — 이번의 핵심

지금 깊이 축은 **시료의 `depth_cm` 에서만** 나온다(`data.locality_detail`).
관찰이 없으면 `axis` 가 `None` 이고 화면은 "깊이가 적힌 시료가 없어 축을 그릴 수
없습니다" 를 낸다. **RS14-GC04·RS19-GC17 이 정확히 그 상태다.**

그래서 **축의 근거를 넓힌다** — `bottom` 은 `max(시료 깊이, 측정 항목의 최대
깊이)` 다. 이러면 관찰이 하나도 없는 코어에도 축과 프로파일이 서고, 나중에 관찰이
붙으면 **같은 축 위에 얹힌다.**

안내 문구도 갈라야 한다. 지금 것은 "정보 편집에서 깊이를 채우면 여기 나옵니다"
인데, 자료도 관찰도 없는 코어에는 맞지 않는다 — 노두에 안 내는 것과 같은 이유다
(없는 값을 채우러 가게 만든다).

## 7. 수동 입력

- **좁은 문이다.** `POST` 는 **측정 항목 하나** 단위로 받는다. `/review` 처럼
  범위를 갈아치우지 않는다 — 017·027·053 계열의 사고가 구조적으로 안 생긴다.
- **층이 다른 것을 한 payload 에 싣지 않는다**(116). 항목의 속성(이름·단위·기본
  켜기)과 점 목록은 요청을 가른다.
- 넣는 꼴은 **붙여넣기**다. 엑셀에서 두 칸(깊이, 값)을 긁어 넣는 것이 실제
  작업이고, 칸을 하나씩 만드는 화면은 600행 앞에서 못 쓴다.
- 미리 보인 다음 저장한다. 몇 행이 들어오고 몇 행이 덮이고 몇 행이 버려지는지를
  **누르기 전에** 보인다(063 의 지우기 문턱과 같은 줄).
- **서버가 다시 검사한다** — 화면에서 막는 것은 막는 것이 아니다.

## 9. 시험

**되살려서 잡히는 것만 적는다**(064). 목록은 위에서 실제로 물릴 자리들이다.

- 매핑표에 없는 시트는 **반입되지 않는다**. 머리글로 짐작하는 갈래가 없다.
- RS14 `MS`·`Opal` 의 깊이가 **cm 로 앉는다** — 1.1 이 사람이 확인한 사례이므로
  값을 검사에 박는다(낡은 목록이 아니라 틀린 전제를 잡는 자리다).
- **재반입이 `manual` 항목을 안 덮는다** (3.1).
- **관찰이 없는 지점에 축이 선다** (6절).
- **노두 지점에는 이 자리가 안 뜬다** (5절).
- **XRF 를 켠 화면이 20만 행을 내려보내지 않는다** — 줄인 점 수가 화면에 뜬다.
- 체크를 껐다 켠 뒤 **주소만으로 같은 화면이 돌아온다**.
- 화면 시험은 **자료가 어느 갈래로 가는지**를 본다(086) — 항목이 없는 코어 ·
  있는 코어 · 노두 셋을 각각 연다.

## 10. 안 하는 것

- **암상 띠를 채우지 않는다.** 기재 규칙이 아직 없다(`locality_detail` 머리말).
  프로파일은 그 옆자리에 앉고, 띠는 비워 둔 채로 둔다.
- **속성을 여기서 고치지 않는다.** 지점·지역은 `/d/<slug>/edit/` 이 고친다 —
  같은 행에 쓰는 문을 둘로 만들지 않는다.
- **xlsx 를 화면에서 올리지 않는다.** 1.1 의 매핑이 사람의 확인을 거쳐야 하므로
  올리기 한 번으로 끝나는 문을 만들면 그 확인이 사라진다.
