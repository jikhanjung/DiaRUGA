# 남극 시야의 완료 표시를 걷는다 — 직접 그리기를 포함한 2차 검토

2026-08-09. 검토자 요청.

## 왜

직접 마스크를 그리는 길(P09)이 열리기 전에 검토한 시야는 **엔진이 낸 것 중에서
고르는 일**만 거쳤다 — 엔진이 아예 못 낸 개체는 손댈 방법이 없었다. 검토자가
기능을 실제로 써 보고(18건, `260731_rs23-gc03_369cm`) 남극 시료를 다시 보기로
했다. 놓친 개체를 그려 넣는 것이 재현율의 나머지 절반이자 다음 학습의 가장
값진 양성 표본이다.

## 무엇을

`reset_review_done.py` 로 남극 9개 슬라이드, 시야 366개의 완료 표시
(`ViewpointReview.done`, 검토 대상 묶음)를 걷었다.

- **교정 7,493건과 시야 코멘트는 건드리지 않았다** — 체크만 풀었다
- 백업: `manual/DiaRUGA_20260809_151343_before-review-reset.db`
- 한국(BP) 둘은 그대로 — 별개 갈래다

## 회차를 어떻게 가르는가 — 새 칸을 만들지 않았다

검토자 판단은 "구분할 필요는 없겠지만 진척은 보고 싶다"였다. 그래서:

- **1차의 기록은 git 에 이미 있다** — `review/` 감사 기록과 이 시점 이전의
  백업이 1차 완료 상태를 그대로 들고 있다
- **지금부터 남극에 다시 붙는 완료가 곧 2차다** — 걷은 시점(08-09 15:14)이
  분수령이라 따로 표시할 것이 없다
- **직접 그린 개체는 저장부터 구분돼 있다** — `batch IS NULL` (P09 0단계)

진척은 `review_progress.py` 가 슬라이드별로 보여준다 — 완료/전체와 그린 개체
수. 그린 개체 수가 곧 "엔진이 놓친 것"의 실측이라, 이 표가 그리기 기능의
가치와 다음 판 재현율 개선폭을 함께 말해 준다.

```
deploy/host/dbrun.sh review_progress.py
```
