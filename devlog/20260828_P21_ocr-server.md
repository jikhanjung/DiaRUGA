# PDF 를 OCR 서버로 읽는다 — 무엇이 대체되고 무엇이 안 되나 (설계)

사용자가 **"도감·논문 PDF 처리하는 부분을 OCR 서버로 대체하려고 한다"** 고
했다(2026-08-28). 사내에 `ocrserver` 가 이미 돌고 있고
(`http://172.16.112.150:8080`, 명세는 `docs/WRAPPER_API.md`), 여기서 닿는다.

**대체를 결정하기 전에 시험 6쪽을 실제로 넣어 보고 원문과 대조했다.** 아래
판단은 전부 그 실측에서 나온 것이다.

## 1. "PDF 처리" 는 한 가지가 아니다 — 갈래를 먼저 가른다

지금 저장소에서 PDF 를 만지는 자리가 다섯이고, **대체되는 것은 둘뿐이다.**

| | 지금 무엇이 하나 | 대체되나 |
|---|---|---|
| **A. 쪽 → PNG** (뷰어 도판) | `tools/render_atlas_pages.py` · pdftoppm 300 dpi · 1,510쪽 | **아니다.** 서버는 이미지를 안 돌려준다(내부 150 dpi 는 OCR 용) |
| **B. 텍스트 레이어 뽑기** | `pdftotext -layout` — `tools/parse_occurrence.py`(한국 p.46–190) · `tools/parse_dsdp87_captions.py` | **그렇다.** 텍스트 레이어가 없는 절반이 열린다 |
| **C. 남이 만든 해설 OCR** | `Diadiction/md/schmidt_atlas_band*_notes_ocr.md` | **그렇다 — 값이 제일 크다** |
| **D. 사람이 쪽을 렌더해 읽기** | `tools/render_verify.py` · 126 의 20쪽 · 147 의 17쪽 · 160 의 27쪽 · #481–680 의 200 항목 | **아니다 — 입력 목록을 좁혀 줄 뿐이다** |
| **E. 도판 그림 번호 짚기** | `tools/crop_plates.py --probe` + 손으로 적는 `ASSIGN` | **아니다.** 161 이 이미 못 박았다 |

## 2. 실측 — 잘하는 것과 못 하는 것이 뚜렷이 갈린다

시험 묶음 6쪽(`pdfseparate`+`pdfunite` 로 원본에서 떴다):
DSDP 1985 p.23(도판 캡션) · Band4 p.74–75(해설+도판면) · Band1 p.236–237 ·
한국 도감 p.200(도판면). 쪽당 **18.8~42.1초**, 그때 모드는 `llm+ocr`
(백엔드 1/2 alive · 권장 동시성 6)이었다.

**같은 쪽을 200 dpi 로 따로 렌더해 눈으로 읽어 대조표를 만들었다.**

### 잘한다 — 구조와 번호

- **Band4 p.74 를 `Tafel 371.` 로 읽었다.** 기존 해설 OCR 이 이 묶음
  (p.74–86)을 통째로 `377` 로 달아 놓아 **137건을 고쳐야 했던 바로 그
  자리다**(121·126). 도판면 머리의 `371` 도 맞다
- Band1 p.236 의 `Tafel 109.` 도 맞다
- 항목이 `<ol><li>` 로, **학명이 `<b>`·`<i>` 로 갈려 나온다** —
  `genus_screen.read_notes` 가 지금 정규식으로 짚는 자리를 마크업이 말해 준다
- **`data-bbox` 와 `data-label`**(Page-Header / Caption / List-Group / Image /
  Text)이 붙는다. 한국 p.200 의 캡션 세 열이 `Caption` 셋으로 정확히 갈렸고,
  **번호↔이름 짝은 12개 다 맞았다**
- Band4 해설 9항목은 **학명까지 무결**했다

### 못 한다 — 학명 철자

원문과 대조해 확인한 것만:

| 원문 | OCR |
|---|---|
| *Crucidenticula punctata* | *Crucidenticula**ta** punctata* |
| *A. Simbirs**k**ianus* (2회) | *A. Simbirsianus* |
| *A. Bolivi**e**nsis* | *A. Bolivensis* |
| *phoenicenteron* var. *Hankensis* | *phoenixienetus* var. *Shankensis* |
| *acros**p**haeria* | *acrophaeria* |
| *disti**n**guenda* (2회) | *distiguenda* |
| *P. **B**raunii* (2회) | *P. braunii* |

**전부 예외가 안 나고 그냥 다른 이름이 된다.** 그리고 `pdftotext` 의 글리프
오독(`Crucidenficula`)보다 **더 그럴듯해서 눈으로 안 걸린다** — 163 의 가짜 종
`Enlarged view` 와 같은 갈래인데 그때보다 훨씬 그럴듯하다.

**대문자 `Braunii` → `braunii`** 가 특히 나쁜 갈래다. 126 의 **"원문 자체의
오식은 고쳐 쓰지 않는다"** 가 성립하려면 원문이 그렇게 찍혔다는 증거가 있어야
하는데, **이 OCR 은 조용히 정상화한다.**

### 버려야 하는 것 — 도판면의 산문은 창작이다

`data-label="Image"` 안의 `<img alt>` 와 설명 문단이 그렇다.

- Band4 p.75 → `Esquisisses of nine freshwater diatom morphological views from
  the vernal pool (Springfeuch)`
- 한국 p.200 → 그림마다 *Pinnularia vogotensis* · *Pinnularia crocophacteria*
  같은 **없는 이름**을 지어 붙였다 (같은 쪽의 진짜 캡션 블록은 따로 맞게 나왔다)

**자료로 쓰면 가짜 종이 색인에 들어온다.**

## 3. 흐름 — 판정하는 자리가 아니라 후보를 만드는 자리다

층이 하나 생기고, 대조 관문은 지금 것을 그대로 쓴다.

```
PDF (Diadiction/origin/ · papers/)
 ├─ pdftoppm 300dpi ──→ /data3/DiaRUGA/atlas/<code>/pNNNN.png     (뷰어 도판 — 안 바뀐다)
 └─ POST /ocr ────────→ Diadiction/ocr/<pdf>/pNNNN.html + job.json  (새로 생기는 자리)
                          ├─ 이름 후보 → harvest_worms.binomial → AlgaeBase/WoRMS 대조표
                          │      ├ 맞는다  → 항목 후보로 앉힌다
                          │      └ 안 맞는다 → render_verify 작업지 (사람이 그 쪽을 본다)
                          ├─ Tafel·쪽 머리 → 해설 md 의 Tafel 번호 검산
                          └─ 분포표·datum 문장 → parse_occurrence 의 입력
```

**`md/` 는 사람이 보는 원본 자리다 — OCR 산물을 거기 섞지 않는다.**
`atlas/*.json` 이 `md/` 의 사본이듯 `ocr/` 은 PDF 의 사본이고, 언제든 지우고
다시 만든다(P15 4.2 와 같은 규칙).

## 4. 반드시 지킬 것 여덟

1. **쪽 번호가 0-based 다.** `pages[i].page` 는 0 부터인데 이 저장소의
   `pdf_page`·`pNNNN.png` 는 1 부터다. **한 칸 어긋나도 예외가 안 나고 옆 쪽이
   된다** — 053(프레임 이름)·103(판이 여럿)과 같은 줄이다. `+1` 은 받는 자리에서
   한 번만 하고, 시험이 그 자리를 박는다
2. **PDF 를 쪼개지 않는다.** `origin/div/`·`dup/` 는 이미 "쪽 번호가 색인과 안
   맞아 넣으면 안 된다" 고 `render_atlas_pages.py` 가 적어 두었다. OCR 도 **그
   스크립트가 쓰는 같은 파일**을 통째로 올린다 — 제일 큰 `Band1.pdf` 가 392 MB
   라 500 MB 상한 아래다. 쪼갤 일이 생기면 **오프셋을 함께 적는다**
3. **`data-label="Image"` 안의 산문과 `<img alt>` 는 버린다.** 자료가 아니다
4. **학명은 OCR 이 정하지 않는다.** 대조표를 통과한 것만 앉히고, 못 통과한
   것은 사람이 그 쪽을 본다
5. **`원문 자체의 오식` 판정은 OCR 로 못 내린다.** 그 갈래는 계속 쪽을 렌더해
   읽는다 (126)
6. **다시 올려도 같은 글자가 안 나온다**(LLM 표집). `client_id` 를 `diaruga` 로
   못 박고 **`job_id` 를 결과와 함께 남긴다** — 나중에 "이 값이 어디서 왔나" 를
   물을 자리가 그것뿐이다. dedup 은 `(file_hash, client_id)` 라 완료된 job 이
   있을 때만 같은 것을 돌려준다
7. **GPU 를 YOLO 학습과 나눠 쓴다** (HANDOFF 8.2 — "두 GPU 를 ocrserver 가 쓰고
   있어 자리를 비워야 한다"). 큰 반입은 학습 없는 날에 돌리고, 큐 깊이는
   `/api/stats` 의 `recommended_concurrency` 를 보고 정한다
8. **인증이 없다.** 사내망 전용이고 `client_id` 는 검증되지 않는다

## 5. 비용 — GPU 시간과 토큰

### GPU

도감 1,336쪽 + 논문 359쪽 = **1,695쪽.** 쪽당 28초·동시성 6 이면 약 2.2시간,
**동시성 12 면 1.1시간이다.** 결과는 쪽당 1.3~4 KB 라 전부 5 MB 남짓 —
**저장소에 안 넣고** NAS `Diadiction/ocr/` 에 둔다.

**시험을 돌린 때는 `llm+ocr`(백엔드 1/2 · 권장 6)이었고, 사용자가 그 뒤
`2ocr` 로 전환했다**(2026-08-28). 그러면 권장 동시성이 12 가 된다 — 위 실측
쪽당 시간은 그대로이고 전수 시간만 절반이 된다. **모드는 고정이 아니므로
`/api/stats` 의 `recommended_concurrency` 를 보고 큐를 채운다**(4장 7번).

### 쪽 하나를 모델에 실을 때

| | 토큰 |
|---|---|
| 쪽 이미지 (200 dpi) | **약 2,290** |
| OCR 텍스트 — 서버가 준 그대로 | 약 650 |
| OCR 텍스트 — 산문·bbox 를 걷은 뒤 | **약 315** |

**dpi 를 올려도 이미지 토큰은 안 는다.** Band1 p.236 을 110·200·300 dpi 로
재 보니 2,127 · 2,289 · 2,291 이다 — 긴 변 1568 px 로 줄여서 세기 때문이다.
`render_verify.py` 의 200 dpi 가 이미 그 상한이라 **더 크게 떠도 잔글씨가 더
읽히지 않는다.**

**걷어내는 동작이 안전 규칙과 같다** — `data-label="Image"` 산문을 버리는 것은
토큰을 절반으로 줄이는 동작이면서 4장 3번을 지키는 동작이다. 도구가 그 한 번을
하면 둘이 같이 된다.

### 세션 하나가 여는 쪽

**상한은 토큰 총량이 아니라 컨텍스트 창 200k 다.** 실작업에 쓸 자리를 120k 로
보면 이미지 52쪽 · 텍스트 380쪽이 들어간다. 그런데 **실적은 그 절반이다** —
쪽 읽기가 세션의 전부가 아니라 대조표·색인 항목·기존 판정을 함께 봐야 하기
때문이다.

| 세션 | 읽은 쪽 | 닫은 것 |
|---|---|---|
| 126 | 20쪽 | 29건 |
| 147 | 17쪽 | 쪽 머리 17개 |
| 160 | 27쪽 | 32건 |

| | **지금** | **OCR 뒤** |
|---|---|---|
| 세션이 여는 쪽 | **17~27쪽** | **1,485쪽 전수** (도구가 훑는다) |
| 모델이 읽는 것 | 그 17~27쪽 **전부** (이미지) | **잔여 수십 건**만 |
| 쪽을 여는 토큰 | 39~62k — 창의 절반 | 도구가 훑는 자리는 **0** |

**쪽 수가 상한이 아니게 되는 것이 요점이다.** 텍스트를 창에 실어 읽기만 하면
150~250쪽으로 6배 늘 뿐인데(쪽당 7배 싸도 창에 쌓이는 것은 그대로다),
**도구가 훑고 잔여만 실으면 상한이 사라진다.**

이건 이미 이 저장소가 md 에 대해 하는 방식이다 — `parse_atlas.py` ·
`harvest_worms.py` · `verify_from_notes.py` 가 색인 2,059 표제어를 그렇게
다뤘고 모델이 본 것은 잔여 140건, 다시 32건이었다. **OCR 서버는 그 방식을
PDF 에도 성립하게 만드는 것**이지 모델이 쪽을 더 많이 읽게 하는 것이 아니다.

**안 줄어드는 것이 하나 있다 — 학명 철자 확인.** OCR 이 흘린 자리는 그 쪽을
이미지로 다시 봐야 하고 값은 지금과 같다. 다만 **어느 쪽을 봐야 하는지를 도구가
골라 준다** — 지금은 그 고르는 일을 사람이 쪽을 열어 가며 한다.

## 6. 순서

1. **Schmidt 해설 1,046쪽 재-OCR** → 기존 `schmidt_atlas_band*_notes_ocr.md` 와
   **Tafel 번호만 대조**한다. 137건 갈래가 얼마나 더 남아 있는지가 이 한 번에
   나온다. 실측에서 371·109 를 맞게 읽었다
2. **한국 도감 p.191–270 도판 캡션** → `parse_occurrence.py` 가 못 덮은 200
   항목(#481–680) 자리다. 실측 p.200 에서 캡션 세 열이 정확히 갈렸고 번호↔이름
   짝이 다 맞았다(철자는 12 중 4 틀렸다). 사람이 처음부터 읽는 대신 **후보를
   놓고 철자만 확인**한다
3. **논문 열다섯** → 분포표(1975 Table 2 · 1986 Table 3·4 · 1993 남해)가
   markdown 표로 나오는지 **한 쪽만 먼저 떠서 확인한다.** 이번 시험에 표 쪽이
   없었다. 2007·2017 의 다이어그램은 `papers/README.md` 가 이미 "안 된다" 고
   못 박은 자리라 OCR 도 못 한다
4. **`plate_figs.CAPTIONS`** → 1936·1992·1993 은 이미 손으로 다 적었으니 새로
   할 일이 아니고, **다음 논문**부터 OCR 후보로 시작한다

## 7. 도구는 하나면 된다

`tools/ocr_pdf.py` — 올리고 · 기다리고 · 쪽마다 파일로 떨어뜨린다.
NAS 를 보므로 `tools/` 자리다(`/srv` 로 안 간다 — `render_atlas_pages.py` 와
같은 이유: 컨테이너는 `/nfs/temp-share` 를 못 본다).

떨어뜨릴 때 **4장 1번(쪽 번호 +1)과 3번(산문 걷기)을 그 자리에서 한다** —
나중에 읽는 쪽마다 하면 한 곳이 빠진다.

## 8. 받아 온 명세가 배포된 것보다 조금 낡았다

`docs/WRAPPER_API.md` 는 `jikhanjung/ocrserver` 에서 그대로 받아 온 것인데
배포된 wrapper(`honestjung/ocrwrapper:0.2.3`)와 어긋나는 자리가 있다.

- `POST /ocr` 응답에 문서에 없는 **`forced`·`total_pages`** 가 있다.
  `forced` 는 dedup 을 건너뛰는 인자가 있다는 뜻으로 보이는데 **4장 6번
  (재현성)과 맞물리는 자리**라 확인해 둘 것
- `/api/services` 에 문서에 없는 `images`·`llm_model` 블록이 있다
