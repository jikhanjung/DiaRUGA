## 1. 계측 기준의 출처를 소급해서 채웠다 (`backfill_scale_source.py`)

004 에서 `zen_meta.py` 를 만들었지만 **전량 배치는 그 이전에 돌아서** 결과 JSON 에
`um_per_pixel_source` 가 없었다. 이 데이터셋에서는 하드코딩 상수가 XML 값과 같아
계측값은 어긋나지 않았지만, 출처가 없으면 나중에 의심할 수가 없다.

먼저 004 에서 남긴 숙제를 처리했다 — **실제 ZEN XML 345개로 파서를 확인**했다
(`source='xml'`, 0.112599 µm/px). 004 는 촬영 데이터가 없는 머신이라 합성 XML 로만
검증했다고 적어 두었는데, 이 머신에는 원본이 다 있었다.

그다음 재추론 없이 출처를 채웠다. 원본 43개는 XML 에서 직접, 합성본 81개는
`focus_stack.py:carry_scaling()` 이 하는 일을 그룹 정의에서 되짚어 **없던 사이드카
81개를 만들고** 그것을 출처로 삼았다.

**채우기 전에 검증한다** — 기록된 배율과 지금 읽은 XML 값이 다르면 그 파일은 손대지
않는다(불일치 0건). 계측값 전체가 그 배율로 계산돼 있으므로 숫자만 갈아 두면 앞뒤가
맞지 않는다. 뒤늦게 채운 값임을 `um_per_pixel_backfilled` 로 남겼다.

## 2. areolae 를 원형 판정에서 더 무겁게 봤다

"원형으로 인식됐는데 areolae 가 뚜렷하지 않은 것은 검출될 확률을 낮추고 싶다" 는
요구였다. 그런데 기존 코드에는 그런 손잡이가 없었다 — 텍스처는 striae·areolae 를
한 숫자로 재고 봉상·원형에 같은 문턱 1000 을 쓴다.

### 형태로는 가려낼 수 없다

원형 통과분을 텍스처 구간별로 갈라 봤다.

| 텍스처 구간 | 개수 | 타원 IoU 중앙 | 볼록성 중앙 | 장축 중앙 |
|---|---|---|---|---|
| 1000~1500 | 159 | 0.887 | 0.962 | 14.2 µm |
| 1500~2000 | 82 | 0.896 | 0.957 | 14.2 µm |
| 2000~3000 | 121 | 0.886 | 0.960 | 15.2 µm |
| 3000~5000 | 124 | 0.891 | 0.959 | 16.6 µm |
| 5000+ | 183 | 0.898 | 0.966 | 18.4 µm |

**IoU 0.886~0.898, 볼록성 0.957~0.966 — 거의 평평하다.** 형태 문턱을 어디에 두어도
areolae 가 약한 원반과 뚜렷한 중심목이 갈리지 않는다. 그래서 areolae 세기 자체를
관문으로 두는 것이 정직하다.

### `--round-texture-min` (기본 1500)

원형에만 걸린다. 봉상은 1000 그대로다. 탈락분은 `원형areolae부족` 사유로 남아
뷰어에서 되살릴 수 있고, 문턱은 `refilter.py` 로 2초에 다시 잡는다.

```
후보 2,675 -> 2,522 · 원형 669 -> 514  (155개가 areolae 부족으로 빠졌다)
문턱 1200 -> 598 · 1500 -> 514 · 2000 -> 432 · 2500 -> 363
```

봉상이 2,006 → 2,008 로 **늘어난다.** 원형이 빠지면서 중첩 정리에서 살아남는 것이
생기기 때문이다.

### 유의 — 이 문턱은 작은 중심목을 먼저 떨어뜨린다

텍스처는 크기와 같이 움직인다(위 표의 장축 중앙 14.2 → 18.4 µm). 작은 개체는
areolae 를 담는 화소가 적어 점수가 낮다. **문턱값 자체와, 이것이 진짜 작은 중심목을
함께 떨어뜨리지 않는지는 실물로 확인해야 한다**(TODOs 1순위).

## 3. 뷰어를 "검토를 실제로 돌릴 수 있는" 도구로 만들었다

전수 검토를 하면서 걸리는 것을 그때그때 고쳤다. 큰 것만 적는다.

### 시야를 넘기는 흐름

- **← →** 로 캐러셀을 넘기고, 끝에서 한 번 더 누르면 이웃 시야로 넘어갈지 묻는다
  ("다시 묻지 않기" 를 고르면 이후로는 바로).
- **Ctrl+← →** 와 **« »** 버튼은 묻지 않고 곧바로 이웃 시야로.
- **검토 완료** 버튼을 누르면 표시를 저장하고 **다음 시야로 넘어간다.** 해제할 때만
  한 번 더 묻는다 — 잘못 눌러 풀리면 "다 본 시야" 표시가 조용히 사라진다.
- 이전 시야로 거슬러 갈 때는 그 시야의 **마지막 사진**에서 시작해 왕복이 끊기지 않는다.
- 시야를 떠나기 전에 **지연 저장 중인 교정을 밀어낸다**(`keepalive`). 지우고 곧바로
  → 를 눌러도 기록이 사라지지 않는다.

### 판정을 사람이 고칠 수 있게

- 우클릭으로 분류를 직접 지정한다: **원형 · 원형 파편 · 봉상 · 봉상 파편**, 그리고
  형태가 아니라 속(屬)으로 알아보는 **Eucampia**(메뉴에서 줄을 그어 나눴다).
  사람의 지정이 자동 판정을 덮어쓰되 원래 값을 `cls_auto` 로 남긴다.
- 개체마다 **코멘트**를 달 수 있고 사진 오른쪽에 나열된다. 목록에 커서를 올리면 그
  개체가 선택되고, 개체를 고르면 그 코멘트가 강조된다.
- **시야 전체 코멘트**는 오른쪽 아래 고정 칸에서 그 자리로 적는다.
- 분류 정의는 `data.py` 의 `CLASS_LABELS` **한 곳**에 있다 — 메뉴·배지·필터·집계가
  모두 그것을 읽으므로 분류를 더할 때 한 줄만 고친다.

### 검출 결과만 보는 화면 (`/d/<slug>/crops/`)

검출된 개체만 bbox 로 잘라 썸네일 격자로 늘어놓는다. 시야를 하나씩 넘겨보지 않고
"이것들이 정말 규조각인가" 를 한 화면에서 훑기 위한 화면이다. 크기 내림차순이라
의심스러운 것이 뒤에 모인다.

- **방향을 세운다** — 마스크 폴리곤의 **면적 모멘트**로 주축을 구해 장축을 세로로
  돌린다. 꼭짓점만 PCA 하면 `approxPolyDP` 로 단순화된 점 간격이 고르지 않아
  결과가 치우친다. 회전과 자르기는 한 번의 affine 으로 함께 한다.
  합성 타원(0·20·45·70·110·160°)을 넣고 **결과 이미지를 다시 재서** 전부 90°로
  서는 것을 확인했다.
- **스케일바**를 얹는다(1·2·5, 이미지 폭의 40% 내림). 바는 칸이 아니라 **이미지에**
  붙인다 — `object-fit` 여백만큼 길이가 어긋나기 때문이다.
- 형태·사람지정·코멘트 유무로 거를 수 있다.

### 재현율을 눈으로 볼 수 있게

우상단 **탈락** 체크박스를 켜면 문턱에서 떨어진 후보가 빨간 점선 테두리로 보인다.
기본은 꺼짐이다(시야당 100개가 넘는다). 이것이 재현율 실측의 도구가 된다 — 보이는
규조각 중 점선만 있는 것을 세면 문턱이 놓친 양이고, 점선조차 없는 것이 분할이
놓친 양이다.

### 그 밖에

머리글을 한 줄로 줄이고(경로·그룹·태그를 제목 옆으로) 본문의 세 줄을 걷어냈다.
교정 버튼을 사진 위로 올렸다. 목록 표지를 합성본으로 바꾸고 검출 마스크를 얹었다.
데이터셋 화면에 **자동 검출 → 교정 후** 개수와 교정량을 한 줄로 넣었다.
확대하면 **원본 화소로 갈아 끼우고**(1600 px 축소본을 늘려 보고 있었다), 배율
표시를 **원본 기준**으로 바꿨다(화면에 맞춘 상태가 53%다).

## 4. 검토 중에 드러난 버그들

도구를 쓰기 시작하니 조용히 틀리던 것들이 드러났다. **전부 "예외가 나지 않고 그냥
틀린 결과를 보여주는" 종류다.**

### 4.1 지운 개체가 저장할 때마다 되살아났다

문턱을 올려 `refilter` 를 돌리면 사람이 지워 둔 개체가 탈락분으로 옮겨간다(실제로
12개 있었다). 그때 서버가 그것을 `manual`(수동 복구)로 표시했고, 클라이언트는
복구 목록을 **`manual` 플래그로 되짚고** 있었다. 그래서 그 개체가 `removed` 와
`accepted` 양쪽에 들어가고, 저장 후 새로고침하면 **지운 것이 살아있는 개체로
뒤집혔다.**

고친 방향은 "**사람이 지웠다가 이긴다**" 다. 복구 목록은 서버가 `accepted_keys` 로
그대로 내려 주고 클라이언트는 추론하지 않는다. 유령에는 `manual` 대신
`from_reject`(기록이 탈락분에서 왔다는 표시)를 붙이고, 유령은 "이 자리의 탈락 후보"
목록에서 빼 같은 개체가 두 곳에 나오지 않게 했다.

### 4.2 교정을 되돌려도 옛 상태가 따라붙었다 (캐시 오염)

`detection_for()` 가 **mtime 캐시에 담긴 원본 dict 에 직접 써 넣고** 있었다.

```
지웠다 되살린 뒤      -> removed: True     (남아 있었다)
분류 지정을 해제한 뒤  -> cls: 'eucampia'   (남아 있었다)
메모를 지운 뒤        -> note: '메모'       (남아 있었다)
```

후보를 복사한 뒤 손대도록 고쳤다. 이 종류의 버그는 화면만 보고는 원인을 짚을 수
없어서(파일에는 제대로 지워져 있다) 특히 나쁘다.

### 4.3 여러 줄 `{# #}` 주석이 화면에 그대로 나왔다

Django 의 `{# #}` 는 **한 줄짜리만** 주석이다. 토크나이저 정규식이 `{#.*?#}` 인데
`re.DOTALL` 이 없어, 줄을 넘기면 주석 토큰으로 인식되지 않고 텍스트로 출력된다.
5개가 화면에 노출돼 있었다. `{% comment %}` 로 바꿨다.

### 4.4 확대하면 bbox 선이 두꺼워졌다

보상 코드가 있었는데 하한 때문에 거꾸로 동작했다.

```js
el.style.borderWidth = Math.max(1, 2 / k) + 'px';   // k > 2 면 1px 에 고정
```

`2/k` 는 맞는 계산인데 `Math.max(1, …)` 이 2배를 넘는 순간 1px 로 묶어서, 화면상
두께가 `1 × k` 로 배율만큼 두꺼워졌다(12배에서 12px). canvas 에 `--inv`(= 1/배율)를
얹고 CSS 가 `calc(2px * var(--inv))` 로 곱하게 바꿨다. hover 후광과 유령 ✕ 표시도
같이 정리됐고(보상이 아예 없었다), 인라인 스타일에 덮여 죽어 있던
`.box.sel { border-width: 3px }` 도 살아났다.

### 4.5 `history` 가 가려져 있었다

이 스코프에는 교정 이력용 지역 변수 `history` 가 있어서 `history.replaceState` 가
조용히 아무 일도 하지 않았다. `window.history` 로 고쳤다.

### 4.6 목록 타일에서 Eucampia 가 황색으로 보였다

되살린 개체(`manual`, 주황)에 Eucampia 를 지정했는데 타일이 `manual` 을 먼저 그렸다.
사진 화면에는 "사람 지정이 이긴다" 규칙이 있었지만 타일에 빠져 있었다. 규칙을
`data.mask_class()` 하나로 모았다 — **사람 지정 > 되살린 표시 > 자동 판정**.

### 4.7 이미지 응답에 캐시 검증자가 없었다

`Cache-Control`·`Last-Modified`·`ETag` 가 전부 없어서, 합성본을 다시 만들어도
브라우저가 옛 그림을 쓸 수 있었다. 주소에 원본 mtime(`v=`)을 박고
`Cache-Control: immutable` 로 보낸다 — 내용이 바뀌면 주소가 바뀌므로 늘 맞고,
두 번째 방문은 오히려 빨라진다. **뒤로 가기**(bfcache)로 돌아올 때도 옛 화면이
남으므로 `pageshow` 에서 다시 받는다.

## 5. 진단만 하고 적용하지 않은 것 — bbox 를 부풀리는 떠돌이 픽셀

"마스크는 같은데 bbox 만 다른 개체가 꽤 있다" 는 관찰에서 시작했다. 사진 한 장을
같은 설정으로 다시 돌려 원본 마스크를 뜯어봤다.

```
SAM bbox (2293, 257, 163, 161)  마스크면적 13003
  성분 1: 면적 13,002  bbox (2293, 257, 139, 162)   <- 본체. 이것이 그려지는 마스크
  성분 2: 면적      1  bbox (2456, 349,   1,   1)   <- 오른쪽 24 px 떨어진 픽셀 한 개
```

**떠돌이 픽셀 하나가 bbox 를 24 px 넓혔다.** 원인은 두 갈래가 다른 것을 본다는
데 있다 — bbox 는 SAM 이 준 것(마스크의 **모든** 픽셀)이고, 폴리곤과 형태 지표는
`shape_metrics()` 가 **가장 큰 윤곽 하나만** 쓴다. 후처리를 껐으므로
(`apply_postprocessing=False`, `min_mask_region_area=0`) 작은 분리 조각이 남는다.

- 이 사진에서 연결 성분이 2개 이상인 마스크: 24/117 (21%)
- 통과분 전체에서 bbox 가 본체보다 10 px 넘게 큰 것: 694/2,522 (27.5%), 50 px 초과
  333개, bbox 면적 1.5배 초과 303개, 최대 8.9배

**그리고 이것이 중복 정리를 무력화한다.** 상호 포함율 0.8 문턱을 bbox 로 재는데,

```
지금:           cover(#4 안에서 #5) = 0.794  <- 문턱을 아슬아슬하게 피해 둘 다 남았다
본체 bbox 라면: cover(#4 안에서 #5) = 0.925  <- 정리되어 텍스처 높은 쪽만 남았을 것
```

### 왜 적용하지 않았나

`tighten_bbox.py` 를 만들어 dry-run 까지 했다(개체 18,936개 중 11,472개의 bbox 가
줄고, 중복 정리를 다시 돌리면 2,522 → 2,193). **그런데 `bbox_xywh` 가 교정 기록의
키다.** 스크립트가 키를 함께 옮기고 `review/` 를 백업하지만, 전수 검토를 막 끝낸
직후에 키를 흔드는 것은 순서가 아니라고 보아 **적용하지 않고 두었다.**

같이 드러난 것 하나 — bbox 를 줄이면 33개가 `크기범위밖` 으로 떨어지는데, 그 33개는
**타원 장축이 11.2 µm(중앙)로 관문 안에 있다.** README 는 "크기 관문은 타원 장축으로
본다" 고 정해 뒀지만 `refilter.py` 와 `filter_records()` 는 bbox 긴 변으로도 한 번 더
걸러 왔다(지금까지는 bbox 가 부풀어 있어 이 관문이 거의 안 걸렸다). 적용할 때
함께 정리해야 한다.

## 6. 검증 방식에 대해

이 머신에는 node·jsdom·브라우저가 없어서 **JS 를 실행할 수 없었다.** 004 의
jsdom 38항목은 다른 환경에서 돌린 것이다. 그래서 이렇게 했다.

- 브라우저가 받는 인라인 JS 를 렌더해서 뽑아 **구문 검사**(esprima)와 **미선언
  참조 검사**를 돌렸다. 이 검사가 4.5(`history` 가려짐)를 잡았다.
- 서버 쪽은 전부 Django 테스트 클라이언트로 왕복 시험했다. 교정 기록을 건드리지
  않도록 **격리된 `REVIEW_DIR`** 로 돌렸다.
- 기하 계산은 **결과를 다시 재서** 확인했다(방향 세우기, 스케일바 길이). 부호
  규약을 추측하지 않는 것이 요령이다.

**브라우저에서 눌러 본 것은 아니다.** 실제 동작 확인은 사용자가 뷰어를 쓰면서
했고, 이번에 고친 것 상당수가 그 과정에서 나왔다.

4. **데이터셋 내보내기** — `labels` 가 정답이 되고 `done` 으로 신뢰도를 가른다.
   전수 검토가 끝났으므로 이제 막을 것이 없다
