## 1. 자동화가 지우기를 눌렀다 — 자료 손실은 없었다

지점을 화면에서 만들려고 브라우저를 몰았는데, 두 번째 지점에서 **방금 만든
`RS14-GC04` 가 지워졌다.**

원인은 폼 선택자다. `form:has(input[name=kind][value=locality])` 로 만들기 폼을
잡았는데, **`_delbtn.html` 도 같은 숨은 칸을 쓴다** — 지점마다 지우기 폼이
하나씩 있으니 선택자가 그것들까지 함께 잡았고, `.first` 가 DOM 순서상 앞선
지우기 단추를 눌렀다. 그리고 확인 대화상자를 **자동으로 승인**하게 해 둔 것이
마지막 문을 열었다.

**잃은 것은 없다** — 방금 만든 빈 지점이라 시료도 코어 자료도 없었고,
`check_db` 도 그대로였다. 다시 만들 때 둘을 고쳤다:

- 만들기 폼은 **`code` 칸이 있는 것**으로 짚는다 (`:has(input[name=code])`)
- **확인 대화상자를 거절한다.** 만들기에는 확인이 없으니, 확인이 뜬다는 것은
  누르려던 것이 만들기가 아니라는 뜻이다

139 가 문턱을 세워 둔 덕에 **자료가 있는 지점이었으면 막혔을 것이다.** 마침
그 커밋이 이 배포 안에 들어 있었다.

## 2. `check_db` 7번이 코어 자료를 몰랐다

반입 직후 새 경고가 떴다 — "지점에 시료가 있다 2건 · 빈 지점이 목록·지도에
자리만 차지한다". `RS14-GC04`·`RS19-GC17` 은 **시료가 0개이고 코어 자료만
있다.** 검사가 그것을 모르면 **경고가 늘 켜져 있게 되고, 늘 켜진 경고는 아무도
안 봐서 진짜 빈 지점을 놓치게 만든다.**

`_has_core_data()` 를 더해 걸렀다. **표가 없는 옛 판에서도 안 죽는다** —
이 검사는 뷰어 이미지 안의 코드로 도는데 무결성 검사가 배포 순서에 매달리면
정작 필요한 날 못 돌린다(같은 파일의 `catalog` 임포트와 같은 자리다).

139 와 같은 줄이다: **모델을 하나 더하면 그것을 모르는 검사·문턱이 조용히
틀린다.**

## 3. 중간 CSV 는 `/data3/DiaRUGA/tmp/coredata` 에 둔다

계획은 `/data3/DiaRUGA/coredata` 였는데 **그 부모가 그룹 쓰기가 없다**
(`drwxr-xr-x paleoadmin:paleoadmin`) — `sclee` 로는 못 만든다. 아래 `tmp/` 는
그룹 쓰기가 되고 `dbtool` 이 `/data3/DiaRUGA` 를 통째로 물고 있어 그대로 보인다.

**중간 CSV 는 언제든 xlsx + 매핑표로 다시 뽑는 산물이라** 그 자리가 맞다.
제 이름을 주고 싶으면 `paleoadmin` 에서 한 번:

```bash
sudo -u paleoadmin mkdir -p /data3/DiaRUGA/coredata
sudo -u paleoadmin chmod g+w /data3/DiaRUGA/coredata
```
