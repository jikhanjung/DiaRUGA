# 090 — 같은 개체 묶기: 문턱 실측과 스키마 (P11 0·1단계)

2026-08-09 · [P11](20260809_P11_object-linking.md) 의 0·1단계

## 0단계 — 실측이 설계를 확인했다

yolo-3차의 이웃 이미지 쌍 13,523곳에서 쟀다 (`tools/measure_link_thresholds.py`,
읽기 전용):

```
[1] 근접 창(기준 bbox 1.5배) 안 후보 수 — 팝업 줄 길이
    0개 46.0% · 1개 37.5% · 2개 13.2% · 3개 2.5% · 4개+ 0.8%
[2] 최선 후보 IoU (겹침이 아예 없는 46% 제외)
    중앙 0.83 · IoU ≥ 0.5 가 77.4%
[3] 최선-차선 간격
    간격 < 0.2 (헷갈리는 자리) 21.4%
    "IoU ≥ 0.5 이고 간격 ≥ 0.3" (안전한 미리 고르기) 65.8%
```

읽는 법:

- **사용자의 직감("하나씩, 많아야 두셋")이 맞다** — 창 안 후보가 1개인 경우가
  37.5%, 2~3개가 15.7%, 4개 이상은 0.8%뿐이다. **K=1.5 로 확정** (2.0 으로
  넓혀도 0개가 46→42% 로 거의 안 줄고 잡음만 는다)
- **0개가 46%다.** 이웃 프레임에서 같은 개체가 안 잡힌 경우가 절반 —
  초점면이 다르면 검출이 안 되는 것이 자연스럽다. **"(없음)" 이 일급 선택지**
  여야 한다는 근거다
- **미리 고르기 규칙 확정** (사용자 승인 2026-08-09): `IoU ≥ 0.5 이고 차선과의
  간격 ≥ 0.3` 일 때만 ✓ 를 미리 찍는다 — 맞을 수 있는 것의 2/3 을 자동으로
  덮으면서, 헷갈리는 21% 는 사람 손에 남긴다. 자동값이 사람 판단을 오염시키는
  자리라 보수적으로 간다

## 1단계 — 스키마

`ObjectLink`(시야·batch·note) + `ObjectLinkMember`(image·batch·mask_key·
is_rep·geom). 마이그레이션 `0030` — **순수 CreateModel 뿐이다** (자료 이동
없음, 자동 생성본을 읽고 그대로 썼다).

결정 그대로다 (P11 §2·§3):

- `Candidate` FK 가 아니라 `(image, batch, mask_key)` — 재검출이 사람의
  묶음을 못 지운다
- `batch` 는 `PROTECT` — RunBatch 를 지우려면 사람의 묶음부터
- 제약 넷: 이미지마다 하나 · 마스크는 한 묶음에만(batch NULL 짝 제약 포함,
  `ObjectReview` 와 같은 모양) · 대표는 둘일 수 없다
- **대표 0개는 DB 가 못 막는다** — 저장 쪽 약속이고 `check_db.py` 8번이 센다

`check_db.py` 에 **8번(같은 개체 묶음)** 을 더했다: 대표가 하나인가 ·
멤버가 둘 이상인가 · 멤버가 묶음의 시야 안인가 · 마스크가 실재하는가.

> **`/srv` 로 아직 안 옮겼다** — 새 check_db 는 `ObjectLink` 를 임포트하므로
> 0030 이 든 뷰어 이미지가 배포된 뒤에 `dbsync.sh` 해야 한다. 지금 옮기면
> 컨테이너의 옛 models.py 가 몰라서 죽는다 (9.2절의 그 제약이다).

시험 7개 — 제약 넷을 어겨 보고 IntegrityError·ProtectedError 가 실제로 나는
것, batch=NULL 짝 제약, 시야 CASCADE 까지. 283개 전부 통과.
